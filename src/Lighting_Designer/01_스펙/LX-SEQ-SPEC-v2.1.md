# LX-SEQ 포맷 명세서 v2.1

> 무대 1곡 단위 조명연출 시퀀스 표준 포맷
> 제정 2026-08-20 · v1.1 (샘플 검증 반영) · **v2.0 (실행 레이어 신설, 타깃 콘솔 grandMA3)** · **v2.1 (RIG 팩 분리)** · 1차 사용자: 조명 콘솔 오퍼레이터 · 기준 축: 곡 구조 + 타임코드

---

## 0. 이 포맷이 풀려는 문제

조명 큐시트는 대개 개인 노트에 가깝다. 작성자가 아니면 실행이 안 되고, 다음 곡·다음 공연에서 재사용이 안 된다. LX-SEQ v1은 다음 세 가지를 강제한다.

1. **한 큐 = 한 행.** 서술형 문장이 아니라 실행 지시로만 쓴다.
2. **모든 큐는 곡의 어디인지(Section)와 언제인지(TC)를 동시에 갖는다.** 음원이 바뀌어도 구조는 남는다.
3. **값의 종류가 제한된다.** 전환 타입·강도·색은 자유 텍스트가 아니라 정해진 값에서 고른다.

성공 기준은 **작성자가 아닌 오퍼레이터가 이 시트만 보고 동일하게 실행할 수 있는가**이다.

---

## 1. 문서 구조

한 곡 = 한 파일(`.xlsx`). **연출 레이어 3시트 + 실행 레이어 3시트**로 구성한다.

| 레이어 | 시트명 | 역할 | 필수 |
|---|---|---|---|
| 연출 | `HEAD` | 곡·공연 메타데이터, 장비 그룹 정의, 색 팔레트 | 필수 |
| 연출 | `CUE` | 큐 시퀀스 본문 (한 큐 = 한 행) — 사람이 읽는 정본 | 필수 |
| 연출 | `NOTE` | 미확정 항목, 리허설 변경 이력, 스펙 개정 후보 | 필수 |
| 실행 | `PATCH` | Fixture ID·기종·모드·Universe/Address·그룹 매핑 | v2.0 |
| 실행 | `PRESET` | 프리셋 정의 (POS/COL/BM/FX) — 콘솔 레코드 대상 | v2.0 |
| 실행 | `CUE-EX` | 큐 × 그룹별 파라미터·타이밍 (long format) — 기계가 읽는 정본 | v2.0 |

연출 레이어(§1~5)만으로도 v1.1 호환 큐시트로 유효하다. 실행 레이어는 콘솔 프로그래밍 레벨이 필요할 때 추가한다.

## 2. HEAD 시트 — 메타데이터

### 2.1 곡·공연 정보

| 키 | 값 예시 | 규칙 |
|---|---|---|
| `SONG_TITLE` | 밤편지 | 필수 |
| `ARTIST` | — | 선택 |
| `RUNTIME` | `03:42.0` | 필수. `mm:ss.f` |
| `BPM` | `72` | 선택. 가변 BPM이면 `72→96` |
| `TIME_SIG` | `4/4` | 선택 |
| `VENUE` | 세종문화회관 대극장 | 선택 |
| `SHOW_DATE` | `2026-09-12` | 선택 |
| `CONSOLE` | `grandMA3` | 필수. 실행 콘솔 |
| `TC_SOURCE` | `LTC` \| `MTC` \| `MANUAL` | 필수. 타임코드 수신 방식. `MANUAL`이면 오퍼 수동 큐잉 |
| `TC_ORIGIN` | `00:00.0 = 곡 첫 음` | 필수. TC 0점의 정의를 반드시 명시 |
| `TC_METHOD` | `VERIFIED` \| `DERIVED` | 필수. §2.4 |
| `SPEC_VER` | `LX-SEQ v2.1` | 필수 |
| `RIG_REF` | 참조하는 RIG 팩 ID + rev (예 `LXSEQ_RIG_01 r1`) | v2.1 필수 |
| `AUTHOR` | — | 필수 |
| `REV` | `r3` | 필수. 개정 차수 |

> **TC_ORIGIN을 생략하지 않는다.** 큐시트 사고의 대부분은 "0초가 어디냐"가 사람마다 달라서 생긴다. 카운트인이 있으면 카운트인 시작인지 첫 음인지 문장으로 적는다.

### 2.4 `TC_METHOD` — 타임코드 신뢰 등급 (v1.1 신설)

| 값 | 의미 | 사용 조건 |
|---|---|---|
| `VERIFIED` | 실제 음원을 듣고 각 섹션 경계를 확인함 | 리허설·음원 대조 완료 후에만 |
| `DERIVED` | BPM·박자로 마디 연산해 산출함 (청취 미검증) | 음원 접근 전 사전 설계 단계 |

`DERIVED` 시트는 **큐시트 상단과 파생 산출물 모두에 경고를 표기**하고, 리허설 LTC 대조 전까지 실행 확정본으로 취급하지 않는다. 픽업 마디·하프바 삽입이 하나만 있어도 이후 전 구간이 어긋난다.

### 2.2 장비 그룹 정의 (`FIXTURE_GROUP`)

CUE 시트의 `Fixture Group` 열은 여기 정의된 **약칭만** 쓴다.

| 약칭 | 정의 | 예시 |
|---|---|---|
| `FOH` | 전면 페이스 라이트 | Profile ×8 |
| `KEY` | 주 인물광 | — |
| `BACK` | 백라이트 / 실루엣 | — |
| `SIDE-L` / `SIDE-R` | 사이드 붐 | — |
| `WASH-U` / `WASH-D` | 업/다운 스테이지 워시 | — |
| `MOVER-U` / `MOVER-D` | 무빙 스팟·워시 | — |
| `BLIND` | 블라인더 | — |
| `STROBE` | 스트로브 | — |
| `LED-W` | LED 월 / 픽셀 | — |
| `HAZE` | 헤이저 / 포거 | — |
| `FOLLOW-1` / `FOLLOW-2` | 팔로우스팟 | 오퍼 별도 |

행마다 실제 기종·대수·주소를 채운다. 프로젝트에 없는 그룹은 행을 지운다. **새 약칭이 필요하면 여기 먼저 추가한 뒤 CUE에서 쓴다.**

### 2.3 색 팔레트 (`PALETTE`)

| 팔레트 ID | 색상명(한글) | 참고값 | 용도 |
|---|---|---|---|
| `P1` | 딥 앰버 | ~2200K / R255 G160 B60 | 따뜻함·회상 |
| `P2` | 웜 화이트 | ~3200K | 인물 기본 |
| `P3` | 뉴트럴 화이트 | ~5600K | 사실·현재 |
| `P4` | 콜드 블루 | ~8000K / R120 G170 B255 | 냉정·거리감 |
| `P5` | 딥 블루 | R30 G50 B140 | 밤·고독 |
| `P6` | 마젠타 | R220 G60 B160 | 고조·화려 |
| `P7` | 시안 | R60 G200 B220 | 각성·전환 |
| `P8` | 블랙아웃 | — | 무광 |

- **흑백 인쇄 대응**: CUE 시트의 색 열에는 팔레트 ID와 **한글 색상명을 반드시 병기**한다(`P5 딥블루`). 셀 배경색만으로 색을 전달하지 않는다.
- 곡마다 팔레트를 재정의해도 되지만 **ID 체계는 유지**한다.

## 3. CUE 시트 — 큐 시퀀스 본문

### 3.1 열 규격 (14열, 순서 고정)

| # | 열 이름 | 필수 | 타입 | 규칙 |
|---|---|---|---|---|
| 1 | `Q#` | ● | 문자 | `Q010`, `Q020` … **10 단위 증분**. 중간 삽입은 `Q015` |
| 2 | `Section` | ● | enum | §3.2 곡 구조 값 |
| 3 | `TC In` | ● | 시간 | `mm:ss.f` (예 `01:12.5`). 미확인 시 `확인필요` |
| 4 | `TC Out` | ○ | 시간 | 다음 큐 시작과 같으면 생략 가능 |
| 5 | `Dur` | ○ | 시간 | `TC Out - TC In` 자동 산출 |
| 6 | `Mood` | ● | 텍스트 | 2~4 단어. 예 `정적, 회상` |
| 7 | `Color` | ● | 문자 | `주색 / 보조색` 형식. 예 `P5 딥블루 / P2 웜화이트` |
| 8 | `Intensity` | ● | 정수 | `0`–`100` (%). 그룹별 차등이면 `KEY 70 / BACK 40` |
| 9 | `Fixture Group` | ● | 약칭 | HEAD §2.2 약칭. 복수는 `+`로 연결 (`KEY+BACK`) |
| 10 | `Movement` | ○ | enum+ | §3.4 |
| 11 | `Effect` | ○ | enum+ | §3.5 |
| 12 | `Transition` | ● | enum | `SNAP` \| `FADE` \| `XFADE` \| `BUMP` |
| 13 | `Fade` | ● | 소수 | 초, 소수 1자리 (`2.0`). `SNAP`/`BUMP`는 `0.0` |
| 14 | `Note` | ○ | 텍스트 | 실행 주의·수동 큐 지시·팔로우 지시 |

### 3.2 `Section` 허용값

`PRE-ROLL` `AMBI` `INTRO` `VERSE1` `VERSE2` `VERSE3` `PRE1` `PRE2` `PRE3` `CHORUS1` `CHORUS2` `CHORUS3` `CHORUS4` `BRIDGE` `BREAK` `DROP` `SOLO` `OUTRO` `TAG`

- `PRE-ROLL` = 곡 시작 전 준비 동작(헤이즈 선투입, 프리셋 이동). **음수 TC 표기 허용** — `-00:30.0`. (v1.1 신설)
- `AMBI` = 곡 전후 앰비언트(입·퇴장, 정적).
- **반복 구간은 모두 숫자를 붙여 구분한다** — 후렴뿐 아니라 프리코러스·벌스도 `PRE1`/`PRE2`, `VERSE1`/`VERSE2`. 같은 이름을 두 번 쓰지 않는다. *(v1.1: v1.0의 `PRE`는 반복 곡에서 즉시 충돌해 `PRE1~3`으로 교체)*
- 더블 후렴(연속 2회분)은 `CHORUS3`+`CHORUS4`로 나누거나, 한 섹션으로 두고 내부에 복수 큐를 배치한다.
- 위 값으로 표현 불가한 구조는 NOTE 시트에 「스펙 개정 후보」로 남긴다.

### 3.3 `Transition` 정의

| 값 | 의미 | Fade |
|---|---|---|
| `SNAP` | 즉시 전환. 이전 상태 소멸 | `0.0` |
| `FADE` | 지정 시간 동안 새 상태로 상승 | `0.1`–`60.0` |
| `XFADE` | 이전 큐와 교차 페이드 | `0.1`–`60.0` |
| `BUMP` | 순간 점등 후 자동 복귀 (히트) | `0.0` |

### 3.4 `Movement` 허용값

`STATIC` `SWEEP-H` `SWEEP-V` `CIRCLE` `FAN-OUT` `FAN-IN` `TILT-UP` `TILT-DOWN` `FOLLOW` `RANDOM`

속도는 뒤에 붙인다: `SWEEP-H @slow` / `@mid` / `@fast` / `@8bar`(마디 동기).

### 3.5 `Effect` 허용값

`NONE` `CHASE` `STROBE` `PULSE` `BREATHE` `TWINKLE` `RAINBOW` `BLINDER-HIT` `HAZE-BURST` `LED-CUE`

비트 동기 이펙트만 마디·박자를 붙인다: `CHASE @1/8` `PULSE @1beat` `STROBE @2bar`.

### 3.6 작성 규칙 (HARD)

1. **한 큐 = 한 행.** 한 행에 두 가지 사건을 넣지 않는다.
2. **TC 역전·중첩 금지.** `TC In`은 단조 증가한다. `TC Out`은 다음 큐의 `TC In`을 넘지 않는다.
3. **첫 큐는 `Q010` / `AMBI` 또는 `INTRO`**, 마지막 큐는 반드시 블랙아웃 또는 다음 곡 인계 상태를 명시한다.
4. **추측 타임코드 금지.** 음원을 실제로 확인하지 못했으면 `확인필요`를 적고 NOTE 시트에 사유를 남긴다. 그럴듯한 초를 지어내지 않는다.
5. **전환 밀도 상한.** 원칙적으로 **8초에 1큐 이하**. 초과 구간은 `Effect`(자동 반복)로 처리하고 수동 큐를 늘리지 않는다.
   - **예외 (v1.1)**: 곡 종료 암전 큐, `PRE-ROLL` 구간, `BUMP`(자동 복귀라 오퍼 부하 없음)는 밀도 계산에서 제외한다.
6. **수동 큐 표기.** `TC_SOURCE`가 `MANUAL`이거나 특정 큐만 수동이면 `Note`에 `[MANUAL]`을 접두로 적는다.
7. **서술형 금지.** `Note`도 명령형·단문으로 쓴다. "여기서 감정이 고조되므로…" → "블라인더 히트, 객석 방향 주의".

### 3.7 예시 행

```
Q010 | AMBI    | 00:00.0 | 00:04.0 | 04.0 | 정적, 여백      | P5 딥블루 / —          | 15            | WASH-U+HAZE   | STATIC        | NONE        | FADE  | 4.0 | 헤이즈 선투입
Q020 | INTRO   | 00:04.0 | 00:28.0 | 24.0 | 회상, 온기      | P1 딥앰버 / P2 웜화이트 | KEY 45 / BACK 25 | KEY+BACK+WASH-U | STATIC     | BREATHE @4bar | XFADE | 3.0 | —
Q030 | VERSE1  | 00:28.0 | 01:12.5 | 44.5 | 담담, 근접      | P2 웜화이트 / P5 딥블루 | KEY 70 / BACK 40 | KEY+BACK      | STATIC        | NONE        | XFADE | 2.0 | [MANUAL] 보컬 첫 소절
Q040 | PRE     | 01:12.5 | 01:24.0 | 11.5 | 축적, 긴장      | P7 시안 / P5 딥블루     | 55            | SIDE-L+SIDE-R | TILT-UP @slow | PULSE @1beat | FADE  | 6.0 | 강도 서서히 상승
```

## 4. NOTE 시트

| 열 | 내용 |
|---|---|
| `구분` | `확인필요` \| `리허설변경` \| `스펙개정후보` \| `장비이슈` |
| `대상 Q#` | 해당 큐 번호. 전역이면 `-` |
| `내용` | 한 문장 |
| `기록일` | `YYYY-MM-DD` |
| `상태` | `미해결` \| `해결` |

**「확인 필요 항목」은 이 시트에 모은다.** 큐시트를 전달할 때 이 시트의 `미해결` 행을 함께 보고한다.

# PART II — 실행 레이어 (v2.0 신설, 타깃 콘솔: grandMA3)

## 8. 설계 원칙

1. **절대값 대신 프리셋 참조.** Pan/Tilt 절대값은 극장·리깅 종속이라 시트에 쓰지 않는다. Position/Beam은 `POS.xx`/`BM.xx` 프리셋 ID로 참조하고, 프리셋의 **무대 의미**만 정의한다. 현장 작업 = 프리셋 레코드로 국한되어 곡 시퀀스가 극장 간 이식 가능해진다.
2. **트래킹(tracking) 의미론.** `CUE-EX`에는 **변경되는 파라미터만** 적는다. 적지 않은 파라미터는 이전 큐 상태를 유지한다(grandMA3 트래킹과 동일). 소등도 명시적 변경이다 — `Dim 0` 행을 반드시 적는다.
3. **파라미터별 개별 타이밍.** 큐 하나 안에서 Intensity/Position/Color/Beam이 서로 다른 페이드·딜레이를 가질 수 있다(MA3 individual timing). 이것이 콘솔급 큐의 본질이다.
4. **연출 레이어가 상위 정본.** `CUE`와 `CUE-EX`가 충돌하면 `CUE`(의도)를 기준으로 `CUE-EX`(구현)를 수정한다.

## 9. PATCH 시트

| 열 | 규칙 |
|---|---|
| `Group` | HEAD §2.2 약칭과 1:1 |
| `Fixture Type` | 기종명 (GDTF 명칭 권장) |
| `Mode` | DMX 모드 |
| `Count` | 대수 |
| `Fixture ID` | MA3 FID 범위 (예 `101 thru 108`) |
| `Universe.Address` | 예 `2.001` — 현장 패치 확정 전 `확인필요` |
| `Note` | 리깅 위치 등 |

## 10. PRESET 시트

프리셋 ID 체계: `{TYPE}.{2자리}` — TYPE ∈ `POS`(Position) | `COL`(Color) | `BM`(Beam: zoom·gobo·prism·frost·focus 통합) | `FX`(Phaser)

| 열 | 규칙 |
|---|---|
| `Preset ID` | `POS.01` 형식 |
| `이름(무대 의미)` | "보컬 센터 페이스" 등 — 현장 레코드의 기준 서술 |
| `대상 Group` | 적용 그룹 (`ALL` 가능) |
| `절대값` | COL은 RGB/CCT 필수, BM은 zoom°·gobo 슬롯 등 가능한 것만, POS는 `현장 레코드` |
| `MA3 Pool` | 콘솔 풀 번호 (예 `Preset 2.1`) — 프로그래밍 후 기입 |

- `COL.xx`는 연출 레이어 팔레트 `P.xx`와 **1:1 매핑을 유지**한다 (`COL.04` = `P4`).
- `FX.xx`는 Phaser 정의: 파형(2-step/sine/random), 대상 어트리뷰트, Low/High 값, 기본 Width·Phase.

## 11. CUE-EX 시트 (long format — 한 큐 × 한 그룹 = 한 행)

### 11.1 열 규격 (17열, 순서 고정)

| # | 열 | 규칙 |
|---|---|---|
| 1 | `Q#` | CUE 시트 Q#와 일치 (부분집합 금지 — 모든 큐에 최소 1행) |
| 2 | `Group` | PATCH 정의 약칭. `ALL` 허용 |
| 3 | `Dim` | 0–100(%). 빈칸 = 트래킹 |
| 4 | `COL` | `COL.xx` 참조. 빈칸 = 트래킹 |
| 5 | `POS` | `POS.xx` 참조 |
| 6 | `BM` | `BM.xx` 참조 |
| 7 | `FX` | `FX.xx` 참조. `OFF` = 페이저 정지 |
| 8 | `FX-Rate` | Phaser 속도 **BPM 단위** (§11.3 공식) |
| 9 | `FX-Phase` | `0` 또는 `0..360`(그룹 내 위상 확산) |
| 10 | `FX-Width` | % (2-step에서 ON 비율) |
| 11 | `I-Fade` | Intensity 페이드(초) |
| 12 | `I-Delay` | Intensity 딜레이(초) |
| 13 | `P-Fade` | Position 페이드(초) |
| 14 | `C-Fade` | Color 페이드(초) |
| 15 | `B-Fade` | Beam 페이드(초) |
| 16 | `Snap` | `Y` = 해당 행 전체 스냅 (CUE `SNAP`과 정합) |
| 17 | `Note` | 실행 주의 |

### 11.2 작성 규칙 (HARD)

1. 변경 파라미터만 기입한다. 빈칸 = 트래킹.
2. 소등은 `Dim 0` + `I-Fade`를 명시한다. 침묵으로 끄지 않는다.
3. `CUE` 시트의 `Intensity`·`Transition`·`Fade`와 모순되면 안 된다 (검증 항목 12).
4. 한 그룹의 이동(FAN-OUT 등 1회성 무브)은 Phaser가 아니라 `POS` 참조 + `P-Fade`로 구현한다. 반복 무브(SWEEP·CIRCLE)만 `FX`.
5. 프리셋 ID는 PRESET 시트에 정의된 것만 쓴다 (검증 항목 13).
6. **분위기 그룹(HAZE 등)은 `CUE` Intensity 정합 비교에서 제외**한다 — 헤이저 출력은 조명 레벨이 아니다. 단, 분위기 그룹도 트래킹 대상이므로 곡 중 출력 변경·종료를 명시적으로 관리한다.

### 11.3 BPM 동기 공식 (HARD)

Phaser 속도는 곡 BPM에서 유도한다:

```
FX-Rate(BPM) = SongBPM ÷ 사이클당 박수
  @1/8  (8분음표) → 120 ÷ 0.5 = 240
  @1beat         → 120 ÷ 1   = 120
  @1bar  (4/4)   → 120 ÷ 4   = 30
  @2bar          → 120 ÷ 8   = 15
  @4bar          → 120 ÷ 16  = 7.5
```

연출 레이어의 `@표기`와 CUE-EX의 `FX-Rate` 수치는 이 공식으로 상호 검증한다 (검증 항목 15). MA3에서는 Speed Master에 곡 BPM(120)을 걸고 Phaser를 Speed Master 비율로 종속시키면 템포 변경에도 동기가 유지된다.

## 12. 콘솔 임포트 경로

- **CUE-EX는 CSV로도 병행 출력한다** (`…​.cue-ex.csv`, UTF-8, 헤더 포함) — 기계가 읽는 정본.
- **grandMA3**: 공식 CSV 임포트는 없다. 커뮤니티 Lua 플러그인(SequenceImporter 등, ma.tools)으로 CSV → 시퀀스 임포트, 또는 Lua로 매크로 생성. 프리셋은 현장 레코드가 선행되어야 한다.
- **ETC Eos**(참고): USITT ASCII 임포트 공식 지원 — CUE-EX → ASCII 변환기를 붙이면 큐 스택 직접 로드 가능.
- **Hog 4**(참고): 임포트 경로 없음. 종이 큐시트 기준 수동 프로그래밍.

## 13. RIG 팩 (v2.1 신설) — 쇼 단위 콘솔 기본설정 파일

곡마다 반복되는 기반 정보(장비·패치·그룹·프리셋·FX·콘솔 설정)를 **쇼 단위 별도 파일**로 분리한다.
파일명: `LXSEQ_RIG_{번호}_{쇼이름}_{rev}.xlsx` + 패치 CSV 병행 출력.

| 시트 | 역할 |
|---|---|
| `RIG-HEAD` | 쇼·베뉴·콘솔 메타 + `DATA_STATUS`(ASSUMED/CONFIRMED) |
| `FIXTURE` | 장비 인벤토리 — 기종·모드·풋프린트(ch)·수량·리깅 위치·용도 |
| `PATCH` | **픽스처 단위** 패치 — FID·Universe.Address·주소 범위 (유니버스 계획에서 자동 계산, 512ch 초과 금지) |
| `GROUP` | MA3 그룹 풀 — 기본 그룹 + 파생 그룹(ALL·ODD/EVEN 등) |
| `PRESET-DIM·COL` | 딤머 레벨 프리셋 + 컬러 프리셋(연출 팔레트 1:1) |
| `PRESET-POS·BM` | 포지션(현장 레코드 가이드 포함) + 빔 프리셋 |
| `FX` | Phaser 라이브러리 — 어트리뷰트·파형·기본 Rate(BPM)·Width·Phase |
| `CONSOLE` | 콘솔 기본설정(출력·트래킹·SpeedMaster·TC·MIB·Inhibit) + 이그제큐터 레이아웃 |
| `NOTE` | 확인 필요 항목 |

**규칙 (HARD)**
1. 곡 파일 HEAD에 `RIG_REF` 필수. 곡 파일의 `CUE-EX` 그룹·프리셋 참조는 **RIG 팩에 정의된 것만** 사용한다 (검증 R7·R8).
2. 곡 파일의 `PATCH`/`PRESET` 시트는 RIG 팩의 **곡 관련 발췌본**이며, 충돌 시 RIG 팩이 정본이다.
3. FID 체계는 그룹당 100번대 블록 (101~ KEY, 201~ BACK …) — 곡 파일과 RIG 팩이 공유한다.
4. 안전 규칙: STROBE·BLIND는 Inhibit 페이더 상시 배치, Phaser는 SpeedMaster 종속, TC 유실 대비 수동 GO 폴백 명시.
5. RIG 검증 8항목(R1~R8): FID 고유성 · 주소 무충돌/512 이내 · 풋프린트 산술 · 유니버스 배치 완전성 · GROUP 유효성 · 프리셋 ID 고유성 · 곡 파일 그룹/프리셋 상호참조.

# design.md — GrandMA3 Copilot **런북 모드** 화면 (M7)

> 구현 대상: `GrandMA3 Copilot M7.dc.html` 디자인 산출물을 React + 순수 CSS로 옮기는 작업.
> **이 페이지는 코파일럿 메인 화면이 아니라 런북 모드(Runbook Mode) 페이지다.**
> 메인 화면(프리셋 풀 브라우저·콘솔 연결 UI 등)은 이미 구현돼 있고, 런북 모드는 그 위에 얹히는 별도 모드다.

## 0. 이 화면의 위치

| 구분 | 내용 |
|---|---|
| 모드 | **런북 모드** — 공연/리허설 중 곡 하나의 큐시트를 보고 수정 요청을 넣는 화면 |
| 아님 | 코파일럿 메인 화면(워크시트 입력, 프리셋 풀 브라우저, 콘솔 연결 관리)이 아니다 |
| SPEC | SPEC-LDDESIGN-001 §3.14 / REQ-078~085 / AC-018~020 |
| 스택 | React + 순수 CSS 단일 파일(`ui/src/styles.css`). Tailwind·shadcn·CSS-in-JS 금지 |
| 사용자 | 콘서트 조명감독. 어두운 객석에서 곁눈질로 확인. 넓은 데스크톱 전제(반응형 모바일 아님) |

### 메인 화면과 공유하는 것 (재구현 금지)
- **프리셋 풀 팝업**: 포지션/컬러/딤머/이펙트/페이저 선택 팝업은 **메인 화면의 프리셋 풀 브라우저 컴포넌트를 그대로 마운트**한다. 이 디자인 파일의 팝업 마크업은 그 컴포넌트의 외형을 재현한 자리표시자다.
  - 헤더: 청록 바 `#12776c`, `프리셋 풀 {번호} · {이름} — {개수}개`, 우측 ◉ / ✕
  - 본문: `#0b1012`, 7열 타일 그리드, 타일 `#0e1519` + 테두리 `#2a5f58`, 선택 시 `#4fd6c6`
  - 타일: 좌상단 번호 → 원형 스와치 → 프리셋 이름 → 보조 값
  - 풀 번호: **1 Dimmer(20) · 2 Position(20) · 3 Phaser · 4 Color · 21 All(이펙트 10)**

## 1. 화면 구조 — 5블록 + 컨셉 패널

순서 고정(REQ-078). 컨셉 패널만 블록 1과 2 **사이**에 신규 삽입.

```
1. 오늘의 곡 · 큐 순서        (기존, 헤더만 유지)
 ─ 컨셉 패널                 (신규 ConceptPanel)
2. 타임라인 + 에너지선 + Q줄   (기존 SongTimeline 수정)
3. CUE SHEET 14열            (기존 CueSheetTimeline 수정)
4. PLAN CUE 카드              (기존 카드 전면 재구성)
5. 상태줄 + GATE              (기존 StatusBanner 수정)
+ 하단 주석(인터랙션 노트 · 감독 확인 필요) — 개발 참고용, 제품에는 미포함 가능
```

전체 폭 1600px 고정 캔버스, 바깥 여백 28px, 블록 간 14px, 블록 배경 `--panel #1e2128` + 테두리 `#2b303a` + radius 10px.

## 3. 데이터 모델 (화면이 요구하는 형태)

```ts
Cue = {
  q: 'Q014', section: 'Chorus 3', rep: '3', t: 106.3,
  trigger: '후렴 3 진입',
  colorKey: 'yellow'|'blue'|'white'|'orange',   // Color Strip 키
  dim: 90,                                       // %
  groups: 'FOH·KEY·MOVER-U 8대·BACK' | '+BACK' | '동일',  // 시트 약어
  motion: '정지' | '팬 ±20°',
  fx: 'White hit' | '—' | …,                     // 원샷 어휘 7종 중 실제 발생분
  fade: '0.4s' | 'long 12.6s',
  mib: '—' | 'dark' | 'mark' | 'live',
  trackEx: '' | 'Block' | 'Cue Only' | 'Release',
  evidence: 'verified'|'practitioner_pattern'|'designed_rule'|'director'
}
```

### 트래킹 해석 (필수)
CUE SHEET의 `groups`는 **직전 큐 대비 약어**다. PLAN CUE 카드는 큐 하나를 독립적으로 보여주므로
`동일` / `+X` 를 앞 큐에서 캐리포워드해 **유효 그룹 집합**으로 해석한 뒤 쓴다.
헤드룸(투입/잔여)도 이 집합 크기에서 파생한다 — 별도 상수로 두지 말 것.

리그는 18그룹. 화면에 이름이 나오는 그룹: `FOH · KEY · SIDE-L · SIDE-R · BACK · MOVER-U 8대 · BLIND`.

## 4. 블록별 사양

### 4.1 오늘의 곡
`Rain` 32px 700 + `76 BPM`, 그 옆 한 줄 메타(길이 3:42 / 큐 26 / 원샷 13 / 후렴 6회·정점 Chorus 6 / 구간 12).
큐 순서 칩 줄은 두지 않는다(타임라인 Q줄과 중복). 안내 한 줄만.

### 4.2 컨셉 패널 (REQ-079/080)
- 기본 **접힘**. 헤더 라벨은 컨테이너 이름 `이 곡의 컨셉`(하위 항목명과 겹치지 않게).
- 펼치면 최상단에 **"한눈에 — 이 곡을 이렇게 끌고 간다"**: 한 줄 분석 + 5단계 카드
  `시작 → 쌓기 → 강조 → 예고 → 정점→마무리`, 각 카드에 색 바·단계명·Q 범위·구간·시간·색 HEX·밝기 범위·한 줄 설명.
  **모든 수치는 큐 데이터에서 파생**해야 한다(하드코딩 문장이 시트와 어긋나면 안 됨).
- 그 아래 **탭 3개** — 라벨 문구는 REQ 고정, 부제만 쉬운 말로:
  1. `이 곡의 연출` (Master Concept) — 왜 이렇게 짰나
  2. `이 곡의 재료` (Micro Concept) — 색 외 재료(감정·공간·움직임·질감·시작–끝)
  3. `지키는 것·하지 않는 것·아껴 두는 것` (Visual Grammar) — 지킴/금지/보류
- 탭 1 본문: **인과 불릿**(워크시트 `concept` 원문, 요약·윤문 금지 — "원문 그대로" 배지 필수) + **6칸 문법표**
  헤더 문자열 고정: `구간 / 색 / 기구·밝기 / 움직임 / 효과 / 그래서 보이는 것`, 12행, 표 자체 세로 스크롤.
- 항목(불릿·칩) 클릭 → **4칸 설명** 펼침: `무슨 뜻 / 무대에서 / 왜 이렇게 제안했나 / 바꾸려면`.
- 항목 수는 곡마다 가변 — 고정 개수 그리드 금지(칩 wrap 레이아웃).

### 4.3 타임라인 (REQ-081)
- 내부 폭 2200px 가로 스크롤. 구간 블록 색 = Color Strip 원색(투명도 금지), 블록 안에 구간명 + `20.9s · D2`.
- 현재 큐가 속한 구간: 흰 2px 아웃라인 + 상단 4px `--accent` 바. 나머지 구간을 흐리게 하지 않는다.
- 블록 위에 겹치는 **점 줄**: 원샷 타격성 ● / 전환성 ▲ / Mark ◇(+ `MARK 104.0s` 라벨, 홀짝 오프셋으로 겹침 회피).
- 에너지선: 구간 중앙 점 + 폴리라인(`--track`), 점 색은 D레벨 램프, `D3` 라벨 병기.
- Q줄: 26개 Q 배지(클릭 시 선택). 선택 배지는 채움 + 확대 + 링.
- 선택 큐 위치에 **세로 플레이헤드**(2px `--accent`, glow).
- 하단 시간 눈금 20초 간격.

### 4.4 CUE SHEET (REQ-082) — 정확히 14열
`Q# / 구간 / 회차 / **Trigger** / 시각 / 색 / 밝기 / 기구 그룹 / 움직임 / 효과 / Fade / MIB / **Track 예외** / 근거 등급`
신규 2열에는 헤더에 `신규` 태그. `Track 예외`는 기본값 `Track`이면 **빈 칸**.

시퀀스 흐름이 읽히도록:
- 행 왼쪽 7px **색 레일** = 그 큐 구간의 Color Strip 색 (세로로 훑으면 곡의 색 진행이 보임)
- 구간이 바뀌는 행에만 상단 구분선, 구간명은 첫 행만 흰색 700 / 이어지는 행 `#9aa0a6` 400
- 밝기 칸: 값 뒤에 % 길이만큼 구간색 막대 + 직전 큐 대비 ▲▼
- 효과 칸: 타임라인 범례와 동일한 ● / ▲ 기호 병기
- MIB 칸: `◐ dark` / `◇ mark` / `◑ live`(경고색 700)
- 행 높이 28px `box-sizing: border-box`, 헤더 30px 고정
- 선택 행: 좌측 5px 바 + 1px 아웃라인 + `rgba(79,140,255,.26)`, Q# 칸이 파란 알약으로 반전

### 4.5 PLAN CUE 카드 (REQ-083) — **그룹 기반 편집기**
카드는 읽기 전용이 아니라 **조작면**이다. 좌(조작) / 우 452px(콘솔) 2단, `align-items: stretch`.

**헤더** — `Q014` 파란 알약(20px mono) · 구간 22px · 회차 · 구분선 · `Trigger` 라벨 + 트리거 18px · 시각 mono · 우측 근거 등급 배지.

**좌측**
1. **기구 그룹 줄** — `전체` 버튼 + 투입 그룹 칩(각 칩에 색 점 + 밝기 %) + 미투입 그룹 `＋ SIDE-L` 점선 칩.
   칩 클릭 = **다중 선택**(빨간 테두리). BLIND는 Q023 전까지 잠금.
2. **선택 상태 줄** — "FOH · BACK 선택됨 — 아래 값은 선택한 그룹에만 적용된다" + `✕ 선택 그룹 해제`.
3. **밝기 / 색** 한 줄(각 1/2) — 스테퍼 ±5%p + 값 + 게이지 / 스와치 4종 + 현재값.
   선택 그룹의 값이 갈리면 `혼합`, `혼합 2색`으로 표기.
4. **페이드 / 팬 폭** 한 줄 — ±0.2s / ±5°.
5. **Fade / Track** — Track·Block·Cue Only·Release 4택.
6. **MIB / 남김** — `없음 · ◐ dark · ◇ mark · ◑ live` 4택 + 판정 문장 + 리저브 상태.
7. **변경 스택** — 바꾼 항목만 diff로 누적(`~ FOH 밝기 90% → 95%`), 규칙 위반 시 경고 문장 병기,
   `코파일럿에게 반영 요청` / `되돌리기`. 좌측 열 남는 높이를 채우도록 `flex:1`.

**우측 — 콘솔 반영 값** (감독이 코파일럿에게 지목할 때 쓰는 참조값이자 조작 지점)
행 구성: 종류(좌측 색 레일) · 풀 배지 · 프리셋명 · `바꾸기` · 둘째 줄에 적용 그룹 전체(줄바꿈, 말줄임 금지).
- `포지션` — 풀 2, 예 `2.11 Sweep L` · MOVER-U 8대 · 팬 ±20°
- `컬러` — 풀 4, **값이 다르면 줄이 갈라진다**(예: 4.2 Amber — FOH·KEY / 4.1 Blue — BACK)
- `딤머` — 풀 1, 값별로 갈라짐. 고정값은 `1.18 Dim 90`, 다이내믹 프리셋은 `1.11 Breathe Soft`
- `이펙트` — 풀 21, `21.1 Drop Slam`
- `페이저` — `Ph 2 step · 38 BPM` + `Abs Pan ±20°`

각 행 클릭 → **메인 화면 프리셋 풀 팝업**(§0). 컬러·딤머는 **선택 그룹에만**, 포지션·이펙트·페이저는 큐 전체에 적용.
선택 결과는 반드시 렌더 상태에 반영돼야 한다 — 이름(`posName` / `dimName` / `effName`)을 저장하고 행에 그대로 표시할 것. 값만 저장하고 이름을 버리면 `Home`·`Wall`·`Center`가 구분되지 않는다.

**경고 규칙(파생, 하드코딩 금지)**
- 밝기가 뒤 후렴(C4 92% · C5 94%)을 역전 → 후렴 상승 곡선 경고
- 팬 폭 ≥ 정점값(±25°) → 정점 구분 약화 경고
- 리저브 항목(BLIND · 짧은 Strobe · 흰색)을 Q023 이전에 사용 → 리저브 위반 경고
- 잔여 그룹 < 4 → 헤드룸 경고
- MIB `live` → GATE WARN 발생 예고
- 페이저 스피드 = 곡 BPM → 박자 동기 경고

### 4.6 상태줄 (REQ-084)
좌측 GATE 요약 배지 4종(통과/경고/실패/해당없음 + 개수), 콘솔 연결 표기, 우측 `GATE 상세 보기 ▼`.
상세는 `판정 / 게이트 / 근거 — 실제 값` 3열 표. 판정은 색 + 기호 + 글자 전부 병행.

### 4.7 스크롤 연동 (REQ-085)
타임라인 가로 ↔ CUE SHEET 세로를 비율로 상호 추적.
**구현 주의**: 핸들러는 동기 실행(`requestAnimationFrame` 안에서 돌리지 말 것 — 프레임이 안 오면 통째로 죽는다),
대상 노드는 ref에서 매 호출 새로 해석, 되먹임은 lock 플래그 + **80ms 트레일링 타임아웃**으로 해제.

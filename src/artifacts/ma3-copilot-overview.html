1이 앱은 무엇인가

grandMA3 콘솔을 대체하지 않고 옆에 붙는 AI 프로그래머입니다. 사용자가 채팅으로 "발라드 느낌의 룩을 만들어줘"라고 하면, AI가 MA3 커맨드·큐·프리셋·Lua 플러그인으로 변환해 콘솔에 실행합니다. 페이드·이펙트 재생 같은 실시간 처리는 전부 MA3 엔진이 그대로 담당하고, 위험한 명령은 반드시 사람의 승인 버튼을 거칩니다.

콘솔로 나가는 유일한 통로는 안전 게이트입니다 — 다른 모듈이 OSC를 직접 부르지 못하도록 아키텍처 테스트가 지키고 있습니다.

연결의 3요소

  • OSC 통신 — 앱이 /copilot/cmd 주소로 명령을 보내고, 콘솔이 /copilot/state(상태 스냅샷)와 /copilot/feedback(실행 결과)으로 응답합니다.
  • Lua 응답기 — 콘솔 안에 상주하는 플러그인(copilot_responder.lua, v1.5)이 상태 조회·속성 읽기·플러그인 배포를 대행합니다. 실제 onPC 2.4.2에서 여러 차례 라이브 보정을 거쳤습니다.
  • 룰북 — 라이브 검증으로 확정된 MA3 문법·오브젝트 모델·한국어 현장 용어·연출 패턴(총 5개 섹션, 500여 줄)이 AI의 시스템 프롬프트에 항상 실립니다. "실기에서 통한 문법만 쓴다"가 원칙입니다.

3안전 계층 — 콘솔을 지키는 장치

① 문법 검증

보내기 전 구조 검사. 오류 시 AI가 스스로 고쳐 재시도(최대 3회).

② 위험 명령 분류

Delete 등 파괴적 명령 블랙리스트 + 간접 호출(매크로 경유)까지 추적 탐지.

③ 사람 승인

위험 묶음은 전체 승인/거부 카드로 표시 — 기본은 거부.

④ 라이브 잠금

공연 중엔 읽기 전용 + 제안 카드만. 실행 버튼은 항상 사람 몫.

⑤ 쇼파일 백업

세션 시작·10분 주기·위험 명령 직전 자동 스냅샷.

⑥ 감사 로그

모든 송신 1:1 기록(JSONL), 90일 보관 — 무엇이 언제 나갔는지 추적 가능.

5사용자 화면(UI) 구성

  • 채팅 뷰 — 한국어 대화. 승인 카드(위험 사유 표시), 플러그인 리뷰 카드(소스 미리보기·정적 스캔 결과), 실행 미리보기 카드가 대화 중간에 뜹니다.
  • 콘솔 대시보드 — 시퀀스·프리셋·그룹 등 풀(pool)을 읽기 전용 타일로 표시.
  • 쇼 컨트롤 패널 — 실행기 타일에서 직접 Go/Stop/고정(pin) 조작.
  • 큐 모니터 — 실행기별 현재 큐 진행 상황 + 최근 실행 이력 (MA3 스타일).
  • 런북 모드 — 자원봉사자용 단순 곡/큐 목록 화면.
  • 상태 배너 & 설정 — 콘솔 온라인/오프라인/응답기 성능 저하 표시, LLM 제공자·키·포트 설정.

배포 형태: 웹 UI + macOS 네이티브 앱(Tauri, 백엔드 사이드카 내장, 트레이 아이콘, .app/DMG 패키징). 자동 업데이트와 정식 서명·공증은 이연 상태입니다.

7추가하면 좋을 기능 제안

설계 로드맵(Phase 3~4)과 개발 중 발견된 미해결 지점, 그리고 사용자 제안(Vectorworks 연계)을 근거로, 효과 대비 난이도 순으로 정리했습니다.

P0. Vectorworks 연계 — 디자인 도면을 콘솔 셋업으로

Vectorworks Spotlight에서 확정한 조명 디자인(장비 종류·수량·패치·배치)을 그대로 가져와 콘솔 셋업의 출발점으로 씁니다. 세 단계로 나누면:

  • 1단계 — 엑셀/CSV 장비 리스트 가져오기: Vectorworks가 내보내는 Instrument Data(픽스처 타입·수량·유니버스·주소·포지션)를 읽어 "설계상 리그" 모델을 만듭니다. 이미 있는 공연 전 점검(precheck_patch)과 붙이면 "도면 vs 실제 콘솔 패치" 차이 리포트가 바로 나옵니다 — 빠진 장비, 주소 충돌, 수량 불일치를 공연 전에 잡습니다.
  • 2단계 — 자동 패치 생성: 차이 리포트에서 사람이 승인하면, 라이브 검증이 끝난 Lua 패치 기법(AddFixtures)으로 부족한 픽스처를 콘솔에 자동 패치합니다.
  • 3단계 — MVR/GDTF 가져오기: MVR 파일(3D 배치+GDTF 장비 정의)을 파싱하면 무대 위 실제 좌표까지 확보됩니다. 원래 설계 로드맵 Phase 2에 예정돼 있던 파서이며, main에 머지된 배치 인식 연출(SPATIAL)·그룹 자동 생성(GROUPGEN)과 결합하면 "도면만 넣으면 포지션 그룹까지 자동 생성"이 가능해집니다.

디자인 이미지(렌더링·도면 그림)는 좌표 정밀도가 없어 자동 반영엔 부적합하지만, AI가 연출 무드를 파악하는 참고 자료로는 유용합니다 — 데이터는 CSV/MVR로, 분위기는 이미지로 나눠 받는 구성을 권합니다.

P1. 음악 분석 → 타임코드 큐리스트 자동화

로드맵 Phase 3의 본편입니다. 곡 파일을 넣으면 구간(인트로/코러스)·BPM·에너지를 분석해 타임코드 큐리스트 초안을 만듭니다. 이미 prepare_songcue(곡 구조 → 큐)와 이펙트/씬 라이브러리가 있어서, 음악 분석 엔진만 얹으면 파이프라인이 완성됩니다. "3분 곡 → 10분 내 검토 가능한 초안"이 목표 기준입니다.

P2. 실행 취소(Undo) · 백업 복원 원클릭

자동 백업(⑤)은 이미 찍히지만 복원 경로가 없습니다. 특히 그룹 풀은 콘솔에서 내용을 되읽을 수 없어 덮어쓰면 복구 불가라는 것이 라이브에서 확인됐습니다. "방금 작업 되돌리기" 버튼과 백업 스냅샷 브라우저는 안전 계층의 마지막 빈칸입니다.

P3. MCP 서버 완성 (현재 초안)

읽기 전용 도구 11종을 Claude Desktop 등 외부 AI 클라이언트에 개방하는 작업이 이미 착수되어 있습니다. 완성되면 이 앱을 띄우지 않고도 "지금 패치 상태 보여줘" 같은 질의를 아무 Claude에서나 할 수 있게 됩니다.

P4. 3D 뷰 비전 자가 검증 루프

로드맵 Phase 2의 잔여 항목. onPC 3D 화면을 스크린샷으로 캡처해 AI가 "의도한 그림이 실제로 나왔는지" 스스로 확인합니다. 현재 이펙트류는 기계 검증이 불가능해 사람 관측에 의존하고 있는데, 이 간극을 메워 줍니다.

P5. 라이브 보조 — 다음 큐 제안 & 이상 감지

로드맵 Phase 4. 라이브 잠금 모드에서 큐 모니터 데이터를 활용해 "다음 큐 후보"와 "실행기 이상(멈춘 시퀀스 등)" 알림 카드를 제안합니다. 실행은 여전히 사람이 누릅니다 — 기존 안전 원칙 그대로입니다.

P6. 쇼파일 인수인계 리포트

이미 있는 서류 3종(패치/큐/프리셋 시트)과 감사 로그를 묶어 "이 쇼가 어떻게 만들어졌는지" HTML 한 장으로 자동 문서화합니다. 기대 효과에 명시된 '작업 로그 자동 문서화'의 완성형이며, 기존 부품 재조합이라 난이도가 낮습니다.

P7. 오프라인 모드 (사전 생성 매크로 캐시)

공연장 인터넷 불안정 리스크 대응책으로 설계 문서에 이미 명시된 항목. 자주 쓰는 지시를 매크로로 미리 구워 두고, API 접속 불가 시 실행 전용 모드로 강등합니다.

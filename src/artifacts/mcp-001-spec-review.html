01무엇을 만드나

지금 앱은 서버측 LLM(Gemini)이 툴을 호출하는 닫힌 웹 앱이다. 이 SPEC은 그 읽기 절반을 MCP 표면으로 연다 — Claude Code / Claude Desktop이 stdio로 붙어 기존 툴 레지스트리의 읽기 전용 부분집합을 직접 호출한다. 서버는 LLM을 호출하지 않는다(키 불요). 새로 생기는 것은 세 가지다:

  • server/mcp/ 패키지 — python -m server.mcp stdio 엔트리포인트. 기존 ToolRegistry의 definitions()/dispatch() 재사용 (사본·포크 금지).
  • MCP 리소스 — 룰북 5종(문법·오브젝트 모델·한국어 용어·플러그인·연출 패턴) + 룩/FX/씬 라이브러리. MCP는 시스템 프롬프트를 주입할 수 없으므로 지식은 리소스로 노출.
  • 등록 아티팩트 — 저장소 .mcp.json(Claude Code) + README의 Claude Desktop 등록 절차.

사전 확정 사실 S1~S4 (재질의 금지)

  • S1 읽기 전용 — 변이 툴 전면 제외. 쓰기 서버는 Stage 2.
  • S2 링크 배타 소유 — 수신 포트(9000) 배타 점유. 웹 앱과 동시 구동 불가, 점유 시 명확한 기동 실패.
  • S3 LLM 키 불요 — Claude 클라이언트가 브레인.
  • S4 공식 Python MCP SDK + stdio 전송.

03무변이 3중 방벽

① allowlist + 분할 테스트

명시적 이름 상수. 11종은 상한 — 축소는 SPEC 개정 없이 허용(정직한 축소), 확장은 개정 필요 (REQ-MCP-010/011).

② 거부 스텁 주입

build_toolset의 필수 인자 execution_port에 어떤 콘솔 발화도 하지 않는 RefusingExecutionPort를 주입 — 필터와 독립인 2중 방벽 (REQ-MCP-007).

③ 기계적 도달성 테스트

노출 11종을 호출 기록형 fake로 대표 호출 → execute/deploy 도달 0건 실측 (REQ-MCP-012, ASSUMPTION-69 판정기).

+ allowlist 밖 호출 거부

변이 툴 이름 호출 시 실행 없이 한국어 사유의 구조화 거부 반환 (REQ-MCP-005).

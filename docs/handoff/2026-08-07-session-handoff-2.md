즉 우리의 절대값 단정은 충돌이 아니라 **그 문서가 지정한 역할**이다.

### ④ §3 미결 2 — TRUNCATE 어휘 통일: **하지 않는다** (사유 코드에 기록)

같은 사실이 아니다. TRUNCATE의 키 이동(`fixtures` → `partial_fixtures`)은 **JSON을

docstring에 있다 — 지우지 않았으니 다시 제안되지 않는다.

> ⚠️ P0-5가 이 판단의 전제 하나를 바꿨다. `build_magic_sheet`는 **실제로**
> `read_spatial_fixtures`를 호출하고 두 형상 분기를 소비한다. 즉 *"페이퍼워크는
> `partial_fixtures`를 만지지 않는다"*는 이제 거짓이며, docstring도 그렇게 정정했다.
> 결론(어휘 비통일)은 바뀌지 않았지만 **근거가 바뀌었다.**

### 1️⃣ 쇼파일 복원 발신부 — **체감 효과가 유일하게 큰 항목**

*"백업은 도는데 되돌릴 수 없다."* 세션 시작·10분 주기·위험 명령 직전에 계속 `SaveShow`를

나쁘다.**

⚠️ **선행 문서·리포트가 "발신부만 없다"고 적은 것은 틀렸다(§1a 리포트 v2-2).**
`BACKUP_COMMAND`는 인자 없는 `SaveShow`(`gate.py:59`)라 매번 **같은 파일을 덮어쓰고**,
`Snapshot`은 콘솔측 식별자를 하나도 갖지 않는다(`backup.py:62-70`). **스냅샷 N개 : 파일 1개**다.
`@MX:NOTE`가 적은 대로 "`find_snapshot`으로 검증된 대상에 reload를 보내는" 발신부를 그대로
만들면 **어느 스냅샷을 골라도 최신본을 복원한다** — 선택했다는 착각을 주므로 없느니만 못하다.

### 4️⃣ 열거 슬롯 회수 이식 — **M4를 재기 전에는 착수하지 마라**

`read_inventory`는 슬롯 단위 회수(`slot_path`, `recover_truncated=True`)를 하는데
`read_spatial_fixtures`와 풀 열거(`collect_rig_sections`)는 **같은 절단을 보고만 하고
회수하지 않는다.** 39대 리그에서 패치시트는 전량, 매직시트 배치는 18대를 낸다.

**그런데 풀이 실제로 잘리는지는 한 번도 관측된 적이 없다.** 픽스처 컨테이너의 절단만
실측돼 있다. 작은 쇼파일이면 **효과 0**이므로, M4(1분)로 재고 잘릴 때만 하라.
안 잘렸다면 **그 사실도 기록**하라 — 안 고친 이유가 된다.

## §3. 이번 세션이 실제로 밟은 함정

1. **⚠️ 머지 전 CI가 없다.** `gh pr merge`가 그냥 머지된다 — PR #29가 그렇게
   들어가서 main을 레드로 만들었다. **머지 전에 `uv run pytest server/tests -q`를
   직접 돌려라.** 이 저장소는 체크 0건이고, PRESERVE 상시 게이트가 CI 대신이다.
2. **⚠️ `BASE..HEAD` 형태의 PRESERVE 단정은 시한폭탄이다.** 그 디렉터리를 건드리는
   **모든 후속 작업**이 깨진다. 고칠 때 게이트를 약화시키지 말고 이 파일의 선례대로
   명명된 grant를 얹어라(`test_overlap_preserve.py`의 2026-08-02 · 08-03 · 08-07 세 건).
3. **⚠️ 절대 개수 리터럴은 두 곳에 있었다.** `grep -rn "== 22" server/tests`로는
   부족하다 — 다음에 툴을 추가하는 사람은 `TOOL_NAMES`를 참조하는 **모든** 단정을
   먼저 찾아라.
4. **⚠️ 새 워크트리의 `ui/`에 `node_modules`가 없다.** `npm ci` 먼저.
5. **⚠️ 메인 리포가 더러우면 거기서 리베이스할 수 없다.** 남의 미커밋 83건을
   stash하지 말고, 우리 소유의 깨끗한 워크트리에서 새 브랜치로 리베이스하라.
   (같은 브랜치를 두 워크트리에 체크아웃할 수 없으므로 브랜치명이 바뀐다.)
6. **⚠️⚠️ `BASE..HEAD` 게이트는 커밋 전에 눈이 멀다 — 이 세션이 두 번 밟았다.**
   그 게이트들은 `git diff BASE..HEAD`로 진단하므로 **커밋되지 않은 워킹트리를 보지
   못한다.** `git commit` 전의 전수 그린은 그 게이트를 **아예 실행하지 않고**, 실패는
   커밋 직후에야 드러난다. PR #33이 그렇게 main에 들어가 `test_songcue_bundle.py`를
   깼다(#34로 복구). 앞서 #29 → #30도 같은 형태다.
   **규율: 커밋한 뒤에 한 번 더 돌리고 머지한다.** 순서를 바꾸면 안 잡힌다.
   해당 게이트 3종 — `test_overlap_preserve.py` · `test_songcue_bundle.py`
   (`_tools_hunks_from_run_phase_base`) · `test_prechk_tool.py` 라우트 계수.
7. **⚠️ 닫힌집합 리터럴을 고치면 "왜 고쳤는지"를 묻는 테스트가 함께 걸린다.**
   블랙리스트 v3는 `test_safety_ruleset.py`의 version 핀·개수 핀·REVISION HISTORY
   검사 3중으로 마찰을 준다. **의도된 설계다.** 우회하지 말고 논증을 파일에 써라.
8. **⚠️ SPEC 문서만 읽고 갭 목록을 쓰면 틀린다.** 리포트 v1·v2가 연속으로 그랬다 —
   v1은 스테일 브랜치를, v2는 **측정이 뒤집은 plan-phase 문서**를 근거로 삼았다.
   plan-phase(`research.md`·`plan.md`)를 인용할 때는 **그 뒤의 M0/M4 실측을 반드시
   대조하고**, 판정마다 근거를 **코드 좌표**로 달아라.

## A. 통신을 트기까지 (회차 3)

### A-1. 화면 자동화를 포기한 날 ✅

- **언제**: 2026-07-23
- **출처**: `feedback_computer_use_unreliable_on_grandma3.md`
- **무슨 일**:
  AI에게 화면 좌표를 보고 클릭하게 했더니, 다른 프로그램 창이 반복적으로 포커스를 가져가
  클릭과 키 입력이 콘솔이 아닌 엉뚱한 프로그램으로 갔다. 심지어 실수로 눌린 `a` 한 글자가
  파일 탐색기의 검색 기능을 발동시킨 것이 확인됐다.
  **이 과정에서 살아 있는 콘솔에 빈 `UserPlugin 5`와 빈 `Macro 13`이 만들어졌다** — 의도치 않은 흔적.
- **인용할 사용자 발언** (교재의 힘이 되는 문장):
  > "전혀 변화가 없어. 심도있게 고민하지 않고 되지도 않는 테스트를 반복하는 거 같아"
- **교훈**: 살아 있는 콘솔에 좌표 기반 자동화를 쓰지 않는다. 되돌릴 수 없는 흔적이 남는다.
- **대체 경로 (우선순위 순)**: ① OSC 브리지로 읽기 ② 사용자가 직접 입력하고 결과 보고 ③ 스크린샷은 위치 안내용으로만

### A-2. 화면엔 켜져 있는데 안 통한다 📇

- **언제**: 2026-07-18, 2026-07-23 (두 번 겪음)
- **출처**: `feedback_grandma3_osc_stale_socket_and_send_row.md`, `copilot-onpc-site-config.md`
- **무슨 일**: OSC 왕복이 실패. 화면 표시는 `Yes`인데도 입출력을 껐다 켜는 사이클이 필요했고,
  응답 슬롯 번호가 실제 송신 설정된 행을 가리키지 않았다.
- **교훈**: 화면 표시와 실제 상태는 다를 수 있다.
- **⚠️ 강의 전 확인**: 원문에서 정확한 설정 항목명을 확인할 것

### A-3. 결과를 볼 수 없어서 증거 채널을 발명하다 ✅

- **언제**: 2026-07-23
- **출처**: `feedback_copilot_console_macro_label_evidence_channel.md`
- **무슨 일**:
  콘솔에서 로그를 출력하는 표준 방법(`Printf`/`Echo`)의 결과가 Message Center·Command Line History 등
  **어느 창에서도 보이지 않았다.** `OK: Call Plugin N`은 확인되는데 내용만 안 보였다.
  여러 턴 동안 사용자가 스크린샷을 반복 전송하며 창을 찾았으나 실패.
- **해결**: 결과를 **매크로 이름에 써넣는** 방식.
  `Store Macro 150` → `Label Macro 150 "<결과>"` → 매크로 풀 화면에 그대로 보인다.
  (이 패턴은 이미 저장소의 배포된 플러그인들이 쓰고 있었다.)
- **부수 발견**: 콘솔은 플러그인의 최상위 문장을 실행하지 않는다.
  `local function main() ... end` + `return main` 형태여야 한다.
- **교훈**: **관측 수단이 없으면 만들 수 없다. 없으면 만들어야 한다.**

## B. 가정이 틀린 순간들 (회차 4 — 핵심)

### B-1. 화면의 번호가 진짜 주소가 아니었다 ✅ ★

- **언제**: 2026-07-22 (라이브 실측)
- **출처**: `copilot-executor-number-is-not-an-address.md`
- **무슨 일**:
  실행기 목록에서 읽은 인덱스 `i`로 명령을 보냈더니 대부분 `Illegal object`.
  실제 주소는 **`i + 100`** 이었고, 페이지1의 실행기 8개 전부 균일했다 (라이브 16회 발화로 실측).
- **★ 가장 중요한 부분 — 조용한 오발**:
  `Off Executor 101`도 `Off Executor 201`도 **둘 다 오류 없이 성공한다.**
  101은 다른 실행기의 주소이기도 하므로, **아무 경고 없이 엉뚱한 시퀀스가 발화된다.**
  → 7건이 거절당하는 것보다 1건이 조용히 잘못 실행되는 게 나쁘다.
- **정정 이력** (이것도 교재로 쓸 것):
  이 기록의 이전 판본은 "8개 중 101만 발화"라고 적혀 있었으나, 그건 **실제로 관측하지 않은 주장**이었다.
  원래 세션은 1건만 발화했을 뿐이다. 재확인 세션에서 8개를 전부 쏴 보고 나서야 `+100` 규칙이 드러났다.
  → **기록조차 틀릴 수 있다. 관측하지 않은 것을 관측한 것처럼 적지 않는다.**
- **교훈**: 조회로 얻은 식별자로 조작이 된다는 보장은 없다.

### B-2. 같은 규칙이 문맥에 따라 정반대 ✅

- **언제**: 2026-07-19 (패치), 같은 시기 (연출)
- **출처**: `project_copilot_patch_cracked.md`, `project_copilot_choreography.md`
- **무슨 일**:
  - **패치 작업**: 플러그인이 스스로 작업 위치를 지정하면(`ChangeDestination`) 실패한다.
    콘솔이 이미 패치 화면에 있어야 하고 플러그인은 위치 지정을 **하면 안 된다**.
    이 조건이 맞자 무빙 9대(FID 2~10)가 실제로 패치됐다.
  - **연출(프로그래밍) 작업**: `ChangeDestination Root`가 **반드시 필요하다** — 정반대.
- **부수 발견 (배포 형식)**: 플러그인 파일을 가져올 때 **파일 이름 참조 방식은 빈 컴포넌트를 만든다.**
  내용을 파일 안에 직접 넣는 형식이어야 실제로 동작한다.
- **교훈**: "한 번 됐으니 다른 데서도 되겠지"가 조용히 틀린다.

### B-3. `childCount: 0`은 "비었다"가 아니었다 ✅ ★

- **언제**: 2026-08-03 (실측)
- **출처**: `grandma3-group-membership-not-readable.md`
- **무슨 일**:
  실사용 중인 그룹을 조회했는데 `childCount: 0`, `children: []`.
  그룹은 정상 동작하고 있었다 — **조회 경로가 그 정보를 담지 않았을 뿐**이다.
- **왜 치명적인가 (삼중 잠금)**:
  1. 재조회로 검증할 채널이 없다
  2. 덮어쓰기 전 백업이 불가능하다
  3. 삭제는 금지 목록, 복구 경로도 없다
  → **이미 쓰고 있는 그룹 슬롯 자동 생성은 금지로 확정.** 선호가 아니라 강제 제약.
- **교훈**: `ok: true` + `0`은 "확인된 0"이 아니다. 긍정적으로 보이는 응답도 "이 경로엔 정보가 없다"일 수 있다.

### B-4. 존재하지 않는 명령이 성공을 반환했다 ✅ ★★

- **언제**: 2026-08-01
- **출처**: `lesson-fabricated-control-probe.md`
- **무슨 일**:
  옵션 플래그의 실제 동작 여부를 확인하려고 **일부러 오타를 낸 가짜 명령**을 먼저 쏴 봤다.
  `... /CueOnlyy` (y 하나 추가) → **`ok`를 받았고 큐까지 만들어졌다.**
  콘솔은 모르는 플래그를 조용히 무시한다.
- **만약 대조군이 없었다면**: 진짜 플래그를 쏘고 `ok`를 받아 "확인됨"이라 적었을 것이고,
  **아무 일도 하지 않는 기능 위에 설계 전체를 세웠을 것이다.**
- **딸린 교훈 3가지** (원문에 함께 기록됨):
  1. **실패한 프로브 설계가 더 큰 발견을 낸다** — 거절 메시지가 "큐 생성은 사실상 추가만 가능"임을 드러냈다
  2. **거절 메시지 문구를 단정 근거로 쓰지 말 것** — 원인마다 문구가 다르다
  3. **감사 점수가 떨어졌다고 품질이 나빠진 게 아닐 수 있다** — 이전 측정이 과대평가였을 수 있다
- **교훈**: **반드시 실패해야 하는 것을 먼저 시켜보라.** 그게 실패해야 성공이 의미를 갖는다.

### B-5. 정적 조회가 답할 수 없는 질문에 답하고 있었다 ✅

- **언제**: 2026-07-22
- **출처**: `static-probe-cannot-answer-what-only-firing-can.md`
- **무슨 일**:
  읽기 전용 프로브가 실행기 번호를 읽고 "번호 모양이 불연속이니 실제 번호가 맞다 → 가정 성립"이라 판정했다.
  라이브에서 실제로 발화해 보니 8개 중 7개가 `Illegal object` — **판정 기준 자체가 틀렸다.**
  번호의 *모양*으로 주소의 *유효성*을 추론하고 있었다.
- **교훈**: 식별자를 코드에 심기 전에 **그것으로 실제 동작을 한 번 해 본 증거**를 요구하라.
  정적 조회의 결론은 가설로 기록하고 "미검증"으로 표시한다.

## F. 사례를 추가할 때

이 교육을 계속 운영하면서 사례를 추가할 때 지킬 것:

1. **기록에 없는 사례를 만들지 않는다.** 기억나는 대로 각색하면 교재의 근거가 무너진다.
2. **출처 파일명과 날짜를 반드시 적는다.**
3. **확인 수준(✅/📇)을 정직하게 표기한다.** 원문을 안 읽었으면 📇다.
4. **"성공했다"보다 "틀렸다가 어떻게 알았나"를 우선 채택한다.** 이 교육의 가치는 거기 있다.

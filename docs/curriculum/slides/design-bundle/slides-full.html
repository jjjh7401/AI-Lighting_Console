  • 자기가 쓴 걸 자기가 검사하니 틀린 걸 못 본다

  • 권한을 줄여두면 실수해도 안 망가진다

셋 다 “사람 주의력에 안 맡긴다”는 뜻입니다

하네스 규칙 + 자동 검사 원래 뜻은 말에 씌우는 마구. 힘이 세다고 아무 데나 뛰게 두지 않고 원하는 방향으로 몬다.
극장 하우스 룰에 해당합니다.

AI가 깜빡해도 규칙을 못 어깁니다.
루프 될 때까지 스스로 반복 단, 그만둘 조건을 반드시 같이 겁니다.

M5-1 · 오케스트레이션

감독은 직접 다 하지 않습니다

조명 현장AI 팀에서는
조명감독지휘 담당 AI — 방향 정하고, 일 나누고, 최종 판단
오퍼레이터실제로 만드는 AI
포커스 크루특정 작업만 하는 AI
외부 검수검사만 하는 AI — 만든 쪽이 아닌 다른 쪽

이 저장소에서는 지휘 담당이 10종의 일꾼에게 나눠 줍니다. 그리고 지휘 담당은 직접 만들지 않습니다 — 규칙으로 못 박혀 있습니다.

28 · 실패 사례 ★ 최중요

실제 사건 · Case D

존재하지도 않는 명령이 “성공”이라고 답했습니다

무슨 일이 있었나
// 일부러 오타를 낸 가짜 명령을 쏴 봤다 Store Cue 5 /CueOnlyy ↑ 이런 옵션은 없다 // 콘솔의 대답 { "ok": true } ← 성공이라고 왔다 // 게다가 큐까지 실제로 만들어졌다

콘솔은 모르는 옵션을 조용히 무시합니다. 틀렸다고 알려주지 않습니다.

그래서 확인 절차는 이렇게 됩니다
01반드시 실패해야 하는 가짜 명령을 먼저 쏜다실패한다 → 이 길은 믿을 수 있다
성공한다 → 이 길은 아무것도 구별 못 한다
02진짜 명령을 쏜다
03다시 조회해서 확인한다

가짜를 안 쏴봤으면 아무 일도 안 하는 기능 위에 전부를 세웠을 것입니다.

28
발표자 노트 이 슬라이드가 강연 전체에서 가장 중요하다. 다른 걸 다 잊어도 이건 남아야 한다. 가능하면 라이브로 재현한다 — 오타 명령을 실제로 쏴서 ok가 오는 걸 눈앞에서 보여준다. 청중이 웅성거린다. 그게 목적이다.
29 · 실패 사례

실제 사건 · Case A

화면에 보이는 번호가 진짜 주소가 아니었습니다

7번 거절당하는 것보다, 1번 조용히 잘못 실행되는 게 나쁩니다.

29
발표자 노트 조명으로 번역 — “패치가 한 칸씩 밀려 있는데 아무도 모르고 리허설까지 간 상황”. 현업은 이 공포를 안다. 여기서 “읽을 수 있다 ≠ 시킬 수 있다”를 자연스럽게 꺼낸다.
30 · 정리 ★

오늘 딱 세 문장만 가져가신다면

이 셋입니다

01 ok는 증거가 아니다 말은 말일 뿐입니다. 다시 확인한 결과가 증거입니다.
02 읽을 수 있다 ≠ 시킬 수 있다 조회되는 번호로 조작이 된다는 보장은 없습니다.
03 도구를 먼저 의심하라 실패해야 할 걸 먼저 시켜봅니다. 그게 실패해야 성공이 의미가 있습니다.

페이더를 올렸는데 안 밝으면 램프부터 보지 않습니다 — 채널 → 밝기 → 패치 순으로 봅니다. 이미 이 습관이 있습니다. AI에게도 쓰면 됩니다.

31 · 정직한 한계

M6-2 · M6-3 · 정직한 한계

안 되는 것과, 일부러 안 하는 것은 다릅니다

반만 되는 것
  • 그룹 자동 만들기 — 빈 자리만. 이미 쓰는 자리는 되돌릴 수 없어서 막아뒀습니다
  • 추상적인 지시 — “웅장하게”는 아직. 장비 배치를 더 깊이 읽어야 가능합니다
  • 이펙트가 잘 도는지 확인 — 기계로는 못 봅니다. 사람이 눈으로 봐야 합니다
일부러 안 하는 것
  • 공연 중 AI가 스스로 실행 — 기술 문제가 아니라 선택입니다. 제안만 하고 버튼은 사람이 누릅니다
  • 예쁜지 판단 — AI는 초안까지. 확정은 사람
  • 읽을 수 없는 걸 자동화 — 백업도 복구도 안 되면 막습니다
31
발표자 노트 “일부러 안 하는 것”이 신뢰를 만든다. 못 하는 걸 숨기고 다 되는 척하면, 청중이 한 번 시도해보고 배신감을 느낀다. 특히 공연 중 자동 실행 금지는 조명 청중이 가장 듣고 싶어 하는 말이다.

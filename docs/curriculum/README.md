# 조명감독을 위한 AI 도구 제작 과정 — 강의계획서

> **한 줄로 말하면**
> 조명 하는 사람이 **AI에게 일을 시켜서, 자기한테 필요한 프로그램을 직접 만드는 법**을 배우는 과정이다.
> 코드를 타이핑하는 법은 안 배운다. **말로 시키고 · 결과를 의심하고 · 안전하게 콘솔에 연결하는 법**을 배운다.

교재의 모든 사례와 숫자는 이 저장소에서 실제로 만들어진 grandMA3 AI 코파일럿의 개발 기록에서 나왔다. 지어낸 예제는 없다(근거는 §8).

---

## 1. 누가 듣나

이 과정은 **두 종류의 수강생**을 함께 상정한다.

| | **현업 트랙** | **학생 트랙** |
|---|---|---|
| 누구 | 조명감독 · LD · 오퍼레이터 · 조명 시스템 담당 | 조명·무대 전공생 · 신입 · 조명에 관심 있는 사람 |
| 이미 아는 것 | 콘솔 실무, 현장 관행 | 컴퓨터를 좀 쓴다 (그 정도면 충분) |
| 어려워하는 곳 | **컴퓨터 용어** (M2 · M5) | **조명 용어** (M4) + 컴퓨터 용어 |
| 이 과정에서 얻는 것 | 내 현장의 반복 작업을 도구로 만들 판단력 | 도구를 만들 줄 아는 조명인이라는 출발점 |

### 아무것도 전제하지 않는다

- **프로그래밍 지식** — 필요 없다. 파이썬도 Lua도 몰라도 된다
- **터미널 사용 경험** — 필요 없다. M2에서 처음부터 알려준다
- **콘솔 실무 경험** — 필요 없다. 조명 용어는 [`glossary.md`](./glossary.md)에 전부 있다

> ⚠️ **학생 트랙이 있으면 강사가 반드시 할 것**
> 조명 비유를 쓸 때마다 **비유에 쓴 조명 용어부터 설명한다.**
> "큐 리스트 짜는 것과 같다"는 큐 리스트를 아는 사람에게만 설명이다.

## 2. 시작하기 전에 — 용어 사전

[**`glossary.md`**](./glossary.md) — **1회차에 인쇄해서 나눠준다.**

- **A. 조명 용어 20개** — 컴퓨터 쪽 사람에게
- **B. AI · 컴퓨터 용어 35개** — 조명 쪽 사람에게
- **C. 헷갈리기 쉬운 짝 7개** — 학생들이 가장 자주 섞는 것들

이 과정의 가장 큰 걸림돌은 개념이 아니라 **단어**다. 사전을 먼저 깔고 시작한다.

## 3. 커리큘럼 지도 — 7개 모듈

각 모듈에 **난이도**를 표시했다. 🟢 기본은 전원 필수, 🔵 심화는 현업 트랙 위주(학생은 건너뛰어도 됨).

| # | 모듈 | 쉬운 말로 하면 | 난이도 | 시수 |
|---|---|---|:---:|---:|
| **M1** | 왜 조명감독이 바이브 코딩을 해야 하는가 | 왜 남이 안 만들어 주나, 왜 내가 만들 수 있게 됐나 | 🟢 | 2h |
| **M2** | 무엇으로 만드나 — AI 모델과 도구 선택 | 어떤 AI를 어디에 쓰나 | 🟢🔵 | 3h |
| **M3** | 어떻게 만드나 — 아이디어에서 실물까지 | 첫날부터 뭘 어떤 순서로 하나 | 🟢 | 4h |
| **M4** | 조명 콘솔과 어떻게 연동하나 | AI가 어떻게 콘솔을 실제로 움직이나 | 🟢🔵 | 6h |
| **M5** | **바이브 코딩의 기술** | AI 한 대가 아니라 **여러 대를 부리는 법** | 🟢🔵 | 8h |
| **M6** | 결과 — 무엇을 할 수 있게 되었나 | 그래서 실제로 뭐가 되나 | 🟢 | 2h |
| **M7** | 앞으로의 과제 | 아직 안 되는 건 뭔가 | 🟢 | 2h |
| **P** | 수료 프로젝트 | 내 것 하나 만들어 보기 | 🟢 | 3h |
| | | | | **30h** |

**M4와 M5가 전체의 절반이다.** M4는 조명 쪽(도메인), M5는 컴퓨터 쪽(기술) — 이 둘이 두 기둥이다.

### M5의 다섯 가지, 미리 한 줄씩

M5가 가장 어렵다. 미리 쉬운 말로만 보고 가자. 자세한 건 [`glossary.md`](./glossary.md) §B-2.

| 용어 | 쉬운 말로 | 비유 |
|---|---|---|
| 오케스트레이션 | 여러 AI에게 **일을 나눠 시키고 결과를 모으기** | 조별과제 조장 |
| 에이전트 | **역할과 권한이 정해진 AI 한 명** | 조별과제 팀원 |
| 하네스 | AI가 지킬 **규칙 + 자동 검사 장치** | 실습실 안전수칙 + 안전 커버 |
| 루프 | 조건이 될 때까지 **AI가 스스로 반복** | "다 될 때까지" — 단, 그만둘 조건도 필수 |
| 그래프 엔지니어링 | **순서 짜기** + **기억 관리** | 지하철 노선도 |

## 4. 도달 목표

수료생은 다음을 **직접 할 수 있어야 한다**.

| # | 능력 | 쉬운 말로 | 확인 방법 |
|---|---|---|---|
| 1 | 작업을 만들 수 있는 단위로 쪼개 문서화 | "뭘 만들지 글로 정리" | 수료 프로젝트 계획 문서 |
| 2 | AI 도구를 설치하고 규칙을 심어 운용 | "AI에게 우리 현장 규칙 가르치기" | 규칙이 실제로 작동하는지 시연 |
| 3 | 콘솔과 통신 채널을 열고 왕복 확인 | "컴퓨터랑 콘솔이 말 트게 하기" | 라이브 콘솔에서 명령 1건 왕복 |
| 4 | AI 결과를 의심하고 기계로 검증 | "됐다는 말을 안 믿고 확인하기" | 가짜 명령 대조군 포함 검증 수행 |
| 5 | 되돌릴 수 없는 작업을 식별하고 안전장치 설계 | "망하면 못 되돌리는 것 구분하기" | 안전 규칙 목록 작성 |
| 6 | 여러 AI에게 역할을 나눠 일을 시킴 | "혼자 말고 나눠서 시키기" | 계획/구현/검사 역할 분리 시연 |

**학생 트랙 완화**: 3번(라이브 왕복)은 강사 콘솔에서 함께 수행해도 인정한다.

## 5. 표준 편성 — 10회차 × 3시간

| 회차 | 모듈 | 내용 |
|---|---|---|
| 1 | 용어 사전 + M1 | **사전 배포** · 왜 만드나 |
| 2 | M2 | 도구 지형 · 선택 기준 · 설치 · 첫 실행 |
| 3 | M3 | 계획 → 구현 → 정리 |
| 4 | M3 실습 | 아주 작은 것 하나 만들기 |
| 5 | M4 | 연동 4계층 · 명령/응답 채널 |
| 6 | M4 실습 | 라이브 콘솔 왕복 + 검증 |
| 7 | M5 | 오케스트레이션 · 에이전트 |
| 8 | M5 | 하네스 · 훅 |
| 9 | M5 | 루프 · 그래프 |
| 10 | M6 + M7 + P | 결과 · 과제 · 발표 |

### 편성 변형

| 편성 | 시수 | 구성 | 대상 |
|---|---:|---|---|
| **표준** | 30h | 10회 × 3h — 전 모듈 | 직무 정규 과정 |
| **학생 입문** | 20h | 🟢 기본만 · 🔵 심화 생략 · M4 실습은 시연 중심 | 전공 수업 · 동아리 |
| **부트캠프** | 30h | 5일 × 6h | 단기 집중 |
| **핵심 단축** | 12h | M1~M5 · M6·M7 요약 | 시간 제약 있는 현업 |
| **기술 심화** | 16h | M4 + M5 + P (M1~M3은 사전 자료) | AI 도구 경험자 |
| **인식 강연** | 3h | M1 + M5 개요 + M6 시연 | 경영진 · 의사결정자 |

> **어떤 편성에서도 빼지 않는 것**: M4의 검증 규율과 M5의 루프 상한.
> 이 둘이 빠지면 수강생은 **비용을 태우거나 쇼파일을 손상시킨다.**

## 6. 실습 환경

| 항목 | 요구 | 학생 트랙 대안 |
|---|---|---|
| **콘솔** | grandMA3 onPC (무료) | 동일 — 무료라 부담 없음 |
| **AI 개발 도구** | 에이전트형 CLI 1종 (M2에서 선택) | 강사 계정 화면 공유 |
| **AI 사용료** | 개인 또는 기관 공용 계정 | 기관 공용 계정 권장 |
| **컴퓨터** | 1인 1대 | 2인 1조 가능 |
| **네트워크** | 콘솔↔컴퓨터 로컬 네트워크 + 인터넷 | 동일 |

**M4 실습 안전 규칙 (필수)**
- 실습용 쇼파일을 따로 만든다. **실제 공연 쇼파일은 열지 않는다**
- 매 실습 전 백업
- 삭제 계열 명령은 실습 범위에서 제외

## 7. 평가와 수료

시험은 없다. **수료 프로젝트 1건**으로 갈음한다.

1. 자기가 자동화하고 싶은 작업 1개 선택 *(학생: 실습실·동아리 작업도 인정)*
2. 계획 문서 작성 — 무엇을 / 안 할 것 / 완료 기준
3. AI와 함께 구현 — **완성 못 해도 됨**
4. 발표 — 무엇이 됐고, 무엇이 안 됐고, **왜 안 됐는지**

> **"안 됐다"를 정확히 설명하면 통과다.** 이 과정의 핵심은 성공이 아니라 판별과 검증이다.

## 10. 강사를 위한 주의사항

1. **용어를 먼저, 개념을 나중에.** 새 단어는 **일상어 설명 → 용어** 순으로 말한다.
   - ✅ "AI가 지금 기억하는 내용 — 이걸 **컨텍스트**라고 합니다"
   - ❌ "컨텍스트가 부족하면…"
2. **조명 비유에 쓰는 조명 용어도 설명한다.** 학생 트랙에서는 비유가 오히려 장벽이 된다.
3. **M2의 도구 비교표는 갱신 대상이다.** 강의 전 §M2-8의 출처를 재확인할 것.
4. **M5를 이론으로만 가르치지 말 것.** 전부 이 저장소에 실물 파일이 있다. 열어서 보여줘라.
5. **성공담으로 만들지 말 것.** 실패 기록이 성공 기록보다 많고, 그게 M4의 교재다.
6. **비용을 숨기지 말 것.** AI 사용료는 실재한다. M2에서 정직하게 다룬다.
7. **시간 예측을 하지 말 것.** "하루면 됩니다" 대신 "먼저 A, 되면 B".
8. **모르겠다는 말을 환영하라.** 이 과정에서 가장 흔한 실패는 학생이 못 알아듣고 가만히 있는 것이다.

01

한눈에 보기

이 문서의 결론은 간단합니다. Fei Hu 영상은 "멋진 효과 모음"이 아니라 Copilot이 사용자 요청을 분류하는 데 쓸 수 있는 어휘 사전입니다.

핵심 요약

MA2 영상의 캡션은 효과 의도를 직접 말해 줍니다. Copilot은 이 이름을 그대로 명령으로 실행하지 않고, Phaser, Cue timing, SpeedMaster, MAtricks, Macro 작업 중 어디에 속하는지 먼저 판단해야 합니다.

  • Beat/BPM 계열은 SpeedMaster 연결이 우선입니다.
  • Preset Pack 계열은 단일 효과가 아니라 라이브러리 생성 요청입니다.
  • Prism/Zoom/Gobo 계열은 픽스처 프로파일 확인 없이는 확정 실행하면 안 됩니다.

03

효과 카테고리 지도

사용자가 "Fei Hu 스타일로 해줘"라고 말했을 때 Copilot이 먼저 떠올려야 하는 큰 묶음입니다.

빔/프리즘 체이스

PrismBeamSpeedMaster

프리즘이 박자에 맞춰 들어오거나, 빔이 순서대로 튀는 효과입니다. 픽스처별 Prism 어트리뷰트 확인이 필요합니다.

바운스/런 체이스

PhaseMAtricksReverse

선택 순서나 X/Y 좌표를 따라 빛이 달리는 효과입니다. `phase_from_x`, `phase_to_x`, `reverse`, `wings`가 핵심입니다.

팬/틸트 모션

PanTiltCircle

스윕, 서클, V-shape, 원형 배치 대칭 효과입니다. 위치값보다 위상 분산과 좌우 대칭 규칙이 룩을 결정합니다.

디머/줌 브리딩

DimmerZoomCurve

밝기와 빔 폭이 같이 숨쉬는 효과입니다. 느린 속도와 부드러운 Accel/Decel 곡선이 어울립니다.

페이드/딜레이

CueFadeDelay

반복 이펙트가 아니라 큐 전환의 질감입니다. "순서대로 켜지고 꺼짐"은 Phaser보다 Cue timing으로 가야 합니다.

템플릿/프리셋 팩

PresetSequenceMacro

단일 룩이 아니라 공연에서 재사용할 프리셋·시퀀스·익스큐터·매크로 묶음입니다.

05

콘솔 연동 모델

조명감독의 말이 실제 grandMA3 onPC 명령으로 이어지려면, 중간에 구조화된 의도 객체와 안전 게이트가 있어야 합니다.

1. 자연어"바운스 체이스를 비트에 맞춰"
2. 의도 객체EffectRequest로 효과 종류·대상·속도 분리
3. 리그 확인Group, Fixture, GDTF attribute, free Sequence 확인
4. 명령 번들Phaser/Cue/Macro에 맞는 command bundle 생성
5. 실행/보고OSC 전송, 안전 차단, 저장 위치와 한계 보고
{
  "intent": "create_lighting_effect",
  "effect_kind": "bounce_chase",
  "target": { "group_label": "MOVER-U", "fixture_class": "moving_head" },
  "attributes": ["Pan", "Tilt", "Dimmer"],
  "timing": { "sync": "speed_master", "speed_master": 1, "phase": "x_spread" },
  "store": { "destination": "sequence", "sequence_label": "FX Bounce Chase", "cue": 1 },
  "safety": {
    "audience_blinder": false,
    "destructive_pool_operation": false,
    "profile_dependent_attributes": []
  }
}
표현 Copilot 의도 필수 확인 MA 객체 명령 생성 골격
바운스 체이스bounce_chase Phaser대상 그룹, 선택 순서 또는 X/Y 좌표Sequence Cue 1Group → Step 1/2 → Phase 0 Thru 360 → SpeedMaster → Store Sequence
비트에 맞춰speed_master bindingSpeedMaster 번호, 기존 할당SpeedMaster / Executor speed여러 효과를 같은 SpeedMaster에 묶음
페이드 인 딜레이cue timing recipe적용 그룹, 순서, Fade/Delay 값Sequence CueLook 저장 → Cue Fade/Delay fan 입력
프리즘 비트beam PhaserPrism attribute 이름과 지원 범위Sequence 또는 Presetprofile 확인 후 Prism Step 1/2 생성
트리거 타이밍 매크로macro helper대상 Sequence/Cue, overwrite 여부Macro검증된 명령 묶음을 Macro에 저장

Phaser 계열

  1. 대상 Group 선택
  2. Step 1/2 값 생성
  3. Phase, Speed, Width 적용
  4. Sequence 또는 Preset으로 저장

Cue timing 계열

  1. 정적 Look 저장
  2. Fade/Delay fan 지정
  3. Follow/trigger 필요 여부 결정
  4. Phaser와 분리 보고

Profile-dependent 계열

  1. Prism/Zoom/Gobo attribute 확인
  2. 지원 값 범위 확인
  3. 확인 전에는 실행 금지
  4. 계획만 사용자에게 제시
06

Copilot 판단 규칙

사용자의 한국어 요청을 안정적으로 해석하기 위한 우선순위입니다.

Effect와 Cue timing을 분리

"이펙트"라고 말해도 반복 룩이면 Phaser, 순차 점등/소등이면 Cue Fade/Delay로 보냅니다.

Beat는 SpeedMaster 우선

비트, BPM, 템포, sync 요청은 여러 효과를 하나의 SpeedMaster에 묶는 방향으로 해석합니다.

대칭은 MAtricks 문제

V-shape, mirror, circular layout은 Pan/Tilt 값보다 X/Y phase, wings, selection order를 먼저 봅니다.

Preset Pack은 라이브러리

팩 요청은 단일 큐가 아니라 Dimmer, Movement, Color, Beam, Timing, Macro 묶음으로 계획합니다.

07

구현 후보

아래는 바로 실행 가능한 검증 완료 레시피가 아니라, Fei Hu 영상 사례에서 수요가 확인된 Copilot 라이브러리 확장 후보입니다.

beam-prism-chase

프리즘 체이스. Prism 어트리뷰트가 기종 의존이므로 GDTF/fixture profile 가드 필요.

prism-beat

프리즘 비트. Beat 요청이면 SpeedMaster 연결을 기본값으로 둔다.

bounce-run-x

바운스 런 체이스. X축 phase spread, reverse, wings 조합이 핵심.

vshape-pan-swing

대칭 V 팬 스윙. 좌우 wings 또는 그룹 split 후 반대 방향 phase를 적용.

zoom-dimmer-breath

줌과 디머가 같이 숨쉬는 룩. 느린 속도와 부드러운 곡선으로 제한.

fade-delay-fan-in/out

순차 페이드 인/아웃. FX 라이브러리가 아니라 시퀀스 큐 타이밍 레시피로 설계.

09

주의할 점

이 문서는 연구·분류 문서입니다. 영상 사례를 실행 가능한 콘솔 명령으로 단정하지 않습니다.

MA2 캡션을 MA3 명령으로 바로 변환하지 않기

MA2 Effect와 grandMA3 Phaser는 개념적으로 이어지지만, 저장 구조와 명령 세부는 다릅니다. Copilot은 먼저 의도와 작업면을 분류해야 합니다.

블라인더·플래시·삭제는 안전 가드 우선

Audience Blinder Beat, Flash, Delete Presets 계열은 자동 실행하면 위험하거나 되돌리기 어렵습니다. 낮은 강도, 수동 승인, 명확한 확인 절차가 필요합니다.

# draft SPEC 12건 전수 대조 — 「초안」이라 적힌 것 중 열하나는 이미 배포됐다

> 기준: `origin/main 77eca28` · 2026-09-08 · 읽기 전용 회차 (콘솔 접촉 0, 코드 변경 0)
> 물음: `status: draft` 로 적힌 12건 각각이 **진짜 초안인가, 이미 배포됐는가, 무엇이 막고 있는가.**

## 왜 이 대조가 필요했나

구조조정 회차에 `.moai/specs/` 를 훑다가 **draft 12건 중 고아가 하나도 없다**는 것이 먼저
걸렸다 — 12건 전부 코드·문서에서 9~21회 참조된다. 참조가 그만큼 있다는 것은 그 SPEC 이
가리키는 일이 이미 저장소에 들어와 있을 가능성을 뜻하고, 그렇다면 `draft` 라는 라벨이
거짓이다. 표본 셋(`TREEID` · `INTROSPECT` · `VWX`)을 열어보니 셋 다 배포돼 있었다.

**이것은 「머지된 PR 은 끝난 카드가 아니다」의 거울상이다.** 그쪽은 장부가 앞서간 것이고,
이쪽은 장부가 뒤처진 것이다. 두 방향 모두 장부를 못 믿게 만든다.

## 판정 — 산출물이 실재하는가

각 SPEC 의 frontmatter `module:` 이 약속한 파일·심볼을 그대로 찾았다. 「참조가 있다」가
아니라 **「약속한 것이 그 자리에 있다」** 를 쟀다.

### 🔴 이 대조에서 내가 낸 오답 하나 (기록으로 남긴다)

`MCP-001` 을 처음엔 「부분 배포」로 판정했다. `.mcp.json` 이 존재했기 때문이다. 열어보니
그 파일은 **MoAI 하네스의 MCP 설정**(`{"command": "moai", "args": ["mcp-server"]}`)이고
이 SPEC 이 약속한 `server/mcp/` 와 무관하다. 파일 이름이 겹쳤을 뿐이다.

「존재는 도달의 증거가 아니다」의 한 형태 — **존재는 그것이 내가 찾던 그것이라는 증거도
아니다.** 이름이 맞는 파일을 찾았을 때 한 번 더 열어보는 것이 이 오답의 값이다.

두 번째 오답: `MCP-001` 의 `progress.md` 에 `§E` 절이 4개라 「실행 기록이 있다」로 읽었다.
열어보니 넷 다 **빈 자리표시자**다(`_(run-phase 대기 — manager-develop 소유.)_`). 제목을
세고 내용을 센 것으로 착각했다.

## `MCP-001` 은 라벨이 정확하다

`progress.md` §0 이 스스로 적는다 — *「plan-phase 아티팩트 4종이 작성된 상태이며
(v0.1.0, status: draft), 다음 단계는 plan-audit → Implementation Kickoff Approval → M1」*.
계획만 있고 실행이 없는 상태를 `draft` 라 부르는 것은 옳다. **12건 중 유일하게 장부가
현실과 맞는 건이다.**

## 그러면 나머지 열하나는 왜 `draft` 로 남았나

이 회차는 그것을 **재지 않았다.** 갈래는 최소 셋이고 SPEC 마다 다를 수 있다:

1. sync-phase 를 안 돌아서 상태 전이가 일어나지 않았다
2. 인수기준 일부가 미충족이라 의도적으로 멈춰 있다 (`LXSEQ-001` 이 `implemented` 에서
   멈춘 것과 같은 형태 — 그건 감독 결정이 명시된 정당한 정지다)
3. 상태를 올릴 사람이 없어 그냥 남았다

**갈래를 안 갈랐으므로 이 문서는 상태 전이를 처방하지 않는다.** 산출물이 있다는 것과
인수기준을 통과했다는 것은 다르고, 후자는 각 SPEC 의 `acceptance.md` 를 실제로 대조해야
답할 수 있다.

무거운 문제일 수 있다 — 통과 여부를 물을 대상 자체가 없다는 뜻이다.

## 안 잰 것

- **각 SPEC 의 AC 통과 여부.** 산출물 존재만 쟀다. `LXSEQ-001` 이 「16/17 PASS 라서
  `implemented` 에서 멈춤」인 것처럼, 배포됐는데도 정당하게 못 닫는 건이 섞여 있을 수 있다.
- **배포 시점.** 어느 커밋이 각 SPEC 을 실어 보냈는지 추적하지 않았다.
- **`in-progress` 9건.** 이 회차의 범위는 `draft` 12건뿐이다.
- **심볼 개수의 의미.** 「심볼 23회」는 그 이름이 파일에 23번 나온다는 뜻이지 기능이
  올바르다는 뜻이 아니다. 존재를 쟀지 정확성을 재지 않았다.

## 다음 사람에게

상태 라벨을 일괄로 올리지 마라. 열하나가 배포됐다는 것은 **이 문서가 잰 것**이고,
닫아도 되는지는 **재지 않았다**. SPEC 하나를 고르고 그 `acceptance.md` 를 실제로 대조하는
것이 다음 단위다. 가장 값싼 출발점은 `acceptance.md` 가 아예 없는 둘
(`COLORPRESET-001` · `PRESETGUARD-002`) — 거기서는 「인수기준을 쓸 것인가, 아니면 이
SPEC 을 회고 기록으로 내릴 것인가」라는 더 앞선 질문이 먼저다.

# 가짜↔실물 괴리를 찾는 방법 — 오프라인은 통과하는데 실기에서만 다르게 도는 자리

> **이 문서는 절차다.** 이번에 찾은 것의 목록이 아니라, 다음 사람이 같은 종류를
> 스스로 찾도록 쓴 것이다. §1 이 뼈대, §2 가 실행 절차, §3 이 지금까지의 축 목록.
>
> 작성 2026-08-23 (카드 t12) · 실기 onPC 응답기 v1.6.1 에서 집행 검증

---

## §0. 왜 이 문서가 필요한가

테스트는 전부 초록인데 실기에서 다르게 도는 일이 반복됐다. 알려진 계열만 셋이다 —
판독 절단(D1) · 핸들↔이름(D2) · 폭 산정(RV1/RV2). 매번 실기에서 우연히 발견됐고,
발견 뒤에 테스트를 하나 추가하는 식으로 닫았다. **점-수정이라 계열이 마르지 않는다.**

그래서 "이번에 뭘 찾았나"가 아니라 "어디를 보면 이런 게 나오나"를 적는다.

---

## §1. 뼈대 — 가짜인 것은 플러그인이 아니라 그 아래 API다

`server/tests/lua_mock_env.py` 는 **실제 플러그인**(`console/lua/copilot_responder.lua`)을
바이트 그대로 Lua 5.4 런타임에 얹고, 그 아래 **MA3 API 표면만** 흉내 낸다 —
`Cmd` · `Printf` · `SendOSCMessage` · `UserVars`/`GetVar` · `Root()`/`DataPool()` 객체 트리.

여기서 따라 나오는 것이 이 방법의 전부다:

> **모든 괴리는 모킹된 API 표면에서 나온다.** 플러그인 로직은 진짜이므로 로직 버그가
> 아니라, 실물 API 가 하는 일 중 모의가 재현하지 않는 것이 원인이다.

그러므로 찾는 절차는 "코드를 훑는다"가 아니라 **모의 표면을 전수로 훑고, 각 항목마다** 
`실물은 여기서 무엇을 더/다르게 하는가` **를 묻고, 읽기 전용으로 재는 것**이다.

## §2. 절차

### 2-1. 착수 전 3줄 — 어긋나면 멈춰라

```bash
uv run python -m server.tools.responder_roundtrip --skip-exec \
  --host 127.0.0.1 --port 8000 --listen-port 9005 \
  --path "Patch/Stages/1/Fixtures" --wait 6
```

- `[PASS] ping … live version=…` 이 나와야 한다. 버전이 예상과 다르면 **재지 마라** —
  어느 응답기의 답인지 말할 수 없다.
- 경로는 `Patch/Stages/1/Fixtures` 다. `Patch/Fixtures` 는 RETIRED_PATHS 라 없다.
- **[HARD] 읽기 전용만.** `--skip-exec` 가 명령을 실행하는 유일한 단계를 뺀다.
  쓰기가 필요한 가설이 나오면 재지 말고 §5 에 적어 리드에게 올려라.

### 2-2. 모의 표면을 전수로 적는다

`lua_mock_env.py` 에서 모의가 제공하는 것을 하나도 빠뜨리지 말고 적는다. 2026-08-23
기준 전역 함수 **8종**(`SendOSCMessage` `Cmd` `Printf` `UserVars` `GetVar` `SetVar`
`DataPool` `Root`) + 노드 메서드 — `__NODE` 8종(`Children` `Count` `Ptr` `GetClass` `Get` `PropertyCount`
`PropertyName` `PropertyType`) · `__SPARSE` 4종(`Children` `Count` `Ptr` `GetClass`).

전수를 세라. 표본으로 훑으면 세지 않은 자리가 그대로 남는다.

### 2-3. 항목마다 세 질문을 던진다

| 질문 | 찾는 것 |
|---|---|
| **모의가 항상 성공하는가?** | 실물이 거절·실패하는 입력이 모의에선 통과한다 |
| **모의의 답이 데이터에 무관한가?** | 실물의 답이 내용·크기에 좌우된다 |
| **모의가 한 가지 형태만 내는가?** | 실물이 여러 형태 중 하나를 낸다(핸들/이름, 슬롯/위치) |

세 질문 모두 "그렇다"에 해당하면 그 자리가 후보다.

### 2-4. 읽기 전용으로 잰다 — 대조군을 함께 쏜다

[HARD] **긍정 프로브만 쏘지 마라.** 있을 수 없는 것을 함께 물어, 채널이 그것을
거절하는지 본다. 거절하지 못하면 그 채널의 `ok` 는 증거가 아니다.

```bash
# 긍정: 실재하는 프로퍼티
... --prop-path "Patch/Stages/1/Fixtures/1" --prop-name FixtureType
# 대조군 A: 있을 수 없는 프로퍼티 이름
... --prop-path "Patch/Stages/1/Fixtures/1" --prop-name FixtureTypeZZZ
# 대조군 B: 있을 수 없는 경로
... --path "Patch/Stages/1/FixturesZZZ"
```

2026-08-23 집행 결과: 대조군 A·B 모두 거절됐다(`property not readable` /
`path segment not found`). **즉 이 두 채널의 `ok` 는 증거로 쓸 수 있다.**
과거 exec 채널에서는 오타 플래그가 `ok` 로 돌아온 전례가 있으므로, 채널마다
따로 재라 — 한 채널의 판별력은 다른 채널로 넘어가지 않는다.

### 2-5. 찾은 것을 축으로 적는다 — 사례가 아니라

"픽스처 86대가 19대로 잘린다"는 사례다. 축은 **"반환 개수가 요청한 개수와 다를 수 있고,
그 절단 지점은 상수가 아니다"** 이다. 축으로 적어야 다음 자리에서도 쓰인다.

## §3. 지금까지의 축 목록

모의의 매개변수 자체가 축의 목록이다 — 하나씩 실기 사고 뒤에 추가된 것들이다.

| 축 | 모의가 하는 일 | 실물이 다른 지점 |
|---|---|---|
| **개수 절단** | 자르지 않는다 | 자른다. **지점이 상수가 아니다**(아래) |
| **핸들↔이름** | 프로퍼티가 값을 돌려준다 | 핸들(`FixtureType 10`)을 돌려준다 |
| **풀의 빈칸** | `__SPARSE` 로 재현 | 삭제·수기번호로 슬롯이 끊긴다 |
| **자기 슬롯 접근자** | `Index` / `index` / `Index0` / 없음 | 어느 형태인지 미확정 |
| **`Ptr` 의 의미** | `slot` 또는 `positional` | 2.4.2 에서 미검증 |
| **폭 산정** | CSV 폭 그대로 | 모드에 따라 다르다(RV1/RV2) |

### 절단 지점은 상수가 아니다 (2026-08-23 신규)

같은 세션에서 잰 값:

| 경로 | childCount | 실제 반환 |
|---|---|---|
| `Patch/Stages/1/Fixtures` | 86 | **19** |
| `Root` | 22 | **18** |
| `DataPool` | 16 | 16 (절단 없음) |

19 와 18 이 다르다. 즉 **고정된 자식 개수 상한이 아니다** — 페이로드 크기에 좌우된다.
따라서 이름이 짧은 가짜 데이터로는 절단이 아예 발화하지 않을 수 있고, "N개가 돌아온다"로
못박은 검사는 가짜와 실물 사이에서 의미가 없다.

미검증: 정확한 기전(바이트 예산인지 자식당 비용인지)은 두 점으로 확정되지 않는다.
확정하려면 이름 길이만 다른 컬렉션 둘을 같은 개수로 놓고 재야 한다.

## §4. 이 방법이 닫지 못하는 것

- **쓰기 경로.** 읽기 전용 프로브는 쓰기에서만 갈리는 괴리를 찾지 못한다.
  가설이 나오면 §5 로.
- **콘솔 상태 의존.** 지금 콘솔에 t9 가 넣은 86대가 있어 절단을 잴 수 있었다.
  빈 쇼파일에서는 이 축이 발화하지 않는다 — **비교 기준이 되는 실기 상태를 먼저 적어라.**
- **모의에 아예 없는 API.** 실물에만 있고 모의가 흉내조차 내지 않는 호출은 이
  절차의 §2-2 전수에 잡히지 않는다. 플러그인이 호출하는 MA3 API 를 따로 훑어야 한다.

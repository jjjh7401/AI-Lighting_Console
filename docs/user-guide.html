1. 이 앱은 무엇인가

한 줄 정의

grandMA3 onPC 위에 얹는 한국어 AI 보조 도구 — 콘솔을 대체하지 않고, 프로그래밍을 돕는다.

AI가 하는 것 프로그래머 역할

  • 한국어 자연어를 MA3 커맨드로 변환
  • 그룹, 프리셋, 시퀀스, 큐, 매크로, Lua 플러그인 생성
  • 장르별 룩/이펙트/씬 초안 제안
  • 패치 점검, 문서 생성, 프리쇼 체크

AI가 하지 않는 것 명확한 경계

  • 라이브 중 자율 운영 (read-only 제안만)
  • 미적 최종 판단 (AI는 초안, 확정은 사람)
  • MA 하드웨어 대체 (onPC + 하드웨어 필요)
  • 위험한 명령의 무단 실행 (반드시 승인 필요)
핵심 철학 이 앱의 설계 원칙은 "AI가 프로그래머, 사람이 연출"입니다. AI는 타이핑과 문법을 담당하고, 연출 판단은 조명감독이 내립니다. 자동화 경계선 연구(arXiv Skip-BART)가 입증한 것처럼, 프레임 단위 동기화는 자동화 가능하지만 공연 전체를 관통하는 미학적 일관성은 인간의 몫입니다.

4. 워크플로우 1 — 쇼 준비 (프로그래밍)

핵심 역량 — 가장 완성도 높은 영역

자연어로 MA3 조작하기

채팅창에 한국어로 원하는 것을 쓰면, AI가 grandMA3 커맨드를 생성해 실행합니다.

시나리오: 그룹 만들기
"무빙라이트 1번부터 8번까지 '프론트 무빙'이라는 그룹으로 만들어줘"
AI가 생성하는 커맨드: Store Group 1; Label Group 1 "프론트 무빙"; Fixture 1 Thru 8 Store Group 1
→ 문법 검증 → 안전 분류 (안전) → 자동 실행 → 결과 확인
시나리오: 프리셋 저장
"보컬 그룹에 따뜻한 앰버 컬러 저장해줘"
AI가 리그 컨텍스트를 읽어 보컬 그룹 번호를 찾고, Color 프리셋 풀의 빈 슬롯에 저장합니다.
시나리오: 큐 빌드
"시퀀스 5에 큐를 하나 추가하고, 프론트 무빙은 50%로, 백라이트는 100% 블루로 설정해"
AI가 Store Cue + Fixture 선택 + 값 설정 명령 시퀀스를 생성합니다.

Lua 플러그인 제작

콘솔 내부 자동화가 필요할 때, AI에게 Lua 플러그인 작성을 요청할 수 있습니다.

플러그인 배포 과정 (5단계)

  1. AI가 Lua 소스 코드 생성
  2. 컴파일 검증 — pcall 하네스로 구문 오류 검사 (실행은 하지 않음)
  3. 파괴적 명령 스캔 — Delete, Off Everything 등 위험 명령 자동 감지
  4. 사람 리뷰 — 소스 코드 + 스캔 결과를 보고 승인/거부
  5. 승인 시에만 onPC에 배포

5. 워크플로우 2 — 연출 설계

커버리지 약 70% — 어휘, 초안, 공간 인식까지 구현

5-1. 룩 라이브러리 — "분위기"를 명령으로

장르별(발라드/록/EDM/워십) 총 32개 룩이 내장되어 있습니다. 자연어로 원하는 분위기를 설명하면 AI가 가장 적합한 룩을 찾습니다.

발라드 (7 룩)

단독 키 · 달빛 · 인트로 웜 · 벌스 소프트 · 코러스 리프트 · 브리지 감정 · 클라이맥스

다이나믹스 1~5: 억제에서 감정 고조까지. 발라드의 5는 록의 5와 다릅니다.

록 (8 룩)

파워 인트로 · 기타 솔로 · 드럼 브레이크 · 파이널 블로우아웃 등

강한 콘트라스트, 빠른 무브먼트, 높은 디머 값.

EDM (9 룩)

빌드업 · 드롭 · 브레이크 · 레이저 체이스 등

채도 높은 색상, 무빙 이펙트, 스트로브 패턴.

워십 (8 룩)

경건한 시작 · 찬양 리프트 · 기도 · 축복 등

부드러운 전환, 웜 톤, 회중석 배려.

시나리오: 룩 찾기 + 적용
"코러스 부분에 어울리는 따뜻하고 웅장한 느낌의 조명 만들어줘"
1. AI가 find_looks로 "따뜻한", "웅장한", "코러스" 키워드 매칭
2. 적합한 룩 제안 (예: "ballad-chorus-lift" 다이나믹스 4)
3. instantiate_look으로 실제 리그의 그룹에 맞춰 프리셋 저장
4. 리그에 "보컬" 역할이 있는 그룹에 자동 매핑

5-2. 이펙트 라이브러리 (12 이펙트)

무브먼트(팬/틸트 웨이브, 서클), 컬러(레인보우 체이스, 펄스), 디머(사인 웨이브, 스트로브)를 자연어로 검색하고 적용할 수 있습니다.

5-3. 씬 컴파일러 — 룩 + 이펙트 + 타이밍 = 큐 1개

룩(정지 화면)과 이펙트(시간 축 움직임)를 합성해 하나의 완성된 큐로 만듭니다.

시나리오: 씬 만들기
"EDM 드롭에 컬러 체이스 이펙트를 넣고 2초 페이드로 시퀀스 3에 저장해"
AI가 compile_scene으로 — 1) EDM 드롭 룩 적용 2) 컬러 체이스 이펙트 적용 3) 시퀀스 3에 2초 페이드 큐 저장

5-4. 큐리스트 초안 (곡 1개 = 시퀀스 1개)

곡의 구간 정보(Intro/Verse/Chorus/Bridge/Outro)를 입력하면, 각 섹션에 맞는 룩을 자동 배정해 시퀀스 1개를 빌드합니다.

시나리오: 곡 큐리스트 만들기
"이 곡은 인트로(0:00)→벌스(0:30)→코러스(1:15)→브리지(2:00)→아웃트로(2:45)인데,
발라드 장르로 큐리스트 만들어줘"
AI가 시퀀스를 생성하고, 각 섹션에 발라드 다이나믹스에 맞는 룩을 배정합니다.

5-5. 버스킹 준비 마법사

"이 리그로 EDM 버스킹 준비해줘" 한 마디면, 해당 장르의 전체 룩 팔레트가 일괄 생성됩니다.

5-6. 공간 인식과 배치 그룹

픽스처의 3D 좌표(x, y, z)를 읽어 위치 기반으로 자동 그룹을 생성합니다 (앞/뒤/좌/우/상/하 6개 위상).

5-7. 빠른 조명 어휘

아래의 명시적 전체-리그 배치 요청은 모델 해석 없이 바로 3D 배치 도구로 전달됩니다. 실제 좌표 쓰기 전에는 항상 원본 좌표를 백업하고, 완료 후 다시 읽어 검증합니다.

의도트리거 단어바로 실행되는 요청 예시
격자 배치그리드, 바둑판, 매트릭스모든 장비를 4행×10열 그리드로 1.5m 간격 배치해줘
일렬 배치일렬, 한 줄, 라인전체 픽스처를 한 줄로 정렬해줘
원형 배치원형, 링, 서클전부 원형 링으로 반지름 6m 배치해줘
높이 변경5m, 5미터, 높이3D 레이아웃의 모든 장비를 바닥으로부터 5미터 높이로 올려줘
반원반원, 세미서클반원의 지름·반지름과 시작 방향을 함께 지정합니다.
다각형 배치사각형, 삼각형, 마름모행·열 또는 꼭짓점 방향을 함께 지정합니다. 예: 전체 장비를 4행×10열 사각형으로 배치해줘
배치 순서번갈아, 홀짝, 1/2, 짝지어두 장비 타입 또는 두 그룹을 이름으로 지정합니다. 예: MMX와 350M을 짝지어 좌→우로 배치해줘
방향좌→우, 앞→뒤픽스처가 각 배치 슬롯을 차지하는 순서를 지정합니다.
높이 기준바닥 위, 무대 위절대 높이를 반드시 함께 지정합니다. 예: 전체 장비를 무대 위 5m로 올려줘
층간 높이1미터 간격으로 높이, 높이 간격기준 높이와 대상 순서가 필요합니다. 예: 바닥 위 2m부터 앞→뒤로 1m 간격 높이 배치해줘

연출 어휘: 펄스, 브리딩, 체이스, 좌우 스윕, 웨이브, 발리후, 대각선은 내장 이펙트 라이브러리의 별칭입니다. 이펙트는 대상 그룹과 저장 위치가 필요하므로, 예: 그룹 3에 느린 발리후를 시퀀스 10에 저장해줘처럼 함께 지정합니다.

6. 워크플로우 3 — 현장 세팅과 점검

커버리지 약 78% — 실전 수준

6-1. 프리쇼 체크

공연 전 자동 점검을 실행해 문제를 미리 발견합니다.

자동 점검 항목 (4종 + 함정 3종)

  • OSC 왕복 확인 — 콘솔과 통신이 되는지
  • 시퀀스/익스큐터 존재 확인 — 쇼에 필요한 시퀀스가 있는지
  • 프리셋 라이브러리 무결성 — 룩이 제대로 저장되어 있는지
  • 함정 진단 — 스테일 소켓, OSC 설정 행 누락, 피드백 포트 불일치

6-2. 패치 점검

1

픽스처 인벤토리

패치된 모든 픽스처를 열거하고, 주소 중복/공백을 감지합니다.

2

DMX 구간 겹침 판정

"겹침 없음"은 확정 증명. 다만 채널폭 직접 판독이 불가해 "충돌 가능"은 상계(보수적 추정)로 판정합니다.

3

응답 확인 매크로 생성

각 픽스처가 실제로 반응하는지 눈으로 확인할 수 있는 매크로를 자동 생성합니다.

7. 워크플로우 4 — 쇼 진행 (런타임)

7-1. 쇼 컨트롤 패널 — 타일 한 번 탭으로 실행

콘솔의 익스큐터/시퀀스를 타일로 표시합니다. 타일을 누르면 Go+, 다시 누르면 Off. 매크로 타일은 한 번 실행(원샷)만 됩니다.

타일 순서는 절대 바뀌지 않습니다. 쇼 진행 중 타일이 밀리면 잘못된 큐를 실행할 위험이 있으므로, 한 번 배치된 타일은 위치가 고정됩니다. 번호도 콘솔의 실제 풀 번호를 그대로 표시합니다 (목록 순서 아님).

7-2. 큐 진행 모니터

각 익스큐터의 현재 큐, 시퀀스 이름, 최근 실행 이력을 실시간으로 보여줍니다.

  • 확인됨 (녹색 ✓) — 앱이 보낸 명령을 콘솔이 확인
  • 실패 (빨간 ✕) — 명령 전송 실패 또는 무응답
  • 미확인 (회색 ○) — 앱이 보낸 적 없음 (콘솔 직접 조작은 감지 불가)

7-3. 볼런티어 런북 모드

기술 지식이 없는 볼런티어 오퍼레이터를 위한 극단적으로 단순한 모드입니다.

런북 모드에서 보이는 것

  • 곡 이름 + 순서 번호 + 큰 "실행" 버튼 — 딱 이것만
  • 주의사항이 있을 때만 한 줄 경고 표시
  • 설정, 도구 목록, 풀 카탈로그, 채팅 전부 숨김

→ "망칠까 봐" 두려움이 볼런티어 현장의 최대 장벽입니다. 런북 모드는 잘못 누를 곳 자체를 없앱니다.

7-4. 라이브 잠금 모드

라이브 공연 중에는 라이브 잠금을 켜세요. AI가 명령을 실행하지 않고 "제안 카드"만 보여줍니다.

라이브 잠금이 켜지면

  • 모든 명령이 실행 차단 — 제안 카드(read-only)만 생성
  • 승인 대기 중인 명령도 즉시 차단 (잠금 우선)
  • 쇼 컨트롤 패널 타일도 제안만 (실행 불가)
  • 상태 조회(읽기)는 계속 가능

8. 워크플로우 5 — 문서화와 인수인계

자동 생성 문서 4종

패치시트

패치된 픽스처 목록: 이름, 주소, 타입, 위상(좌표 기반). 채널폭 상계 포함.

큐시트

시퀀스별 큐 번호, 이름, 트리거 타입/시간. (페이드 시간은 콘솔 제약으로 미판독)

프리셋 목록

프리셋 풀별 저장된 항목: 번호, 이름, 컬러 칩.

인수인계 패키지

위 3종을 한 폴더에 묶고, 불완전성 요약을 첫 화면에 표시합니다.

"일부만 본 목록을 전량으로 오해"하는 것이 인수인계의 최대 위험입니다. 그래서 모든 문서에 불완전성 배지가 붙습니다: truncated(잘림), drilldown_capped(드릴다운 제한), contents_unavailable(내용 판독 불가). 읽지 못한 것은 "읽지 못했다"고 명시합니다.

사용 방법

  1. 헤더의 페이퍼워크 버튼 클릭
  2. 원하는 문서 종류 선택 (패치시트 / 큐시트 / 프리셋 목록)
  3. "생성" 클릭 → 콘솔에서 데이터 수집 → HTML 문서 생성
  4. 브라우저에서 인쇄(Ctrl+P) → PDF로 저장

또는 채팅에서 "인수인계 패키지 만들어줘"라고 요청하면 됩니다.

9. 안전 시스템 — 이것만은 알아두세요

콘솔로 가는 모든 명령은 단 하나의 안전 게이트를 통과합니다. 우회 경로는 없습니다.

3단계 안전 게이트

1

문법 검증

MA3 문법 파서로 구문 오류 차단. 파싱 불가 명령은 실행 자체가 불가능합니다.
측정된 문법 오류율: 0.40% (248회 중 1회)

2

위험 분류

블랙리스트 명령은 무조건 사람 승인이 필요합니다:

  • Delete, Remove — 오브젝트 삭제
  • Off Everything — 전체 끄기
  • Store /overwrite — 기존 데이터 덮어쓰기
  • Shutdown, Format — 시스템 명령
3

사람 승인

위험 명령은 UI에 승인 카드가 뜹니다. 승인해야 실행되고, 거부하면 묶음 전체가 취소됩니다. 연결이 끊기거나 시간이 초과되면 자동 거부.

11. 자주 묻는 질문

Q
인터넷이 안 되는 공연장에서 쓸 수 있나요?
AI 기능(채팅, 자동 생성)은 API 접속이 필요합니다. 단, 미리 만들어 놓은 큐/매크로는 MA3에 저장되어 있으므로 오프라인에서도 쇼 진행(Go/Off)은 onPC에서 직접 가능합니다.
Q
AI가 쇼파일을 망가뜨릴 수 있나요?
위험 명령은 반드시 사람이 승인해야 실행됩니다. 또한 세션 시작 시와 위험 명령 실행 직전에 자동 백업됩니다. 라이브 잠금을 켜면 어떤 명령도 실행되지 않습니다.
Q
MA3 문법을 몰라도 되나요?
네. 한국어로 원하는 것을 설명하면 AI가 MA3 커맨드를 생성합니다. 다만 결과를 검증하려면 콘솔 화면에서 확인하는 것이 좋습니다.
Q
타임코드 쇼를 만들 수 있나요?
섹션 마커(큐 이름 문자열)와 타이밍 기반 큐리스트는 만들 수 있습니다. 다만 MA3의 타임코드 오브젝트 자체를 프로그래밍하는 것은 아직 미지원이며, SMPTE/MTC 레코딩은 MA3에서 직접 해야 합니다.
Q
비용이 얼마나 드나요?
Claude Opus 4 기준, 캐싱 적용 시 1턴(질문 1개) 약 $0.06. 집중 프로그래밍 세션(100턴) 약 8천 원. 월간 헤비 유저(세션 20회) 약 $120. 인건비 대비 무시 가능한 수준입니다.
Q
Gemini로 바꾸면 뭐가 달라지나요?
설정 한 줄로 전환 가능합니다. Gemini는 비용이 저렴하지만 복잡한 Lua 플러그인 작성이나 정교한 문맥 이해에서는 Claude가 더 정확합니다. 단순 커맨드 실행은 둘 다 잘 합니다.

12. 추가 기능 제안 로드맵

현재 구현 상태를 기반으로, 현장에서 바로 효과가 있는 것부터 장기적으로 반영해야 할 것까지 우선순위별로 정리합니다.

A 즉시 착수 가능 — 새 측정 없이 구현 예상 1~2주
#기능효과난이도
A1매직시트 축약형 그룹 이름 + 프리셋 이름 + 배치 좌표(이미 판독 가능)로 한 장 문서 생성. 조명감독이 가장 많이 쓰는 문서이며 현재 누락. 완전형은 콘솔 제약(멤버십 판독 불가)으로 불가하나 축약형은 바로 가능. 중
A2큐 시놉시스 문서 씬/룩/섹션 정보를 이미 갖고 있으므로 "장면별 무엇이 변하는지" 개요서 자동 생성. 연출 회의와 테크 리허설 사전 공유에 활용. 소
A3자주 쓰는 명령 템플릿 콘솔에서 반복되는 작업(전체 블랙아웃, 시작 위치 리셋, 풀 클리어 등)을 원클릭 버튼으로 제공. 안전 게이트를 통과하므로 위험 명령은 여전히 승인 필요. 소
A4익스큐터 레이아웃 계획서 생성한 시퀀스/룩/이펙트가 어느 익스큐터에 배선될지를 한 장 표로 정리. 물리 콘솔 레이아웃 설계 전에 검토 가능. 소
A5세션 히스토리 요약 작업 세션 동안 실행한 모든 명령과 변경 내역을 감사 로그 기반으로 읽기 쉬운 타임라인 문서로 생성. "오늘 뭐 했는지" 한눈에 파악. 소
B 콘솔 측정 선행 후 구현 측정 30분 + 구현 2~4주
#기능효과난이도
B1큐시트 시간 열 (CueFade) 큐시트에 페이드 시간이 없으면 반쪽짜리. 콘솔에서 CueFade 프로퍼티 판독이 가능한지 확인 후, 가능하면 큐시트의 "얼마나 밝나" 정보 완성. 불가하면 명시적으로 비움. 중
B2DMX 채널폭 정확 판정 현재 "겹침 없음"만 증명 가능, "충돌 있음"은 보수적 추정. 채널폭 직접 판독 경로를 측정해 정확 충돌 판정으로 업그레이드. 중
B3쇼파일 복원 기능 백업은 되는데 되돌릴 수 없다 — 현재 콘솔 오퍼레이터 워크플로우의 가장 큰 구멍. 스냅샷 로드 경로를 확인하고, 승인 게이트를 통한 복원 명령 실행. 대
B4풍부한 런북 — "다음 Go의 효과" 큐 내용 판독이 되면, 볼런티어 런북에 "이 버튼을 누르면 무대가 어떻게 바뀌는지" 한국어 설명 추가. "망칠까 봐" 두려움의 핵심 해소. 중
왜 측정이 먼저인가? 이 기능들의 성립 여부가 "콘솔이 그 값을 주는가" 하나에 걸려 있습니다. 측정 없이 착수하면 구현을 다 한 뒤 전제가 거짓으로 드러납니다 — 비파괴 읽기만 하는 30분 프로브로 수주의 낭비를 막을 수 있습니다.
C 상류(기획) 채우기 — 입력 채널 확장 4~8주
#기능효과난이도
C1음원 파일 분석 (오디오 입력) 곡 파일을 업로드하면 AI가 자동으로 구간(Intro/Verse/Chorus) 분할, BPM, 에너지 곡선 추출. 현재는 사용자가 텍스트로 섹션을 직접 입력해야 하지만, 이것이 열리면 곡 1개 = 큐리스트 1개를 완전 자동화 가능. 대

C4플롯 도면 산출 3D 좌표(이미 판독 가능)를 기반으로 간이 평면 배치도 HTML 생성. Vectorworks나 AutoCAD 없이도 "어디에 뭐가 걸렸나" 한 장 정리. 중
3중 잠금 해제 필요 — C1과 C2는 같은 인프라 제약을 공유합니다: (1) 오디오/비전 의존성 0건 (2) WebSocket이 텍스트 전용 (3) Tauri가 업로드 차단. 세 축을 한 번에 열면 두 기능이 동시에 살아납니다.

#기능효과와 판단
D1음성 입력 (한국어 STT) 어두운 공연장에서 키보드 대신 마이크로 지시. "프론트 무빙 50%"를 말로. 로컬 Whisper 또는 클라우드 STT 연동. 현장 소음 환경 테스트 필요.
D2Previz 연계 (MVR 내보내기) 좌표+타입 데이터를 MVR로 내보내 Capture/Depence에서 시각 검증. MVR 쓰기 경로 구현 필요.
D3포커스 차트 포커스(팬/틸트) 값 판독 경로 미조사. MVR/GDTF 또는 VWX 데이터에서 추출 가능성 검토 필요.
D4멀티 콘솔 / 네트워크 모드 MA-Net 환경에서 여러 세션과 연동. 현재는 단일 onPC 대상.
D5사용자 정의 룩/장르 확장 기본 4개 장르(발라드/록/EDM/워십) 외에 사용자가 직접 룩 정의. YAML 편집 UI 또는 "이 분위기 저장" 학습 기능.
D6MCP 서버화 이 앱을 MCP(Model Context Protocol) 서버로 노출해, Claude Desktop이나 다른 AI 도구에서 직접 MA3를 제어. 아키텍처는 검토됨(plan-audit 0.78).
의도적으로 하지 않는 것
라이브 자율 운영 — AI가 공연 중 알아서 조명을 바꾸는 것은 설계에서 명시적으로 배제합니다. 라이브 잠금의 read-only 제안까지가 경계선이며, 이 포지션은 자동화 경계선 연구(arXiv)와 정합하는 의도된 차별점입니다.

무응답 자동 탐지 — MA3가 DMX 리턴 데이터를 제공하지 않아 원리적으로 불가능합니다. 대신 사람이 눈으로 확인하는 응답 확인 매크로를 자동 생성하는 방식으로 대체합니다.

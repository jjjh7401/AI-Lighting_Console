# 곡 구조 기반 조명 연출 기준 (v1)

> 작성 2026-09-11 · 대상: `server/design/`·`server/looks/` 의 곡→큐 경로 · 근거: 아래 §12 출처
>
> 이 문서는 곡을 구간으로 나누는 기준과, 각 구간에 어떤 조명을 붙일지의 기준을 하나로 묶는다.
> 판단의 등급을 문장마다 구분한다 — **실측**(이 조사에서 직접 계산), **학술**(논문 수치),
> **실무**(업계 교육·트레이드지), **미확보**(출처를 찾지 못함). 미확보를 숫자로 메우지 않는다.

## 1. 이 문서가 고치려는 것

현재 구현은 곡을 8마디 고정 단위로 자르고 큐 수를 팔레트 색 수로 제한한다
(`server/design/cue_density.py:89` `BAR_UNIT_BARS = 8`, `:68-70` 팔레트 상한).
그 결과 5구간 입력에서 큐 3장이 나왔다.

실제 대중가요는 **구간이 중앙값 10개**이고 고유한 구간 종류가 6~7개다(실측, §4).
즉 현재 분할은 실제 곡 구조의 3분의 1 수준이다.

## 2. 구간 어휘 — 한 벌로는 안 된다

[HARD] **라벨 집합을 두 벌 들고, 곡의 장르로 선택한다.** 하나로 합치면 한쪽이 반드시 깨진다.

### 2.1 팝 축 — SALAMI 기능 어휘 20개

가장 방어 가능한 원천이다. 통제된 어휘이고 주석 지침서가 따로 있다.

| 묶음 | 라벨 |
|---|---|
| 기본 | intro · verse · chorus · bridge |
| 기악 | instrumental · solo |
| 전환 | transition · pre-chorus · pre-verse · interlude |
| 장르 고유 | head · main theme · secondary theme |
| 형식 고유 | exposition · development · recapitulation |
| 종결 | outro · coda · fadeout |
| 특수 | silence · end |

- 기능 라벨은 **선택**이다 — 모든 구간이 기능 라벨을 받을 필요는 없다(논문 명시).
- 전환·기악·종결 묶음은 **동의어군**이라 필요하면 하나로 접어도 된다(논문 명시).
  조명에서는 접는 편이 낫다 — pre-chorus·pre-verse·interlude·transition 넷의 조명 의도가 같다(§6).
- `fadeout` 은 **겹쳐 붙는 라벨**이다. 코러스가 페이드아웃하면 그 구간은 chorus + fadeout 둘을 갖는다.
- 재즈의 head, 클래식의 main theme 는 팝의 chorus 에 대응한다(논문 명시).

### 2.2 EDM 축 — 7개

EDM 은 팝 어휘로 표현되지 않는다. 학술 쪽이 이것을 수치로 보였다: 팝 어휘 모델을 EDM 에
그대로 쓰면 경계 검출은 4.7%p 만 나빠지지만 **구간 이름 정확도는 0.883 → 0.148 로 무너진다.**
팝 어휘에 drop·build-up 클래스가 없기 때문이다.

| 라벨 | 정의(논문 원문 요약) |
|---|---|
| intro | 에너지 낮고 악기 구성이 희박 |
| build-up | 에너지와 긴장이 점진 상승, 상승 드럼 패턴이나 라이저 |
| drop | 에너지 정점, 주 리듬 모티프와 베이스라인 |
| breakdown | 에너지 축소, 흔히 선율적 |
| outro | 에너지 점진 하강 |
| silence · end | 특수 |

**[HARD] 타이밍은 장르를 넘어 전이되지만 의미는 전이되지 않는다.** 경계 검출기는 공유하고
라벨 집합은 갈라라.

### 2.3 drop 은 정의상 측정 가능한 최대점이다

음악이론 쪽(Osborn 2023)이 chorus 와 drop 을 다른 종류의 절정으로 가른다 —
chorus 는 **구문론적** 절정이고, drop 은 **통계적** 절정이다. "여러 측정 가능한 파라미터에서
최대값, 특히 최대 음량". 조명에 직접 쓰인다: **drop 은 에너지 최대점이므로 조명도 최대점이어야
하고, 그 최대점은 곡에서 한 번이 아니라 회차마다 갱신되어야 한다**(§7).

같은 연구가 riser 안에 **build** 라는 하위 기능을 둔다 — 4분음표 → 8분 → 16분으로 좁혀지는
리듬 크레셴도가 drop 직전 블러 롤로 끝난다. 조명의 빌드도 같은 모양이어야 한다(간격을 좁혀라).

그리고 이 장르에는 `riserchorus`, 마지막 회차의 `riserchorus-drop` 같은 **혼합 구간**이 실재한다.
**한 구간이 라벨 하나를 갖는다는 전제가 깨진다** — 자료 구조가 라벨 복수를 허용해야 한다.

## 3. 구간을 세 필드로 적는다 — 반복 문제의 해법

[HARD] 구간 하나는 **라벨 + 회차 + 변형 표시** 세 필드로 적는다.

**표준 데이터셋은 회차를 주지 않는다.** 이것이 이 조사에서 확인된 가장 중요한 사실이다.
Harmonix 912곡 주석을 전수로 읽은 결과 1·2·3번째 후렴이 **전부 문자열 `chorus`** 다.
실제 파일(`0001_12step.txt`) 그대로:

```
intro / verse / chorus / verse / chorus / verse / chorus / chorus / outro / end
```

숫자 접미사(`chorus2` 38회)는 회차가 아니라 **다른 종류의 후렴**을 뜻한다 —
`chorus2` 를 쓴 파일 20개 중 16개가 평범한 `chorus` 도 함께 담고 있다(실측).

그래서 회차는 **후처리로 만든다.** 분야에 이미 정식 절차가 있다(McFee & Kinnaird 2019):
원본 주석 위에 **각 라벨 인스턴스에 카운터를 붙여 유일하게 만드는 정교화 단계**를 둔다.

변형 표시의 기존 표기는 셋이 서로 다르다 — SALAMI 는 프라임(`a′`), RWC 는 A·B
(`verse A`/`verse B`), Harmonix 는 숫자 접미사. **우리는 하나를 골라 고정한다.**

| 필드 | 값 | 예 |
|---|---|---|
| `label` | §2 어휘 중 하나 (복수 허용) | `chorus` · `drop` · `chorus`+`fadeout` |
| `instance` | 그 라벨의 등장 순번, 1부터 | `chorus` 3번째 → `3` |
| `variant` | 변형이면 표시, 아니면 비움 | 마지막 후렴이 편곡이 다르면 `′` |

[HARD] **조명 판정은 `label` 로 의도를 정하고 `instance` 로 강도를 정한다.**
`label` 만 보면 후렴 셋이 같아지고, `instance` 만 보면 의도가 사라진다.

### 3.1 반복을 신호에서 찾는 자료 구조

곡 구조 분석은 **자기유사도 행렬(SSM)** 로 반복을 표현한다. 두 가지 구조가 두 알고리즘 계열로
갈린다 — **대각선은 반복**, **블록은 동질성**이다. 대표 후렴을 뽑는 문제(thumbnailing)도
segment family · path family · coverage · fitness 로 이미 정식화돼 있다.

주의 — **경계 검출만으로는 반복을 복원할 수 없다.** 종설이 명시한다: novelty 원리는
A와 A를 같은 것으로 묶지 못한다. 반복은 별도 원리다.

### 4.1 EDM 표준 지도 (실무)

DJ 용 트랙 기준. 총 5~7분이고 스트리밍용은 인트로를 줄여 3~4분으로 압축한다.

| 구간 | 마디 |
|---|---|
| intro | 16–32 |
| build 1 | 8–16 |
| drop 1 | 16–32 |
| breakdown | 8–16 |
| build 2 | 8–16 (1차보다 길거나 강함) |
| drop 2 | 16–32, **drop 1의 변형** |
| outro | 16–32 |

**드롭이 두 번이고 두 번째가 첫 번째의 변형**이라는 것이 표준이다. §7 의 상승 규칙이 여기 걸린다.

멜로딕 테크노의 브레이크다운은 **32마디 4단계**가 기본이고 48 또는 16으로 신축한다 —
1~8 걷어냄 / 9~16 감정 코어 / 17~24 긴장(해소 없음) / 25~32 프리드롭, 마지막 2마디 급단순화 뒤
킥 복귀 직전 짧은 공백. 조명의 브레이크다운도 이 4단계를 따라야 한다.

## 5. 마디 격자 — 지배적이지만 하드 제약은 아니다

실측 분포(반올림 마디): **8마디 42.6%**, 4마디 12.3%, 16마디 12.1%, 12마디 5.7%.
4의 배수 이내 63.9%, 8의 배수 이내 47.8%.

[HARD] **8마디를 기본값으로 쓰되 하드 제약으로 걸지 마라.** 절반 이상이 8의 배수가 아니다.
현재 구현의 `BAR_UNIT_BARS = 8` 고정 분할은 이 지점에서 틀린다.

격자를 쓰는 올바른 방법은 **가중치**다 — EDM 분할 연구가 8번째·16번째 마디에 비대칭 가중을
주는 음악적 규칙을 넣어 허용창 0.5초 F-score 를 약 10포인트 올렸다. 격자는 제약이 아니라
정확도 자원이다.

### 5.1 다운비트 스냅은 10%에서 틀린다

구간 시작의 **81.1%만 다운비트에서 시작한다.** 약 10%는 앞 마디 4박에서 시작하고(카운트인),
나머지 약 9%가 2·3·5박이다.

[HARD] 경계를 다운비트로 스냅하되 **원래 시각을 함께 보존**하고, 보컬 진입이 앞 박에 있으면
그쪽을 쓴다. 코러스 큐는 **보컬이 들어오는 정확한 순간**에 떨어져야 하며 두 박 늦으면 안 된다(실무).

### 5.2 하프타임 — BPM 만 보면 정확히 두 배 빠르게 튄다

덥스텝 140BPM 은 스네어가 3박에만 떨어져 70BPM 처럼 들리지만 **템포는 140 그대로**다.
DnB·트랩의 하프타임 브레이크다운도 같다 — 170이 85처럼 들리는데 템포 변화는 없다.

[HARD] 조명 템포는 BPM 이 아니라 **체감 박(스네어 위치)** 으로 정한다. 마디 격자는 유효하고
체감 속도만 반토막이다.

## 6. 구간별 조명 의도

출처는 전부 **실무**다. 곡 구간별 조명에 대한 학술·표준 문헌은 이 조사에서 찾지 못했다
(부재의 증거가 아니라, 이 검색으로는 안 잡혔다는 뜻).
자료 둘이 수치를 직접 주는데 **서로 다르다.** 둘 다 싣는다 — 그 차이가 스타일 폭이다.

| 구간 | 밝기 | 색 | 빔·움직임 | 스트로브 |
|---|---|---|---|---|
| intro | 20~40% | 단색 1색(청·자 계열) | 무빙 정지 또는 아주 느림 | 없음 |
| verse | 25~50% | 주색 1색, 웜 계열도 가능 | 정지 또는 아주 느림, 보컬 구간은 고정 | 없음 |
| pre-chorus · build | 40~55% | 베이스에서 소폭 색 이동 | 느린 팬 또는 틸트 추가, 점점 좁힘 | 없음~최소 |
| 텐션(드롭 직전 마지막 마디) | 60~80% | 대비 큰 색 | 중속, 마지막 마디에 작은 줌 변화 | 없음, 또는 아주 짧은 예비 히트 1개 |
| chorus · drop | **80~100%를 짧게** | 굵은 단색 또는 고대비 2색 | 짧은 버스트 또는 통제된 스윕 | **짧게만** — 연속 금지 |
| post-chorus | 60~75% | 코러스 색 유지, 채도 낮춤 | 코러스보다 느리게 | 없음 |
| breakdown · bridge | 20~35% | 부드럽고 덜 채도 높은 색 | 무빙·이펙트 정지 | 없음 |
| solo | 솔로이스트만 강조 | 전용 스페셜 + 백라이트 | 정지 | 없음 |
| 마지막 drop | 전 리그 + 백색 플래시 | 최대 대비 | 최대 | 여기서 풀어라 |
| outro | 리셋 큐 | 디밍한 베이스 | 느린 페이드 1회 | 없음 |

**절정의 지속 시간에 상한이 있다.** 최강 효과는 **1~4박**, 백색 플래시는 **1~2박**.
그 뒤 통제된 룩으로 복귀한다. 규칙은 "최강 효과로 그 순간을 찍고 곧 돌아온다".

### 6.1 액센트는 한 번에 하나

코러스 순간을 찍는 수단이 일곱 가지다 — 밝기 히트 · 무빙 버스트 · 색 스냅 · 백색 플래시 ·
드롭 직전 짧은 블랙아웃 · 짧은 스트로브 · 빔·포지션 히트.

[HARD] **한 큐에 하나만 쓴다.** 셋을 한꺼번에 쓰면 아무것도 안 찍힌다.

[HARD] **밝기는 예외다 — 밝기만 누적한다**(감독 결정 2026-09-12). 이 절과 §7.1 의 사다리
표(「여기까지 그대로 + 하나 더」)가 서로 부딪혔고, 갈래는 이렇게 났다: 회차를 거듭하며
**밝기는 계속 올라도 되고**, 나머지 여섯(무빙 버스트 · 색 스냅 · 백색 플래시 · 드롭 직전
블랙아웃 · 짧은 스트로브 · 빔·포지션 히트)은 **큐당 하나**다. 뒤 회차는 앞 회차의 액센트
위에 하나를 더 얹는 것이 아니라 **갈아탄다**.

고치기 전 실측(2026-09-12, `051e98b`): 후렴 4회차 한 큐가 `Zoom At 13`(빔 히트)과
`Iris At 55`(빔 히트)를 함께 실었다 — 둘 다 실제로 값을 바꿨다.

### 6.2 기구는 세 층으로 역할을 나눈다

앰비언트 워시 / 텍스처(고보·소프트 빔) / 에너지(스트로브·빠른 빔).
실무 원문: **"기구마다 역할을 부여하라. 전부가 전부를 하는 것이 아니다."**

- 프론트 필은 밝은 워시가 아니라 **부드러운 보정광으로 항상 유지**한다 — 없으면 연주자가 안 보이고
  영상이 어둡게 나온다.
- 빔·ACL 은 코러스 펀치용 경질 샤프트, 블라인더는 관객 인터랙션, 헤이즈는 빔을 보이게 하는
  필수 요소(단 비상구 표시를 가려선 안 된다).
- 프레이밍 원칙: **"빛으로 연주자를 감싸라. 빛 뒤에 숨기지 마라."**

### 6.3 색

세 자료가 같은 방향으로 수렴한다 — **적게 쓴다.**
"색에 커밋하라, 한 색 많아도 두 색" / "곡당 2~3색, 곡당 감정 하나" /
동시에 보이는 색은 최대 2개(지배색 1 + 액센트 1).
순색 RGB 를 한꺼번에 켜면 시각적 소음이 되고 그림자가 탁해진다.

### 6.4 움직임 속도

느림 = 빌드·앰비언스 / 중속 = 그루브 / **빠름 = 드롭 전용**.
**쇼의 약 70% 구간은 느린 무빙(5~20%)** 으로 유지한다.

빔은 관객 눈높이 위 **20~30°** 를 유지하고, 하드룰이 하나 있다 —
**빔이 관객 한 명의 눈에 5초 넘게 머물러선 안 된다.**

## 7. 반복 회차의 상승 — 이 문서의 핵심

[HARD] **곡 안에서는 반복이 미덕이고, 곡 사이에서는 반복이 결함이다.** 이 비대칭이 실무 규범이다.

- 곡 안: **코러스 1에 쓴 색과 발리후는 이후 코러스에서 되돌아와야 한다.** 관객이 연주와의
  연결감을 그렇게 느낀다.
- 곡 사이: 룩·고보·이펙트·콘텐츠를 곡들 사이에 **재사용하지 않는다.**

[HARD] **상승은 「매번 다른 룩」이 아니라 「같은 룩 + 새 요소 하나」로 만든다.**

현재 구현은 이 규범을 정반대로 위반한다 — 값이 앞 큐와 같으면 큐를 **버린다**
(`server/looks/songcue.py:558-566` `VALUE_LINE_COLLISION`). 실측에서 후렴이 드롭과 값이
같아 스킵되어 5구간이 큐 3장이 됐다. 돌아와야 하는 것이 사라진다.

### 7.1 머리 공간을 남긴다

실무 원문: 버스에서 이미 빠른 무빙·플래시·색 변화를 다 쓰면 **"곡이 나중에 자랄 여지가 없다."**
"무빙 500대가 있다고 항상 500대를 쓸 필요는 없다."

[HARD] **아껴두기 사다리** — 회차마다 하나씩만 더한다. 순서는 아래를 기본값으로 하고
장르·리그에 따라 조정한다.

| 회차 | 더하는 요소 |
|---|---|
| chorus 1 | 기준 룩 — 백라이트 + 워시, 지배색 1 |
| chorus 2 | chorus 1 그대로 + **무빙 포지션 전환 1회** |
| chorus 3 (마지막) | 여기까지 그대로 + **블라인더 또는 백색 플래시**(1~2박) |
| 앙코르·피날레 | 스트로브를 처음 푼다 |

[HARD] **「여기까지 그대로」가 누적하는 것은 밝기뿐이다**(§6.1 의 감독 결정). 표의 「더하는
요소」가 찍는 액센트이면 앞 회차의 액센트를 **끄고 갈아탄다** — 밝기만 쌓이고 액센트는
한 큐에 하나로 남는다. 표를 문면대로 쌓으면 §6.1 [HARD] 와 정면으로 부딪힌다.

스트로브는 **클라이맥스 브레이크다운이나 세트 피날레까지 보류**한다.
"처음 두 곡에 최고의 트릭을 다 노출하지 않는" 것이 실무의 칭찬 대상이다.

## 8. 어둠과 대비 — 자동화가 가장 놓치는 축

원칙: **"어둠은 빛만큼 중요하다."** "피크와 밸리로 생각하라. 쇼의 매 초가 전광량이어야 한다는
생각을 버려라."

메커니즘이 명확하다 — **"큰 스트로브 순간은 플래시 자체가 아니라 플래시 앞에 무슨 일이
있었는지가 만든다."** 눈은 어둠에서 리셋되고, 이미 밝고 바쁜 무대에는 플래시가 등록될 여지가 없다.

[HARD] **드롭 직전에 밝기를 빼는 큐를 넣는다.** 더 어두운 큐, 짧은 블랙아웃, 줄인 워시 중 하나.
이것 없이 드롭만 올리면 드롭이 안 커진다.

- 균일하게 밝힌 무대는 지루하다 — **의도적 암부**로 시선을 유도하고 백라이트·사이드라이트로
  연주자를 배경에서 분리한다.
- 상시 무빙 대신 **아이리스·고보로 텍스처**를 만든다.
- 발라드는 룩 하나를 **곡 전체 동안 유지**하는 것이 최선일 수 있다.
- **안전 한계**: 어떤 룩에서도 비상구·통로·안전 표지는 읽혀야 하고 헤이즈가 비상구 표시를
  삼켜선 안 된다. 오퍼레이터는 전 회장을 즉시 밝히는 큐 또는 수동 오버라이드를 갖는다.

## 9. 큐 밀도와 타이밍

**밀도는 자료마다 크게 갈린다 — 이 차이는 현장 규모의 차이다.**

| 현장 | 곡당 큐 |
|---|---|
| DIY·DJ | 5 (Base / Lift / Tension / Impact / Reset) |
| 원오프 공연 실무 | 약 10 |
| 대형 투어(타임코드) | 수백 — 실측 사례 매일 밤 600큐, 큐의 97%를 타임코드로 발사 |

우리 시스템의 기본값은 **구간 수(중앙값 10)에 맞춘 10 부근**이 적절하다. 5는 너무 적고
600은 프로그래밍 근거가 없다.

- 발사 지점은 비트마다가 아니라 **프레이즈 단위 4~8마디마다**.
- 템포 탭은 스네어·하이햇이 아니라 **킥드럼**에 맞춘다(그루브를 정의하므로).
- 페이드: 부드러운 전환 **2~4초**, 극적인 컷 **0.2초**.
- 브레이크다운과 드롭은 같은 룩의 변형이 아니라 **반대**(긴장 대 해소)로 프로그램한다.
- 전환에서 대부분의 타이밍 오류가 생긴다. 어수선하면 **빼라** — 색 변화 하나 제거, 무빙 감속,
  스트로브 단축.

## 10. 아마추어로 읽히는 것 — 금지 목록

디자이너들 본인의 표현을 그대로 옮긴다. 이 목록은 자동 생성 결과의 검사 항목으로 쓴다.

1. **모든 큐가 같고 밝기만 다름** — 상시 80~100%면 빔이 거칠고 색이 날아가고 카메라에서 얼굴이 뜬다.
2. **동기 없는 색 변화 / 과다 채도** — 순색을 동시에 다 켜면 시각적 소음, 싸구려 나이트클럽 룩.
3. **움직임을 위한 움직임** — 빠른 무빙은 잠깐 인상적이고 이후 눈 피로.
4. **스트로브 남용** — "스트로브는 조명업계의 착암기", **"스트로브는 액센트여야 한다, BPM 카운터가
   아니다."** 권장 상한 약 4Hz 이하. 관객이 이미 적응했다면 너무 길었다.
5. **관객 눈에 오픈 화이트** — 모든 다운비트에 오픈 화이트를 쏘는 것. 관객 빔은 채도 있는 색으로
   두거나 느리게 움직인다.
6. **기구가 할 수 있다고 해야 하는 건 아니다** — 셔터 매크로가 초당 40가지를 낸다고 2절에서 쓸 이유는 없다.
7. **어두운 연주자** — 연주자 1인당 최소 1개 광원.
8. **곡 사이 대비 없음** · **구조·레이어 없음** — 전부 동시에 켜지면 깊이가 없다.

### 11.1 구간 변화 신호 — 오디오로 잡히는 것과 아닌 것

EDM 경계 검출 연구가 가장 강한 단서 셋을 지목한다: **에너지 노벨티 · 드럼 온셋 밀도 ·
스펙트럴 플럭스(음색 변화)**. 이 셋을 학습 임베딩에 더하면 경계 검출이 3%p 이상 개선된다.

| 신호 | 오디오 검출 | 비고 |
|---|---|---|
| 드럼 드롭아웃 · 갑작스런 정적 | 강함 | 에너지 노벨티가 직격 |
| 라이저 · 필터 스윕 | 강함 | 상승 스펙트럼 중심 + 플럭스 |
| 스네어 롤 · 드럼 필 | 강함 | 온셋 밀도 급증, 전환 마지막 1~2마디 |
| 서브베이스 진입·이탈 | 강함 | 드롭 직전 하이패스 뒤 개방 |
| 보컬 진입 | 중간 | 소스 분리 전제 |
| 화성 변화 | 중간 | **EDM·테크노에서 신호가 약하다** |
| 하프타임 전환 | 약함 | BPM 이 안 변해 템포 추정으로 안 잡힘 |
| 드롭 2가 드롭 1의 변형임 | **불가** | 편곡 지식 필요. 오디오로는 같은 라벨 |

### 11.2 K-pop — 실측 2곡과 확정된 공백

한국어 자료·학위논문·업계 언론을 브라우저로 직접 열어 **페이지에 보이는 숫자만** 채집했다.
통계는 없고 곡별 실측 두 건이 있다.

| 구간 | 레드벨벳 Russian Roulette (1절) | 세븐틴 손오공 (전곡) |
|---|---|---|
| intro | 8 | 8 |
| verse | 8 | 16 |
| pre-chorus | 8 | 8 |
| chorus / drop+hook | 8 | drop 8 + hook 8 |
| post-chorus | 8 | (drop 이 그 자리) |
| bridge | — | 8 |
| 합계 | 40 (1절만) | **104** |

[HARD] **개별 구간 길이를 상수로 박지 마라.** 버스가 8과 16 둘 다 실측됐다. 8마디 격자는
안전한 가정이지만 구간 길이는 검출해야 한다.

**댄스 브레이크** — 위치는 확정됐다: **2절 후렴 뒤, 브릿지 자리**. 실측 구조도 하나가
「브릿지는 댄스브레이크 반주로 대체됨」이라고 적는다. 학술 쪽도 방향을 확인한다 —
100곡 분석 학위논문(2025)이 「댄스 브레이크나 포스트 코러스와 같이 퍼포먼스를 강조하는
구조의 비중이 증가」한다고 결론한다.

[HARD] **그런데 길이는 어떤 출처에도 없다.** 한국어 실무 자료·학위논문·영어 언론 전부에서
댄스 브레이크를 명시하면서 길이를 함께 준 페이지를 찾지 못했다. **오디오에서 검출해야 하며
상수로 두는 것을 금지한다.** 조명으로는 이 구간이 가장 큰 기회다 — 보컬이 없고 퍼포먼스만
남으므로 §6 의 「움직임은 드롭 전용」 제약이 여기서는 풀린다.

**후렴 전조** — 마지막 후렴에서 반음·온음 상승하는 사례가 확인된다(한 곡은 후렴에서 두 번 상승).
빈도 통계는 없다. 서양 팝 대조군은 측정치가 있다 — 1958~1990년 1위곡의 **23%** 가 복수 조성이고
그중 **52%** 가 후반 상승형이며, 2010년대 1위곡에서는 단 1곡뿐이다(이 자료에 K-pop 언급은 없다).

[HARD] 마지막 후렴을 별도 취급하는 것은 정당하다(§7 사다리가 이미 그렇다). 다만 **전조를
전제한 설계는 조건부로 두어라** — 빈도가 안 잡혔다.

**곡 중간 템포 변화** — 한국어·영어 양쪽에서 **출처를 전혀 찾지 못했다.**
[HARD] 이것을 전제한 설계는 근거가 0이므로 만들지 않는다.

**구간 밀도** — 학술 측정은 없고 작곡가 증언이 있다: 「평균적인 미국 곡은 멜로디가 4개, 많아야
5개다. 평균적인 K-pop 곡은 8~10개다」(2018, 업계 언론). **멜로디 파트 수 증언이지 재현 가능한
구간 카운트 연구가 아니다.** 별도 근거로는 post-chorus 를 독립 구간으로 잡을 수치가 있다 —
200곡 중 **39곡(20%)** 에서 post-chorus 가 나타난다(2023 학위논문).

**조립식 작곡은 문서화가 잘 돼 있다.** 여러 작곡가의 제출물 조각을 이어 붙이는 방식이고
업계 용어는 「Frankenstein」이다(「song block」·「kitchen sink」라는 용어를 쓴 학술 자료는 없었다).
송라이팅 캠프 시스템으로 정착됐다는 것이 국내 학술 쪽 서술이다. 조명 관점의 함의는 하나다 —
**구간 사이의 음악적 연결이 약할 수 있으므로, 구간 경계를 부드럽게 잇는 것보다 분명히 끊는 편이
곡에 맞을 가능성이 높다.**

| 2 | **룩을 이름 알파벳 순으로 고른다** | `server/looks/songcue.py:461` `matches[0]`, 정렬은 `busking.py:95-96` `(dynamics, look_id)` | **코드** — §6 의 구간별 의도를 명시 사상으로 걸고, 같은 세기 안에서는 앞 큐와 가장 대비되는 룩을 고른다 |
| 3 | **반복 후렴이 삭제된다** | `songcue.py:558-566` `VALUE_LINE_COLLISION` | **코드** — §7. 값이 같은 것은 결함이 아니라 규범이다. 회차 필드를 넣고 사다리로 요소를 하나 더한다 |
| 4 | **브레이크다운에 큐가 안 나간다** | `server/looks/matching.py` 의 `DYNAMICS_TERMS` 에 breakdown·브레이크다운 0건 | **데이터** — 어휘 추가. §2 의 두 라벨 집합을 넣는 일의 일부 |
| 5 | **8마디 고정 분할** | `server/design/cue_density.py:89` `BAR_UNIT_BARS = 8`, `:68-70` 팔레트 상한 | **코드** — §5. 격자를 가중치로 바꾸고 팔레트 상한을 구간 수 상한으로 바꾼다 |
| 6 | **역할 어휘 6개가 리그의 절반을 못 부른다** | `server/looks/roles.py:43-77` 대 실기 그룹명 — `WASH-*`·`MOVER-*`·`BLIND`·`STROBE`·`HAZE` 전부 미매칭, 탑·배경 no_match. 5큐가 쓰는 것은 32/86대 = 37% | **감독 결정 + 데이터** — 역할 집합을 닫힌 6개로 유지할지가 SPEC 결정사항이다. 유지하면 블라인더·스트로브 없이 드롭을 만들어야 하고 §7 사다리의 마지막 두 칸이 불가능해진다 |
| 7 | **어두운 큐의 개념이 없다** | 큐 값에 페이드·딜레이가 없고, 드롭 직전 감광 규칙이 없다 | **코드** — §8. 드롭 앞 큐에 감광을 넣고 페이드 시간을 큐에 싣는다 |

**우선순위**: 3 → 1 → 2 가 눈에 보이는 변화가 가장 크다. 3은 사라지는 후렴을 되살리고,
1은 드롭을 드롭으로 만들고, 2는 절정용 룩에 도달 경로를 준다. 4·5는 그 다음, 6은 감독 결정이 먼저다.

**항목 2 는 절반이 닫혔다**(카드 t358, 2026-09-12). 곡 **사이**의 재사용은
`server/looks/song_history.py` 의 세션 기억으로 막는다 — 같은 세기 안에서 앞 곡들이 이미
쓴 룩을 뒤로 보내므로, 같은 장르의 다음 곡은 다른 룩으로 열린다(실측:
`server/tests/test_songcue_cross_song.py`). 아직 열려 있는 절반은 §6 의 구간별 의도를 명시
사상으로 거는 것과, **같은 곡 안에서** 앞 큐와 가장 대비되는 룩을 고르는 축이다.

## 13. 미확보 — 숫자로 메우지 않은 것

이 문서가 다루지 못한 것을 명시한다. 나중에 여기를 채우는 것이 후속 조사의 범위다.

- **K-pop 통계.** §11.2 로 실측 2곡과 댄스 브레이크 위치는 확보했으나 여전히 없는 것:
  댄스 브레이크 길이 · 전조 빈도 · 곡 중간 템포 변화 유무 · 구간 수의 서양 팝 대비 측정치.
  **회수 경로 하나가 값이 붙어 있다** — DBpia 유료 논문(안서윤·박재록 2022, 멜론 연간 top5
  댄스음악 150곡)이 마디표를 가졌을 가능성이 가장 크고 6,000원이다. 감독 결제 승인이 필요하다.
  실패하면 우리 곡 자료를 직접 주석해서 재는 것이 유일한 경로다.
- **팝의 구간별 마디 수 원전.** §4 는 Harmonix 실측이고, 문헌이 직접 준 값은 32마디 AABA 의 8마디 A 뿐이다.
- **발라드(60~80BPM) 구간 길이** — 직접 출처 없음. 앰비언트·다운템포 대역으로 대체했다.
- **록 라이브 세트의 구간 신축 정도** — 정량 출처 없음.
- **곡 구간별 조명의 학술·표준 문헌** — 존재를 확인하지 못했다. §6~§10 은 전부 실무 자료다.
- **4~5분 EDM 실측 구간 길이** — §4 는 중앙값 3분 39초의 서양 팝·EDM 혼합 기준이다.
  EDM 전용 데이터셋 주석을 내려받아 다시 재야 한다.
- **출처 두 건은 본문을 열지 못했다** — 큐 600개·타임코드 97% 수치와 컬러 피로 대목은
  검색 발췌 근거이므로 재확인이 필요하다.

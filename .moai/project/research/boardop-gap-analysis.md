# boardop 격차 분석 (SPEC-COPILOT-EVAL-001 — REQ-EVAL-007~009)

> 평가 방법: **문서 폴백 모드** (REQ-EVAL-014 — 접근 시도 기록 + 사용자 확정, 2026-07-16).
> 근거 자료와 시나리오별 관찰 행은 `boardop-eval-log.md` §1·§3 참조. boardop 소스 코드(스크린샷 내 코드 전사 포함)는 포함하지 않는다 (REQ-EVAL-010).

## 1. 평가 축 요약

| 축 | 종합 관찰 |
|---|---|
| ① 한국어 UX | 전 표면 영어 전용. 다국어 지원의 흔적 없음 |
| ② 안전장치 | 3중 장치(blast-radius 필터 / 플러그인 리뷰 게이트 / y·n 승인) 존재는 확인, **실차단 범위는 미검증**. 개발자 스스로 "guardrails, not guarantees" 선언 |
| ③ 도구 커버리지 | 컨텍스트 export + 명령 생성 + 플러그인 배포 + 상태 질의 관찰. 대표 작업 10종 중 화면으로 확인된 것은 4종(큐 스토어·이펙트·상태 조회·플러그인) — 나머지는 관찰 불가 |
| ④ 신뢰성 | 베타·클로즈드 배포·Windows 전용·raw SDK 경고 노출 등 성숙도 격차 다수 |

## 3. FSL-1.1-Apache-2.0 라이선스 검토 결론 (REQ-EVAL-009)

**결론**: 내부 사용·평가는 허용된다. 경쟁 상용 제품에의 코드 재사용은 각 릴리스가 Apache 2.0으로 전환되는 시점(릴리스별 2년) 이전까지 제약된다. 따라서 본 프로젝트는 **아키텍처만 벤치마킹하고 코드는 자체 구현(clean-room)한다.**

**근거**:
- FSL-1.1(Functional Source License)은 "free to use, modify, and redistribute for any purpose … **except offering it as a competing product**" 구조로, 사용·수정·재배포는 허용하되 **경쟁 제품 제공**을 금지한다 (boardop README License 절, fsl.software 템플릿과 일치).
- 본 프로젝트의 MVP(SPEC-COPILOT-MVP-001)는 grandMA3 AI 코파일럿이라는 동일 문제 영역의 제품이므로, boardop 코드를 재사용·파생하면 "competing product" 제약과 충돌할 위험이 있다. 코드를 일절 가져오지 않는 자체 구현이면 FSL은 적용되지 않는다 (라이선스는 코드에 붙는 것이지 아이디어·동작 관찰에 붙는 것이 아님).
- 각 릴리스는 2년 후 Apache 2.0으로 전환되지만, boardop은 현재 **릴리스 0건**이므로 전환 시계가 시작된 공개 릴리스 자체가 없다 — 재사용 가능 시점을 기다리는 전략은 성립하지 않는다.
- 예외: `ma3_plugins/`(콘솔 측 플러그인)는 MIT 라이선스로 별도 선언되어 있으나, 본 프로젝트는 이 경로도 사용하지 않는다 (clean-room 일관성 유지).
- 준수 장치: REQ-EVAL-010 + AC-EVAL-005 4항목 검수 (아래 §4) — 관찰·서술 기반 평가만 수행했고 코드 열람 자체가 불가능했다(소스 미공개). clean-room 오염 위험은 원천적으로 낮다.

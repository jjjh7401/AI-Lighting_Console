## 1. 서버 (Backend)

| 항목 | 선택 | 비고 |
|---|---|---|
| 언어/런타임 | Python 3.11+ | |

## 2. 콘솔측 (Console-side)

- **grandMA3 Lua 5.4 responder 플러그인**: socket 기반 상태 회수. 콘솔 오브젝트 트리 조회, 실행 결과 확인, 플러그인 풀 관리를 담당하는 콘솔 상주 컴포넌트.

## 3. UI

- **한국어 채팅 웹 UI**: React 또는 Svelte (미확정 — DESIGN.md는 두 옵션을 병기, 선택 기준 미정)
- 콘솔 옆 태블릿/세컨드 모니터 사용을 상정
- 음성 입력 옵션 (DESIGN.md §3 다이어그램에 언급, 상세 미정)

## 4. Phase 3 전용 — 음악 분석

- **librosa** 또는 **essentia**: 로컬 처리, API 불필요. 구간/BPM/에너지 분석 → 타임코드 큐리스트 초안 생성에 사용.

### 5.2 Tool Use 설계

Anthropic SDK tool runner 기반, `@beta_tool` 데코레이터로 다음 5개 도구를 정의:

```python
run_commands(commands: list[str], risk_note: str = "") -> str
# MA3 커맨드라인 명령 시퀀스를 검증→승인→OSC 실행하고 결과 반환.
# 파괴적 명령(Delete, Off Everything 등)은 승인 게이트에서 자동 정지.

query_state(path: str) -> str
# Lua responder를 통해 콘솔 오브젝트 트리 조회.
# 예: 'DataPool/Sequences', 'ShowData/Patch'

deploy_plugin(name: str, lua_source: str) -> str
# Lua 플러그인을 pcall 하네스로 컴파일 검증 후 리뷰 게이트 대기 → 배포.

get_rig_context(scope: str) -> str
# showfile XML / MVR에서 패치·그룹·프리셋 어휘·3D 배치 요약 반환.

propose_plan(...)
# 시스템 아키텍처 다이어그램(§3)에 언급된 5번째 도구. 상세 시그니처는 DESIGN.md §4.2 코드 블록에
# 명시되지 않음 — 미정(TBD).
```

- 승인 게이트는 **도구 함수 내부**에서 구현: 위험 명령이면 사용자 확인 전까지 실행하지 않고 "승인 대기/거부" 결과를 반환.
- 기본 설정: `thinking={"type": "adaptive"}` + `output_config={"effort": "high"}`.

### 5.3 프롬프트 캐싱 전략 (비용 최적화의 핵심)

시스템 프롬프트가 크다 (문법 룰북 + 오브젝트 모델 요약 ≈ 1~2만 토큰). 프리픽스 캐싱 구조:

```
[tools 정의]              ─┐
[룰북 + 오브젝트 모델]      ─┴─ 고정 프리픽스 → cache_control (ttl: "1h")
[쇼 스냅샷 · 대화 이력]     ── 매 턴 변하는 부분 → 캐시 뒤에 배치
```

- 캐시 읽기 = 기본 입력가의 ~0.1배 → 룰북 15K 토큰 기준 턴당 $0.075 → **$0.0075**로 감소.
- **주의**: 룰북에 타임스탬프·세션 ID 등 가변 값을 절대 삽입 금지 (프리픽스 1바이트만 바뀌어도 캐시 전체 무효화).
- 쇼 스냅샷은 messages의 마지막 user 턴에 주입 (캐시 프리픽스 보존).

## 6. 안전 아키텍처 (Safety Architecture)

4단계 안전 게이트 (데이터 흐름: 명령 생성 → **①문법 검증** → **②위험도 분류**(위험 시 승인 대기) → OSC 실행 → **③인간 승인 UI**를 거쳐야 하는 명령은 대기 → **④라이브 잠금**):

| 계층 | 내용 |
|---|---|
| ① 문법 밸리데이터 | 생성된 명령을 MA3 문법 파서로 실행 전 검사. 파싱 불가 명령은 실행 자체를 차단 |
| ② 위험 명령 분류 | 블랙리스트: `Delete`, `Remove`, `Off Everything`, `Store /overwrite`(라이브 시퀀스), `Shutdown`, `Format` 등 → 무조건 인간 승인. 번들 명령은 all-or-nothing |
| ③ 인간 승인 UI | 위험 명령에 대한 사용자 확인 게이트 |
| ④ 라이브 잠금 모드 | "라이브 모드" 토글 시 AI는 read-only + 제안 카드만 생성, 실행 버튼은 사람 |

추가 안전 요소:
- **파라미터 가드레일**: 스트로브 주파수·디머 급변 등 광과민성 발작 위험 패턴 경고
- **감사 로그**: 모든 실행 명령·승인·거부를 타임스탬프와 함께 기록 (쇼파일 백업 자동화 포함)
- **plugin 배포**: pcall 하네스로 컴파일 검증 후 리뷰 게이트를 거쳐 배포

## 7. 환각(문법 오류) 억제 — 3중 방어

1. **지식 레이어(Knowledge Layer)**: 검증된 MA3 문법 룰북을 시스템 프롬프트에 상주시킨다 (boardop 방식 벤치마킹).
2. **밸리데이터(Pre-execution Validator)**: 생성된 명령을 MA3 문법 파서로 실행 전에 검사한다 (키워드·오브젝트 참조 형식 확인).
3. **실행 피드백 루프(Self-correction Loop)**: 콘솔 에러 응답을 Claude에게 되돌려 자가 수정하게 한다. **재시도 상한 ≤3회**.

## 8. 통신 프로토콜

- **OSC (Open Sound Control)**: boardop에서 검증된 경로를 그대로 채택.
  - out: `/gma3/cmd` (또는 시스템 다이어그램 표기 `/cmd`, UDP)
  - in: `/python/feedback` (피드백 수신)

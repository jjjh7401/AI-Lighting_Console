# 제품 정의 (Product)

> 출처: `/DESIGN.md` (2026-07-15, 초안 v1). 이 문서는 DESIGN.md를 요약·재구성한 것이며, 새로운 사실을 추가하지 않는다. DESIGN.md에 없는 항목은 **미정(TBD)**으로 표기한다.

## 1. 한 줄 정의

**grandMA3 onPC 위에 얹는 Claude 기반 AI 코파일럿.**

콘솔을 대체하지 않는다. 사용자의 자연어(한국어) 의도를 grandMA3 커맨드/매크로/Lua 플러그인으로 변환해 실행하고, 콘솔 상태를 읽어 피드백 루프를 도는 **프로그래밍 보조 + 연출 초안 생성 도구**다.

- 실시간 재생(페이드, 이펙트, 타임코드 추종)은 MA3 엔진이 그대로 담당한다.
- AI는 "프로그래머" 역할을 수행한다: 큐·프리셋·그룹·매크로·이펙트를 만들고 수정한다.
- 라이브 쇼 진행 중에는 제안 전용(read-only) 모드로 강등된다.

## 2. 대상 사용자

- 조명 오퍼레이터 / LD(Lighting Director) — grandMA3 문법에 익숙하지 않거나 반복 프로그래밍 작업 시간을 줄이고 싶은 사용자.
- 소규모 공연장, 교회, 학교 등 **전문 오퍼레이터가 상주하지 않는 현장** — MA3 신규 인력의 온보딩 장벽을 낮추는 것이 핵심 가치.

## 3. 핵심 가치 제안

1. **자연어 → MA3 명령 변환**: "코러스에서 금색 톤으로 웅장하게" 같은 자연어 지시를 grandMA3 커맨드/큐/프리셋으로 변환한다 (추상 지시 해석은 Phase 2 이후 목표).
2. **Lua 플러그인 민주화**: 개발자 없이는 수일이 걸리거나 불가능했던 커스텀 Lua 플러그인 제작을, 자연어 요청으로 수 분 내 가능하게 한다.
3. **한국어 지원 차별화**: 선행 사례인 boardop은 영어 전용이며, 한국어 자연어 인터페이스는 국내 시장에서 뚜렷한 차별화 요소다.

## 4. 벤치마크 — boardop

가장 가까운 선행 사례이자 설계 출발점. OSC 통신(`/gma3/cmd`, `/python/feedback`), Lua responder + 플러그인 풀, `run_commands`/`deploy_plugin`/`query_state` 도구 세트, 3계층 지식 레이어(검증된 문법 룰 / 콘솔 오브젝트 모델 / 사용자 커스텀 룰), blast-radius 안전 필터 등의 **아키텍처 패턴을 벤치마킹**한다.

> ⚠️ **라이선스 제약**: boardop은 FSL-1.1-Apache-2.0 라이선스다. 내부 사용·평가는 자유이나, 경쟁 상용 제품에 코드를 재사용하는 것은 각 릴리스가 Apache로 전환되는 2년 시점까지 제약된다. 따라서 **아키텍처만 벤치마킹하고 코드는 자체 구현**한다.

## 5. 개발 로드맵 (5단계)

| Phase | 목표 | 성공 기준 |
|---|---|---|
| **Phase 0 — 검증** | grandMA3 onPC 설치 + boardop 실사용 평가, 격차 목록 도출, FSL 라이선스 검토 결론 문서화 | 자체 구현 범위 확정 |
| **Phase 1 — MVP 코파일럿** | OSC 브리지 + Lua responder 자체 구현, Claude tool-use 서버 + 한국어 채팅 UI, 안전 게이트 v1(문법 검증+블랙리스트+승인 UI) | 대표 프로그래밍 작업 10종을 자연어로 수행 · 문법 오류율 <5% · 지시→실행 왕복 <10초 |
| **Phase 2 — 리그 컨텍스트 인식** | showfile XML/MVR/GDTF 파서로 리그 이해, 프리셋 어휘 온보딩 마법사, onPC 3D 스크린샷 비전 자가 검증 루프 | "코러스에서 금색 톤으로 웅장하게" 수준의 추상 지시를 리그에 맞게 실행 |
| **Phase 3 — 음악분석 → 큐리스트 자동화** | 음악 분석(구간/BPM/에너지) → 타임코드 큐리스트 초안 생성, 장르별 룩 템플릿 | 3분 곡 1개 → 검토 가능한 큐리스트 초안을 10분 내 생성 |
| **Phase 4 — 라이브 보조** | 라이브 잠금 모드에서 다음 큐 제안, 버스킹 팔레트 추천, 이상 감지 알림 | 미정(TBD) — DESIGN.md에 정량 기준 없음 |

## 6. 명시적 비목표 (Non-Goals)

- **라이브 실시간 자율 운영 배제**: 라이브 쇼 진행 중 AI가 자율적으로 실행하는 것은 안전상 설계에서 원천 배제한다. 라이브 잠금 모드에서는 read-only + 제안 카드만 생성하며, 실행 버튼은 항상 사람이 누른다.
- **미적 최종 판단은 사람의 몫**: AI는 초안을 생성할 뿐, 연출의 최종 확정은 항상 사람이 한다.
- **MA 하드웨어 없는 DMX 실출력 불가**: onPC 정책상 실제 DMX 출력에는 MA 하드웨어가 필요하다. 개발·프리비즈(previz) 목적은 하드웨어 없이 무료로 가능하다.

## 8. 기대 효과 (요약)

- 그룹/프리셋 대량 셋업, 큐 시퀀스 빌드 등 반복 프로그래밍 작업 시간 대폭 단축 (정량 수치는 DESIGN.md §7의 추정치이며 Phase 1~2 기준).
- 비개발자에게 Lua 플러그인 제작이라는 새로운 능력을 부여.
- MA3 신규 인력의 문법 학습 없이도 즉시 작업 가능 → 온보딩 러닝커브 완화.
- 작업 로그 자동 문서화로 쇼 인수인계·복구 용이.

# t232 판정 — 프리셋 참조 안정성, 1단계 판독

- 카드: t232 (클래스 B), 레인 lane-2 · 브랜치 `WT-preset-ref-check` · 기준 origin/main `910e198d`
- 범위: 판독만 한다. 코드 수정 0, 콘솔 접촉 0.
- **답: 번호다.** 우리가 만드는 큐는 프리셋을 모두 **슬롯 번호**(`At Preset <풀>.<슬롯>`)로 참조한다. 이름으로 참조하는 생산 코드는 0곳이다.
- **하지만 모든 경로가 깨지지는 않는다.** 번호를 어떻게 정하는지가 경로마다 다르다.
  - 시트 경로와 페이저는 쓰는 순간 **이름으로 슬롯을 찾아** 번호를 적는다. 그래서 쇼파일마다 번호는 달라도, 각 쇼파일 안에서는 맞는 프리셋을 가리킨다.
  - 감독 확정 곡 큐와 대화 수정 경로는 `시작 번호 + 순서`로 번호를 계산한다. 시작 번호도 **점유 여부만** 확인한다. 그 10칸이 기본 포지션 10종이 아니면, 이름이 다른 프리셋을 조용히 부른다(재현 D).

## 1. 카드 전제와 이번 질문의 차이

카드 본문(2026-09-01)의 선행 조건은 「콘솔 큐 안에 참조가 저장되는가, 생값이 저장되는가」((A)/(C), t230)였다. 이것은 감독이 GUI로 확인해야 하는 **콘솔 쪽 질문**이고, 이번에도 재지 않았다.

리드가 이번에 물은 것은 **우리가 보내는 명령**이 번호로 참조하는지 이름으로 참조하는지다. 이것은 코드만으로 답할 수 있다. (A)/(C)와 무관하게, 번호가 틀리면 틀린 프리셋이 불린다.

## 2. 전수 판독

## 3. 재현 — 가짜 쇼파일 두 상태

명령: `.venv/bin/python .moai/reports/t232/repro_preset_ref.py` (출력 원문: `repro_output.txt`)

```
(1) 시트 경로 — 같은 CSV, 두 쇼파일 상태
  A 빈 풀: 배정 [('POS.01', 1), ('POS.02', 2)]  refusal=None
      큐의 POS.01 참조 -> At Preset 2.1 (그 슬롯의 이름: 'POS01 보컬 센터')
  B 1~6 점유: 배정 [('POS.01', 7), ('POS.02', 8)]  refusal=None
      큐의 POS.01 참조 -> At Preset 2.7 (그 슬롯의 이름: 'POS01 보컬 센터')

(2) 대화 경로 — 연속 10칸 점유만 보는 시작점 제안
  C 기본 10종이 1~10: 제안 시작점 [1] -> 'Center' 큐는 At Preset 2.4 = 실제 이름 'Center'
  D 시트 프리셋 10개가 1~10: 제안 시작점 [1] -> 'Center' 큐는 At Preset 2.4 = 실제 이름 'POS04 시트'
```

- (1) 카드 본문의 관찰대로, 같은 CSV가 상태에 따라 다른 슬롯(1 대 7)에 앉는다. 그래도 큐 참조는 두 상태 모두 `POS01 보컬 센터`를 가리킨다. **깨지지 않는다.**
- (2) D에서 앱은 시트 프리셋 10개가 앉은 1~10을 「기본 포지션 저장 확인됨」 시작점으로 제안한다. 감독이 그대로 고르면 'Center' 큐가 `POS04 시트`를 부른다. **경고 없이 틀린 위치로 간다.**

재현의 한계: (1)에서 풀의 ID → 슬롯 표는 `tools.py`의 `preset_id_from_console_head`를 부르지 않았다. 대신 첫 어절을 흉내 내는 스크립트 코드로 만들었다. (2)의 `_position_preset_ready_starts`와 (1)의 `map_presets`·`resolve_preset_ref`는 생산 함수를 그대로 불렀다.

## 4. 결론과 리드 판단 요청

- 카드를 「이름이라 안전」으로 닫을 근거는 **없다**. 번호 참조이고, 곡 큐와 대화 수정 두 경로가 깨질 수 있다.
- 깨지는 조건은 두 가지가 겹칠 때다. 하나는 포지션 풀의 연속 10칸이 기본 포지션 10종이 아닌 것이다(예: 시트 프리셋이 앞 칸을 채운 쇼파일). 다른 하나는 감독이 그 시작점을 고르는 것이다.
- 고치는 방향(판단은 리드): 시작점을 제안할 때 점유뿐 아니라 **라벨이 `BASIC_POSITION_SEQUENCE` 순서와 맞는지**도 보게 하는 방안이 있다. 이렇게 하면 곡 큐와 대화 수정이 함께 막힌다. 또는 페이저처럼 라벨로 슬롯을 찾는 방식으로 바꾸는 방안도 있다. 코드 수정은 리드 확인 후에 한다.

## 5. 안 잰 것

- 콘솔 큐 안에 참조가 저장되는지 생값이 저장되는지((A)/(C), t230): GUI 확인 대기 그대로다.
- 포지션 FX의 `fx_preset_start` 선택 방식: 점유만 보는지 라벨도 보는지 읽지 않았다.
- 실제 쇼파일에서 D 상태(시트 프리셋이 기본 10종 자리를 차지한 상태)가 생기는지: 콘솔 0회.
- 프리셋이 저장된 뒤 콘솔에서 옮겨지거나 번호가 바뀌는 경우의 큐 동작.

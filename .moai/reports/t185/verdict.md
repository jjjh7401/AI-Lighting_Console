## 1. drop·undrop·--expect 4축 실측 (전용 카드로)

전용 카드 t189·t190 을 만들어 썼다(t185 착수 직후, 판정 뒤 둘 다 drop 으로 정리).
카드 본문에 미측정으로 남아 있던 것 셋을 쟀다.

### 1.1 drop 한 카드가 기본 출력에 보이는가 - 보인다

    $ moai todo drop t189 "..."
    dropped t189 t185 실험용 — 끝나면 drop (reason: ...)

    $ moai todo | grep t189
    t189  dropped  [DROPPED — 사유] t185 실험용 — 끝나면 drop

우려("안 보이면 사라진 것처럼 보인다")는 반증됐다. state 는 dropped 로 바뀌고
본문 앞에 [DROPPED — 사유] 가 붙어 기본 list 출력에 그대로 남는다. --json 으로도
확인했다 - state: "dropped" 필드가 그대로 있다.

### 1.2 undrop 이 원래 자리로 돌리는가 - 그렇다

    undrop 전: t188(queued) t189(dropped) t190(queued)  <- 순서 그대로
    $ moai todo undrop t189
    undropped t189 ...
    undrop 후: t188 t189 t190  <- 같은 자리, 끝으로 안 감

t190 을 t189 뒤에 만들어 t189 가 더는 마지막이 아니게 한 뒤 쟀다 - 위치 보존을
증명하려면 t189 가 끝자리가 아니어야 했다. undrop 뒤 본문 접두([DROPPED —...])도
사라지고 원문·상태(queued) 모두 원상복구됐다.

### 1.3 --expect 가 실제로 거절하는가 - 두 팔 다 확인

    음성: --expect "존재하지않는접두XYZ" (틀린 접두)
      -> exit 1, "mutation refused: ... not matching --expect ..."
      -> 카드 원문 그대로 (안 건드림)
    양성: --expect "t185 실험용 2"(맞는 접두)
      -> exit 0, edited, 본문 실제로 바뀜

대조군 두 팔 다 확인했다 - 거절도 하고(1) 통과도 한다(2). 계기가 실제로 판별력이
있다.

## 2. (1) done 예외 - 없애라

t113 기록(2026-08-26)의 done 예외는 "내용을 잃어도 되는 카드(중복·오타)에만
쓴다"였다. 지금 drop 을 재보니 그 예외가 설 자리가 없다:

    done   파괴. 본문·배차 맥락·측정 조건 전부 사라진다. 복구 불가(1.1·1.2 실측)
    drop   사유를 남기고 버린다. 기본 출력에 여전히 보인다. undrop 으로 완전 복구된다

중복·오타처럼 "내용을 잃어도 되는" 카드조차 drop 이 더 낫다 - 잃어도 되는 게
아니라 안 잃는 게 공짜이기 때문이다. done 을 고를 이유가 사실상 없다. 유일하게
남는 변론은 "list 출력이 dropped 항목으로 길어진다"는 것인데, 이건 표시 필터의
문제이지 파괴를 정당화하지 않는다.

권고: done 예외를 없애고 drop 을 기본 종료 수단으로 삼는다.

## 3. (2) 닫힘 표시 - 긴장이 있다, 단정 안 함

edit 접두 관행(t181 실측: status 는 안 바뀌고 queued 그대로, 닫힘은 본문 접두로만
읽힌다)과 drop 을 나란히 놓으면 후보가 둘로 갈린다:

    edit 접두   status 는 그대로 queued. 본문에 "closed ..." 를 적어 사람이 읽는다.
                queued 개수를 열린 일의 양으로 오독하게 만든 그 형태다(관측된 사고 1건)
    drop        state 가 실제로 dropped 로 바뀐다 - --json 으로 기계가 구별 가능.
                다만 drop 의 도구 의미론은 "폐기"이지 "완료"가 아니다
                (--help: "Discard a queued card ... recording the reason")

drop 을 닫힘 표시로 쓰면 의미가 어긋난다 - "이 카드는 완료됐다"를 "이 카드는
버려졌다"로 기록하는 셈이다. 반대로 edit 접두를 유지하면 오늘 실제로 난 오독
(queued 개수 문제)이 계속 재현된다.

**단정하지 않는다.** 세 갈래가 있고 각각 값싼 이유와 비싼 이유가 있다:

| 후보 | 값싼 이유 | 비싼 이유 |
|---|---|---|
| edit 접두 유지 | 도구 변경 없음, 지금 관행 | queued 오독이 계속 남 |
| drop 을 닫힘으로 전용 | state 가 기계로 구별됨 | 도구 의미론과 어긋남(폐기≠완료) |
| 새 상태(예: done-but-kept) 요청 | 의미가 정확함 | 도구에 없다 - 하네스 코드 변경 필요, 이 카드 범위 밖 |

권고는 안 낸다 - 이건 도구 의미론과 관행 중 무엇을 우선할지의 결정이고, 감독·리드
판단이 필요하다.

이 문면의 집: lane-protocol.md §1(착수) 또는 새 절 - §3 이 74행이라 t184 가
절 쪼개기를 먼저 판정한다고 들었다. 이 문면은 §3(검증)이 아니라 카드 종료
관행이므로 §1 이 더 가깝다고 본다.

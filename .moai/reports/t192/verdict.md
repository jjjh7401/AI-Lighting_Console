## 0. 이 카드가 답해야 하는 둘

리드가 갈아준 카드 본문의 「잴 것」:

그리고 카드가 적은 ⚠️미측정: **발생 3건이 전부 같은 계열 세션인가.**

## 1. Claim — 무엇을 주장하는가

- C1. 명령줄은 **transcript 안에만** 살고, 산출물과 함께 이동하지 않는다.
- C2. `| head` 는 이 계열의 습관이 아니다 — **89개 프로젝트 중 88개**, 전체 Bash
  명령의 **26.8%**. 그러므로 「head 를 쓰지 마라」류 처방은 성립 불가.
- C3. 사고가 가능해지는 순간은 **포화**(출력 행수 == N)뿐이고, 그것은 `head -N`
  호출의 **18.5%** 다. 나머지 81.5% 는 상한에 안 닿아 개수로 읽어도 참이다.
- C4. 저장본으로 밀려난 결과 **68건 중 35건**이 head 로 자른 명령이다. 이때
  배너의 「Output too large」가 **자기 head 를 하네스 탓으로 읽히게 만든다** —
  내 사고 #3 의 기계적 뿌리이고, 다른 세션들에서 같은 형태가 반복된다.
- C5. 따라서 처방은 **경보가 아니라 라벨**이어야 한다. 경보는 표적이 413건이라
  값이 안 나오고, 라벨은 애매해지는 그 순간에만 붙는다.
- C6. (2)번 값싼 대조는 **넣을 만하다** — 1개 명령으로 거짓 결론을 뒤집었다.
  다만 재실행 가능한 명령에만 적용되므로 조건을 명시해야 한다.

## 4. 판정 재료 — 어디가 싼가

| 축 | 상태 | 값 |
|---|---|---|
| 규약 문면 | **이미 있다** (§3.6 + §4.0) | 있는데도 3회 발생. **소진됨** |
| 보고 서식 | 없음 | 보고자가 기억해야 함 → 문면과 **같은 실패 방식** |
| 기계 — 경보 | 없음 | 표적 413건. 알려진 사고 3건 대비 138:1 |
| 기계 — 라벨 | 없음 | 788건에 표시. 경보 아님 → 소음 문제 없음 |

🔴 **138:1 을 「시끄럽다」의 증거로 쓰지 마라.** 3 은 *우리가 알아채고 적은* 사고
수이지 실제 발생 수가 아니다. 413건 중 몇 건이 틀린 결론으로 갔는지는 **아무도 안
쟀고 스캔이 볼 수 없다** — 추론 단계는 명령줄에 안 남는다. 그러니 이 비율로
「경보는 비싸다」를 결론내면 그 자체가 이 카드가 다루는 오류다.
말할 수 있는 것은 하나: **경보라면 이 코퍼스에서 413번 울린다.**

### 권고 — 경보 말고 라벨

경보와 라벨은 실패 모드가 다르다. 경보는 무시되면 죽고, 라벨은 안 읽히면 그냥
안 읽힐 뿐 거짓을 만들지 않는다. 표적이 애매한 지금은 라벨이 맞다.

**제안**: PostToolUse 에서 명령이 `head -N` 을 포함하고 출력 행수가 정확히 N 이면,
출력 끝에 한 줄을 덧댄다.

```
[head -N 상한에 닿음: 출력이 정확히 N행이다 — 이 N 은 개수가 아니라 상한일 수 있다]
```

근거 둘:
- 이 훅은 **실재한다.** `.claude/hooks/moai/handle-post-tool.sh` 주석:
  `v2.1.121+: hookSpecificOutput.updatedToolOutput extends to all tools (not MCP-only).`
  즉 출력에 덧대는 통로가 이미 있다.
- 훅은 명령과 출력을 **동시에** 본다 — 사람이 못 하고 있는 바로 그 결합이다.

⚠️ **안 잰 것**: 출력이 저장본으로 밀려난 경우(E5 의 35건) 훅이 전체 출력을
보는지, 배너만 보는지 **안 쟀다.** 내 사고 #3 이 바로 그 경우이므로 **이 처방이 내
사고 자리에 닿는지가 미검증이다.** 구현 전에 이것부터 재야 한다.

## 5. §4.0 에 넣을 문면 제안 (파일은 안 건드림 — 리드에게 올림)

### 제안 A — 「온전하다」의 기준을 명시한다 (수정)

현행 §4.0 표 1행은 「하네스 출력 상한 → 그 **파일**을 읽어라 — 온전하다(md5 동일
실측)」이다. **이 문장은 참이지만 기준이 안 적혀 있고, 그 빈칸이 나를 속였다.**

저장본은 **하네스에 들어간 스트림 기준으로** 온전하다. 네가 앞 단에서 잘랐다면
저장본도 잘려 있고, 배너는 그것을 하네스 탓으로 읽히게 만든다.

> 저장본은 **하네스가 받은 스트림 기준으로** 온전하다 — 네 파이프라인이 앞에서
> 자른 것까지 되돌려주지 않는다. 저장본 68건 중 **35건이 `head` 로 자른 명령**이고,
> 그때 배너의 「Output too large」는 **네 상한을 하네스 탓으로 읽히게 만든다.**
> (2026-08-31 t192 실측) **배너를 보면 먼저 자기 명령줄을 읽어라.**

### 제안 B — 값싼 대조 한 줄 (추가)

> 🔴 **「계기가 잘랐다」를 주장하기 전에 파이프를 떼고 한 번 더 돌려라.**
> 명령 하나이고, 2026-08-31 에 그 한 번이 거짓 결론을 뒤집었다.
> 적용 조건: **재실행이 싸고 부작용이 없는 명령**에 한한다 — 비싸거나 쓰기를
> 하거나 출력이 시각에 따라 변하는 명령은 이 대조가 성립하지 않는다. 그때는
> 대신 **명령줄을 인용**해라(§3.6).

### 제안 C — 표에 3행을 추가한다 (추가)

현행 표는 잘림을 둘로 가른다(하네스 / `head`). 실측된 셋째는 **둘의 합성**이고,
신호가 「없다」가 아니라 **거짓 신호**라 가장 나쁘다.

| 잘림 | 신호 | 복구 |
|---|---|---|
| `head` **와** 하네스 저장이 겹침 | **거짓 신호** — 배너가 하네스 탓으로 읽힌다 | 자기 명령줄을 읽어라. 저장본은 안 도와준다 |

## 6. Gaps — 안 잰 것

1. **라벨 처방이 저장본 경우에 닿는지 안 쟀다** (§4 ⚠️). 내 사고가 그 경우다.
2. **413건 중 실제로 틀린 결론으로 간 비율을 안 쟀다.** 추론 단계는 기계가 못 본다.
   3 은 하한이지 개수가 아니다.
3. **`over/banner` 2,486건의 내부를 안 갈랐다.** head 가 중간 단인 경우와 배너가
   붙은 경우가 섞여 있다.
4. **§4.0 의 「30,000바이트」를 검산하지 않았다.** 내 관측 하한은 141.5KB 이고
   30,000 근처를 안 쐈다. 이 카드의 범위 밖이라 두었다.
5. **보고 서식 축을 문면 축과 같다고 판정했지만 실측이 아니다.** 「보고자가 기억해야
   하므로 같은 실패 방식」은 추론이다.
6. **다른 사람/다른 기계에서도 같은지 안 쟀다.** 코퍼스는 이 기계의 이 사용자뿐이다.

## 7. Residual-risk

- **숫자가 만료된다.** 코퍼스가 살아 있어 재실행하면 값이 다르다(늘기만 한다).
  인용할 때 날짜를 떼면 「흐르는 기준」이 된다.
- **정규식 판별의 과대/과소.** `PIPE_HEAD` 는 따옴표 안의 `| head` 도 센다 —
  표면 측정이라 과대 쪽으로 의도했지만 값을 부풀린다. 반대로 `bash -c` 안에 숨은
  형태는 못 본다.
- **라벨을 넣어도 안 읽힐 수 있다.** 라벨은 경보와 달리 실패해도 조용하다 —
  그것이 장점이자 한계다. 넣고 나면 **다음 발생까지 효과를 알 수 없다.**
- 이 보고서 자체가 **head 함정의 표적**이다. 위 명령을 재현할 때 `| head` 를
  붙이면 같은 자리에 다시 선다.

## 8. 부록 — 이 회차에서 추가로 잰 둘

### 8.1 탐침 재작성은 행동을 안 바꿨다 (회귀 확인)

pre-push 게이트가 막았다 — **게이트는 내가 건드린 파일을 린트하고, 탐침 `.py`
들이 거기 걸린다.** 원인은 내 것이었다(선행 상태에서는 안 나던 실패).

```
make test-fast
  -> 2 failed, 314 passed
     TestTouchedFilesPassLint::test_ruff_check_passes_on_them
     TestTouchedFilesPassLint::test_ruff_format_reports_no_change
     "Would reformat: .moai/reports/t192/probes/_t192_subforms.py"
```

탐침 5개를 공용부(`_t192_common.py`) + f-string + 컨텍스트 매니저로 다시 썼다.

```
uv run ruff check  .moai/reports/t192/probes/   -> All checks passed!
uv run ruff format --check .moai/reports/t192/probes/  -> 6 files already formatted
python3 _t192_saturation.py  -> saturated=788 (재작성 전과 동일)
```

포화 788 이 재작성 전후로 같다 — **양식 수정이 계기를 안 깨뜨렸다.** 나머지
값들이 조금씩 움직인 것은 §3 의 코퍼스 생존 때문이고, 방향이 전부 증가라
일관된다.

⚠️ 이 사실 자체가 관행 하나를 드러낸다: **`.moai/reports/` 아래 탐침도 린트
대상이다.** 조사 카드가 `.py` 탐침을 커밋하면 게이트에 걸린다 — 다음 레인이
같은 자리에 선다.

### 8.2 규약 §2 의 「heredoc 방아쇠는 중괄호」가 이 세션에선 재현되지 않았다

§2 는 「Bash 히어독의 방아쇠는 중괄호다 … 정규식 `[0-9]` 세자리 하나로 거절됐다」
로 적는다. 이 세션에서 **재현되지 않았다.**

```
cat > .moai/reports/t192/probes/_braceprobe.py <<'EOF'
x = 3
print(f"value={x}")
EOF
echo wrote     ->  wrote      (중괄호 · f-string 둘 다 통과)
```

이 회차에서 실제로 거절된 것은 **복합 명령**이었다:

```
rm ... && cat > ... <<'PYEOF' ... PYEOF && uv run ruff check ...
  -> "this command is too complex to verify that it stays inside the worktree"
```

거절 문구가 중괄호가 아니라 **워크트리 이탈 검증 불가**를 말한다. 즉 §2 의
방아쇠 진단은 최소한 이 세션에서는 **축이 다르다** — 중괄호가 아니라 정적으로
경로를 못 따라가는 구조(체이닝·`cd`)다.

⚠️ **안 잰 것**: §2 를 낳은 세션과 이 세션의 차이가 무엇인지 안 쟀다. 가드가
버전·설정·시작 디렉터리에 따라 갈릴 수 있으므로 **§2 를 지우자는 뜻이 아니다** —
「환경에 따라 갈린다」를 §2 에 붙일 재료로 리드에게 올린다.

## 1. 카드 전제

"인계문이 터미널을 통과하면서 잘린다 — 붙여넣기 사본이 원본과 다르고, 잘린 명령이
여전히 실행된다." 실측 A(plan 세션, t182 워크트리)와 실측 B(리드 세션 t98)를
근거로 든다.

## 2. 실측 A 재확인 — 원본과 어긋난다

카드 문면: "원본 memory/project-lane-resume-t182.md 의 「다음 세션이 할 일」 4번은
심볼명 unreadable_root 와 grep 의 -c 플래그를 다 들고 있는데, 붙여넣기 사본은
… -c 가 사라지고 _root 가 잘려 있었다."

원본을 직접 다시 읽었다(같은 파일, 같은 경로):

    $ grep -n "다음 세션이 할 일" -A 12 memory/project-lane-resume-t182.md
    54:## 다음 세션이 할 일
    ...
    63:4. 검사 6개와 뮤테이션 6/6 은 그대로 산다 — 수용 기준을 단언으로 옮긴 것이라
    64:   구현 형태와 독립이다. 되돌릴 것은 patchplan 의 import + try/except 뿐이다
    65:5. t182 unreadable_root 독스트링의 "예외 이름을 부르는 것은 거기 안 걸린다"는
    66:   반증됐다 — 어느 안으로 가든 그 한 줄은 고쳐야 한다

    $ grep -n "grep -c\|unreadable_root" memory/project-lane-resume-t182.md
    48:- grep -c 'except StateQueryError' 가 주석까지 센다. 자리는 grep -n 으로
    65:5. t182 unreadable_root 독스트링의 "예외 이름을 부르는 것은 거기 안 걸린다"는

「다음 세션이 할 일」 4번(63~64행)은 grep -c 도 unreadable_root 도 담고
있지 않다. 둘은 서로 다른 두 자리에 있다 — grep -c 는 48행(번호 목록 밖의
독립 불릿), unreadable_root 는 65행(4번이 아니라 5번). 카드가 "4번이 둘 다
갖고 있었다"고 적은 전제 자체가 원본과 안 맞는다.

결론(A): 이 표본은 붙여넣기 전송이 잘랐다는 증거로 못 쓴다. 오히려 규약
§3.6 이 경고하는 형태 — 근거를 대기 전에 원본을 다시 안 읽은 것과 더
닮았다. 두 서로 다른 위치의 내용이 "같은 자리(4번)"로 합쳐져 기억/재구성된
것이라면, 이건 전송 계기의 결함이 아니라 인용 재구성의 결함이다.

## 3. 실측 B — 재확인 불가 (전제, 원본 미회수)

카드가 인용한 t98 원문(lsof -p (pid) -a -d cwd -Fn, gh api repos/{REPO}/…
check-runs, moai todo done/next/unpick/edit/move/drop/undrop)의 원본
소스를 이 저장소의 메모리 색인에서 찾지 못했다:

    $ grep -rl "lsof -p\|check-runs" memory/*.md
    (매치 없음)

session-handoff.md § Auto-Memory Integration 6항("close-time pruning")은
SPEC 종결 시 인계문의 원문 블록을 한 줄 요약으로 가지치기하도록 규정한다.
t98 인계문이 이미 가지치기됐다면, "지금 원문이 안 보인다"는 전송 손상이 아니라
설계된 보존 정책의 결과일 수 있다 — 이 갈래를 실측 A처럼 반증도 확증도
못 했다. 미측정으로 남긴다.

## 4. 이번 회차에 직접 잰 통제 팔 — 교차세션 메시지 채널

이 세션이 이번 카드를 받는 과정에서 리드로부터 SendMessage 로 긴 한국어+
영문 혼합 메시지(하이픈 플래그·백틱·경로 다수 포함)를 두 차례 받았다. 수신
본문을 그대로 대조했을 때 하이픈 플래그, 백틱 코드, 경로 표기 어느 것도
잘리거나 합쳐지지 않았다.

결론: 적어도 SendMessage(교차세션 메시지) 경로는, 카드가 지목한 잘림을
이 회차 표본에서 재현하지 않았다. 이는 카드가 원래 지목한 "터미널 붙여넣기"
경로(사람이 렌더된 텍스트를 복사해 터미널에 붙여넣는 경로)와는 다른 채널이므로
대체 증거이지 대체 판정은 아니다 — 잘림이 사람의 클립보드/붙여넣기 단계에서만
나는 것이라면 이 팔은 애초에 안 걸릴 수 있다.

## 6. 이번 회차가 못 잰 것 (Gaps)

- 실측 A·B 모두 사람이 실제로 터미널에 붙여넣는 물리적 단계를 거쳐 나온
  주장인데, 이 세션은 그 단계를 재현할 도구가 없다(4절의 SendMessage 관측은
  방증일 뿐 대체 실측이 아니다).
- 자동 주입(handoff.mode: auto) 경로는 카드도 "아무도 안 쟀다"고 적었고,
  이번 회차도 못 쟀다.
- 실측 B의 원문을 어디서도 못 찾아 재확인 자체가 불가했다 — pruning 정책과
  전송 손상을 가르는 후속 조사가 필요하다.

## 7. 잔여 위험 (Residual-risk)

- 실측 A가 무너지면서 카드의 "잘림이 실재한다"는 전제 자체의 신뢰도가
  낮아졌다. 다만 이것이 "잘림이 없다"의 증거는 아니다 — 실측 B가 검증 안 된
  채 남아 있고, 저장소엔 이미 "잘못된 귀속" 사고가 반복적으로 기록돼 있다
  (lesson-a-summary-is-not-evidence, 규약 3.6절). 다음 회차는 실측 B의 원문부터
  회수하거나, 아니면 리드/t98 세션에 직접 물어 그 인계문이 실제로 어느 파일·어느
  전송 경로에서 나왔는지부터 확정해야 한다.

## 9. 갱신 — 실측 B 원문 확보 (리드 = t98 자신, 2차 회차)

리드가 t98 세션 본인이며, 손상본이 디스크가 아니라 **그 세션의 대화 컨텍스트**에
그대로 남아 있었다. 정본을 알 수 있는 자리만 골라 대조쌍으로 고정한다(리드
제공, 이 세션은 원문 접근 불가 — 리드의 관측을 그대로 인용하고 출처를 밝힌다):

    (1) moai todst done next unpick edit move drop undrop
        → moai todo list done …  에서 o·l·i 유실, "todo list" 가 "todst" 로 뭉침
    (2) done 은 dit 접두로              → edit 의 e 탈자
    (3) status  ueued 개수를            → queued 의 q 탈자
    (4) gh api rs/<headRefOid>/check-runs
        → repos/<owner>/<repo>/commits/ 가 "rs/" 로 대량 유실
    (5) 레인은   <pid> -dcwd -Fn 으로 정체 확인)
        → "lsof -p" 통째 유실, "-a -d cwd" 가 "-dcwd" 로 뭉침
    (6) sync=100— 셋 다/clear 대상이거나  → sync=10050 잘리고 다음 문장과 융합
    (7) 개수  | head 가붙은 출력을      → 공백 소실 + 중복 공백
    (8) "그 다음 큐에서 / 감독이 고른"     → 문장 미완결

### 9.1 카드의 물음 (1)(2)에 대한 답

- **한국어 산문은 멀쩡한데 ASCII 명령만 뭉개졌다** — 문자 의존 쪽에 무게가
  실리는 첫 신호다. 길이 의존은 여전히 안 갈린다(짧은 토큰 `q`, `e` 도 빠졌다).
- **유실이 행 단위가 아니라 문자 단위다**(`q` 하나, `e` 하나, `o`·`l`·`i`
  묶음). 그래서 손상된 명령이 **문법적으로 죽지 않고 실행되어 다른 값을
  답한다** — "잘림"보다 **탈자**가 정확한 이름이다. §4.0 표의 두 잘림 유형
  (하네스 상한 / `head`)과는 또 다른 셋째 형태로, **행 경계가 아니라 문자
  경계**에서 난다는 점이 갈림점이다.

### 9.2 여전히 못 가르는 것 (정직하게 남긴다)

- **손실 자리**(클립보드 / 터미널 bracketed paste / 하네스 입력 처리) —
  이 표본으로도 세 경로 중 어디인지 못 가른다.
- **"붙여넣기에서 났다" vs "애초에 그렇게 작성됐다"** — 엄밀히는 이것도
  이 표본만으로 완전히 못 가른다. 다만 (1)(3)(5)는 정본이 명백해 작성
  당시부터 그렇게 썼을 가능성은 낮다(예: "moai todst" 라고 처음부터 쓸
  이유가 없다) — 그 정도의 방증이지 확정은 아니다.
- 카드가 요청한 판정 셋(§5 표)은 **그대로 미측정**이다. 사람의 실제
  클립보드→터미널 붙여넣기 단계를 이 세션이 재현할 수단이 여전히 없다.

### 9.3 통제 팔 재평가

§4의 SendMessage 관측(하이픈·백틱 무사)은 여전히 다른 채널이라 판정은
아니지만, 이제 대비가 더 뚜렷하다: **SendMessage 경로는 이 회차까지
무사하고, 사람이 개입하는 붙여넣기 경로에서만 탈자가 관측됐다.** 이 대비
자체가 다음 회차가 어디를 먼저 봐야 하는지의 근거다.

### 9.4 판정 갱신

- 실측 A: **철회**(§2, 유지).
- 실측 B: **확보·고정함**(원문 8쌍, 위 §9 본문). 탈자가 실재한다는 것
  자체는 이제 이 표본으로 지지된다. 다만 손실 자리·작성 대 전송의 구분은
  여전히 미해결.
- 카드 제목/프레이밍 정정 제안: "잘림"이 아니라 "탈자(문자 단위 유실)".
- 통제 붙여넣기 실험을 사람에게 요청할지는 **감독 판단**으로 남긴다 —
  이 보고서는 그 필요성만 적고 요청은 하지 않는다.

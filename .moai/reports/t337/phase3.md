# t337 국면 3 — 별표 임포트를 명시 임포트로, 유예 70쌍 → 62쌍

측정 트리: `.claude/worktrees/t337c` · 기준 커밋 `9bd11b7`(국면 2 머지 후) · 일자 2026-09-08

## 1. 주장

- `from X import *` 4곳을 명시 임포트로 바꿨다.
- F403 4건 · F405 49건 = **53건 소멸**. 전수 위반 **232 → 179**.
- 유예 쌍 **70 → 62** (F403·F405 를 4개 파일에서 각각 제거). `_PAIR_CEILING` 도 62 로 하향.
- 산출물 13개 동일 · `validate.py` 실행 출력 바이트 동일.

국면 1·2 와 달리 이번엔 유예 목록이 실제로 줄었다. 카드의 출구(목록 비우기)에
처음 다가간 국면이다.

## 2. 증거

### 2.1 카드가 경고한 함정 둘을 먼저 확인

카드는 「어느 이름이 어디서 오는지 실제로 확인해야 하고, 가려져 있던 이름 충돌이
드러날 수 있다」고 했다. 두 가지를 착수 전에 쟀다.

**(가) 재수출 위험.** `from X import *` 는 X 가 임포트한 것까지 재수출하므로,
소비자가 별표를 통해 `os`·`csv` 같은 모듈을 받고 있었다면 명시 임포트로 바꾸는
순간 `NameError` 가 난다. 두 소스 모듈에 임포트문이 있는지 쟀다:

```
$ grep -nE '^(import|from) ' rig_data.py seq_data.py
(출력 없음)
```

둘 다 상수·함수만 정의하고 아무것도 임포트하지 않는다 → 이 축의 위험은 없다.
`__all__` 도 어느 파일에도 없다(전수 grep).

**(나) 이름 충돌.** AST 로 각 소비자가 별표 이름과 같은 이름을 스스로 묶는지
쟀다(`.moai/state/verify/t337c/star_survey.py`). 4곳 모두 충돌 후보 0건.

### 2.2 필요한 이름만 골라냈다

| 소비자 | 소스 | 모듈 공개 이름 | 실제로 쓰는 것 |
|---|---|---|---|
| `make_rig.py` | `rig_data` | 15 | **13** |
| `make_timeline.py` | `seq_data` | 9 | **5** |
| `make_xlsx.py` | `seq_data` | 9 | **6** |
| `validate.py` | `seq_data` | 9 | **4** |

별표가 가리고 있던 것: `make_rig` 는 15개 중 2개를, 나머지 셋은 9개 중 3~5개를
쓰지 않는데 전부 받고 있었다.

### 2.3 파일 하나씩 — 카드 지시대로

카드는 「파일 하나씩. 11개를 한 번에 걷지 마라 — 하나가 터지면 어디서 터졌는지 못
가른다. 산출물 바이트 비교를 파일마다」라고 했다. 그대로 했다.

| 순서 | 파일 | 산출물 대조 |
|---|---|---|
| 1 | `make_rig.py` | 13/13 SAME |
| 2 | `make_timeline.py` | 13/13 SAME |
| 3 | `make_xlsx.py` | 13/13 SAME |
| 4 | `validate.py` | 13/13 SAME + 실행 출력 바이트 동일 |

`validate.py` 는 산출물을 만들지 않고 **검사만** 하는 파일이라 산출물 대조로는
아무것도 안 잡힌다. 그래서 실행 출력(21행, `결과: 15/15 PASS` 포함)을 변경 전후로
받아 `diff` 로 대조했다 — 바이트 동일. 이 축을 안 쟀으면 이 파일은 실질적으로
검증 없이 통과했을 것이다.

### 2.4 유예 목록 검산

전수 출력에서 뽑은 62쌍이 `pyproject.toml` 의 목록과 정확히 일치한다(불필요 0 · 빠짐 0).
`ruff check .` → `All checks passed!` · `ruff format --check` → 11 files already formatted.

### 2.5 상한이 실제로 조이는지 — 뮤테이션

`make_rig.py` 의 유예에 `F405` 를 되살렸더니 `test_the_pair_count_did_not_grow` 가
FAIL 했다. 62 라는 값이 장식이 아니라 걸려 있음을 확인했다.

## 3. 미검증 (Gaps)

- **`E402`(19건) 는 이번에 안 건드렸다.** 명시 임포트로 바꾼 4곳 모두 `sys.path.insert`
  뒤에 임포트가 오는 구조라 E402 는 그대로다. 카드가 「E402 가 가장 위험하다 —
  옮기기 전에 왜 아래에 있는지 읽어라」라고 지목한 자리이고, 이번 국면의 범위가 아니다.
- **쓰이지 않는 것으로 판정한 이름들.** `used_names` 는 AST 의 `Name` 노드를 세므로
  `globals()`·`eval`·`getattr` 로 간접 참조하는 경로는 못 본다. 그런 참조가 실제로
  없다는 것은 **파이프라인 5개 실행이 전부 exit 0 이고 산출물이 동일했다는 사실로만**
  지탱된다 — 정적으로 증명하지 않았다.
- 남은 179건: UP031 62 · E501 36 · E402 19 · I001 16 · UP009 11 · B007 9 · E401 9 ·
  E741 6 · B905 5 · F401 4 · SIM115 1 · SIM300 1.

## 4. 잔여 위험

- 간접 참조(`globals()` 류)가 다른 실행 경로에만 있으면 이번 실행에서 안 드러나고
  그때 `NameError` 로 터진다. 다만 이 실패는 **조용하지 않다** — 즉시 예외로 나타나고
  파이프라인이 exit 0 을 못 낸다. 조용히 틀리는 형태가 아니라는 점이 이 축의 유일한 위안이다.
- 유예에서 F403·F405 를 지웠으므로 누군가 별표 임포트를 다시 넣으면 `ruff check .` 가
  바로 빨개진다 — 되돌아오는 경로는 막혔다.

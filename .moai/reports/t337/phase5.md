# t337 국면 5 — 「구조적 유예」를 기계로 못박고 출구 조건을 고친다 (결정 B)

측정 트리: `.claude/worktrees/t337f` · 기준 커밋 `daf21e1`(국면 4b 머지 후) · 일자 2026-09-09

## 1. 결정

`phase4a.md` §4 가 올린 감독 판단 사항(카드 t343)에 **안 B** 를 채택했다.

- **A(기각)** — 임포트 기제를 바꿔 `sys.path.insert` 를 없앤다.
- **B(채택)** — E402 6쌍을 「구조적 유예」로 **기계 검산과 함께** 명시하고, 카드의 출구를
  「목록 비우기」에서 「구조적 쌍 외 전부 제거」로 고친다.

### A 를 기각한 근거 (실측)

**(가) 폴더 이름이 파이썬 모듈명이 될 수 없다.**

```
$ python -c "print('90_빌드파이프라인'.isidentifier())"
False
```

숫자로 시작하므로 `import` 도 `python -m` 도 불가능하다. 패키지로 만들려면 **디렉터리
이름을 바꿔야** 하는데, 이 폴더는 번호로 정렬된 형제 7개 안에 있다 — `01_스펙` ·
`02_RIG팩` · `03_곡파일_Sugar` · `04_grandMA3` · `05_문서인덱스` · `90_빌드파이프라인` ·
`99_플러그인`. 파일 브라우저 정렬을 의도한 조직 방식이고, 린트 코드 하나를 없애려고
깨기에는 값이 안 맞는다.

**(나) 지금 호출 방식은 「파일 경로로 실행」이 전부다.**

전수로 찾으면 이 스크립트들을 **모듈로 임포트하는 곳이 하나도 없다.** 테스트도
`[sys.executable, str(SCRIPT)]` 로 파일을 직접 돌리고(`test_rig_pipeline_csv.py:51`,
`test_pipeline_out_paths.py:40`), `server/lxseq/preset_parser.py:537` 은 주석에서 경로를
언급할 뿐이다. 즉 `sys.path.insert` 는 「독립 스크립트가 옆 파일을 읽는」 관용구이고
결함이 아니다.

**(다) 목록을 비우는 것은 목적이 아니라 이상이다.** t115 가 이 목록을 만든 값은
「조용한 무검사를 밝은 유예로 바꾸고, 줄어드는 것이 보이게 하는 것」이었다. 그 값은
85→22 와 증가금지 상한으로 이미 실현됐다. 0 이라는 숫자 자체는 부수적이다.

## 2. B 를 「적어두기」로 하지 않은 이유와 그 구현

명단에 이름을 적는 것만으로 면제되면, 앞으로 무엇이든 「구조적」이라 부르면 통과하는
문이 된다. 그래서 **주장을 검산하는 검사**를 함께 넣었다.

`server/tests/test_overlap_preserve.py` 에 셋을 추가했다.

| 검사 | 무엇을 못박나 |
|---|---|
| `test_the_structural_list_is_not_vacuous` | 명단이 비지 않았고, 적힌 쌍이 실제 유예 목록에 있다 |
| `test_every_structural_pair_is_actually_structural` | **주장의 검산** — 파일을 읽어 그 E402 가 진짜 구조인지 본다 |
| `test_the_non_structural_pairs_did_not_grow` | 새 출구 조건 — 구조적 쌍을 뺀 나머지(16)가 늘지 않는다 |

가운데 검사가 핵심이다. 각 쌍에 대해 유예를 끄고 ruff 를 돌려 E402 자리를 받고,
**그중 로컬 모듈을 임포트하는 줄이 `sys.path.insert` 보다 아래에 있는지** 확인한다.
아래에 있다면 그 임포트는 위로 올릴 수 없고(올리면 `ModuleNotFoundError`) 그 쌍은
못 지우는 것이 맞다.

이 설계의 효과는 **미래에 자동으로 드러난다**: 나중에 폴더 체계를 손봐
`sys.path.insert` 가 사라지면 이 검사가 빨개져 「이제 구조적이 아니다」를 알린다.
즉 A 를 영구 포기한 것이 아니라, **A 를 할 이유가 생겼을 때 스스로 신호를 내는 상태**로
미룬 것이다.

## 3. 증거 — 뮤테이션 4갈래

검사 셋이 공허하지 않은지 일부러 망가뜨려 쐈다.

| 뮤테이션 | 결과 |
|---|---|
| `make_timeline.py` 의 `sys.path.insert` 를 주석으로 없앰 | `actually_structural` FAIL — "이 쌍은 더 이상 구조적이 아니다" |
| 구조적 코드를 `E402` → `UP031` 로 바꿔 주장 | `actually_structural` FAIL — E402 외 주장은 검산 불가라고 거절 |
| 유예에 없는 파일(`make_rig.py`)을 구조적이라 적음 | `not_vacuous` + `actually_structural` 둘 다 FAIL |
| 구조적이 아닌 쌍 추가(`rig_data.py` 에 UP031) | `pair_count` + `non_structural` 둘 다 FAIL |

네 갈래 모두 잡힌다. 부수적으로 발견한 것: 새로 쓴 코드가 `SIM300`(Yoda 조건)을
하나 만들었고 — 이 저장소의 린트가 테스트 코드에도 걸린다 — `.issubset()` 으로 고쳤다.

## 4. 카드 t337 의 새 출구 조건

```
현재 유예 22쌍 = 구조적 6쌍(E402) + 남은 일 16쌍(UP031 9 · E501 7)
출구: 남은 일 16 → 0
```

`_PAIR_CEILING = 22` 는 그대로 두고 `_NON_STRUCTURAL_CEILING = 16` 을 추가했다. 전자만
있으면 구조적 쌍이 그 안에 섞여 「더 줄일 게 없는지」를 못 읽는다.

## 5. 미검증 (Gaps)

- 이 회차는 **소스 코드를 한 줄도 바꾸지 않았다**(테스트 파일과 보고서만). 그래서
  산출물 대조를 하지 않았다 — 파이프라인 동작에 닿는 변경이 없기 때문이고, 이건
  생략이 아니라 해당 사항 없음이다.
- 검산 검사는 **E402 만** 다룬다. 다른 규칙을 구조적이라 주장하면 검사가 거절하므로
  잘못 통과하지는 않지만, E402 아닌 구조적 사유가 생기면 검사를 확장해야 한다.
- 「로컬 모듈 임포트」 판정은 `from <이름> import` 의 첫 토큰이 이 폴더의 `*.py`
  파일명과 일치하는지로 한다. `import <이름>` 형태(from 없는)는 못 잡는데, 6개 파일의
  그 형태를 전수로 뽑으니 `csv · html · os · re · sys · xml.etree.ElementTree` 로
  **전부 표준 라이브러리**다 — 로컬 모듈을 그 형태로 받는 자리는 없다(실측).
  새로 생기면 검사가 놓치므로, 그때는 판정 조건을 넓혀야 한다.
- A 의 세 번째 길(디렉터리 이름을 안 바꾸고 `importlib` 로 로드)은 **재지 않았다.**
  가능하긴 하지만 스크립트마다 로더 보일러플레이트가 붙고 지금의 관용구보다 읽기
  어려워지므로 후보로 올리지 않았다 — 이건 측정이 아니라 판단이다.

## 6. 잔여 위험

- 구조적 명단은 **줄어들기만** 하도록 상한이 없다(`_STRUCTURAL_PAIRS` 자체는 상수라
  늘리려면 코드를 고쳐야 하고, 그 경우 검산 검사가 새 항목도 검사한다). 즉 늘리는
  것 자체는 막히지 않지만, 근거 없이 늘리면 검산에서 걸린다.
- 「구조적」이라는 이름이 다른 부채에 전용될 위험이 남는다. 지금은 E402 로 한정되어
  있고, 확장할 때는 그 규칙에 맞는 검산을 함께 넣어야 한다 — 안 넣으면 이 회차가 막은
  문이 다시 열린다.

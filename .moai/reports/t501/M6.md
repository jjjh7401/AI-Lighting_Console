# t501 M6 — 효과 송신 통로: fx.permitted 처방 + REQ-010/011/012

SPEC-LDRENDER-001 M6. 읽기 전용 경계를 지켰다 — 콘솔 쓰기 0건, 실기 접촉
없음(OFFLINE PART ONLY, 배차서 지시). 가짜 콘솔 + 저장된 읽기 전용 증거만
사용했다.

## 주장 (Claim)

1. "effect" 능력 어휘 공백(M1 이 확정한 원인)의 처방은 `Dimmer` 다 — 네
   가지 독립 근거(§4d F1, FXLIB dimmer.yaml 전수, 실기 Dimmer 보급 84/86,
   Strobe/Shutter 배제 근거)로 뒷받침되며, `has_capability("effect")`
   와 `_fx_axes` 가 실측으로 양성 전환됨을 확인했다.
2. `_phaser_cue_value_lines` 가 이제 `cue.fx.permitted` 를 읽는다
   (REQ-010) — 효과 요청은 있지만 D레벨 예산이 0인 큐는 라벨·풀이 둘 다
   해석돼도 recall 을 내지 않는다.
3. 사전 생성(REQ-011)을 `server/fx/instantiate.py` 의 기존 저작 경로로
   구현했지만, **측정 결과 5개 필요 라벨 중 `Wave CM` 하나만 빌드된다**
   — 나머지 넷은 FXLIB 자신의 충돌 가드(`_guard_collision`)가 거부한다
   (날조 아님, 직접 측정·재현 가능).
4. 효과 보고 3계(REQ-012, 요청/허용/송신)를 최종 회신에 노출한다.
5. Rain 5절 정지점 산출물을 콘솔 접촉 없이 만들었다 — Wave CM 명령 전문 +
   나머지 4개의 거부 사유.
6. 전체 스위트 14515 passed(베이스라인 대비 +39, 0 제거) · 뮤테이션 4건
   전부 대상만 사망 · 린트/포맷 전부 통과.

## 미검증 (Gaps)

- 4개 라벨(Drop Slam/Breathe Warm/Breathe Cool/Finale Slam)의 실제 사전
  생성 — 이 경로로는 영구 불가(처방 미정). Rain 의 절정 라벨(Drop Slam)
  포함.
- Wave CM 의 재현 명령이 카탈로그가 약속한 것과 같은 시각 효과를 내는지
  — phase/curve 문법이 달라(§3 [ASSUMPTION]) 실기 육안 확인 전까지 미확인.
- 8곡 측정에서 `fx.permitted` 실측 — 하네스 한계로 0, 처방 자체 증명은
  별도 스크립트(§1)가 대신함.
- C1~C3(기존 쇼 보존·백업·번호 충돌) 실기 재확인 — 콘솔 쓰기 0건 제약.
- AC-LDRENDER-009(기계 증거, 실제 송신)는 PASS 로 보고하지 않는다 — 이
  카드는 전송하지 않았다.
- AC-LDRENDER-016(실기 감독 판정) — 사람 판정, 범위 밖.

  페이저에 남는 위험이다.

## Defects Found (structured defect-list)

D1. GEARS-CONTRADICTION-001 — `spec.md` REQ-LDBEAT-006, clause `(i-6a)` vs clause `(i-7)` — `(i-7)` (unmodified by this delta) states: "**While** 구조화 필드(`brightness`/…) 중 (i-5)의 옮기기 대상이 아닌 자리인 동안, 그 자리는 **shall** 명시적으로 비워 둔 미정(`null`)이다." This is an unqualified blanket rule covering `brightness` for every cell not transcribed by `(i-5)`. The new `(i-6a)` states that for 16 specific cells — which are also not `(i-5)` transcription targets (no `source_ref`) — `brightness` **shall** instead be `{mode: "value", value_percent: 100}`. For the same field (`brightness`), the same 16 cells, and a condition both clauses can simultaneously satisfy, `(i-7)` mandates `null` while `(i-6a)` mandates `100` — a direct `shall`/`shall` conflict. Neither clause states a precedence relationship (e.g., "(i-7) applies except where (i-6a) governs"), nor was `(i-7)`'s wording amended in this delta to carve out the exception, even though `(i-6a)` was deliberately inserted as a new numbered sibling immediately before it. The actual data (`love_attack.yaml`) and tests correctly implement the `(i-6a)` reading (specific-over-general), so no implementation defect exists — this is a pure requirement-text internal-consistency defect. — Severity: major — Class: blocking — Required fix: amend `(i-7)`'s trigger clause with an explicit exclusion, e.g. append "(REQ-LDBEAT-006(i-6a)가 정한 100-채움 예외 자리는 이 비움 규칙의 적용 대상에서 제외한다)" to `(i-7)`, or add an equivalent precedence statement inside `(i-6a)` itself stating it overrides `(i-7)` for the cells it governs.

D2. GEARS-FORMAT-001 — `spec.md` REQ-LDBEAT-006, clause `(i-6a)`, fifth sentence — "(i-6)의 금지(휴지 칸·상대 서술만 있는 칸을 채우는 것) 및 §4가 다른 열에 값을 이미 준 칸(예: BACK 0·3마디의 SCENE 열 서술)은 이 예외의 대상이 **shall not**이다 — 그런 칸은 그대로 미정으로 남는다." This sentence carries `**shall not**` but, unlike every other sentence in `(i-6a)` and in the rest of REQ-LDBEAT-006, does not open with a bolded trigger word (`**While**`/`**When**`/`**Where**`/`**The**`). Content is unambiguous (confirmed consistent with the implementation and with §5 open decision 10's framing of the BACK 0/3 exclusion), so this does not rise to an MP-2 FAIL, but it is a house-style inconsistency within the same clause. — Severity: minor — Class: optional — Required fix: prepend `**The**` (e.g., "**The** (i-6)의 금지 대상 칸 및 §4가 다른 열에 값을 이미 준 칸은 이 예외의 대상이 **shall not**이다…") to match the document's established bold-leading-trigger convention.

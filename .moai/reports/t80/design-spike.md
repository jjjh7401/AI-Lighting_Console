# t80 설계 스파이크 — 처방이 성립하는지 미리 쐈다

- 트리 `.claude/worktrees/t80` · 기준 커밋 `86fee6c` · 2026-08-25
- 스파이크 파일은 측정 후 전부 삭제했다(t80·t86·/tmp). 남긴 것은 이 기록뿐이다.

## 1. 가드의 비교 대상 — 왜 자기 자신이 증인인가

도구 `A/server/tools/foo.py` 가 `from server.tools.<가드> import ...` 를 하면,
가드 모듈은 **인터프리터가 데려온 트리**(B)에서 온다. 그래서 비교는 이렇게 된다.

    caller_tree = foo.py 의 __file__ 을 타고 올라가 찾은 트리   ->  A
    guard_tree  = 가드 모듈 자신의 __file__ 로 찾은 트리        ->  B

A != B 이면 죽는다. git 도, 환경변수도, 서브프로세스도 필요 없다.
**가드 모듈이 실려 온 자리가 곧 증거다.**

트리 뿌리는 `__file__` 의 상위를 훑어 이름이 `server` 인 디렉터리를 찾고 그 부모를 쓴다.
깊이를 가정하지 않으므로 `server/tools/` 아래 하위 디렉터리가 생겨도 견딘다.

## 2. 실측 — 스파이크 3팔

가드(20줄) + 도구 흉내(15줄)를 세워 놓고 쐈다.

| 팔 | 형태 | 기대 | 실측 |
|---|---|---|---|
| 음성 대조군 | 자기 인터프리터 + 스크립트 경로 | 통과 | 본문 실행됨 · **exit 0** |
| 양성 ① | 가짜 트리를 PYTHONPATH 로 | 죽음 | 「트리 동일성 위반」 · **exit 2** |
| 양성 ② | **진짜 t86 venv 인터프리터** | 죽음 | 「트리 동일성 위반」 · **exit 2** |

양성 ①과 ②가 **같은 판정**을 냈다. 가드가 보는 층에서 둘은 구별되지 않는다.

## 3. 테스트가 CI 에서 돌 수 있는가 — 그렇다

핵심 실측: **PYTHONPATH 가 venv 의 editable .pth 를 이긴다.**

    PYTHONPATH=/tmp/t80fake ./.venv/bin/python server/tools/<probe>.py
    -> sys.path[0] = t80/server/tools
    -> server      = /tmp/t80fake/server/__init__.py

그래서 「빌린 인터프리터」를 흉내내는 데 **두 번째 venv 가 필요 없다**.
`server/` 를 tmp 로 복사해(테스트 제외 3.9MB, rsync 1초 미만) PYTHONPATH 로 얹으면
스크립트는 A 트리, server 는 B 트리라는 그 상황이 그대로 재현된다.
CI 러너에는 워크트리가 하나뿐이므로 이 성질이 없으면 테스트 자체가 성립하지 않았다.

복사여야 한다 — 심볼릭 링크로 만들면 `Path.resolve()` 가 링크를 되짚어
두 트리가 같아지고 가드가 통과해 버린다.

## 4. 레버가 있는가 — 뮤테이션으로 확인

도구에서 가드 호출 한 줄만 빼고 같은 양성 팔을 다시 쐈다.

    가드 있음 -> exit 2 (죽음)
    가드 없음 -> exit 0, 본문 실행됨

검사가 `exit == 2` 를 단언하면 가드가 사라지는 순간 빨개진다. **레버 확인됨.**

## 5. 설계 갈림길 — 가드 호출을 어디 두는가

ruff 실측: 임포트 사이에 호출문을 끼우면 뒤따르는 임포트가 전부 `E402` 로 걸린다.

    E402 Module level import not at top of file

그래서 두 갈래가 있다.

| 안 | 호출 위치 | 대가 | 얻는 것 |
|---|---|---|---|
| A | 임포트 블록 **뒤**, 본문 앞 | 남의 트리 모듈이 **임포트는 된다**(본문은 0줄 실행) | ruff 무설정, noqa 0개 |
| B | 임포트 블록 **앞** | `per-file-ignores` 로 E402 예외 1줄, 또는 noqa 다수 | 남의 트리 코드가 한 줄도 안 돈다 |

스파이크는 A 로 했고 세 팔 모두 의도대로 나왔다. A 의 잔여 위험은
「임포트 시점 부작용」인데 이 저장소의 `server/*` 모듈 층에서 그것이 무해한지는
**아직 재지 않았다**. 이 선택은 SPEC 의 열린 결정으로 남긴다.

## 6. 저장소의 기존 경계와 충돌하는가 — 아니다

`server/tests/test_architecture.py` 가 `server/tools/` 를 **파일 단위로** 못박아
`server.bridge` / `pythonosc` 임포트를 막는다(면제 3건: osc_smoke · responder_roundtrip ·
preshow/osc_check). 새 가드 모듈은 둘 다 임포트하지 않으므로 이 경계에 걸리지 않는다.

## 7. 미검증 (Gap)

- **임포트 시점 부작용을 재지 않았다** — 5절 A안의 잔여 위험 그대로다.
- **스파이크 가드는 20줄짜리 모형이다.** 메시지 문면·종료코드·예외 처리는 확정 아니다.
- 양성 ②는 t86 한 트리만 빌렸다. 45개 트리 전수가 아니다.
- 실제 19개 도구에 붙여 본 적은 없다 — 붙는 자리마다 임포트 형태가 다를 수 있다.

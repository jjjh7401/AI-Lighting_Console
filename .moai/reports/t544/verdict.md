# t544 판정 — 위치 프리셋 2.4·2.5 크기 +256B 의 원인

- 카드: t544 (읽기 전용) · 브랜치 `WT-preset-growth` · 기준 HEAD `322d1f89`(15bc4e87 포함, origin/main 과 0 0)
- 콘솔 송신: ping·props·introspect·state 만. **쓰기 0줄, 쇼 저장 0** (`.moai/reports/t538/read_steps.py` → t506 `probe_readonly`, exec 경로 없음)
- 응답기: CopilotResponder 1.6.6 (`s1_reads.txt` pong)

## 결론

**원인은 재생이 아니라 큐 저장이다.** t538 B1 이 `Store Sequence 320` 으로 2.4·2.5 를 가리키는 큐 파트를 만들자, 콘솔이 두 프리셋에 역참조 목록(`REFERENCES`)을 달았다. 첫 역참조가 들어갈 때 256B 블록이 한 번 잡혔고, 그 뒤 참조가 늘어도 크기는 그대로다. 프리셋 값 자체는 바뀌지 않았다(추론 — 값 미판독: 값 칸은 응답기로 읽지 못했고, 크기 변화가 역참조 하나로 설명된다는 데서 미루어 본 것이다).

2.1·2.3 이 같은 시퀀스에 저장됐는데도 안 커진 것은, `Group 11 ; At Preset 2.1/2.3` 이 이 장비들에 **아무 값도 올리지 않아** 큐가 그 프리셋을 가리키지 않았기 때문이다(아래 증거 3).

카드 가설(「페이드/Goto 재생이 런타임 속성을 붙인다」)은 기각한다. 2.1·2.3 도 똑같이 Goto 로 재생됐지만 역참조가 0이다.

## 증거

### 1. 지금 크기 — t538 r28 과 같다 (`s1_reads.txt`)

| 프리셋 | r6 (20:27) | r28 (22:31) | 지금 | OWNDATAPRESENT |

| 2.1 | 1568 | 1568 | 1568 | **false** |
| 2.2 | 2200 | 2200 | 2200 | true |
| 2.3 | 2360 | 2360 | 2360 | true |
| 2.4 | 2176 | 2432 | **2432** | true |
| 2.5 | 2640 | 2896 | **2896** | true |
| 2.6 | 2468 | 2468 | 2468 | true |

r6·r28 값은 `.moai/reports/t538/r6_goto_and_footprints.txt`·`r28_preset_owndata.txt` 의 응답 줄에서 다시 뽑았다. 커밋 시각은 r6 `b0407262` 20:27, r28 `799ce240` 22:31.

### 2. 2.4·2.5 만 다른 값 하나 — `REFERENCES` (`s3_values.txt`, `s3_diff.txt`)

스키마 필드 134개(총 138) 값을 2.1~2.6 전부 읽어 비교했다. 번호·이름·DOSHUFFLE 대상처럼 프리셋마다 원래 다른 값을 빼면, 2.4·2.5 와 나머지를 가르는 필드는 **`REFERENCES` 하나**다.

- 2.4: `3154120427:…, 3154120440:…` (2개)
- 2.5: `3154120429:…, 3154120442:…, 3154120455:…` (3개)
- 2.1·2.2·2.3·2.6: 빈 문자열

개수가 저장 이력과 맞는다. 2.4 → 시퀀스 320·321 큐 2. 2.5 → 320·321 큐 3, 322 큐 2.5. 핸들 간격도 시퀀스마다 13씩 일정하다(427→440, 429→442→455).

### 3. 2.1·2.2·2.3 은 큐에 아무것도 넣지 못했다 — 파트 크기 (`s5_cues.txt`)

2.1·2.2 를 적용한 파트는 디머만 든 파트와 크기가 같다(2976). 2.3 파트는 더 작다(2544, 트래킹된 디머마저 안 들어감). 프리셋을 가리키는 파트만 약 350B 크다. 2.1 은 `OWNDATAPRESENT=false` 로 빈 프리셋이다.

### 4. 첫 참조에서만 커진다 — 시점

- B1 저장(시퀀스 320): 22:16 `0c216ecd` — r6 과 r28 사이
- B2 저장(321): 22:33 `18d8442f`, B3 저장(322): 22:35 `40593d9f` — **둘 다 r28 뒤**

r28 시점에 2.4·2.5 는 역참조가 1개씩이었고 이미 +256 이었다. 그 뒤 2.4 는 1개, 2.5 는 2개가 더 붙었지만 크기는 그대로다.

## 안 잰 것 (Gaps)

- 역참조 핸들(3154120427 등)이 정확히 어느 큐 파트인지 직접 대조하지 못했다. GUID·핸들 필드는 응답기로 읽히지 않는다(17개 필드 읽기 실패). 개수·시점·순서로 추론한 대응이다.
- 2.2·2.3 이 Group 11 장비(MOVER-U)에 값이 없다는 것은 파트 크기로 추론했다. 프리셋의 장비별 내용은 `SELECTIONDATA` 가 `{}` 로만 돌아와서 직접 확인하지 못했다.
- introspect 페이징에서 138개 중 4개 필드 이름이 빠졌다(134개만 수집). 빠진 필드는 비교하지 못했다.
- 프리셋의 위치 값 자체(PRESETDATA 등 값 칸)는 읽지 못했다. 「값은 그대로」는 추론이다.
- 시퀀스 320~322 를 지우면 크기가 2176·2640 으로 돌아오는지는 쓰기가 필요해서 재지 않았다.
- r6 이전(20:27 전)에 2.4·2.5 에 역참조가 있었는지는 기록이 없다. r6 크기가 그때 「역참조 없음」 상태였다는 것도 추론이다.

## 남은 위험

- 무해한 변화로 본다. 프리셋 값은 그대로로 보이고(추론 — 값 미판독), 콘솔이 「이 프리셋을 쓰는 큐」를 기록할 뿐이다. 다만 **MEMORYFOOTPRINT 를 프리셋 내용 변경 감지에 쓰면 오탐**이 난다. 큐 저장만으로도 크기가 바뀐다.
- 시험용 시퀀스 320~322 가 남아 있는 동안 2.4·2.5 에 역참조가 걸려 있다. 정리할지는 리드·감독 판단이다.

## 0. 사례는 둘이 아니라 셋이고, 셋째가 제일 값나간다

카드 본문은 사례 둘을 적는다(리드 세션의 118KB 덤프 · t163 레인의 0건 오독).
**셋째가 있고, 그것은 이 규칙을 만든 사람이 규칙을 만드는 중에 밟은 것이다.**

리드가 자기 오류의 뿌리를 스스로 보고했고, 나는 그것을 **독립으로 재현했다**:

    moai todo --help 2>&1 | head -30
      -> 30행이 `next` 에서 정확히 끊긴다
      -> 31~35행: unpick · edit · move · drop · undrop   (다섯 개가 가려진다)
      -> 전체 도움말은 **40행**뿐이다

여기서 나온 「동사는 add·list·done·next 넷뿐」이 **「닫힌 카드를 고칠 수단이 없다」**를
낳았고, 그 거짓이 네 자리로 퍼졌다:

  1. t166 카드에 문단을 못 넣는다 -> 인계문으로 우회
  2. t173 의 만료된 숫자를 못 고친다고 **감독에게 보고**
  3. **메모리 색인 줄**에 「`moai todo` 에 edit 없음」을 박음
  4. t162·t176·t177 의 `queued` 를 「고칠 수단이 없다」고 레인에게 답함

그리고 **몇 시간 뒤 같은 사람이 `grep -n … | head -5` 로 8건을 5건으로 읽었다.**

🔴 **두 오류가 아니라 같은 형태 하나다.** 같은 파이프, 같은 잘림, 다른 대상.
그리고 그 사이에 그 사람은 **이 함정을 카드(t174)로 세우고 레인들에게 훈수했다.**
`| head` 로 잘라 놓고 그 값을 근거로 규칙을 만든 것이다.

세 가지가 이 사례를 다른 둘보다 값나가게 만든다:

- **개수가 아니라 부재였다.** 「N 건이다」는 다음 사람이 검산하지만,
  **「그런 수단이 없다」는 아무도 검산하지 않는다.** 없는 것을 찾으러 가지 않는다.
- **하네스는 자를 이유가 없었다.** 40행짜리 출력이다. **읽기 편하려고 붙인 `head` 가
  스스로 만든 잘림**이고, 그래서 배너도 안 뜬다.
- **거짓이 메모리 색인까지 갔다.** 세션이 끝나도 살아남는 자리다.

---

## 1. 주장 (Claim)

1. 하네스 출력 상한은 **30,000 바이트 정확**이고, **바이트 기준이지 행 기준이 아니다.**
2. 하네스 잘림에는 **신호가 있다** — 크기·전량 파일 경로·프리뷰 고지. 그리고 그 파일은
   **온전하다.** 카드의 「표시된 것은 앞부분뿐」은 반쪽이다.
3. **진짜 조용한 잘림은 `| head -N` 이다.** 신호가 없고 복구 경로도 없다.
4. 따라서 처방은 **규율 쪽(2번)** 이다. `moai todo` 쪽(1번)은 신호가 이미 있는 쪽의
   한 사례만 없애고, **이 저장소에서 실행 불가능**하다.
5. 부수 반증: **`moai todo` 에 `edit` 이 있다.** 「고칠 수단이 없다」가 틀렸다.

---

## 2. 증거 (Evidence)

### 2.1 상한 — 30,000 바이트, 바이트 기준

경계를 양쪽에서 조였다. **둘 다 한 줄짜리**라 행 수는 변수에서 빠진다.

    python3 -c "print('e'*29999)"   ->  30,000 바이트  ->  **통과** (전량 표시)
    python3 -c "print('a'*30000)"   ->  30,001 바이트  ->  **잘림** ("29.3KB")

행 축은 따로 쟀다:

    3,000행 / 6,000바이트  ->  **통과**   (행 상한은 ≤3,000 에 없다)
    500행 / 50,000바이트   ->  잘림 ("48.8KB")

한 줄 30,001바이트가 잘리므로 **행 기준이 아니다.** 3,000행 6,000바이트가 통과하므로
**행 상한이 있더라도 3,000 위**다. 배너가 보고하는 값은 바이트를 1024로 나눈 KB 이고,
**잘리기 전 전체 크기**다(48.8KB = 50,000바이트, 29.3KB = 30,001바이트).

### 2.2 신호 — 있고, 크고, 복구까지 준다

    <persisted-output>
    Output too large (44.9KB). Full output saved to: <절대경로>.txt
    Preview (first 2KB):

**그 파일이 온전한지**를 md5 로 쟀다 — 이게 이 카드의 핵심 측정이다:

    의도한 내용   46,000바이트 / 2,000행   md5 f58f14573b59d820365c4f5ca2bb8d55
    보존된 파일   46,000바이트 / 2,000행   md5 f58f14573b59d820365c4f5ca2bb8d55

**동일하다.** 잘린 것은 표시뿐이고 데이터는 하나도 안 잃었다.

🔴 그래서 t163 레인의 실패는 이름이 다르다. 「계기가 몰래 잘랐다」가 아니라
**「배너가 있는데 프리뷰를 grep 했다」**다. 실패의 이름이 다르면 처방도 다르다 —
전자는 계기를 고치는 일이고, 후자는 읽는 법을 적는 일이다.

### 2.3 `| head -N` — 이쪽이 조용하다

리드가 자기 사례를 실어 줬고 **독립으로 검산했다**:

    grep -c "raise StateQueryError" server/safety/console.py   ->  8
    grep -n ... | head -5 이 가리는 줄                          ->  752 · 772 · 777

`head -5` 의 출력은 5행 · 100바이트 남짓이라 **하네스 상한 근처에도 못 간다.**
배너가 안 뜨는 게 정상이다 — 사용자가 잘라 달라고 시켰기 때문이다. 그래서
**「개수 5」와 「상한 5」가 바이트 동일**이고, 출력만 봐서는 영원히 안 갈린다.

⚠️ **범위 정정**: 리드의 8 은 `server/safety/console.py` **한 파일** 값이다.
저장소 전체(`grep -rn ... server`)로는 **17건 / 4파일**이다. 숫자에 범위를 붙이지
않으면 다음 사람이 저장소 전체로 읽는다.

### 2.4 `moai todo` — 축소할 수단이 없고, 값은 늘기만 한다

    moai todo         224,087바이트 / 129행   상한의 **7.5배**
    moai todo next    104,265바이트 /  68행   상한의 **3.5배**
    moai todo list --help  ->  플래그는 `--json` 하나뿐 (--limit / --short 없음)

카드가 적은 118KB 는 **그 시점의 한 점**이고, 지금은 그 두 배다. 큐는 카드가 닫혀도
줄지 않으므로(§2.5) 이 값은 **단조 증가**다 — 만료되는 숫자가 아니라 **낮아지지 않는**
숫자다.

`moai` 는 외부 바이너리다 — 이 저장소에 `go.mod` 도 `cmd/` 도 없다. 처방 1 은
**상류 요청**이지 이 카드가 낼 수 있는 산출물이 아니다.

### 2.5 부수 반증 — `moai todo edit` 은 존재한다

    moai todo --help  ->  add  list  done  next  unpick  edit  move  drop  undrop   (아홉)

    moai todo edit <n> <text> [--flags]
      "Rewrite a card's text by id, **preserving its identity**"
      --expect   Refuse the edit unless the card text starts with this prefix

`--expect` 는 낙관적 동시성 가드다 — 접두가 안 맞으면 파일을 **안 건드리고** 거절한다.

그리고 이건 새 관행이 아니다: 큐의 t104·t109·t110·t112·t114·t115 본문이 전부
`✅닫힘 …` 로 시작한다. 누군가 이미 이 수단으로 닫힘을 표시해 왔다.

이 반증이 이 카드에 속하는 이유: **불완전한 계기 판독이 「그런 수단이 없다」를 낳았다** —
이 카드가 다루는 바로 그 실패 형태이고, 대상이 카드 큐라는 것까지 같다.

## 4. 안 잰 것 (Gaps)

- **다른 세션·다른 하네스 버전의 상한은 안 쟀다.** 30,000은 이 세션에서 잰 값이다.
  t163 레인이 본 것이 같은 상한이었는지, 같은 배너를 받았는지 **확인할 방법이 없다** —
  그 세션은 이미 없다. 그래서 「t163 레인은 배너를 보고도 프리뷰를 grep 했다」는
  **가장 그럴듯한 재구성**이지 관측이 아니다.
- **행 상한이 3,000 위에 있는지 안 쟀다.** 6,000바이트에서 멈춘 이유는 그 위를 재려면
  컨텍스트를 그만큼 태워야 해서다. 「행 상한 없음」이 아니라 **「≤3,000에는 없음」**이다.
- **`moai todo edit` 이 `status` 필드를 바꾸는지 안 쟀다.** 도움말은 「text」라고만 한다.
  실제로 실행해 보지 않았다 — 남의 카드를 고치는 것이라 리드 판정 없이 안 쐈다.
- **다른 잘림 벡터를 전수하지 않았다.** `head` 말고 `tail` · `-m` · `--max-count` ·
  `sed -n '1,Np'` · `awk NR<=N` 도 같은 형태다. 규칙 문면은 `head` 를 예로 들되
  술어는 「상한에 걸린 출력」으로 넓게 적었다.

## 5. 잔여 위험 (Residual-risk)

- 규칙에 박은 **224,087바이트**는 오늘 값이다. 규칙 본문에 「늘기만 한다」를 같이
  적었지만, 다음 사람이 그 숫자를 **현재값으로** 읽을 위험은 남는다.
- 30,000 바이트는 하네스 구현값이고 **우리가 통제하지 않는다.** 하네스가 바뀌면 이
  문면이 조용히 틀려진다 — 그때 알려 주는 것은 배너의 KB 표시뿐이다.
- 이 카드는 **규율을 적었지 집행하지 않는다.** `| head` 를 기계적으로 막는 것은
  이 저장소가 통제하는 표면이 아니다(하네스의 Bash 도구). 규율이 지켜지는지는
  다음 사고가 나야 안다.

## 6. 실행 확인 (문서 카드에도 붙인다 — 규약 §5)

「코드 변경 0 이니 검증할 게 없다」가 함정이라는 규약대로, 규칙에 박은 숫자를
**커밋 직전에 다시 쟀다.** 규칙이 주장하는 것은 전부 실행 가능한 명제다.

    moai todo 2>/dev/null | wc -c            ->  224087      (규칙 문면과 일치)
    moai todo --help 2>&1 | wc -l            ->  40          (하네스가 자를 이유 없음)
    moai todo --help | head -30 | tail -1     ->  "next [<n>] …"   (끊기는 자리)
    moai todo --help | sed -n '31,35p'        ->  unpick edit move drop undrop

상한 측정은 하네스 도구 자체가 계기이므로 명령 하나로 재현된다:

    python3 -c "print('e'*29999)"   ->  30,000바이트  전량 표시
    python3 -c "print('a'*30000)"   ->  30,001바이트  <persisted-output> 배너
    3,000행 / 6,000바이트           ->  전량 표시

보존 파일 온전성:

    md5(의도한 46,000바이트) == md5(보존 파일) == f58f14573b59d820365c4f5ca2bb8d55

**이 절이 재측정 지시서다.** 하네스가 바뀌면 위 명령들이 다른 답을 낸다 — 그때
§5 의 잔여 위험이 실현된 것이고, 규칙 문면의 숫자를 고칠 근거가 이 절에 있다.

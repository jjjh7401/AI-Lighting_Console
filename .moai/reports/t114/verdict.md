감독이 콘솔 화면을 보고 판정했다. **판정 주체는 감독이고, 아래는 그 판정의 기록이다.**

### 화면에서 같이 드러난 것 — 예상 밖의 발견 둘

감독이 보낸 풀 화면에서 두 가지가 보였다.

**① 슬롯 7 에만 내용물이 그려진다.** 타일에 원과 세로 막대(레벨 표시로 보이는
것)가 있고 `U` 표시가 붙어 있다. 슬롯 1~6 타일에는 그것이 없다.

**② 🔴 한글 이름이 화면에 렌더되지 않는다.** 슬롯 2 는 이름이 `쇼 하이 OLD` 인데
화면에는 **`OLD` 만** 보인다. 풀 헤더의 `1 Dimmer` 는 ASCII 라 정상 표시된다.
슬롯 1·3~6 이 「비어 보이는」 것도 이름이 전부 한글이기 때문일 수 있다.

⚠️ **②가 ①의 해석을 제한한다.** 슬롯 1~6 이 비어 보이는 것이 「값이 없어서」인지
「이름이 안 그려져서」인지 이 화면으로는 **못 가른다.** 그러므로 **질문 A(옛 경로가
값을 날랐나)는 이 화면으로 답해지지 않았다.** 답해진 것은 질문 B 뿐이다.

### 후속 카드감 — 한글 이름 표시

RIG 시트의 프리셋 이름은 **전부 한글**이다(풀·쇼 하이·미드·로우·잔광·아웃).
콘솔 화면에 한글이 안 나오면 **운영자가 프리셋을 이름으로 식별하지 못한다.**
이 카드의 범위 밖이므로 관측만 남긴다 — 렌더 실패인지 폰트 문제인지, 다른
풀·다른 화면에서도 같은지는 **미측정**이다.

## 9. 감독 정밀 판독 (2026-08-26, 2차) — 내 보고서 두 곳을 고친다

감독이 화면을 더 정밀하게 읽었다.

    슬롯 7   프리셋 **잡힘**. 다만 라벨 '쇼 하이' 는 **표시 안 됨** (한글 안 됨)
    슬롯 2   '쇼 하이' 없이 **'OLD' 만** 보이고, **디머 값 없음**
    슬롯 1·3·4·5·6   **프리셋 안 잡힘**

같은 시각 OSC 판독은 이렇게 답한다(직접 재측정):

    slot 1  class Preset  NAME '풀'
    slot 2  class Preset  NAME '쇼 하이 OLD'
    slot 3  class Preset  NAME '미드'
    slot 4  class Preset  NAME '로우'
    slot 5  class Preset  NAME '잔광'
    slot 6  class Preset  NAME '아웃'
    slot 7  class Preset  NAME '쇼 하이'

### 정정 ① — 질문 A 가 답해졌다. §8 이 「안 답해졌다」고 적은 것은 틀렸다

**슬롯 2 에 디머 값이 없다.** 그것이 옛 경로(M4, t108 이전)의 산물이다.
그러므로 **옛 경로는 값을 나르지 못했다.** §8 은 「한글이 안 그려져서 못 가른다」로
적었는데, 감독이 슬롯 2 를 값 축으로 따로 읽어 그 애매함을 없앴다 — 슬롯 2 는
이름이 부분적으로(ASCII 만) 보이므로 「타일이 비어 보인다」의 경우가 아니고,
그럼에도 **값이 없다**.

    질문 A  옛 경로가 값을 날랐나   →  **아니다** (슬롯 2, 감독 육안)
    질문 B  t108 경로가 값을 나르나 →  **그렇다** (슬롯 7 = 85%, 감독 육안)

두 경로가 값 축에서 갈렸다. 이것이 t108 수정이 실제로 필요했다는 실기 증거다.

### 🔴 정정 ② — 「슬롯 점유 = 무언가 저장됐다」는 **너무 센 문장이었다**

이 저장소가 여러 보고서에서 이렇게 적어 왔다(이 보고서 §1 포함):

> 슬롯 점유만 읽힌다 — 「슬롯이 찼다」는 「무언가 저장됐다」까지는 말한다

**그 절반이 틀렸다.** OSC 는 슬롯 1~6 을 `class Preset` + 이름으로 답하는데
콘솔에는 값이 없다. 그러므로 이 판독이 보증하는 것은:

    보증한다      그 슬롯에 **이름을 가진 오브젝트가 존재한다**
    보증하지 않는다  그 안에 **무언가 저장돼 있다**

「점유」와 「내용」이 다른 축이고, 이 채널은 앞의 것만 답한다. 앞으로 저장 결과를
「슬롯이 찼으니 무언가 저장됐다」로 적지 마라 — **이름 있는 빈 껍데기가 실제로
여섯 개 있었다.**

이 정정은 이 카드 밖으로 번진다. t104 verdict · M4 기록 · 메모리의 같은 문장이
전부 같은 교정을 받아야 한다. 이 카드는 관측만 남기고 전파는 별도다.

### 정정 ③ — 라벨은 「작성 안 됨」이 아니라 「저장됐으나 표시 안 됨」이다

감독은 슬롯 7 의 라벨이 작성되지 않았다고 읽었다. 데이터 축의 측정은 다르다:

    발사 기록   Label Preset 1.7 '쇼 하이'   executed_ok "OK"
    OSC 판독    slot 7  NAME = '쇼 하이'      (한글 그대로 왕복)
    화면        표시 안 됨

슬롯 2 가 이 둘을 가른다 — 이름이 `쇼 하이 OLD` 인데 화면에는 **ASCII 부분만**
남아 `OLD` 로 보인다. 이름 전체가 없는 것이 아니라 **한글 글리프만 사라진다.**

그러므로 **쓰기는 성공했고 렌더가 실패한다.** 두 결함은 처방이 다르다 —
쓰기 실패면 명령 문형을 고쳐야 하고, 렌더 실패면 폰트·표시 계층 문제다.
어느 쪽인지는 이 카드가 판정하지 않는다(폰트 설정을 안 쟀다).

⚠️ 운영 영향은 그대로다: RIG 시트의 프리셋 이름이 **전부 한글**이라, 데이터에
이름이 있어도 **운영자는 화면에서 프리셋을 이름으로 식별하지 못한다.**

>
> **Out of Scope** — 프리셋 내용(픽스처별 값 집합)을 되읽어 재기록하는 경로가
> 이 앱에 **없고**, 그것을 만드는 일은 응답기 확장과 별도 SPEC 을 요구한다.

§1·§4 가 이 한계를 마치 이번에 확정한 것처럼 적었다. **틀린 서술은 아니지만
출처가 빠졌다.** 앞으로 이 한계를 말할 때는 PRESETGUARD-001 A.3 을 인용한다.

같은 SPEC 이 이 카드의 규율도 이미 갖고 있었다:

    REQ-PRESETGUARD-007  「저장했습니다」 같은 형용사는 요구를 만족하지 않는다.
                         기대 수 · 확인된 수 · 미확인 슬롯 번호를 **산술로** 운반하라
    REQ-PRESETGUARD-008  판독 불가는 **통과가 아니다**
    A.3                  이 저장소는 이미 「쓰기 전에 되읽는다」를 규율로 갖고 있다
                         (`tools.py:3724` 「성공은 관측에서만 나온다」)

**「N건 성공으로 보고하지 마라」도 내가 세운 규율이 아니라 REQ-007 이다.**

### 새 관측이었다 — SPEC 이 안 적은 것

**정정 ②(§9)는 재발견이 아니다.** 다만 겨냥이 틀렸으므로 여기서 바로잡는다.

PRESETGUARD-001 의 되읽기(REQ-006/007)는 **슬롯 집합 대조**다 — 「기대 슬롯 집합과
대조」·「확인되지 않은 슬롯 번호의 열거」. 그 SPEC 은 **슬롯 존재가 내용 존재를
뜻한다고 주장한 적이 없다.** A.3 이 내용 판독 불가를 이미 알았으므로 되읽기를
슬롯 산술로 **의도적으로 좁힌 것**이다.

과하게 말한 것은 SPEC 이 아니라 **하네스 회신과 이 저장소의 보고서 산문**이다
(「슬롯이 찼다 = 무언가 저장됐다까지는 말한다」). 그러므로 §9 정정 ②의 대상은
SPEC 이 아니라 **보고 문면**이고, 이 카드가 보탠 것은 원칙이 아니라 **증거**다 —
**이름을 가진 빈 껍데기 여섯 개를 실기에서 처음 관측했다.**

### 한글 이름 — LDGUIDE-001 에 규약이 없다. 다만 선례는 있다

`SPEC-COPILOT-LDGUIDE-001`(completed)에 이름 규약이 **없다**(`한글`·`naming`·`ASCII`
검색 결과는 전부 무관한 문맥). 그러므로 이 축은 아직 아무 SPEC 도 안 정했다.

**그런데 선례가 있다.** `SPEC-COPILOT-COLORPRESET-001` 의 표준 팔레트 10색 라벨은
**전부 ASCII 다** — `Warm White` · `Cool White` · `Red` · `Amber` … 그리고
REQ-COLORPRESET-004 가 `Warm White` 를 재생성 가족 필터의 `first_label` 로 쓴다.

즉 **컬러 축은 이미 ASCII 이름을 쓰고 있고, LXSEQ-003 의 dim/col/bm 시트만
한글이다.** 이 불일치가 오늘 화면에서 드러난 것이다. 후속 카드는 「한글이 왜
안 보이나」보다 **「축마다 이름 규약이 다른 것을 어떻게 맞출 것인가」**로
물어야 한다 — 한쪽에 이미 답이 있기 때문이다.

⚠️ 다만 **COLORPRESET-001 의 ASCII 선택이 이 제약을 알고 내린 것인지는 미측정**이다.
SPEC 본문에 그 이유가 안 적혀 있다. 「선례가 있다」까지가 관측이고 「그래서
ASCII 로 통일하라」는 이 카드의 판정이 아니다.

## 11. t114 의 성과를 정확히 다시 쓴다 — 「새 발견」이 아니라 「잇힘」이다

§9·§10 을 쓰고 나서도 문면이 여전히 발견 쪽으로 기울어 있었다. 정확한 형태는
이것이고, **코드 두 자리로 확인했다**:

    Position 프리셋 경로   session.py:5325 `_store_position_preset_looks`
        docstring 그대로:  「룩마다 **적용 → Store → Label → ClearAll** 을
                           별개 번들로 디스패치한다」
        commands = [*apply(aims), *_preset_store_commands(...), "ClearAll"]
        → **이 규율은 원래 있었다.**

    LXSEQ 시트 경로        tools.py:114 `preset_apply_command` 임포트
                          tools.py:1700 `_lxseq_preset_apply_command`
                          tools.py:1688 「적용 줄이 겨눌 그룹 번호.
                                         감독 결정(2026-08-26): dim 은 전 픽스처」
        → **오늘(t108) 생겼다.**

그리고 `preset_apply_command` 는 `server/presets/store.py` — **문형을 아는 유일한
일반형 자리**(그 모듈 docstring)에 산다. 즉 t108 은 새 설계를 만든 것이 아니라
**이미 있던 것을 두 번째 경로에 이었다.**

### 그러므로 t114 가 답한 것은

    ❌ 「프리셋 저장에 값 적용이 필요하다는 것을 발견했다」
    ✅ **「Position 경로에 있던 적용→저장→ClearAll 규율이 LXSEQ 시트 경로에는
         없었고, 그 부재가 실제로 값 없는 프리셋 여섯 개를 만들었으며,
         이제 이어져서 값이 남는다」**

슬롯 2(옛, 값 없음)와 슬롯 7(새, 85%)이 그 **부재와 잇힘을 나란히 보여 주는
실물**이다. 이것이 이 카드의 실질이다.

### 질문의 형태도 바뀐다

completed SPEC 이 있는 축에서는 물음이 다르다:

    새 SPEC 을 쓸 때           「무엇이 결함인가」
    completed SPEC 이 있을 때   **「왜 이 경로엔 없나」**

이 카드는 후자였는데 전자처럼 조사했다. `PRESETGUARD-001` 을 착수 1번에 읽었다면
「Position 에는 있는데 LXSEQ 에는 왜 없나」로 바로 갔을 것이고, §1~§9 의 상당 부분이
필요 없었다.

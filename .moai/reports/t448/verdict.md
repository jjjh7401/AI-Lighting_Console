## 0. 감독용 요약

지금 곡 조명 큐를 만드는 길이 둘이다.

- **A. 대화(인터뷰) 길** — 채팅·웹에서 감독과 문답으로 곡을 설계한다. 콘솔에는 "기구 번호 목록에 포지션
  프리셋·밝기 %·색 값"을 직접 넣는다. 무빙이 켜진 채 움직이지 않게 미리 옮기는 기능(MIB)이 있다.
  **절정 길이 제한·후렴 강조 사다리·드롭 전 어둠은 없다.**
- **B. 곡 업로드 길** — 곡 구간을 받아 장르별 "룩 라이브러리"에서 모양을 골라 저장한다. 콘솔에는 "그룹에
  룩 속성 값"을 넣는다. 절정 길이 제한·강조 사다리·드롭 전 어둠이 **있다.** MIB 는 **없다.**

두 길이 공유하는 것은 색 결정 하나뿐이다(카드 t441).

| | ① A의 조립기로 합치기 | ② A를 B로 옮기기 | ③ 지금 그대로 |
|---|---|---|---|
| 무엇을 하나 | B의 절정·강조·어둠 기능을 A의 조립기 안에 다시 만든다 | A를 B의 룩 방식으로 바꾼다 | 둘 다 둔다 |
| 옮길 양 | B의 기능 코드(업로드 길 파일 3594줄 중 절정·강조·어둠 부분)를 A의 데이터 모양으로 **새로 짜야** 한다 | A의 조립기가 가진 MIB·린트·밝기 예산·재질의를 B에 새로 만들어야 한다 | 없음 |
| 다시 써야 할 시험 | B를 직접 부르는 시험 파일 17개(호출 55곳) — 이 중 12개는 실제 입구(`prepare_songcue`)를 거치지 않는다 | A의 조립기를 직접 부르는 시험 파일 8개(호출 25곳) + A 세션 시험 | 없음 |
| 콘솔 명령 변화 | **B(업로드 길)** 의 명령이 바뀐다 | **A(대화 길)** 의 명령이 바뀐다 — 감독이 매번 확정하는 길 | 없음 |
| SPEC 과 부딪힘 | REQ-077 「절정 상한·강조 사다리 자체는 이 SPEC 이 건드리지 않는다」 — 옮기며 다시 짜는 것이 "건드림"인지 해석이 갈린다 | REQ-073 「린트·밝기 예산·페이드·MIB 는 재구현하지 않는다」, REQ-077 「사다리는 별도 코드 경로로 남지 않는다」와 정면으로 어긋난다 | REQ-003 「단일 조립기」가 계속 미충족 |
| 가장 큰 위험 | 다시 짜는 동안 8곡 게이트가 흔들리면(REQ-075) 이 마일스톤 전체가 멈춘다 | 대화 길이 이미 가진 안전장치(MIB)를 잃는다 | **대화 길로 만든 곡에는 지금도 절정 길이 제한·강조 사다리·드롭 전 어둠이 전혀 걸리지 않는다** — 구조 문제가 아니라 지금 큐 품질의 차이다 |

**권고 한 줄:** ①을 좁혀서 가되, 그 전에 REQ-077 의 「건드리지 않는다」가 코드를 옮기는 것까지 막는지 감독이 먼저 정한다 — 전제: 옮기기는 허용하고 절정·사다리의 기준값은 바꾸지 않는다.

## 1. 실측

### 1.1 두 조립기의 기능 흔적 — `measure.py` → `measure.txt`

단어 출현 **횟수** 기준(대소문자 무시, 줄 수가 아님).

| 파일 | 줄 수 | climax | accent | darkness | ladder | yield | front_fill | mib | premove |
|---|---|---|---|---|---|---|---|---|---|
| `server/looks/songcue.py` (B) | 3594 | 103 | 173 | 93 | 116 | 27 | 30 | 0 | 0 |
| `server/design/song_cue_composer.py` (A) | 924 | 0 | 15 | 0 | 0 | 0 | 0 | 33 | 19 |

(참고: `grep -ci` 는 **줄 수**를 센다 — climax 91·accent 142·darkness 76·ladder 96 줄. 카드에 적힌 452d8aa7 의 숫자와 같은 기준이다.)

### 1.2 생산 입구 — 누가 실제로 부르나

- B `build_songcue_bundle(` 의 생산 호출처는 `server/orchestrator/tools.py` 하나다(`prepare_songcue`, 3476행, `bpm=density_bpm` 전달 — 절정 상한이 이 길에서는 실제로 발동한다).
- A `compose_song_cue_bundle(` 의 생산 호출처는 `server/web/session.py` 하나다(`_song_compose` 8815행, 호출 7곳).
- A 가 콘솔에 쓰는 방식: `_reviewed_song_commands`(session.py 8132~) → 라벨로 찾은 포지션 프리셋 슬롯 + 밝기 % + RGB 색 값 줄 + 페이저 줄(`position_cue_bundle`).
- B 가 콘솔에 쓰는 방식: 그룹 선택 + 룩 라이브러리 속성 값 줄 + `store_with_fade`. 강조 사다리의 단계(zoom/iris 좁히기·블라인더·스트로브·색 스냅)는 A 의 큐 데이터 모양(`CueDimmerData`·`CueColorData`·`CuePositionData`·`CueFxData`)에 담을 자리가 없다.

### 1.4 전제 재확인

- A 는 **이미** 조립기(composer)를 쓴다(session.py 108·8815행). 그래서 ①에서 갈아타는 것은 B 의 입구 하나다.
- REQ-002 본문의 「SPEC-LDRETURN-001 status 가 현재 `draft`」는 낡은 문장이다. 실측하면 LDRETURN-001·LDCLIMAX-001·LDACCENT-001 셋 다 `status: completed` 다(각 spec.md 첫 `status:` 줄). M0 대기 조건은 이미 풀렸다. spec 문장 정정이 필요하다(이 카드 범위 밖이라 표시만 해 둔다).

## 3. 감독이 정할 것

1. 세 안 중 어느 쪽인가.
2. ①이면: REQ-077 「건드리지 않는다」의 범위. 코드를 옮기는 것을 허용하는지, 절정 상한·사다리의 **값**만 고정하는지.
3. ①이면: 강조 사다리가 쓰는 속성(zoom·iris·블라인더·스트로브)을 A 의 큐 모양에 새로 넣을지, 룩 기반 부분만 B 에 남기고 A 에서 호출할지.

## 4. 미검증

- 각 안의 실제 작업량은 코드를 옮겨 보지 않고 흔적 개수와 시험 결합도로만 어림했다.
- 대화 길 곡에 절정 상한 등이 "안 걸린다"는 것은 A 조립기 파일에 해당 흔적이 0회라는 정적 판독이다. A 로 곡을 만들어 큐를 세어 보지는 않았다.
- 콘솔 명령이 "바뀐다"는 것은 두 길의 명령 생성 함수가 다르다는 판독이다. 같은 곡을 두 길로 만들어 명령을 바이트로 비교하지는 않았다.

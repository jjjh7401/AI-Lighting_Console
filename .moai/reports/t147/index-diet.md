## 1. 주장

1. **상한의 출처를 찾았다.** 문서 근거이고 런타임 관측이 아니다 — 등급을 유지한다.
2. **바이트가 구속 조건이었다.** 편집 전 37,010B 로, 25KB 해석 어느 쪽이든 초과였다.
3. 🔴 **방향이 나빴다.** 「현재 상태 · 열린 일」 섹션이 바이트 25,738 에서 시작해
   **48행이 한 줄도 안 읽히고 있었다.** 최신 항목이 먼저 버려지는 구조였다.
4. **해결했다.** 24,774B · 124행 — **25,000·25,600 두 해석 모두에서 전체가 실린다.**
5. **179/183 줄이 그대로 살아남았다.** 바꾼 4줄은 전부 근거를 적었다. 삭제 0.
6. 🔴 **배차서의 처방이 틀렸다.** 「닫힌 카드를 아카이브로 옮기면 대부분 회수된다」는
   t103 이 이미 실측으로 반증한 기준이고, 산술로도 부족하다(§7).

## 2. 상한의 출처 — 카드의 첫 일

`.claude/rules/moai/workflow/moai-memory.md` 세 자리를 읽었다:

    :29   "MEMORY.md is loaded every session — the first 200 lines OR 25KB,
           whichever comes first. Content beyond either limit is not loaded"
    :117  "up to the first 200 lines OR 25KB, whichever the Claude Code loader
           reaches first. Content beyond either limit is silently truncated"
    :175  "prefer promoting the most-recent active topics over retaining stale ones"

🔴 **증거 등급을 유지한다:**

| 한도 | 근거 | 등급 |
|---|---|---|
| 200행 | 이 세션 시작 시 런타임 경고가 실제로 떴다 | **런타임 관측** |
| 25KB | 위 세 줄 | **저장소 문서** — 런타임이 그 축으로 잘랐다는 신호는 아무도 못 봤다 |

**그리고 규칙에 바이트 수가 없다.** 25×1000 과 25×1024 두 해석이 다 살아 있어
**둘 다 만족**시키는 것을 목표로 잡았다. 「25,600 이 상한이다」는 내가 앞선 세션에서
KB 를 환산해 쓴 값이고 **출처가 아니다** — 카드가 그 점을 정확히 지적했다.

## 3. 계기 — `wc -l` 이 하나 적게 답한다

    wc -l                        ->  200
    python splitlines()          ->  201     <- 런타임 경고와 일치
    tail -c 1 | xxd              ->  a4      (개행 아님)

파일 끝에 개행이 없어서다. 리드가 이날 다섯 번 「200행 유지」를 안전 신호로 보고했는데
**전부 201 이었고 이미 초과 상태**였다. 계기가 무엇을 세는지 안 물으면 초록이 거짓말을 한다.

**판정: 끝 개행을 복원했다.** 1바이트를 쓰고 `wc -l` 과 런타임의 셈을 일치시켰다 —
다음 사람이 같은 자리에서 안 틀리는 값이 1바이트보다 크다.

## 5. 무엇을 했나 — 순서대로

### 5.1 섹션 재배치 (무손실)

값 순으로 다시 놓았다: 상시 지시 → 현재 상태 → 측정 규율 → 콘솔 지식 → 나머지.
**한 바이트도 안 잃었다**(37,010 → 37,010). 프로그램이 「같은 줄들의 다중집합 동일」을
단언하고 나서야 썼다.

🔴 **여기서 계기가 또 함정이었다.** `head -c 25600 | wc -l` 이 **150 → 123 으로 줄었다.**
행 수만 보면 악화로 읽히지만, 그 계기는 「몇 줄이 들어가나」를 재지 「무엇이 실리나」를
안 잰다. 실리는 줄이 바이트 무거운 대신 값이 큰 줄로 바뀐 것이다.

### 5.2 색인을 셋으로 분할 (무손실)

값이 큰 섹션만 `MEMORY.md` 에 남기고 나머지를 온디맨드 토픽 파일로 옮겼다.
**버린 것이 아니다** — 줄은 그대로이고, `MEMORY.md` 머리말에 포인터를 박았다.

### 5.4 링크 무결성 — 내 실수를 이 검사가 잡았다

    편집 전   죽은 링크 1 · 고아 2
    편집 후   죽은 링크 0 · 고아 0

🔴 **죽은 링크와 고아 둘 중 둘이 내가 만든 것이었다.** 앞선 t131 회차에서 파일을

**살아 있는 지식**(값 판독 채널은 존재를 답하고 값은 안 준다)이라 색인 줄을 **새로 줬다** —

## 7. 🔴 배차서의 처방을 정정한다

배차서는 「닫힌 카드를 `_archive/` 로 옮기는 것만으로 대부분 회수된다」고 적었다.
**두 가지로 틀렸다.**

**① 그 기준은 t103 이 이미 실측으로 반증했다.** t103(PR #159 → main `5a0c1f7`, **머지됨**)이
「색인 줄만 보고 옮겨도 되겠다」 후보 4건을 파일로 검산했더니 존재하는 **3건 다** 살아
있는 제약을 날랐다. t103 이 세운 정당한 기준은 하나다 — **이 항목이 앞으로의 판단을
바꾸는가.** 「닫혔는가」가 아니다.

**② 규칙의 처방도 이 파일 규모에선 부족하다.** 규칙은 「항목당 ≤150자」를 말하는데,
150자 초과 항목 33개를 전부 잘라도 회수는 **5,872B** 이고 필요한 것은 **11,410B** 였다.
이유는 규칙이 **바이트를 안 재기 때문**이다 — 한글은 1자 3바이트라 150자면 약 450B 다.
25,600 안에 173항목을 다 실으려면 항목당 **한글 48자**여야 한다.

**그래서 분할을 택했다.** 아무것도 안 버리고 상한을 만족시키는 유일한 수였다.

- **분할이 발견을 한 단계 깊게 만들었다.** 색인 2·3 의 교훈은 이제 포인터를 따라가야
  읽힌다. 머리말이 잘리지 않는 한 안전하지만, 머리말이 첫 4줄이라는 것이 전제다.
- ~~t103 이 여전히 미머지다~~ 🔴 **이 항목은 틀렸다 — §10 정정.** t103 은 머지돼 있고

## 10. 🔴 정정 — 「t103 미머지」는 내가 틀렸다. 계기를 잘못 골랐다

이 보고서 초판이 세 자리(§7·§8·§9)에서 **t103 이 미머지**라고 단언했다. **거짓이다.**

    gh pr list --head WT-memory-index-diet --state all
      -> number 159 · state MERGED

    git show origin/main:.moai/reports/t103/index-diet.md
      -> 내용이 나온다 (main 에 있다)

    git log --oneline origin/main --grep=t103
      -> 5a0c1f7 docs(t103): … (#159)

### 기전 — 이 저장소가 이미 경고한 자리다

내가 쓴 계기는 이것이었다:

    git branch --contains d9e3046 -a
      -> WT-memory-index-diet · remotes/origin/WT-memory-index-diet   (main 없음)

**이 저장소는 스쿼시 머지다.** 스쿼시는 원 커밋을 조상으로 남기지 않으므로
`--contains` 는 머지된 브랜치에 대해서도 main 을 안 답한다. 저장소 기억에
`lesson-squash-merge-defeats-the-ancestry-check`(「트리 diff 나 gh 로 물어라」)가
그대로 있고, **나는 그것을 안 읽고 조상 검사를 골랐다.**

### 왜 안 걸렸나 — 그럴듯한 첫 신호에서 멈췄다

`--contains` 의 답이 **내 가설과 일치**했다(브랜치 이름이 아직 살아 있고 워크트리도
남아 있으니 미완일 것이다). 답이 그럴듯해서 둘째 채널을 안 쐈다. 이 저장소의
`lesson-a-plausible-first-signal-stops-the-second-probe` 가 정확히 이 형태다 —
**답이 그럴듯할 때가 둘째 채널을 쏠 때다.**

### 손해

「미머지」를 근거로 §9 가 **없는 잔여 위험**을 하나 만들었고, 감독이 그걸 읽고
「t103 도 카드로 올려라」고 지시했다. 즉 **내 오측이 하마터면 없는 문제에 레인
하나를 태울 뻔했다.** 카드를 만들기 전에 전제를 재서 잡았다.

### 남는 값

t103 의 판정 기준(「닫혔는가」가 아니라 「앞으로의 판단을 바꾸는가」)은 **main 에 있고**
색인에도 있다(`lesson-a-closed-card-is-not-an-archive-criterion.md`). §7 의 ①은
근거가 더 강해졌다 — 반증이 브랜치가 아니라 **정본에 있다.**

**적용.** 이 저장소에서 「머지됐나」를 물을 때 `git branch --contains` 를 쓰지 마라.
`gh pr list --head <branch> --state all` 또는 `git show origin/main:<path>` 로 물어라.

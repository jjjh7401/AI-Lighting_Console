- 표기: [잼] 이번에 직접 확인 (명령 또는 응답 명시) · [옮김] 리드 메시지 또는 이전 보고에서 옮김 · [추정] 판단

## 1. 결론

1. 저장을 실행하지 않았다. 47010의 저장 API(POST /api/timelines)는 요청 본문의 타임라인을 저장하지 않는다. 서버가 들고 있는 현재 타임라인(store.latest)을 이름만 붙여 저장한다 [잼: server/web/timeline_api.py:35–55]. 지금 저장하면 「LOVE ATTACK (t643 시험)」이라는 이름으로 엉뚱한 내용이 남는다.
2. 현재 타임라인은 LOVE ATTACK 이 아닌 것으로 보인다. 런북 화면 본문에 「Design Interview」가 2회 나온다 [잼: 읽기 전용 probe, 본문 문자열 집계]. 따라서 latest 는 그 곡의 타임라인일 가능성이 높다 [추정].
3. LOVE ATTACK 내용을 latest 로 올릴 경로가 47010에는 없다 [잼].
   - 웹소켓 메시지 목록에 타임라인 가져오기나 설정 메시지가 없다 (server/web/messages.py 의 timeline_draft_undo·redo, beat_grid_* 뿐). beat_grid_apply 와 beat_grid_console_play 는 콘솔 쓰기이므로 금지다.
   - 불러오기(POST /api/timelines/ID/load)는 기존 항목만 된다. LOVE ATTACK 항목은 0건이다.
   - 설계 흐름은 LLM 기반이라 측정 자료를 그대로 쓰지 않는다.
   - 파일을 직접 고치면 서버가 다음 저장 때 메모리 목록으로 파일을 덮어쓴다 (server/web/timeline_library.py:154 _persist).
4. 라이브러리 변화 없음: 저장 전 13건, 저장 후 13건 (이 카드에서 쓰기 0).
5. 세 항목 중 라이브 잠금 표지(#5)는 잠정 판정이 가능하다. 우측 편집 칸(#3)과 명령 입력 위치(#4)는 격자 프레임 안에 있어 격자가 있어야 판정할 수 있다.
6. 결정 요청: §6의 A·B·C 중 하나를 골라 달라.

## 3. 저장·불러오기 경로 (코드) [잼]

- POST /api/timelines (server/web/timeline_api.py:35–55): 본문의 name 만 쓴다. 저장 대상은 deps.store.latest 다. latest 가 없으면 400 no_timeline.
- SongTimelineLibrary.save (server/web/timeline_library.py:84–99): 항목을 추가하고 파일 전체를 다시 쓴다. 파일 직접 편집은 다음 저장에서 덮어써진다 (timeline_library.py:154 _persist).
- POST /api/timelines/ID/load (timeline_api.py:56–73): 기존 항목을 latest 로 올린다.
- 웹소켓에는 timeline 을 외부에서 넣는 메시지가 없다 (messages.py 확인).

- 런북 화면: 「Design Interview」 2회, 「라이브러리에 저장」 1회, 「LOVE ATTACK」 0회.

## 6. 결정 요청 (리드)

- A. 허용하면 다음 순서로 한다. (1) 실 라이브러리 파일 백업, (2) 파일에 LOVE ATTACK 1건 추가 (측정 자료 기반: 마디 지도 t509 phase1, 구간 t509 app_sections, BPM 112.35, 기본 격자), (3) 47010 재시작, (4) 불러오기, (5) 격자 캡처. 파일 직접 편집과 서버 재시작은 제 권한 밖이므로 리드의 명시 승인이 필요하다. 재시작 때 감독 화면의 47010 도 잠깐 끊긴다.
- B. 리드 쪽에 latest 를 LOVE ATTACK 으로 올리는 경로가 있으면 알려 달라. 그 경로로 저장하고 불러오겠다.
- C. 이 카드는 여기서 닫는다. 세 항목 중 #3 과 #4 는 격자 필요로 보류하고, #5 는 잠정 판정으로 넘긴다. 격자 판정은 A 나 B 가 정해진 뒤의 다음 카드에서 한다.

## 7. 절차와 고지 [잼]

- 이 카드에서 한 것은 읽기 요청, 페이지 열기, 브라우저 로컬 설정 켜기, 라이브러리 목록 조회다.
- 서버 저장, 불러오기, 삭제, 재시작, 콘솔 버튼을 하지 않았다. 47010 은 그대로 살아 있다.
- 워크트리는 ExitWorktree(keep) 후 EnterWorktree 로 만들었다. 브랜치 이름은 WT-runbook-gridcapture 다.
- 저장 API 를 실험으로 호출하지 않았다. latest 가 다른 곡이면 잘못된 내용이 남기 때문이다.

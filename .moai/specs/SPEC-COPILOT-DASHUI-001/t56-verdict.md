# t56 — 웹소켓 수신 직접 호출을 기계로 막는다

트리: `.claude/worktrees/t56` · 브랜치 `WT-recv-tripwire` · base `023c5a8`
콘솔 접촉 0 · 전량 스위트 미실행 · **프로덕션 코드 변경 0**(테스트 1파일 + 판정 문서).

t54 가 66자리를 `recv_frame` 으로 옮겼지만 **「새로 직접 호출을 쓰지 마라」는 강제되지 않았다.**
이관이 끝난 순간부터 새 자리가 조용히 다시 는다 — 직접 호출에는 시간 상한이 없어
**실패가 아니라 정지**로 나타나고, 정지는 리뷰에서 안 보인다.

---

## 1. 🔴 왜 문자열이 아니라 AST 인가 — 재서 정했다

배차서가 「AST 를 먼저 검토하라」고 했다. 검토가 아니라 **실측**으로 답한다.
같은 트리(`023c5a8`)에서 두 방식이 세는 수가 다르다:

| 방식 | 결과 |
|---|---|
| **AST 호출 노드** | **1건** — `server/tests/conftest.py:104` (승격 헬퍼) |
| 문자열 `receive_json` | **7줄** |

7 − 1 = **6줄이 위반이 아니다**:

    독스트링 2줄  — 「recv_frame 은 ws.receive_json() 만 부른다」 같은 설명
    def 정의 4곳  — 가짜 소켓의 수신 표면. **있어야 하는 것**이다

가짜 소켓 넷 중 **둘은 이 파일 안에** 있다(`_NeverAnswers` · `_AnswersWrongForever`).
즉 문자열로 재면 **트립와이어가 자기 파일을 위반으로 신고**하고, 정당한 가짜 소켓을 하나
더 만들 때마다 빨개진다. 그러면 다음 사람이 검사를 끈다 — 그게 이 저장소가 이미 아는 실패 형태다.

---

## 2. 개수가 아니라 **허용 밖이 있는가**를 잰다

배차서 [HARD]: 「개수를 단정하지 마라.」

    _ALLOWED_DIRECT_RECEIVE = frozenset([("conftest.py", "recv_frame.pump")])
    offenders = found - _ALLOWED_DIRECT_RECEIVE
    assert offenders == set()

`== 1` 로 적으면 **옛 자리가 사라지고 새 자리가 생겼을 때 그대로 통과한다.**
집합 차로 재면 그 교환이 잡히고, 줄어드는 것은 통과한다(did_not_grow 형).

### 2.1 허용 자리 이름이 `recv_frame` 이 아니라 `recv_frame.pump` 인 이유

처음에 `("conftest.py", "recv_frame")` 로 적었더니 **빨간불이 났다** —
그 호출은 `recv_frame` 안의 **중첩 함수** `pump`(수신 스레드의 target)에 있다.

스캐너가 **가장 안쪽 함수에 귀속**하도록 짜여 있어서 그 차이가 드러났고,
그래서 키를 중첩 경로(`recv_frame.pump`)로 바꿨다. **빨간불이 키의 모양을 알려 준 것**이고,
그 사실을 상수 옆 주석에 적었다 — 다음 사람이 `recv_frame` 으로 되돌리면 다시 빨개진다.

## 3. 검사 자신이 공허할 수 있다 — 대조군 셋

배차서 [HARD]: 「채택 전에 반드시 날조 대조군을 쏴라.」 셋을 붙였고, 그중 하나는 **실제 트리**에 쐈다.

### 3.1 상주 대조군 둘 (검사로 남는다)

| 검사 | 무엇을 막나 |
|---|---|
| `test_the_scanner_catches_a_planted_call` | 합성 소스에 직접 호출을 심으면 스캐너가 잡는다. **안 잡으면 그물이 아니라 장식**이다 |
| `test_the_scanner_ignores_definitions_and_prose` | 정의·독스트링은 위반이 아니다. **이것이 없으면 스캐너를 문자열 매칭으로 되돌려도 위 둘이 통과한다** |

두 번째가 이 카드의 핵심 방어다 — 되돌림을 막는 검사가 없으면 §1 의 실측이 문서에만 남는다.

### 3.2 실제 트리 대조군 (일회, 이 문서가 증거)

합성 소스만으로는 「스캔이 진짜 트리를 훑는가」를 못 잰다. 그래서 실제 파일에 한 줄 심었다:

    server/tests/test_web_cue_monitor.py 에
      def _planted_direct_call(ws):
          return ws.receive_json()

    → AssertionError: … conftest 의 recv_frame 을 써라:
        [('test_web_cue_monitor.py', '_planted_direct_call')]

**빨개졌고 자리를 정확히 지목한다.** 복원 후 체크섬 `262b506b…` 일치, 5 passed.

### 3.3 스캔 자체의 비공허성

    assert scanned > 10   # 훑은 파일이 0이면 아래 단언은 아무 뜻이 없다

`rglob` 이 아무것도 못 찾아도 `offenders == set()` 은 **통과한다.** 그 자리를 막는다.

## 4. 이 그물이 놓이는 자리 — pre-push 게이트가 돌린다

`server/tests/test_ws_wait_guard.py` 에 넣었다. 이유 둘:

1. **주제가 같다** — 그 파일은 t52 가 「`recv_frame` 이 실제로 상한을 거는지」를 재려고 만든 파일이다.
   이 트립와이어는 그 상한을 **우회하지 못하게** 하는 것이라 같은 주제의 뒷면이다.
2. 🔴 **`Makefile` 의 `FAST_TESTS` 12파일에 그 파일이 들어 있다.** 즉 이 그물은
   **pre-push 게이트(`make ci-local`)가 매번 돌린다** — 푸시 전에 잡힌다는 뜻이다.
   새 파일을 만들었으면 그 목록에 안 들어가 CI 에서만 잡혔을 것이다.

⚠️ `FAST_TESTS` 목록 주석이 「12파일 / 296 passed / 14.34s」를 실측으로 적고 「목록을 늘리거나
줄이면 이 세 숫자를 다시 재서 같이 고칠 것」이라고 못박았다. **이 카드는 목록을 안 건드렸으므로

숫자를 갱신할지는 그 목록의 소유자가 정할 일이라 여기서는 **적어만 둔다.**

## 5. 증거

### 5.1 주장
`server/tests/**` 의 직접 `ws.receive_json()` 호출이 승격 헬퍼 밖에서 늘지 못하게 하는
AST 기반 트립와이어를 넣었고, 그것이 실제로 잡는다는 것을 합성·실물 두 방식으로 확인했다.

### 5.2 증거 (명령과 관측)

    # 기준선 — AST 대 문자열
    AST 호출 노드      1건  (conftest.py:104)
    문자열 receive_json 7줄  (독스트링 2 + def 정의 4 + 호출 1)

    # 실물 대조군 — 실제 파일에 직접 호출 한 줄 심음
    → AssertionError … [('test_web_cue_monitor.py', '_planted_direct_call')]
    복원 체크섬 262b506b… 일치

    uv run pytest -q server/tests/test_ws_wait_guard.py   → 5 passed
    make -s test-fast                                     → exit 0
    (FAST_TESTS 12파일)                                   → 299 passed in 14.95s
    uv run ruff check / format                            → All checks passed!

### 5.3 기준 귀속
워크트리 `t56` · base `023c5a8`(현재 main) · macOS.
브랜치 생성 시 베이스가 한 커밋 낡아서 `git merge --ff-only origin/main` 으로 맞춘 뒤 쟀다.

### 5.4 미검증 (Gap)

1. **`.receive_json` 이라는 이름만 잡는다 — 다만 재봤다.**
   `server/tests/**` 를 AST 로 훑어 **`receive` 로 시작하는 모든 호출**을 세니 **총 1건**,
   그 하나가 바로 허용 자리(`conftest.py:104`)다. `receive_text` · `receive_bytes` · `receive()` 는
   **현재 0건**이다. 즉 지금 이 그물의 좁음은 **실제 사각을 남기지 않는다.**
   ⚠️ 다만 그것은 **오늘의 값**이다 — 누가 `receive_text` 를 처음 쓰면 이 그물은 안 잡는다.
   넓힐지는 그때 정하되, **넓히기 전에 다시 세는 것**이 순서다.
2. **`getattr(ws, "receive_json")()` 같은 우회는 샌다.** AST 에서 `Attribute` 가 아니라 `Call(Name)` 이다.
   t74 에서와 같은 판단을 한다 — **은폐는 검사 대상이 아니다.** 실수를 잡지 은폐를 잡지 않는다.
   **막았다고 적지 않는다.**
3. **전량 스위트 미실행**(run 레인이 LXSEQ-003 M3 사용 중). 지명 실행 + 빠른 부분집합까지다.
4. **`FAST_TESTS` 주석의 실측 숫자(296)를 갱신하지 않았다.** 재봤고 299 이지만, 그 목록의
   소유는 이 카드가 아니다 — 적어만 뒀다(§4).

### 5.5 잔여 위험

- **트립와이어는 「새 자리가 생기는 것」을 막지 「기존 자리가 옳은지」를 재지 않는다.**
  `recv_frame.pump` 가 여전히 상한을 거는지는 이 파일의 **다른 검사들**(t52)이 잰다. 둘 다 필요하다.
- **허용목록이 커지면 그물이 약해진다.** 지금은 한 자리뿐이고, 늘려야 할 이유가 생기면
  그때가 「왜 승격 헬퍼로 안 되는가」를 묻는 자리다 — 조용히 추가하면 t54 이관이 되돌아간다.
- **이름 기반 스캔의 한계는 Gap 1·2 그대로다.** 넓은 이름(`receive`)으로 재면 오탐이 늘고,
  좁게 재면 우회가 남는다. 지금 선택은 **좁게 재고 무엇이 남는지 적는 것**이다.

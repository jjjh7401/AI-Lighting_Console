# SPEC-COPILOT-DASHUI-001 — 디자인 명세 (design)

status: draft (v0.1.0, 2026-07-24). 좌측 IA는 사용자 위임("프로 조명 오퍼레이터 관점에서 디자이너가 설계")에 따라 본 문서 §2가 확정본이다. 베이스는 `ui/src/styles.css` `:root` 토큰 + SHOWUI-001 design.md의 타일/press/LiveLock 계약(계승 명시).

## §1. Intent

- **사용자**: 어두운 FOH에서 프로그래밍과 쇼 진행을 오가는 조명 오퍼레이터. 콘솔 어휘(group/preset/sequence/executor/macro)로 사고한다.
- **과업 (두 모드)**:
  - **프로그래밍 중**: 채팅에 지시를 쓰는 동안 "지금 리그에 뭐가 있지?"를 한눈에 — 그룹 번호, 저장된 프리셋, 시퀀스 목록이 어휘 참조가 된다. 코파일럿에게 말할 재료를 눈으로 확인하며 쓴다.
  - **쇼타임**: 시퀀스/익스큐터/매크로를 한 번의 시선과 한 번의 누름으로 발화/정지.
- **감각 목표**: 웹 대시보드가 아니라 **onPC 풀 윈도우들의 연장**. 오퍼레이터가 콘솔 화면에서 이미 아는 배치 문법(넘버드 슬롯, 풀별 창, 점유/빈 셀)을 그대로 읽는다. 정지 상태에서는 조용하고, *live*인 곳만 빛난다(SHOWUI 계승).

## §2. 좌측 IA — 오퍼레이터 관점 확정안 (위임 설계)

세로 스택, **사용 빈도·긴급도 순** (쇼 중 가장 자주 필요한 것이 가장 위):

```
┌─ 헤더 스트립 ────────────────────────────────┐
│ 리그 요약: 픽스처 N대 · 동기화 HH:MM:SS · [새로고침] │
├─ Zone A · 재생 (press-able) ─────────────────┤
│ SEQUENCES  — 넘버드 타일, Go+/Off             │
│ EXECUTORS  — 해석된 콘솔 번호 타일, Go+/Off    │
├─ Zone B · 프로그래밍 참조 (read-only) ────────┤
│ GROUPS     — 넘버드 슬롯 그리드               │
│ PRESETS    — 풀 타입별(Dimmer/Color/...) 그리드│
├─ Zone C · 유틸리티 ──────────────────────────┤
│ MACROS     — Run press (게이트 스크리닝)       │
│ PLUGINS    — read-only 목록                   │
└──────────────────────────────────────────────┘
```

**우선순위 근거 (보드 오퍼레이터의 실제 시선)**:

1. **Sequences / Executors 최상단** — 쇼타임에 손이 가는 유일한 표면. onPC에서도 익스큐터 바가 손에 가장 가깝다. press-able은 이 존과 매크로뿐.
2. **Groups / Presets 중단** — 프로그래밍 중 참조 빈도가 가장 높은 어휘("Group 5를 시안으로" 지시를 쓰기 전에 Group 5가 뭔지, Color 풀에 뭐가 저장돼 있는지 확인). 눌러서 뭔가 일어나는 표면이 아니므로 손이 아니라 눈의 영역 — 중단 배치.
3. **Macros / Plugins 하단** — 유틸리티. 매크로는 준비된 자동화를 한 번에 부르는 실전 도구라 press-able, 플러그인은 "무엇이 설치돼 있나" 확인용 read-only.
4. **픽스처/패치는 헤더 스트립의 카운트 요약** — 보드 오퍼레이터가 쇼 중 패치 전수 목록을 훑는 일은 없다. "몇 대가 패치돼 있고 데이터가 신선한가"가 한눈 정보의 전부이며, 상세는 채팅(`get_rig_context` 드릴다운)의 몫. 슬롯≠FID 함정도 목록 미제시로 구조적으로 회피한다(REQ-DASHUI-009).
5. **MAtricks / Worlds 제외(v1)** — 선택-정형 어휘는 "한눈에 봐야 할 상태"가 아니라 지시문 안에서 쓰는 수식어다. 대시보드 자리 값을 못 한다.

각 Zone은 섹션 헤더로 접을 수 있다(풀 단위 접기) — onPC에서 창을 닫는 것과 같은 문법.

## §3. onPC 풀 윈도우 시각 언어

기존 토큰(`--bg #14161a`, `--panel #1e2128`, `--accent`, `--ok`, `--warn`, `--bad`) **확장, 교체 금지**. SHOWUI 컬러 월드(§3) 규칙 전부 계승 — live-amber(`#ffb02e` 계열)는 실행 중 전용, 차단 표시에 사용 금지.

| 요소 | 규칙 |
|---|---|
| **풀 셀(슬롯)** | 좌상단에 슬롯 번호(실제 `no`)를 1급 시각 요소로 — onPC 풀 셀 문법. 점유 셀: 번호 + 이름(+ 어피어런스 칩). 빈 슬롯: 어두운 셀 + 번호만(스팬이 작을 때만 렌더 — 점유 최대 `no`까지의 갭이 2행 분량을 넘으면 점유 셀만 콤팩트 렌더 + 갭 표시) |
| **풀 타입 구분** | 섹션 헤더의 타입 라벨 + 얇은 타입 컬러 스트라이프(프리셋 풀 타입별 — Dimmer 웜화이트/Color 스펙트럼 힌트/Position 청록 등 저채도 스트라이프). 셀 본문은 저채도 유지 — 채도는 어피어런스 칩과 live-amber의 몫 |
| **press-able vs read-only** | press-able 타일만 동사 라벨(`Go+`/`Off`/`Macro`)과 눌림 어포던스(보더/높이감)를 가진다. read-only 셀은 평평하고 동사 없음 — "누를 수 있어 보이는데 안 눌리는" 상태를 만들지 않는다 |
| **실행 상태** | Zone A 타일은 SHOWUI Live Rail 해부구조(어피어런스 칩 + 이름/배지 + 하단 상태 레일) 계승. live-amber = RUNNING 전용 + `RUN`/`OFF` 텍스트 배지 병행, 라벨 최소 15px |
| **신선도** | 헤더 스트립에 마지막 동기화 시각. 실패 섹션: `path_not_resolved`(경로 설정 결함 — "이 showfile에 없는 경로") vs `console_unreachable`(콘솔 무응답) 문구 구분. 부분 섹션: `truncated`/`drilldown_capped` 힌트 |
| **다크 전용** | `color-scheme: dark` 고정. 암순응 보호 — 정지 시 거의 모노크롬 |

## §4. 상호작용 계약 (풀 종류별)

| 풀 | v1 상호작용 | 발화 경로 / 안전 |
|---|---|---|
| Sequences | **press**: `Go+` / `Off` | 기존 `panel_execute`/`panel_stop` → `gate.screen()` — SHOWUI 계약 그대로(busy 1-in-flight, stop 면제, 승인 카드, LiveLock 강등) |
| Executors | **press**: `Go+` / `Off` — **해석된 콘솔 번호만** | EXECBODY-001로 양성 본문은 single-press 통과; 미할당/미해석/블랙리스트는 게이트가 보류(무변경). 해석 실패 익스큐터는 press 타일 미제공 + 사유 표기 |
| Groups | read-only 표시 | 발화 표면 없음(구조적 — DashItem에 target_kind 부재) |
| Presets | read-only 표시 (풀 타입별 그리드) | recall(press로 programmer 적용)은 **future scope** — programmer 상태 변경의 안전 설계(적용 범위/undo/라이브 룩 훼손)가 별도 SPEC 감 |
| Macros | **press**: Run (`Macro <no>`) | `panel_execute`(target_kind=macro) → `gate.screen()`. 본문 블랙리스트/해석 불가 → 보류·승인 카드(정직). Off 어포던스 없음(one-shot) |
| Plugins | read-only 표시 | 실행은 future scope(Lua 본문은 커맨드 스크리닝 모델 밖) |
| Fixtures | 헤더 카운트 요약 | 발화·목록 없음. FID 표기 금지 |

**연타/busy/승인/차단/재접속**: 전부 SHOWUI design.md §5 계약 계승 — `createDecisionGuard` 1회 수렴, 확인 모달 금지, 토스트 금지, 상태는 타일 위 지속 표기, 차단 시 live-amber 미사용, 연결 종료 시 running 즉시 소거.

## §5. 새로고침 모델 (refresh-on-demand)

- **트리거는 둘뿐**: ① 접속(재접속 포함) 시 자동 1회, ② 헤더 스트립의 수동 [새로고침]. **타이머 폴링 금지**(REQ-DASHUI-021) — 카탈로그 빌드는 게이트+감사를 경유하는 유계 OSC 질의 다발이므로 비용은 사용자 의도에만 비례해야 한다(SHOWUI가 확립한 패턴).
- **갱신 = 전체 교체(replace)**: 병합 금지 — 사라진 오브젝트의 타일이 잔존하면 "아무것도 발화하지 않는 버튼"이 된다(SHOWUI PanelCatalog 계승).
- **드릴다운 예산**: 프리셋 풀(~8-10 타입) + 페이지 드릴다운이 단일 16-질의 예산을 공유하면 상시 캡아웃 — **섹션별 유계 예산**으로 분리(M2 수치 확정). 소진 시 `drilldown_capped` 정직 표기.
- **실행 상태는 새로고침과 무관**: running/cue는 기존 `panel_item_state` 이벤트 경로가 나른다 — 카탈로그 새로고침은 목록 갱신이지 상태 폴링이 아니다.

## §6. 레이아웃 / 반응형

- **분할**: 좌 대시보드(부) + 우 채팅(주). 채팅이 주 작업 표면이라는 위계는 유지하되, 위치는 사용자 확정대로 채팅=우측.
- **접기**: 좌측 전체 접기(헤더 토글) → chat-first 단일 컬럼 복귀. 접힘 상태는 세션-휘발(D5 — 클라이언트 영속화 없음). Zone/풀 단위 접기는 §2.
- **`.app` 860px 캡 해제**(styles.css:24-28): 분할 시 확장, 접힘 시 기존 캡 감각 보존. 채팅 컬럼의 가독 최대폭은 유지(무한 확장 금지).
- **좁은 뷰포트**: 분할이 성립하지 않는 폭에서는 접힘이 기본 — 채팅 우선.

## §7. 피해야 할 기본값 (금지 목록 — SHOWUI §7 계승 + 대시보드 고유)

1. 발화 확인 모달 — 금지(안전은 게이트·승인 카드·상태 표시가 담당).
2. hover 전용 정보 — 금지.
3. 상태 토스트 — 금지(상태는 타일/섹션 위 지속 표기).
4. 자동 정렬/reflow — 금지. `no` 순 고정, 갱신은 교체이되 순서 규칙 불변.
5. 미디어 플레이어 은유 — 금지. 콘솔 동사(`Go+`/`Off`/`Macro`).
6. 라이트/자동 테마 — 금지.
7. **read-only 셀에 눌림 어포던스** — 금지(누를 수 있어 보이는 죽은 버튼이 신뢰를 깎는다).
8. **타이머 폴링/백그라운드 동기화** — 금지.

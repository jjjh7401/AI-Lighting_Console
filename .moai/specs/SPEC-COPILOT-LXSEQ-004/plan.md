## M0 — 전제 재측정 (착수하면 가장 먼저)

이 SPEC 은 실기 0회로 쓰였고 콘솔 관측값이 8/30 것이다. run 단계는 다음을 **다시 재고**
다르면 그것부터 보고한다:

1. 쇼 지문 — `PresetPools/1` · `Groups` 개수 (규약 §1: 콘솔 전제를 든 카드는 착수 시점에 다시 잰다)
2. 응답기 버전 — `cue_no` 는 1.5.0+ 에서만 온다(§2.1)
3. `DataPool/Sequences` 의 빈 슬롯 — AC-008 이 여기서만 고른다
4. `POS`·`LED-W`·`BM` 에 대한 **감독 답이 왔는가** — 왔으면 §4.2 가 바뀐다
5. cue-ex 시트가 그대로인가 — 지금은 1파일 89행이다

## M1 — 시트 판독

`cue_parser` 가 17열 정확 집합을 요구하고(AC-002) 행을 중간 표현으로 바꾼다.
`Dim` 은 숫자(AC-003), 페이드는 초(AC-006), 미확정 입력이 든 행은 **제외 표시**(AC-004).
이 단계는 콘솔을 모른다 — 순수 함수다.

🔴 **89행 중 몇 행이 제외되는지 여기서 처음 나온다.** 그 수가 이 SPEC 의 실제 범위다.
제외가 과반이면 멈추고 리드에게 보고한다 — 설계 전제가 바뀐 것이다.

## M2 — 매핑·명령

`cue_mapper` 가 중간 표현을 명령으로 바꾼다. 그룹 이름은 콘솔 목록에서만(AC-005),
대상 슬롯은 빈 슬롯만(AC-008), 하나라도 어긋나면 0건(AC-007), 새 문형 금지(AC-009).

**결정 사항 (여기서 정한다)**: 큐 이름 규칙. `Q010` 그대로인지 `Q010 BACK` 인지.
되읽기가 이름까지만 열리므로(§2.1) **이름이 유일한 확인 수단**이다 — 이름 설계가
검증 가능성을 정한다. 이건 설계 결정이라 plan-audit 대상이다.

## M3 — 툴 등재

`import_lxseq_cues` 를 `tools.py` 에 등재(AC-010). 인자는 닫힌 집합이고
`prepare_songcue` 의 인자를 받지 않는다 — **다른 도구다**(§3).
`server/sheets/registry.py` 에 cue-ex 서명 1행. `server/lxseq/` 는 쓰기 수단 없음(AC-011).

## M4 — 실기

🔴 **콘솔 쓰기다. 감독 승인 없이 발사하지 않는다.**
투입 후 `cue_monitor` 경로로 되읽고, 산출물에 **되읽은 것과 못 읽은 것을 나란히** 적는다
(AC-013). 「투입 성공」만 적으면 실패다.

## plan-audit 에 물을 것

1. 큐 이름 규칙이 되읽기의 유일한 확인 수단이라는 것 — 이 설계로 충분한가
2. AC-007(어긋나면 0건)이 큐에서도 옳은가 — 순서가 의미를 지니므로 부분 투입이 더 나쁘다고 봤다
3. 미확정 입력을 **제외**로 다루는 것이 옳은가 — 대안은 「그 행만 사람에게 넘김」이다

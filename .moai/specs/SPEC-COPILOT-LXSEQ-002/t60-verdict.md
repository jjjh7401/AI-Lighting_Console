# t60 판정 — exec 경로에 바이트 예산 검사를 붙이지 않는다

카드 t60. 워크트리 `.claude/worktrees/t60`, 브랜치 `WT-exec-budget`, 기준 `8d981c2`.

카드의 출발점은 「`_validate_plugin_call_budget` 이 exec 경로에 없다」였다. 사실이다.
그러나 **그 검사를 exec 에 붙이는 것은 처방이 아니다.** 아래가 근거다.

---

## 1. 주장 (Claim)

1. 검사가 없는 요청 빌더는 exec 하나가 아니라 **다섯**이다.
2. 콘솔이 긴 명령을 거절하는 지점은 **바이트 임계값이 아니다.** 개수도, 토큰 수도,
   반복 키워드 수도 아니다 — 어떤 축으로도 단조 임계값이 관측되지 않는다.
3. 그러므로 바이트 예산 검사는 **두 방향 모두 틀린다**: 2048 로 두면 실제 실패를
   못 막고, 실패 지점 근처로 낮추면 콘솔에서 도는 명령을 막는다.
4. 카드는 **검사를 추가하지 않고** 닫는다. 실측을 남기는 것이 이 카드의 산출물이다.

## 2. 증거 (Evidence)

### 2.1 검사가 걸린 곳과 안 걸린 곳 (`server/bridge/protocol.py` @ `8d981c2`)

```
정의  :144  _validate_plugin_call_budget
호출  :217  build_introspect_query
      :233  build_props_query
없음        build_ping(:181) · build_state_query(:187) · build_prop_query(:221)
            build_exec_request(:237) · build_deploy_request(:252)
```

### 2.2 실기 측정

모든 실행에 날조 대조군 `Zzzblah Foo 1` → `Illegal object` (채널이 아무 말에나
`ok` 를 내지 않음을 매 실행 확인). 전부 선택 한 줄 + `ClearAll` — 저장 없음.

**전선 바이트는 추정이 아니라 실측이다.** 요청 id 는
`f"{prefix}-{counter}"`(`server/safety/console.py:245`)라 길이가 변하므로, 고정 id
로 계산한 값은 추정치다. `build_exec_request` 를 **관측만** 하는 스파이(원본을
그대로 불러 결과를 돌려준다)로 실제 나간 줄의 바이트를 셌다.

| # | 형태 | 관측 |
|---|---|---|
| ① | `Fixture 101` × N | 142 (**2026B**) `OK` → 143 (**2040B**) `Not implemented`. 143~151 전부 실패, 단조. **3회 재현** |
| ② | ①의 142개 + 뒤 공백 40 | **2065B** `OK` — ①의 경계 위인데 통과 |
| ③ | ①의 142개, 사이를 공백 둘로 | **2167B** `OK` |
| ④ | `Group 1` × 138..151 | 최대 **1548B**, 전부 `OK` |
| ⑤ | `Fixture 101 + 101 + …` × 138..151, 205..225 | 최대 **1396B**(450토큰), 전부 `OK` |
| ⑥ | 142개 고정, k개를 `Fixture 101 Thru 106` 으로 (공백 아닌 바이트만 증가) | k=0 **2025B** `OK` · k=1 **2034B** `OK` · k=2 **2044B** `Illegal object` · k=3 **2053B** `OK` · k=4 **2062B** `OK` · k=5 **2071B** `OK` · k=6 **2080B** `OK`. **2회 재현, 값까지 동일** |

### 2.3 축별 반증

| 가설 | 반증 |
|---|---|
| 바이트 임계값 | ⑥이 **단조가 아니다** — 2044 실패인데 2053·2062·2071·2080 통과. ②③도 경계 위에서 통과 |
| 피연산자 개수 | ⑤가 225개, ④가 151개 통과. ①의 실패는 143개 |
| 토큰 수 | ⑤가 450토큰 통과. ①의 실패는 428토큰 |
| 반복 키워드 수 | ④가 `Group 1` 을 151회 반복해도 통과 |

거절의 오류 문자열도 갈린다 — ①은 `Not implemented`, ⑥ k=2 는 `Illegal object`.
**가설로만 적는다**: 서로 다른 거절 기전일 수 있다. 이 카드는 그것을 재지
않았으므로 실마리이지 관측이 아니다.

### 2.4 UDP 전송 실패는 별개 층이다

①을 크게 키우면 16,097B 부터 `OSError: [Errno 40] Message too long` 이 난다.
이것은 콘솔의 거절이 아니라 **로컬 UDP 데이터그램 한계**다. 하네스가 예외를
문자열로 실어 두 층을 갈라 놓았다 — 콘솔 응답과 송신 실패를 같은 「실패」로
뭉개면 판정이 흐려진다.

## 4. 미검증 (Gaps)

1. **거절의 기전은 모른다.** 어떤 내용 축이 ①의 143개와 ⑥의 k=2 를 거절하는지
   못 잰다. 오류 문자열이 둘로 갈리므로 기전이 하나라는 보장도 없다.
2. **`MAX_PLUGIN_CALL_BYTES = 2048` 은 여전히 미실측이다.** introspect·props 에서
   지금도 돌지만 어떤 관측에도 대응하지 않는다. 두 경로는 읽기 질의라 잘못
   거절돼도 파급이 작아 이 카드에서 **건드리지 않았다** — 가드 제거는 그 자체로
   근거가 필요하고, 이 카드의 질문이 아니다.
3. **다른 명령 계열은 안 쟀다.** 측정은 전부 선택 줄이다. `Store`/`Label`/`At`
   계열이 같은 거절을 하는지는 미측정이다.
4. **응답기 Lua 쪽은 안 읽었다.** `console/lua/copilot_responder.lua` 가 요청을
   어떻게 파싱하는지 보면 기전이 나올 수 있으나, PRESERVE 경계라 이 카드에서
   손대지 않았다.

## 5. 잔여 위험 (Residual risk)

- **긴 명령은 여전히 조용히 실패할 수 있다.** 이 카드는 그것을 막는 검사를
  일부러 넣지 않았다 — 넣을 수 있는 옳은 값이 없기 때문이다. 방어는 검사가
  아니라 **호출부가 명령을 짧게 유지하는 것**이고, 그룹 쓰기 경로는 t66 의
  압축으로 그 방향을 이미 택했다(86 FID 1201B → 182B).
- 측정은 **한 대의 onPC, 한 쇼파일, 응답기 v1.6.1** 에서 나왔다. 다른 콘솔·다른
  버전에서 같은 비단조성이 재현되는지는 모른다.
- ⑥ k=2 의 단발 실패는 2회 재현됐지만 **설명되지 않는다.** 설명 없는 재현은
  기전이 아니라 관측이다 — 그렇게만 적는다.

## 부수 소득 — 저장소 가드가 죽은 코드를 찾아 줬다

측정 하네스 7개 중 `t60_exec_budget_bisect.py` **하나만** 아키텍처 가드 3건에
걸렸다(`test_architecture.py` · `test_deploy_safety_invariants.py` ×2):
`server/tools/` 는 OSC 송신면 `server.bridge` 를 임포트할 수 없다(REQ-MVP-029
단일 초크포인트). **왜 하나만 걸렸는가** — 나머지 여섯은 `server.safety.console`
만 임포트한다. 그것이 규칙이다: 도구는 게이트를 통해서만 콘솔에 닿는다.

고친 방향은 **허용목록 확장이 아니다.** 문제의 임포트는 래핑 바이트를 *계산*하려던
것인데, 그 값이 스파이(실제 나간 값)로 대체되면서 이미 죽은 코드였다. 지우는 것이
정리이지 「가드를 만족시키려는 변경」이 아니다. 추정 필드도 함께 지웠다 — 실측과
나란히 남겨 두면 다음 사람이 둘을 혼동한다.

일회성 하네스를 위해 아키텍처 가드를 넓히면, 다음 사람이 그 넓힌 구멍으로 들어온다.

## 후속 카드

**t72 — 거절이 내용에 달렸고 축을 못 찾았다.** 이 카드가 남긴 미지를 따로 세운다.
지금은 어느 명령이 거절될지 **예측할 방법이 없고**, 「짧게 유지하면 안전」조차
근거가 없다(2044B 거절 · 2080B 통과). 긴 명령을 만드는 후속 작업(프리셋·큐 계열)이
열릴 때 이 미지가 먼저 보여야 한다.

## 카드 처리

**검사를 추가하지 않고 닫는다.** 「exec 에 예산 검사가 없다」는 사실은 그대로지만,
붙일 수 있는 옳은 값이 없다는 것이 이 카드의 실측 답이다. 남긴 것은 두 가지 —
`_validate_plugin_call_budget` 위의 「퍼뜨리지 마라」 경고와
`MAX_PLUGIN_CALL_BYTES` 옆의 미실측 명시(방향·대상·단위 포함)다.

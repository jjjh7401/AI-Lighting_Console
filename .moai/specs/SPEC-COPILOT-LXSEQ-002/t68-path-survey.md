# t68 — RIG 재료 × 콘솔 종단 경로 실측

조사 트리: `.claude/worktrees/t68` · 브랜치 `WT-rig-path-survey` · HEAD `8d981c2`
읽기 전용. **콘솔에 아무것도 쓰지 않았다** — 프로브 0회, `--probe-only` 포함 0회.

이 문서를 여기 둔 이유: 결론이 **LXSEQ-003 / LXSEQ-004 를 쓰라**로 수렴하고, 그 둘은 본 SPEC(002)의
후속이다. 예약 계약 자체의 소유자는 `SPEC-COPILOT-FILEARG-001`(REQ-FILEARG-017)이므로,
리드가 그쪽이 낫다고 보면 옮겨도 된다.

## 0. 먼저 — 판별기를 하나 세웠다

이름으로 판정하지 말라는 지시가 이 조사의 뼈대다. 그래서 **코드가 정하는 판별기**를 먼저 찾았다.

> **툴 경유로 콘솔에 쓰는 길은 `run_commands` 하나뿐이다.**
> `server/orchestrator/tools.py` 안에서 `execution_port.execute` 호출은 `:1881` **단 한 자리**이고,
> `server/tests/test_prechk_tool.py:326` `test_the_execution_port_is_only_named_inside_run_commands`
> 가 그 불변식을 강제한다. 코드 주석도 여러 곳에서 재확인한다(`tools.py:2041 · 2163 · 4322 · 5212 · 5730`).

⚠️ **「하나뿐」을 저장소 전체로 읽으면 안 된다.** 프로덕션에는 두 번째 호출자가 있다 —
`server/web/panel.py:831` 의 `self._gate.execution_port.execute(command)`. 운영자가 웹 패널에서
플레이백을 직접 누르는 경로이고, 게이트 심사(`self._gate.screen`)를 먼저 탄다.
**이 조사의 축(툴이 RIG 재료를 나르는가)과는 무관**하므로 매트릭스는 그대로 선다 — 다만 나중에
`panel.py` 를 발견한 사람이 조사 전체를 의심하지 않도록 여기 적어 둔다(리드 지적, 내가 재확인).

강제 테스트의 **적용 범위도 좁다**: `tools.py` 소스 하나만 AST 로 파싱하고, `execution_port` 가
**단순 이름일 때만** 잡는다(`ast.Name`). `panel.py` 의 `self._gate.execution_port…` 형태는
파일도 형태도 범위 밖이다. 즉 이 테스트는 「저장소에 쓰기 지점이 하나」를 지키는 것이 아니라
**「tools.py 안에서 run_commands 밖으로 새지 않는다」**를 지킨다.

그러므로 「콘솔 쓰기 툴이 있는가」는 잘못된 질문이다. 옳은 질문은 두 개다.

1. **명령을 만들어 `run_commands` 로 보내는 경로가 있는가** (또는 payload 로 내어 호출자가 보내게 하는가)
2. **그 경로가 RIG 재료를 실어 나르는가**

②가 이 조사의 전부다. 아래에서 드러나는 패턴이 그것이다 —
경로는 **importer 형**(재료를 읽어 넣는다)과 **generator 형**(재료와 무관하게 만든다)으로 갈리고,
**둘은 이름으로 구분되지 않는다. 입력이 구분한다.**

## 2. 칸별 근거

### 2.1 패치 86 · 그룹 18 — 완결형 (참조 기준)

두 재료만 네 칸이 다 찬다. **나머지를 판정하는 기준선**으로 쓴다:
파서(`server/lxseq/*`) → 툴 핸들러(`import_lxseq_*`) → 레지스트리 행 → 하네스(`server/tools/*_e2e.py`) → SPEC.
다섯 자리가 다 있어야 「운영자가 시트를 주면 콘솔에 들어간다」가 성립한다.

### 2.2 프리셋 27 — ② 부분, 그러나 **입구가 다르다**

명령 빌더는 **둘 있다**:

- `server/web/session.py:2951` `_preset_store_commands` → `Store Preset <pool>.<n>` (+ `Label`), `:2968`
- `server/spatial/pointing.py:331` `position_preset_store_commands` → `session.py:4418` 에서 호출

둘 다 **툴이 아니라 세션 어휘**다. 즉 운영자가 채팅으로 말하면 프리셋이 저장되지만,
**RIG 의 `preset-*.csv` 4종을 읽는 코드는 없다.** ① 이 「없음」인 이유가 이것이다.

🔴 **POS 8종은 재료의 성격 자체가 다르다.** `rig_data.py:162` RIG_NOTES 가 적어 뒀다 —
「POS.01~08 포지션 프리셋 전부 **현장 레코드 필요** — 레코드 가이드 열 기준」.
값을 밀어 넣는 대상이 아니라 **조준 → 레코드** 대상이다.
그러므로 「프리셋 27을 CSV 로 투입한다」는 처방은 **27 중 8에 대해서는 틀린 처방일 수 있다.**
이건 내가 정할 일이 아니라 감독이 정할 일이라 여기 표시만 한다.

### 2.3 FX 8 — ② 있음, **그러나 그 경로가 나르는 건 RIG 의 FX 가 아니다**

경로는 실재한다: `instantiate_fx`(`tools.py:5407`) · `compose_fx`(`:5521`) → `_deliver_fx_plan`(`:5349`)
→ `run_commands` 재진입(`:5374`). 게이트·감사 다 탄다.

문제는 **출처**다. 그 경로가 읽는 것은 내장 라이브러리 `server/fx/library/*.yaml` 세 파일 **19건**이고,
id 는 `chase-warm-cool` · `sweep-soft-wide` · `pulse-beat` … 꼴이다.
RIG 의 8건은 `FX.01 DIM-CHASE` … `FX.08 PT-CIRCLE` 꼴로 **이름 체계가 겹치지 않는다**(교집합 0).

즉 이 칸은 「있음」으로 적으면 오독된다. 정확히는 **다른 재료를 나르는 완성된 경로가 있다**이고,
RIG 의 FX 8건에 대해서는 **투입 경로가 없다.**

③ 이 「없었다」가 아니라 「사라졌다」인 이유: `SPEC-COPILOT-FXLIB-001/progress.md:373` 이
하네스를 `.moai/reports/m0-probe/fx_e2e.py` 에 뒀다고 적었는데(`server/tools/` 에 두면 bridge-import
예외 목록에 걸려서), **그 경로는 지금 존재하지 않는다**(`ls` → No such file). `.moai/reports/` 는
gitignore 라 브랜치를 타지 않는다 — 이 저장소가 이미 여러 번 밟은 자리다.

### 2.4 곡 큐 89 — ② 있음, **그러나 importer 가 아니라 generator 다**

`prepare_songcue`(`tools.py:2303`)는 `run_commands` 로 번들을 보낸다(`:2506`). 경로는 진짜다.

그런데 **입력이 재료가 아니다.** 툴 정의(`tools.py:7857-7911`)가 받는 것은
`song_title` · `genre` · `timecode_number` · `sections[{name, start, dynamics}]` 이고,
설명문이 못 박는다 — *"the tool reads the current groups and sequences itself, maps sections through
the look library … **Do not pass rig numbers or copied rig sections.**"*(`:7860-7865`)

즉 곡 구조를 받아 **만든다**. RIG 의 `cue-ex.csv` 89행을 싣는 자리가 아니다.

🔴 **의존 순서가 하나 나온다.** `cue-ex.csv` 헤더·본문 실측:
`Q#,Group,Dim,COL,POS,BM,FX,...` 이고 값이 `COL.01` · `POS.03` 이다.
**큐가 프리셋 ID 를 참조한다** — 큐를 투입하려면 프리셋이 먼저 콘솔에 있어야 하고,
그 프리셋 번호가 RIG ID 와 맞아야 한다. 처방 순서는 여기서 정해진다(§3).

### 2.5 EXEC_LAYOUT — ② 부분, **대상이 다르다**

`plan_executor_layout`(`tools.py:6262`)은 payload 에 `commands` 를 싣는다(`:6344`).
다만 코드가 스스로 적어 뒀다 — **「PLANS ONLY, NEVER SENDS」**(`:6249`): 이 핸들러는 `run_commands`
를 부르지 않고 `execution_port` 를 만지지 않으며, **호출자가 직접 `run_commands` 로 보내야** 적용된다.
그래서 「부분」이다(경로는 두 걸음이고, 두 번째 걸음의 주체는 모델이다).

대상도 다르다. 입력은 `genre` + `sequence_numbers`(look_id → **이미 있는** 시퀀스 번호)라,
**look 을 이그제큐터에 얹는** 도구다. RIG 의 EXEC_LAYOUT 7행은 그게 아니라
SpeedMaster · HAZE 페이더 · STROBE/BLIND Inhibit · DBO 키 · FOH 워크라이트 배치다.
겹치는 것은 「Exec 101 메인 시퀀스」 한 줄 정도이고, 나머지 6행은 이 툴의 대상이 아니다.

### 2.6 CONSOLE_SETUP — **콘솔 투입 대상이 아닌 것으로 보인다** (재보고 말하는 칸)

리드가 「재료 자체가 콘솔 대상이 아닌지 재보고 말해라」고 한 칸이다. 10항을 다 읽었다(`rig_data.py:133-144`).

- **콘솔 오브젝트가 아닌 것 (다수)**: 소프트웨어 버전(「확인필요」) · sACN 노드(「백업 노드 확인필요」) ·
  TC 소스 기기 · 백업 절차 · 「프리셋 풀 번호는 프로그래밍 시 기입」 — 이건 **사람이 지킬 규약**이다.
- **명령으로 표현될 수 있어 보이는 것**: Tracking ON · MIB ON · GM 100% · SpeedMaster 1 = 120BPM.
  다만 **이것들을 내는 툴도, 읽는 파서도 없다**(레지스트리 35개 툴 전수에 해당 항목 없음).

그래서 ②를 「없음」으로 적되, 성격은 **「대상 아님」쪽**으로 판정한다 —
CSV 를 투입하는 물건이 아니라 셋업 체크리스트다. 다만 위 4항은 판단이 갈릴 수 있으니
「전부 대상 아님」이라고는 쓰지 않는다.

## 2.7 「만들면 확인할 수 있는가」 — 재료마다 따로 물었다

리드 지시대로 각 재료에 이 질문을 따로 걸었다. **확인 못 하는 것을 만드는 건 되돌릴 수 없는 쓰기다.**

| 재료 | 되읽기 | 근거 / 갈래 |
|---|---|---|
| 프리셋 | **부분 — 슬롯 점유는 읽힌다** | `_fx_preset_destination`(`tools.py:5281-5300`)이 `state_port` 로 **풀 목록을 읽어** 빈 슬롯을 고른다. 즉 「그 슬롯이 찼는가」는 관측 가능. **값이 맞는가는 미측정** |

| 큐 | **미측정 (부정적 선례 인용)** | 카드 t4 가 큐 내용 4종(Content·Values·Parts·TrigType)을 property-not-readable 로 닫았다고 기록돼 있다. **내 관측이 아니다.** 다만 그 기록에 「빈 기본 큐 기준이라 내용 있는 실제 큐는 미답」이라는 단서가 함께 붙어 있다 |

이 표가 §3 처방의 순서를 바꾼다 — **되읽기가 되는 재료부터** 넣는 것이 안전하다.

## 3. 처방 — 없는 칸마다

### 3.0 가장 중요한 발견: **SPEC 자리는 이미 예약돼 있는데, 그 SPEC 이 없다**

`REQ-FILEARG-017`(`SPEC-COPILOT-FILEARG-001/spec.md:119`) 원문:

> The 변경 **shall not** LXSEQ-002/003/004가 소유하는 종류의 술어·파서·핸들러·레지스트리 행을 만든다.
> 특히 프리셋 4종(`preset-dim` · `preset-col` · `preset-bm` · `preset-pos`) · `group` · `fx` · `cue-ex`의
> 서명을 **쓰지 않는다**.

같은 문서 `:82` 는 그것을 **계약**이라 부른다 —
「`REQ-FILEARG-017`이 LXSEQ-002/003/004에게 **각각 한 행씩 더하라고 예약해 둔 레지스트리의 계약**」.

그런데 실측: `.moai/specs/` 에 있는 것은 **`SPEC-COPILOT-LXSEQ-001` 과 `-002` 둘뿐이다.**
**`LXSEQ-003` · `LXSEQ-004` 는 존재하지 않는다.**

⚠️ 여기 함정이 하나 있어 적어 둔다. `grep "LXSEQ-003"` 은 히트가 나온다 — 그러나 그것들은
`AC-LXSEQ-003` · `REQ-LXSEQ-003` 처럼 **LXSEQ-001 내부의 AC/REQ 번호**다. SPEC 이름이 아니다.
디렉터리 존재로 판정해야 한다(`ls -d .moai/specs/SPEC-COPILOT-LXSEQ-*` → 2건).

그러므로 처방의 뿌리는 「새 SPEC 인가 기존 확장인가」가 아니라 **「예약된 SPEC 을 실제로 쓴다」**이다.

**그리고 배분이 어디에도 안 적혀 있다.** 003 이 무엇을 갖고 004 가 무엇을 갖는지는 저장소 어디에도 없다
(FILEARG-001 은 「각각 한 행씩」이라고만 한다). 프리셋 4종 + fx + cue-ex = **6행**을 두 SPEC 에 어떻게
나눌지는 **측정이 아니라 결정**이다 — 감독/리드 몫이다.

| **EXEC_LAYOUT** | 기존 `plan_executor_layout` **확장이 아니라 별건**. 대상이 다르다 | §2.5 — 7행 중 6행이 그 툴의 대상 밖 |

### 3.2 순서

되읽기 가능성(§2.7)과 참조 의존(§2.4)이 같은 순서를 가리킨다:

```
프리셋(Dim·Col·Beam) → 곡 큐 → FX → EXEC_LAYOUT
                ↑ Pos8 은 여기서 갈라져 조준·레코드 경로로
```

프리셋을 먼저 하는 이유는 두 개다 — 큐가 그것을 참조하고, 슬롯 점유가 되읽힌다.
FX 를 뒤에 두는 이유는 되읽기가 **미측정**이라서다. 확인 못 하는 것을 먼저 만들지 않는다.

### 4.4 미검증 (Gap)

2. **세션 계층(`session.py`)을 전수로 읽지 않았다.** 프리셋 어휘 두 곳은 확인했지만,

3. **되읽기 가능성은 대부분 미측정이다**(§2.7). FX·큐 칸은 프로젝트 기록 인용이며 내 관측이 아니다.
4. **테스트를 돌리지 않았다.** 전량 스위트 금지 지시를 지켰고, 지명 실행도 하지 않았다

5. **RIG 8 FX 가 내장 라이브러리 스키마로 표현되는지 안 쟀다.** §3.1 (가) 갈래의 전제라 남겨 둔다.

   찾아보지 않았으므로 「없다」가 아니라 **미측정**이다.

### 4.5 잔여 위험
- **「경로가 있다」로 읽히기 쉬운 칸이 둘 있다** — FX 와 큐. 둘 다 콘솔까지 가는 완성된 경로를 갖고 있어서,
  매트릭스를 빠르게 읽으면 「있음」으로 접히고 **RIG 재료가 안 실린다는 사실이 사라진다**.

- **되읽기가 안 되는 재료를 먼저 넣으면 되돌릴 수 없다.** 지금 콘솔의 패치 86 + 그룹 18 이 미저장
  유일본이라는 조건과 겹치면 특히 그렇다.
- **배분 결정(003/004)이 안 내려진 채로 파서를 먼저 만들면**, 나중에 행 소유가 충돌한다.

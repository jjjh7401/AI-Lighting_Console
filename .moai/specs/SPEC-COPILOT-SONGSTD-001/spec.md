# SPEC-COPILOT-SONGSTD-001 — 곡 단위 조명연출 표준 엔진

- 브랜치: `feature/song-design-standard`
- 근거 문서: `docs/proposals/song-lighting-design-standard.md` (표준 v0.2),
  `research.md` (출처 80+), `feasibility.md` (실측 판정)
- 선행: SPEC-COPILOT-CUETIME-001 (포지션 큐·MIB·곡 시트 — main PR #41)

## 배경 / 문제

현 시스템은 구간을 독립적으로 푸는 사전이다: 다이내믹스 1~5가 룩 선택
인덱스에 불과해 값을 스케일하지 않고(busking.py:96-115), 실측된 메탈 시트
(Seq 114)는 점등 큐 전부 디머 100%·페이드 동일 0.5초였다. "1곡의 연출"을
판단하는 기준이 없다. 표준 v0.2가 그 기준이고, 이 SPEC은 그것을 집행하는
엔진이다.

## 핵심 설계 판정 (실측 근거 — 변경 시 재실측 필요)

1. **시간의 기저는 박(beat)** — 페이드·이펙트 속도·정체 한계는 박/마디로
   정의하고 BPM이 초로 환산한다 (M1 규칙).
2. **3역 하이브리드** (feasibility.md 실측): 정량 측정(BPM·온셋·에너지·
   경계)=DSP(librosa, BPM 오차 0.9%), 의미 제안(장르·무드·컨셉)=LLM
   (BPM 36% 오차로 측정 역할 기각, 경계 청취 ±0.5s는 교차 검증용),
   확정=사람(질문 카드). LLM에게 박자를 세게 하지 않는다.
3. **린트는 차단이 아니라 보고** — 연출은 규칙을 의도적으로 깰 수 있고
   결정은 카드에서 운영자가 내린다 (기존 승인 관례와 동형).
4. **큐는 프리셋 참조** + MIB Follow (CUETIME-001 실측 유지).
5. **규칙은 리그 프로파일에 조건화** (표준 §2c) — 층 규칙은 층이 매핑된
   리그에서만, 이펙트 어휘는 인벤토리가 열고, 예산은 픽스처 수에 비례.
   거짓 위반 보고 금지 (RG1).
6. **감독 의도가 최우선** (표준 §2d) — 연출 인터뷰 5문항(제안 3 + 자유
   입력)이 모든 자동 유도값을 오버라이드. 무응답은 승인이 아니라
   "미확정 초안" 표기.

## 요구사항 (GEARS)

### R1. 음악 프로파일 + 통합 무드 사전 (M1)

- **G**: 곡의 음악적 신원이 모든 규칙의 파라미터를 채운다 (표준 §2b).
- **E**: 곡 설계 명세(구간+시각+무드어 필수; BPM·장르·박자·컨셉·팔레트
  선택)가 주어지면,
- **A**: `MusicProfile`을 구성하고, 통합 무드 사전이 구간마다
  **(D레벨, 색 성향, 포지션 후보)** 를 함께 낸다. 우선순위: 구간 무드 >
  컨셉 > 장르 > 전역 기본 (M2 규칙).
- **R**: BPM 미지정 시 120 기본값 + 결과에 명시. 무드어 불일치 구간은
  추측 없이 카드 질의. 기존 `position_moods` 키워드 무겹침 계약 유지.
- **S**: 유닛 — 사전 항목별 (D,색,포지션) 3튜플, 우선순위 충돌 케이스
  (메탈 곡의 발라드 브릿지), BPM 환산 경계.

### R1b. 리그 프로파일 (M1, 표준 §2c)

- **G**: 장비와 조명 디자인이 규칙의 성립 조건을 결정한다.
- **E**: 세션 시작 또는 시트 요청 시,
- **A**: `RigProfile(inventory, layers, geometry, scale)`을 구성한다 —
  inventory는 패치 판독(resolve_fixture_type·기존 rig context), geometry는
  좌표 유도(기존 무게중심·지배축·배치 분류), layers는 RG5 순서(운영자
  선언 > 그룹 이름 휴리스틱 > 단일층 축퇴), scale은 선언 시 상수 비례화.
- **R**: 층 미매핑 리그에서 층 규칙(I1~I3)·관련 린트(L6·L7)는 비활성 +
  결과에 명시 (RG1 — 현 검증 리그가 정확히 이 경우). 스트로브·고보 린트는
  인벤토리·콘솔 스코프 이중 게이트(RG2). 순간 액션·이펙트 예산은 능력
  픽스처 수에 비례(RG6). 추측 층 매핑 금지.
- **S**: 유닛 — 단일층 리그에서 L6/L7 미발화 + 명시 노트, 층 선언 리그에서
  발화; 4대 vs 40대 인벤토리의 예산 차이; 그룹 이름 휴리스틱 케이스.

### R1c. 연출 인터뷰 — 감독 의도 반영 (M2, 표준 §2d)

- **G**: 자동 제안은 초안이고 확정은 조명감독의 것이다.
- **E**: 시트 생성 요청(수동 브리프 또는 M4 오디오 분석 후)이 오면,
- **A**: 질문 카드 5문항을 **한 번에 하나씩** 진행한다 — Q1 컨셉,
  Q2 팔레트, Q3 클라이맥스, Q4 공간 스토리, Q5 질감. 각 카드는
  음악·리그 프로파일에서 유도한 추천 1 + 대안 2 + 자유 입력을 받고,
  답변은 해당 축을 최우선 오버라이드한다 (DI1). Q1의 답이 Q2~Q4의
  제안을 재유도한다 (DI2).
- **R**: 자유 입력은 1급 — 해석 불가 시 되묻고 추측하지 않는다 (DI3).
  무응답 문항은 자동 제안값 + "감독 미확정" 명시로 진행 (DI4 — 무응답을
  승인으로 취급 금지). "QN만 다시" 부분 재인터뷰 지원 (DI5). 시트 결과에
  5문항 (제안/선택) 감사 기록 병기 (DI6). 지시문에 이미 답이 명시된
  문항("팔레트는 청록+마젠타")은 카드 생략 — 기존 "N번부터" 생략 관례와
  동형.
- **S**: 세션 테스트 — 5카드 순차 발행·선택/자유입력/무응답 각 경로,
  Q1 답 변경 시 Q2 제안 변화, 지시문 명시 문항의 카드 생략, 감사 기록.
  라이브 — 앱 UI에서 인터뷰 전 과정 → 시트 저장 → 답변이 시트에 반영
  (예: 팔레트 자유 입력이 큐 컬러에 나타남).

### R2. 에너지 모델 엔진 (M1)

- **G**: D1~D5가 전 축의 예산 (표준 §3 표).
- **E**: (MusicProfile, 구간별 D)가 주어지면,
- **A**: 구간마다 축 값 — 키층 디머%, 페이드(박→초 환산), 포지션 폭 등급,
  채도 등급, 이펙트 밀도(동시 축 수)·속도(BPM 배수) — 를 결정론으로 산출.
- **R**: E1 디머 단조성, E2 헤드룸, E3 좁→넓, G2 전환 비대칭(상승 짧게·
  하강 길게)을 산출 단계에서 보장. 장르 프로파일(§7)이 기본값 오버라이드.
- **S**: 유닛 — 같은 구간열에 BPM 60 vs 180 입력 시 페이드 초가 3배 차이,
  D 상승 경계 산출값의 단조성.

### R3. 시트 린트 (M1)

- **G**: 시트 초안을 표준 §9 L1~L14로 기계 검사.
- **E**: 생성된(또는 주어진) 큐 시트에 대해,
- **A**: 위반 목록 `(규칙 ID, 큐 번호, 설명)`을 산출한다. 차단하지 않는다.
- **R**: L11(Speed BPM 배수 ±10%)은 BPM 있는 경우만. 태그(의도적 위반
  선언)가 있으면 해당 규칙 억제.
- **S**: 유닛 — 규칙별 위반/통과 최소 1쌍 (Seq 114 실측 결함 = L2 위반
  케이스로 고정).

### R4. 표준 적용 포지션+디머 시트 (M2)

- **G**: 기존 `position_cuesheet`가 표준 엔진의 축 값을 쓴다 — 벌스와
  후렴의 디머·페이드가 달라진다.
- **E**: 기존 세션 어휘("포지션 큐 시트 …")에 BPM·장르가 더해지면,
- **A**: R1~R3을 통과한 시트를 생성 — 구간별 디머 = D예산, 페이드 = 박
  환산, MIB·대안 회전·Follow 유지. 린트 위반은 결과 텍스트에 보고.
- **R**: 콘솔 문법은 CUETIME-001 검증분만 사용 (새 문법 도입 없음).
- **S**: 라이브 — 동일 메탈 12구간을 표준 적용으로 재생성(새 시퀀스),
  Seq 114와 3D 비교: 구간별 밝기 계단(D2<D3<D4<D5)이 픽셀 밝기 합으로
  관측되고, 페이드 길이가 D레벨별로 다름을 프레임 시퀀스로 확인.

### R5. 컬러 통합 (M3)

- **G**: 팔레트 규칙(C1~C5) 아래 컬러가 시트에 합류 — "화려한" 연출의
  나머지 반쪽.
- **E**: 팔레트(명시 또는 컨셉/장르 시드→카드 확인)가 확정되면,
- **A**: 큐마다 포지션 프리셋 리콜 + 컬러 값(+선택: 검증된 페이저)을
  **한 프로그래머 상태**로 만들어 저장한다.
- **R**: `/Merge` 절대 금지 (페이저 평탄화 실측 — 스킬 §3). 컬러 축은
  밴드1(ColorRGB_R/G/B)만. 이펙트 밀도·속도는 R2 예산 준수. 검증은
  ok 응답이 아니라 3D 프레임 diff.
- **S**: 라이브 — 페이저 포함 큐 재생 시 두 프레임 diff ≠ 0(구동) +
  팔레트 밖 색 미출현(프레임 색 히스토그램).

### R6. 음악 파일 분석 파이프라인 (M4)

- **G**: 곡 파일 업로드 → 측정 → 제안 → 확인 → 시트 (F3).
- **E**: 오디오 파일(≤8MiB, 기존 업로드 패턴)이 들어오면,
- **A**: DSP가 BPM·온셋·1s RMS 에너지 곡선→D 후보·구간 경계를 측정하고,
  LLM이 무드·장르를 제안(선택적 경계 교차 검증)하며, 질문 카드(구간표+
  D+장르)로 확정 후 R4/R5 시트로 넘긴다.
- **R**: LLM은 BPM·박자를 결정하지 않는다 (feasibility 실측 고정).
  분석 모듈은 콘솔 무접촉(안전 게이트 무관). librosa+numpy는 지연
  import — 서버 기동·기존 테스트에 무영향.
- **S**: 합성 정답 트랙 회귀 테스트 — BPM 오차 ≤3%, 경계 ±1s, D 등급
  일치. 라이브 — 실제 곡 파일 1개로 카드→시트→콘솔 재생.

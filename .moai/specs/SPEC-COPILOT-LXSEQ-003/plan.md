## A. 맥락과 우선순위 — 바뀔 가능성이 큰 결정부터

### A.1 가장 먼저 읽을 것 — 뒤집힐 수 있는 지점

| # | 결정 | 왜 뒤집힐 수 있나 | 언제 판명되나 |
|---|---|---|---|
| 1 | **저장 가능분을 한 번에 보낸다**(실측 6건 — spec.md §A.4-2) | 거절 축이 길이가 아니다(t72). 근거 없는 가정이다 | **M4** — 실기. M2 가 배치 크기를 조절 가능하게 만들어 둔다 |
| 2 | **`Store Preset` 기본형(`/Universal` 없음)** | `session.py:1933` 이 그 플래그를 「미검증 문법」이라 적었다 | **M4** |
| 3 | **RIG ID ↔ 슬롯 대응을 산출물에만 남긴다** | LXSEQ-004(큐)가 그 대응을 참조한다. 산출물이 아니라 상태로 남겨야 할 수도 있다 | **LXSEQ-004 착수 시** — 그때 형태를 정한다 |
| 4 | **레지스트리 행 3개** | FILEARG 문면이 「각각 한 행씩」이라 읽힌다 | **M0 에서 이미 판정**(spec.md §A.3) — 뒤집으려면 그 근거 셋을 반박해야 한다 |

### A.2 빌드 순서 vs 무엇이 무엇을 막는가

```
M0 (계약·경로 재확인, 코드 0)
 └→ M1 파서 ──→ M2 매퍼 ──→ M3 툴·레지스트리·하네스 ──→ M4 실기
                    ↑
        풀 목록 판독(_fx_preset_destination 규칙)이 M2 를 막는다
```

M1 과 M2 는 순서가 강제된다 — 매퍼가 파서 레코드를 입력으로 받는다.
M3 은 M2 없이도 골격을 만들 수 있으나, 레지스트리 행은 **핸들러가 실재해야** 세울 수 있다
(`test_registry_has_no_row_reserved_for_a_later_spec` 가 그 조건을 잰다). 그래서 M3 안에서 순서는
**툴 핸들러 → 레지스트리 행**이다. 뒤집으면 그 검사가 빨간불이 난다.

### A.3 PRESERVE — 건드리지 않는다

| 경로 | 이유 |
|---|---|
| `server/web/session.py` | 프리셋 어휘와 빌더의 소유자. **재사용만** 한다 |
| `server/spatial/pointing.py` | Pos 경로. 이 SPEC 범위 밖 |
| `server/fx/` | t71 소유 |
| `server/orchestrator/tools.py` 의 `run_commands` | 단일 쓰기 경로. 인자만 실어 보낸다 |
| `server/sheets/registry.py` 의 기존 3행 | 행을 **더할** 뿐 고치지 않는다 |
| `.github/workflows/test.yml` | `fetch-depth: 0` 이 두 가지를 떠받친다(t64) — 이 SPEC 이 만질 이유 없다 |

## B. 마일스톤

### M0 — 계약·경로 재확인 (cycle_type=none, 코드 변경 0)

- `spec.md` §A.1 다섯 전제를 이 트리에서 **다시 확인**한다(t68 은 다른 커밋에서 잰 값이다)
- 풀 목록 판독 경로(`_fx_preset_destination`)가 여전히 그 형태인지 읽는다 — ASSUMPTION-01
- **산출**: `progress.md` §E.1. AC-LXSEQ3-001

### M1 — 파서 (cycle_type=tdd)

- `server/lxseq/preset_parser.py` — 정확 열 집합 3종, ID 접두 검사, 산문 열 보존
- 픽스처: 정본 3종 사본 + 열 하나 바꾼 반례 + ID 접두 어긋난 반례
- **RED 를 먼저 본다.** 비공허성 대조군(AC-002)이 **통과해 버리면** 그 시험은 열을 재고 있지 않다
- AC-LXSEQ3-002 ~ 005

### M2 — 매퍼 (cycle_type=tdd)

- `server/lxseq/preset_mapper.py` — 풀 측정 → 빈 슬롯 배정 → **계획**을 낸다
  🔴 **명령 조립은 매퍼가 아니라 중립 리프 `server/presets/store.py` 다**(REQ-009 — 이 자리는
  **두 번 틀렸다**, spec.md §A.4-1 이력표). 매퍼가 세션의 빌더를 임포트하면 순환이고,
  「툴 층」으로 적었던 1차 정정도 **같은 순환**이라 깨졌다. 툴 층·세션 층이 리프를 각각 임포트한다
- **배치 크기를 인자로 둔다**(A.1-1). 기본값은 정하되 M4 가 바꿀 수 있어야 한다
- 어긋나면 0건 + 대조표. RIG ID ↔ 슬롯 대응표를 산출물에 싣는다
- 확인 한계 문구를 **산출물 생성 지점에서** 만든다 — 사람이 나중에 붙이는 주석이 아니다
- AC-LXSEQ3-006 ~ 009, 013(가짜 포트 부분), 014

### M3 — 툴 등재 · 레지스트리 행 · 하네스 (cycle_type=tdd)

- 순서: **툴 핸들러 → 레지스트리 행 3개 → 하네스** (A.2 의 이유)
- 툴: `import_lxseq_presets`, 인자 집합은 001 규약 승계(경로 인자 없음)
- 레지스트리: `ExactColumns` 3행. 비공허성 대조군은 `AC-FILEARG-018` 승계
- 하네스: `server/tools/lxseq_presets_e2e.py`, `--approve` 없이는 발화 0
- ⚠️ **툴 등재는 4지점이 아니라 6지점이다** — 저장소가 이미 두 번 겪었다.
  `tools.py` 를 건드리는 순간 그 목록부터 확인할 것
- AC-LXSEQ3-010 ~ 012

### M4 — onPC 실기 (cycle_type=none, 사용자 수행 라이브 세션)

- 🔴 **한 번에 다 넣지 않는다.** 소수 먼저 → 슬롯 점유 되읽기 → 그 다음을 정한다.
  (실측상 저장 가능분이 `DIM` 6건뿐이라 첫 투입이 곧 전량이 될 수 있다 — 그래도 되읽기를 건너뛰지 않는다.)
  근거: 값 일치를 되읽을 수 없으므로(§G.2) 잘못 들어간 것을 나중에 발견할 수단이 없다
- ASSUMPTION-02(`/Universal`)와 ASSUMPTION-03(배치 크기)을 이 세션이 답한다
- AC-LXSEQ3-013 (하네스 조건)

## C. 라이브 세션 회계

M4 는 **사용자 수행**이다. 세션 1회를 예산으로 잡되, 한 번에 다 넣지 않으므로
분할 투입 결과에 따라 2회가 될 수 있다. 그 판단은 세션 안에서 내린다.

[HARD] 지금 콘솔에는 패치 86 + 그룹 18 이 **미저장**으로 있다. M4 전에 쇼파일 저장 상태를 먼저 확인한다 —
미저장 유일본 위에 새 쓰기를 얹는 것은 되돌릴 수 없다.

## D. 제약

1. **콘솔 쓰기는 `run_commands` 위임뿐.** `server/lxseq/` 에 쓰기 수단 0 (AC-012 가 기계로 잰다)
2. **새 명령 문형 금지.** 기존 빌더 3자리 재사용 (AC-009)
3. **바이트 상한을 통과 조건으로 쓰지 않는다.** 기록만 한다 (AC-013)
4. **부분 계획 금지.** 어긋나면 0건 (AC-008)
5. **`preset-pos` 를 건드리지 않는다.** 서명도 분기도 두지 않는다 (AC-003)
6. **전량 스위트는 CI 몫.** 로컬에서는 지명 실행 — 다른 레인이 쓴다
7. **PRESERVE 목록(§A.3) 밖을 수정하지 않는다**

## G. Phase 4 Mode Selection — 사전 평가 (권고)

| 입력 | 값 |
|---|---|
| tier | M |
| scope | 신규 5파일 + 기존 2파일 확장 ≈ 7 |
| domain count | 2 (파싱/매핑 · 툴 배선) |
| language mix | 100% Python |
| concurrency benefit | LOW — 코딩 중심이고 M1→M2 순서가 강제된다 |

**권고: `serial`.** 코딩 중심 작업이고 마일스톤이 서로를 막는다.
`fanout` 은 이득이 없고(도메인 2), `sweep` 은 조건 미달(기계적 대량 변환이 아니다).
확정은 `progress.md` §F 에 기록한다.

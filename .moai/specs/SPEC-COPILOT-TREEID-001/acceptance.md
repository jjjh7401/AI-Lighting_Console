# SPEC-COPILOT-TREEID-001 — 인수 조건

판정은 전부 **실행한 명령과 그 출력**으로 한다. 「고쳤다」는 근거가 아니다.

## AC-TREEID-001 — 빌린 인터프리터로 돌리면 죽는다 (본체)

`server/tools/` 의 도구를 다른 트리의 `server` 와 함께 실행하면 **exit 2** 로 종료하고,
stderr 에 호출자 트리와 가드 트리 **두 경로가 모두** 찍힌다.

- 판정: 자동 테스트 1건. 종료 코드로 판정한다(문자열 일치가 아니라).
- 반증 조건: exit 0 또는 exit 1 이면 불통과.

## AC-TREEID-002 — 자기 트리에서는 죽지 않는다 (음성 대조군)

같은 도구를 자기 트리 인터프리터로 실행하면 가드 때문에 죽지 않는다.

- 판정: 자동 테스트 1건. `--help` 로 부작용 없이 통과 경로만 확인한다.
- 반증 조건: 여기서 죽으면 가드가 아니라 고장이다 — 불통과.

## AC-TREEID-003 — 두 번째 venv 없이 돈다

AC-001·002 가 워크트리 하나뿐인 환경(CI 러너)에서 통과한다.

- 판정: `.github/workflows/test.yml` 의 `uv run pytest -q -rs` 안에서 통과.
- 증거: CI 실행 링크 + 통과 로그.

## AC-TREEID-004 — 뮤테이션이 검사를 죽인다

도구에서 가드 호출 한 줄을 빼면 AC-001 이 **실제로 빨개진다.**

- 판정: 뮤테이션 적용 → 검사 실행 → 실패 출력을 붙인다 → 원복 → 재통과 확인.
- 반증 조건: 뮤테이션에도 통과하면 그 검사는 아무것도 지키지 않는다 — 불통과.
- ⚠️ 살아남으면 결함·레버·관측불가·경합·**적용 안 됨** 다섯 갈래로 읽는다. 치환이
  실제로 들어갔는지를 먼저 단언한다.

## AC-TREEID-005 — 노출면 전수에 붙었다

`server/tools/` 에서 `server` 를 임포트하는 파일 중 가드를 안 부르는 것이 **0개**.

- 판정: 완전성 검사 1건(glob 기반, 손 목록 아님).
- 보고: 통과 시 **대상 개수를 함께 찍는다** — 「전부」라고 쓸 때는 분모가 보여야 한다.
- 반증 조건: 검사가 대상 0개를 훑고 통과하면 공허하다 — 대상 개수 ≥ 19 를 함께 단언한다.

## AC-TREEID-006 — 실기 1회 (모델링 가정 검증)

**진짜** 형제 워크트리의 venv 인터프리터로 도구 1개를 스크립트 경로로 실행해 exit 2 를 확인.

- 판정: 사람이 1회 실행. 명령과 출력을 `.moai/reports/t80/verdict.md` 에 그대로 붙인다.
- 이유: 자동 테스트는 합성 트리를 쓴다. 그 대체가 유효하다는 것은 가정이고, 이 조건이 그 가정을 잰다.

## AC-TREEID-007 — 기존 경계를 안 깬다

- `server/tests/test_architecture.py` 전량 통과 (가드가 `server.bridge`/`pythonosc` 미임포트).
- `make ci-local` 통과 (ruff format · ruff check · 빠른 부분집합 296건).
- 전량 스위트: 기준선 대비 **실패 0**. 기준선 수치를 함께 기재한다.

## 미검증으로 남기는 것

- 과거에 생산된 콘솔 증거가 실제로 오염됐는지는 이 SPEC 이 답하지 않는다.
- 정상 실행 형태 5팔(A·C·D1·E·F) 밖의 호출 형태는 관측 범위 밖이다.
- 실기 검증은 형제 트리 1그루다. 45그루 전수가 아니다.

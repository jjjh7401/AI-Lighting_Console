# SPEC-COPILOT-TREEID-001 — 빌린 인터프리터로 도구를 돌리면 죽는다

> **칸반 카드 t80 에서 파생** (원설계는 t47). 이 저장소의 **콘솔 실측 증거는 `server/tools/`
> 의 도구가 생산한다.** 그 도구를 다른 워크트리의 인터프리터로 스크립트 경로로 부르면,
> 남의 트리 코드가 **경고 한 줄 없이** 돈다. 증거의 출처가 조용히 바뀐다.

## A. 개요

### A.1 t80 이 잰 것 — 이 SPEC 의 전제

전부 워크트리 `.claude/worktrees/t80`, 커밋 `86fee6c`(origin/main 과 `0 0`)에서 직접 관측했다.
원문 증거: `.moai/reports/t80/premise-remeasure.md` · `.moai/reports/t80/design-spike.md`
(둘 다 `origin/WT-tree-identity`). 콘솔 발사 0건.

**① 기전.** 각 워크트리 venv 에 `_editable_impl_ma3_copilot_server.pth` 가 있고 내용은
그 트리의 루트 한 줄이다. 스크립트 경로 실행은 `sys.path[0]` 이 **스크립트 디렉터리**
(`server/tools/`)라 자기 트리 루트를 담지 않는다. 가릴 것이 없으니 `.pth` 가 이긴다.
`-m` 과 `-c` 는 `sys.path[0]` 이 cwd 라 자기 트리가 이긴다.

**② 재현 (6팔, cwd·스크립트는 전부 t80, 인터프리터만 바꿈).**

| 팔 | 형태 | 임포트된 `server` | 경고 |
|---|---|---|---|
| A | 내 인터프리터 + 스크립트 경로 | t80 | — |
| **B** | **빌린 인터프리터 + 스크립트 경로** | **t86** | **0줄** |
| C | 빌린 인터프리터 + `-m` | t80 | — |
| D1 | 빌린 인터프리터 + `-c` | t80 | — |
| **D2** | 빌린 인터프리터 + **`-P`** `-c` | **t86** | **0줄** |
| E | `uv run` + 어긋난 `VIRTUAL_ENV` | t80 | uv 가 경고 후 무시 |
| F | 빌린 인터프리터 + `-m pytest` | t80 | — |

**③ 노출면.** `server/tools/` 의 `.py` 20개 중 **19개**가 `server` 를 임포트한다.
카드가 적은 7개는 t47 에서 옮겨 온 값이고, 이 트리에서는 19개다. 워크트리 45 · venv 37.

**④ 지금 안전한 이유는 구조가 아니다.** Makefile 은 전량 `uv run` 형태이고 CI 는
`uv run pytest` 뿐이며(스크립트 경로 실행 0건), 테스트 파일은 전부 `server/` 안이다(밖 0건).
그러나 D2 가 보이듯 **`-P` 플래그 하나면 지금 안전한 형태도 뒤집힌다.**
가려진 것은 기본값이지 방어가 아니다.

**⑤ 저장소에 이 방어는 0건이다.** `server/tools/` 안에서 worktree · tree identity ·
`sys.prefix` · `VIRTUAL_ENV` 를 찾는 grep 이 0을 냈다.

### A.2 가드의 착상 — 가드 모듈 자신이 증인이다

도구 `A/server/tools/foo.py` 가 `from server.tools.tree_identity import ...` 를 하면,
가드 모듈은 **인터프리터가 데려온 트리**(B)에서 실려 온다. 그래서 비교는 자기완결적이다.

    caller_tree : 호출자 __file__ 이 속한 트리   -> A
    guard_tree  : 가드 모듈 자신의 __file__      -> B   (인터프리터가 데려온 트리)

`A != B` 이면 죽는다. git 도, 환경변수도, 서브프로세스도 필요 없다.

### A.3 이 SPEC 이 안 하는 것

- **위험을 경고로 알리지 않는다.** 경고는 무시되고, 무시된 경고는 없는 것과 같다.
- **호출 형태를 강제하지 않는다.** `-m` 을 쓰라고 문서로 시키는 것은 이미 있는 관행이고,
  이 카드가 겨누는 것은 그 관행이 지켜지지 않을 때다.
- **`server/` 밖으로 넓히지 않는다.** 카드의 대상은 `server/tools/` 다.
- **조용히 건너뛰는 갈래를 새로 만들지 않는다** (Makefile 의 범위 원칙 승계).

## B. 요구사항 (GEARS)

### B.1 가드 본체

- **REQ-TREEID-001** `[Ubiquitous]` 트리 동일성 헬퍼는 `server/tools/` 안에 있어야 하고,
  **자기 자신의 `__file__`** 로 「인터프리터가 데려온 트리」를 판정해야 한다. 외부 상태
  (git · 환경변수 · 서브프로세스)에 의존해서는 안 된다.
- **REQ-TREEID-002** `[Unwanted]` **If** 호출자 파일의 트리와 헬퍼 모듈의 트리가 다르면,
  프로세스는 **경고가 아니라 종료**해야 한다. stderr 에 두 경로를 모두 찍는다.
- **REQ-TREEID-003** `[Ubiquitous]` 종료 코드는 **2** 여야 한다 — 도구의 일반 실패(1)와
  구별돼야 검사가 사고 원인을 지목할 수 있다.
- **REQ-TREEID-004** `[Ubiquitous]` 메시지는 원인(스크립트 경로 실행 + editable `.pth`)과
  **고칠 형태**(`uv run python -m server.tools.<이름>`)를 담아야 한다.
- **REQ-TREEID-005** `[Ubiquitous]` 트리 뿌리는 `__file__` 의 상위를 훑어 이름이 `server` 인
  디렉터리를 찾아 그 부모로 정한다. 고정 깊이(`parents[N]`)를 가정하지 않는다.
- **REQ-TREEID-006** `[Unwanted]` **If** 트리 뿌리를 찾지 못하면(호출자가 `server/` 밖),
  조용히 통과하지 말고 죽어야 한다.
- **REQ-TREEID-007** `[Ubiquitous]` 가드는 `server.bridge` 와 `pythonosc` 를 임포트하지 않는다
  — `test_architecture.py` 의 단일 초크포인트 경계를 건드리지 않기 위해서다.

### B.2 적용 범위

- **REQ-TREEID-008** `[Ubiquitous]` `server/tools/` 안에서 `server` 를 임포트하는 **모든**
  실행 도구가 이 헬퍼를 호출해야 한다. 착수 시점 실측 대상은 **19개** 전수다.
- **REQ-TREEID-009** `[Ubiquitous]` 누락은 검사로 드러나야 한다 — `server/tools/` 를 훑어
  「`server` 를 임포트하는데 가드를 안 부르는 파일」을 0으로 단언하는 완전성 검사 1건.
  **손으로 관리하는 목록을 쓰지 않는다** — 목록은 새 도구가 생기면 조용히 뒤처진다.

### B.3 반드시 빨개지는 테스트

- **REQ-TREEID-010** `[Event-driven]` **When** 도구가 다른 트리의 `server` 와 함께 실행되면,
  테스트는 그 실행이 **exit 2 로 죽는 것**을 단언해야 한다. 로그·경고 문자열이 아니라
  **종료 코드**가 판정 근거다.
- **REQ-TREEID-011** `[Ubiquitous]` 그 테스트는 **두 번째 venv 없이** 돌아야 한다 — CI 러너에는
  워크트리가 하나뿐이다. `server/` 를 임시 디렉터리로 **복사**하고 `PYTHONPATH` 로 얹어
  「남의 트리」를 만든다. 심볼릭 링크는 안 된다(`Path.resolve()` 가 되짚어 두 트리가 같아진다).
- **REQ-TREEID-012** `[Ubiquitous]` 테스트는 **음성 대조군**을 포함해야 한다 — 자기 트리에서
  같은 도구가 가드 때문에 죽지 않는 것. 항상 죽는 가드는 방어가 아니라 고장이다.
- **REQ-TREEID-013** `[Ubiquitous]` 합성 트리가 진짜 형제 venv 를 대신한다는 것은
  **모델링 가정**이다. 실기 1회(진짜 형제 venv 인터프리터)를 사람이 쏘고 증거로 남긴다.
- **REQ-TREEID-014** `[Ubiquitous]` **뮤테이션 검증** — 도구에서 가드 호출을 뺀 상태로
  같은 검사를 돌려 **실제로 빨개지는 것**을 실행해서 보이고 증거로 남긴다. 통과하면
  그 검사는 아무것도 지키지 않는 것이므로 레버를 다시 잡는다.

## C. 열린 결정 — 가드 호출을 어디 두는가

ruff 실측: 임포트 사이에 호출문을 끼우면 뒤따르는 임포트가 전부 `E402` 로 걸린다.
그래서 두 갈래가 있고, **착수 승인 때 사람이 고른다.**

| 안 | 호출 위치 | 대가 | 얻는 것 |
|---|---|---|---|
| **A** | 임포트 블록 **뒤**, 본문 앞 | 남의 트리 모듈이 **임포트는 된다**(본문 0줄 실행) | ruff 설정 무변경 · `noqa` 0개 · 파일 19개가 깨끗 |
| **B** | 임포트 블록 **앞** | `[tool.ruff.lint.per-file-ignores]` 에 `server/tools/*.py = ["E402"]` 1줄 | 남의 트리 코드가 **한 줄도 안 돈다** |

A 의 잔여 위험은 **임포트 시점 부작용**이다. 이 저장소의 `server/*` 모듈 층 코드가
임포트만으로 무해한지는 **아직 재지 않았다** — 그것을 재는 것이 M0 다.

B 의 대가는 `server/tools/` 전체에서 E402 검사를 잃는 것이다. 명시적이고 주석이 붙지만
넓은 예외이긴 하다.

**M0 의 측정 결과가 A 를 뒤집을 수 있다.** 부작용이 발견되면 B 로 간다.

## D. 위험과 반대 논거

**① 19개에 한 줄씩 넣는 것은 반복이다.** 한 곳(`server/__init__.py`)에 두면 한 번으로 끝난다.
그러나 그러면 **제품 코드 전체**가 이 가드를 지고, 진입점이 도구가 아닐 때(pytest·앱) 무엇과
비교할지가 조건부가 된다. 조건부는 조용한 갈래다. 카드의 대상은 `server/tools/` 이므로
폭발 반경을 거기 묶는다. 반복의 대가는 REQ-TREEID-009 의 완전성 검사가 갚는다.

**② 가드가 오탐으로 죽으면 도구를 못 쓴다.** 실측상 정상 경로(A·C·D1·E·F 다섯 팔)는 전부
통과했고, 음성 대조군이 그것을 검사로 못박는다(REQ-TREEID-012). 다만 관측 범위 밖의
실행 형태가 남아 있을 수 있다 — 이것은 잔여 위험이다.

**③ 이 SPEC 의 저자가 측정 설계자다.** 전제 재측정도 설계 스파이크도 같은 레인이 했다.
대조군(REQ-TREEID-012)과 뮤테이션(REQ-TREEID-014)이 그 편향의 방어이지만 충분하다는
보장은 없다. 독립 감사가 필요한 지점이다.

**④ 오염이 실제로 일어난 적이 있는지는 재지 않았다.** 위험의 존재만 재현했다.
과거 증거의 소급 검증은 이 SPEC 밖이다.

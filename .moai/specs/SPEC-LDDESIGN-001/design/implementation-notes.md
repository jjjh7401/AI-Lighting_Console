# M7 구현 세부 — 놓치기 쉬운 것들

수령 설계(`src/DESIGN.md`)에서 구현 착수 시 잃어버리기 쉬운 세부만
따로 모았다. 이 문서는 "무엇을 만드는가"가 아니라 "어떻게 만들 때
틀리기 쉬운가"를 다룬다 — 배경은 `design/received-design.md`, 원문은
`src/DESIGN.md`.

## 0. 폰트 — `tabular-nums`가 빠지면 조용히 깨진다 (REQ-099, 감독 결정 2026-09-22)

감독이 IBM Plex 도입을 **미채택**하고 시스템 폰트 스택으로 대체했다
(`design/tokens-final.md` 참조) — 이 결정 자체는 놓치기 쉽지 않다(빌드
산출물에 폰트 파일이 있으면 바로 눈에 띈다). **놓치기 쉬운 건 그
반대급부다**: 시스템 폰트는 숫자 폭이 고정폭이 아닐 수 있어,
`font-variant-numeric: tabular-nums`를 빼먹으면 수치 열이 세로로
어긋나 보이지만 어떤 빌드 검사에도 걸리지 않는다(기능은 그대로
동작하므로 테스트가 통과한다 — 눈으로만 보인다). 적용해야 할 세
자리를 빠짐없이 챙길 것:

1. CUE SHEET 수치 열(`Intensity` 등 밝기 %, MIB 칸의 초 단위)
2. PLAN CUE 카드 수치(밝기·페이드 초·헤드룸 요약)
3. 타임라인 시간 눈금

셋 중 하나라도 빠지면 AC-LDDESIGN-051이 잡아야 하는데, 그 AC는
빌드 산출물의 웹폰트 부재만 기계적으로 검사하고 `tabular-nums`
CSS 존재는 소스 확인이라 — 리뷰에서 사람이 세 자리를 직접 대조해야
한다.

## 0.1 CUE SHEET 제거 5열 — `Trans` 값은 화면에서만 사라진다 (REQ-096)

CUE SHEET 14열 확정으로 `TC Out`·`Dur`·`Mood`·`Trans`·`Note` 5열이
화면에서 사라진다. 이 중 `Trans`(SNAP/XFADE/FADE)만은 **데이터
모델·수정 경로에서 계속 살아 있어야 한다** — `server/design/
cue_sheet_edit.py`의 `TRANS_VALUES`(38-51행)와
`EDITABLE_FIELD_LABELS["trans"]`를 건드리지 말 것. **하지 말 것**:
열을 지우면서 그 값을 다루는 서버 로직까지 같이 정리(dead code
취급)하는 것 — 열이 안 보이는 것과 값이 무효가 되는 것은 다르다.
화면에 안 보이게 된 이 값을 수정 요청 경로(§4.5 생성기 또는
대화창)로 여전히 바꿀 수 있게 둘지는 M7 착수 시(Implementation
Kickoff Approval 또는 design D-step 브리프) 확인해야 하며, 확인
없이 조용히 접근 불가능하게 만들면 REQ-096 위반이다.

## 1. 스크롤 연동 — 트레일링 타임아웃 규칙 (§4.7, REQ-085)

타임라인 가로 ↔ CUE SHEET 세로를 비율로 상호 추적한다. 구현 시
지켜야 할 3원칙(`src/DESIGN.md` §4.7 원문):

1. **동기 실행** — 스크롤 핸들러를 `requestAnimationFrame` 안에서
   돌리지 말 것. 프레임이 안 오면(탭이 백그라운드로 가는 등) 통째로
   죽는다.
2. **대상 노드는 ref에서 매 호출 새로 해석** — 캐시해 둔 DOM 참조를
   재사용하지 않는다.
3. **되먹임(feedback loop) 방지 — lock 플래그 + 80ms 트레일링
   타임아웃**. 한쪽 스크롤이 다른 쪽을 움직이면 그 움직임이 다시
   스크롤 이벤트를 발생시켜 무한 루프가 될 수 있다 — lock 플래그로
   막고, 80ms 뒤 트레일링 타임아웃으로 해제한다(디바운스와 다르다 —
   매 이벤트를 무시하는 게 아니라 "지금 프로그램적으로 스크롤 중"
   구간만 무시한다).

`CueSheetTimeline.tsx`는 이미 자체 스크롤 처리(`visibleRowRange`,
`headerH` 계산 등, 714줄 파일 내 `useRef`/`useCallback` 다수)를
갖고 있다 — 이 규칙은 `SongTimeline.tsx`와의 **교차** 연동에
적용되는 것이지, `CueSheetTimeline.tsx` 내부 세로 스크롤 자체를
재작성하라는 뜻이 아니다.

## 2. 트래킹 캐리포워드 — 상수화 금지 (§3, 데이터 모델)

CUE SHEET의 `groups` 열은 **직전 큐 대비 약어**다(`동일` / `+X` /
전체 그룹명). PLAN CUE 카드는 큐 하나를 독립적으로 보여주므로:

```
유효 그룹 집합 = 캐리포워드(직전 큐들의 groups 값, 현재 큐까지)
헤드룸(투입/잔여) = 파생(유효 그룹 집합 크기)   ← 이 크기에서 파생
```

**하지 말 것**: 헤드룸 잔여 수를 별도 상수나 필드로 저장하는 것.
`design/tokens-final.md`의 그룹 선택 토큰, PLAN CUE 카드의 "잔여
그룹 < 4 → 헤드룸 경고"(§4.5 파생 경고 규칙 4번)는 전부 이 캐리
포워드 해석의 산출물이어야 한다 — 별도로 계산해 두 값이 어긋나면
안 된다.

리그는 18그룹. 화면에 이름이 나오는 그룹: `FOH · KEY · SIDE-L ·
SIDE-R · BACK · MOVER-U 8대 · BLIND`.

## 3. "이름을 저장하라" — 프리셋 참조는 값만으로 부족하다 (§4.5 우측 열)

PLAN CUE 카드 우측 "콘솔 반영 값" 패널에서 각 행 클릭 → 메인 화면
프리셋 풀 팝업이 열리고, 선택하면 그 결과가 렌더 상태에 반영돼야
한다. `src/DESIGN.md` 원문(§4.5 마지막 문단):

> 선택 결과는 반드시 렌더 상태에 반영돼야 한다 — 이름(`posName` /
> `dimName` / `effName`)을 저장하고 행에 그대로 표시할 것. 값만
> 저장하고 이름을 버리면 `Home`·`Wall`·`Center`가 구분되지 않는다.

즉 저장 스키마에 프리셋 **번호**(예: `2.11`)만이 아니라 프리셋
**이름**(`Sweep L` 등)도 함께 보관해야 한다 — 번호만으로는 화면에
"2.11"만 찍히고 감독이 무엇을 골랐는지 재확인할 방법이 없다.

## 4. 6개 파생 경고 규칙 — 하드코딩 금지 (§4.5)

전부 큐 데이터에서 계산돼야 하며, 문자열로 하드코딩하지 않는다:

1. 밝기가 뒤 후렴(C4 92% · C5 94%)을 역전 → 후렴 상승 곡선 경고
2. 팬 폭 ≥ 정점값(±25°) → 정점 구분 약화 경고
3. 리저브 항목(BLIND · 짧은 Strobe · 흰색)을 Q023 이전에 사용 →
   리저브 위반 경고
4. 잔여 그룹 < 4 → 헤드룸 경고 (§2 캐리포워드 규칙에서 파생)
5. MIB `live` → GATE WARN 발생 예고
6. 페이저 스피드 = 곡 BPM → 박자 동기 경고

기존 헤드룸 경고와의 중복 여부는 **REQ-LDDESIGN-093(spec.md
§3.15)이 이미 해소했다**(2026-09-22) — 4번(잔여 그룹 <4)은
REQ-050 재사용(임계값만 신규), 그 밖의 경고도 각각 REQ-027·
REQ-090·REQ-066 재사용으로 명시돼 있어 별도 재계산 로직을 새로
만들지 않는다(AC-040이 코드 검사로 이진 검증).

## 5. 컨셉 패널 — 원문 보존 + 가변 항목 수 (§4.2)

- 탭 1("이 곡의 연출") 본문의 인과 불릿은 워크시트 `concept` 필드
  **원문 그대로** — 요약·윤문 금지, "원문 그대로" 배지 표시 필수
  (REQ-032와 일치).
- "한눈에" 5단계 카드의 모든 수치는 큐 데이터에서 파생해야 한다 —
  하드코딩 문장이 시트와 어긋나면 안 됨.
- 항목(불릿·칩) 수는 곡마다 가변 — **고정 개수 그리드 금지**, wrap
  레이아웃으로 구현.

## 6. Q### 배지 — 실행기 번호 규칙 (§4.3, §4.5, REQ-083)

기존 배선 그대로: **실행기 번호 = Page children 의 index + 100**
(메모리 `project-songcue-on-console-0913.md`에 기록된 실측 규칙).
새로 지어내지 말 것 — 타임라인 Q줄·CUE SHEET·PLAN CUE 카드 3곳
모두 같은 규칙으로 같은 값을 표시해야 한다(AC-019).

## 7. 구현 순서 (`src/DESIGN.md` §6, 원문 인용)

1. 토큰 추가(§2 신규)
2. 트래킹 해석 유틸(§3)
3. CUE SHEET 14열 + 색 레일
4. 타임라인 색/점줄/플레이헤드
5. 스크롤 연동(§4.7 — 본 문서 §1)
6. PLAN CUE 수정요청 생성기(§4.5, REQ-087~095 — 로컬 그룹 편집기가 아니다.
   코파일럿에게 보낼 수정요청 문구를 만들어 주는 생성기다)
7. 프리셋 풀 팝업을 메인 화면 컴포넌트로 교체
8. 컨셉 패널(§4.2)
9. 상태줄 GATE(§4.6)

이 순서는 의존성 순이 아니라 **위험도 순**(감독 원문 표현) — 1~3이
CUE SHEET의 근간을 흔드는 변경이라 먼저, 8~9는 국소적이라 나중.
milestone 분할 시 이 순서를 그대로 M-시퀀스에 매핑하는 것이
합리적이나, 최종 매핑은 `manager-develop` 배차 시 결정한다.

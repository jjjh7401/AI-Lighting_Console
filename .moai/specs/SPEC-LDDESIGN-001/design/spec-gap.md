## 1. REQ-078 — "전면 교체·별도 화면 없음" 전제 재검토 [정정]

- **대상 파일**: spec.md §3.14
- **대상 REQ**: REQ-LDDESIGN-078
- **현재 문장 요지**: "기존 앱 레이아웃은 SHALL 유지된다 — 전면
  교체·별도 화면을 만들지 않는다."
- **바뀌어야 할 내용**: `src/DESIGN.md` §0이 확정한 전제 —
  "이 페이지는 코파일럿 메인 화면이 아니라 런북 모드(Runbook Mode)
  페이지다. 메인 화면은 이미 구현돼 있고, 런북 모드는 그 위에 얹히는
  별도 모드다." REQ-078을 "5블록 레이아웃 순서·구성은 유지되나, 이
  페이지 자체는 메인 화면과 별개인 런북 모드다(새 최상위 내비게이션
  항목이 아니라 기존 앱 안의 모드 전환)"로 재기술해야 한다. 정정하지
  않으면 REQ-078과 실제 착지 컴포넌트(`RunbookMode.tsx`)가 문면상
  모순된다.
- **근거**: `src/DESIGN.md` §0, §0의 "메인 화면과 공유하는 것" 절
- **분류**: 정정. `RunbookMode.tsx`는 t-e부터 이미 존재하는 모드
  전환 구조이므로 작업량이 늘지 않는다 — 문서만 실제와 안 맞았다.

## 2. REQ-082 — CUE SHEET 열 구성 전면 재대조 [정정 — 해결됨 2026-09-22 · REQ-082/096]

- **대상 파일**: spec.md §3.14
- **대상 REQ**: REQ-LDDESIGN-082
- **현재 문장 요지**: "기존 12열에 정확히 2열을 추가한다 —
  `Trigger`, `Track 예외`."
- **실측**: `CueSheetTimeline.tsx`(`scratchpad/wt-main`, 714줄)의
  `SHEET_COLUMNS`는 이미 **14열**이다: `Q# / Section / TC In /
  TC Out / Dur / Mood / Color(주/보조) / Intensity / Fixture Group /
  Movement / Effect / Trans / Fade / Note`. "기존 12열"이라는 전제
  자체가 틀렸다.
- **`src/DESIGN.md` 14열**: `Q# / 구간 / 회차 / Trigger / 시각 / 색 /
  밝기 / 기구 그룹 / 움직임 / 효과 / Fade / MIB / Track 예외 /
  근거 등급`. 기존 14열과 개념 대조하면 — 겹침 9개(Q#·구간·
  시각≈TC In·색·밝기·기구그룹·움직임·효과·Fade), **기존에만 있던 것
  5개**(TC Out·**Dur**·Mood·Trans·Note — 제거 후보), **신규 5개**
  (회차·Trigger·MIB·Track 예외·근거 등급 — 추가). 9+5=14(겹침+신규)이고,
  걷어낼 후보 쪽도 5개다 — "Dur"를 빼먹고 4개로 적었던 이전 버전은
  산수 오류였다(2026-09-22 정정).
- **[2026-09-22 최종 해결]** spec.md REQ-LDDESIGN-082가 재확정됐다 —
  CUE SHEET는 **정확히 14열**이다: 기존 9열(겹침 개념) 유지 + 신규
  5열(회차·Trigger·MIB·Track 예외·근거 등급) 추가 + 기존에만 있던
  5열(TC Out·Dur·Mood·Trans·Note) **전부 제거**. 이 사이에 있던
  중간 상태("결정 전까지 5열 전부 유지, 최대 19열 과도 상태 허용")는
  이 최종 결정으로 대체됐다 — 더 이상 유효하지 않다. `Trans` 값의
  데이터 모델 존속은 REQ-LDDESIGN-096이 별도로 지킨다(열은 사라져도
  `cue_sheet_edit.py`의 `TRANS_VALUES`·`EDITABLE_FIELD_LABELS`에서는
  계속 유효하다 — 화면 노출 여부는 M7 착수 시 확인). AC-LDDESIGN-019도
  14열 확정에 맞춰 재기술됐다(§5 참조).
- **바뀌어야 할 내용(원안, 2026-09-22 이전 — 참고용으로 보존)**: REQ-082를
  "기존 CUE SHEET(14열: 위 목록)를 다음 14열로 재구성한다 — [DESIGN.md
  14열 목록]. TC Out·Mood·Trans·Note 4열은 제거하고, 회차·Trigger·MIB·
  Track 예외·근거 등급 5열을 추가한다"로 다시 쓴다. AC-LDDESIGN-019의
  "12→14, 정확히 2열 추가" 검증 문장도 같이 고쳐야 한다(§4 참조).
- **근거**: `src/DESIGN.md` §4.4, 실측 `CueSheetTimeline.tsx:225-239`,
  감독 결정 2026-09-22(REQ-LDDESIGN-082/096)
- **분류**: 정정(열 개수 전제) + 범위 확대(제거 여부) — **둘 다
  해결됨**. 감독이 5열 전부 제거로 확정했다.

## 3. REQ-083 — PLAN CUE 카드 "하단 3줄" → 수정요청 생성기 [범위 확대 — 해결됨, 편집기가 아니다]

- **[2026-09-22 해결됨]** 감독 결정으로 이 확대분이 채택됐다 — M7 안에서
  받되(별도 SPEC 분리 아님), 이름은 **"그룹 편집기"가 아니다** — "PLAN
  CUE 수정요청 생성기"로 아키텍처가 확정됐다: 제안된 큐 카드에서 바꿀

  **생성기**이지, 큐시트를 로컬에서 직접 변형하는 **편집기가 아니다**
  (변형·판정 로직은 여전히 서버 `apply_cue_sheet_edit`가 단일 진실
  지점). REQ-LDDESIGN-087~095(spec.md §3.15)로 요구사항화됐다. REQ-083
  본문(하단 3줄 + `Q###` 배지)은 그대로 유지되고, 아래 원안이 요구한
  "2단 조작면 재정의"는 그룹 다중 선택 편집이 아니라 수정요청
  생성기의 UI로 구현된다.
- **대상 파일**: spec.md §3.14, §3.15(REQ-087~095)
- **대상 REQ**: REQ-LDDESIGN-083, REQ-LDDESIGN-087~095

  `MIB/남김`, 헤드룸 요약)과 `Q###` 배지를 추가로 갖는다."
- **바뀌어야 할 내용(원안, 참고용으로 보존)**: `src/DESIGN.md` §4.5는
  카드를 "읽기 전용이 아니라 조작면"으로 재정의한다 — 좌측(그룹 다중
  선택 칩·밝기/색 스테퍼·페이드/팬 폭·Fade/Track 4택·MIB/남김 4택·
  변경 스택 diff + 코파일럿 반영 요청/**선택 취소**)과 우측 452px
  (콘솔 반영 값 패널 — 풀 1/2/4/21 프리셋 참조 행 + 프리셋 풀 팝업
  연동)의 2단 구성. 하단 3줄이 사라지는 게 아니라 그 정보가 좌측
  조작면 안으로 흡수되고, 그 위에 수정요청 생성 기능 전체가 얹힌다.
  (변경 스택의 취소 버튼은 **"선택 취소"**이며, 기존
  `CueSheetTimeline.tsx:612`의 `↶ 되돌리기` 버튼과는 다른 별개
  컨트롤이다 — REQ-095가 이 라벨 구분을 명시한다.)
- **근거**: `src/DESIGN.md` §4.5 전체, spec.md §3.15(REQ-087~095),
  2026-09-22 감독 결정
- **분류**: 범위 확대 — 해결됨(M7 안에서 채택. 아키텍처는 편집기가 아니다 — 생성기로 확정됐다).
  AC-LDDESIGN-020 범위에도 영향 없음(해당 AC는
  스크롤/색/GATE만 검증) — 새 AC(AC-021~044)가 생성기 흐름(선택·요청·

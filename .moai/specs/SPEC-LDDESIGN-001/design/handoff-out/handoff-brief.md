# Claude Design 핸드오프 브리프 — SPEC-LDDESIGN-001 M7 (UI)

이 문서는 Claude Design(claude.ai/design)에 그대로 붙여 넣는 브리프다. SPEC을
읽지 않은 사람이 이 문서 하나만으로 무엇을 만드는지 알 수 있게 쓴다.

## 1. 무엇을 만드는가

**GrandMA3 Copilot** — grandMA3 조명 콘솔 옆에서 쓰는 데스크톱 앱(Tauri 셸,
React + 순수 CSS). 콘서트 조명 감독이 곡 하나를 골라 워크시트를 채우면, 이
앱이 그 곡의 전체 큐시트(조명 명령 시퀀스)를 자동으로 조립해 화면에 보여
준다. 감독은 이 화면을 보고 "이 구간 더 밝게", "빌드업 2마디로" 같은 말로
수정을 요청하고, 승인되면 실제 grandMA3 콘솔에 큐가 반영된다.

이번 작업(M7)은 **새 화면이 아니다.** 기존 5블록 레이아웃은 그대로 두고,
그 위에 신규 컨셉 패널 1개와 각 블록에 국소적인 추가 요소만 얹는다.

## 2. 누가 쓰는가

- **1차 사용자**: 콘서트 조명 감독. 개발자가 아니다. grandMA3 콘솔 운용에는
  능숙하지만 코드나 데이터 구조는 모른다.
- **사용 환경**: 어두운 공연장/리허설장, 콘솔 옆에 놓인 노트북. 화면을
  오래 들여다보는 게 아니라 곁눈질로 확인한다 — 그래서 색만으로 상태를
  구분하면 안 되고, 넓은 데스크톱 화면을 전제로 설계한다(반응형 모바일
  대상 아님).
- **감독은 한국어로 일한다.** 라벨은 한글이 기본이고, 영어 용어(Master
  Concept 등)는 작게 보조로만 병기한다.

## 3. 오늘 화면(기존, 유지) — 5블록

```
1. 오늘의 곡 · 큐 순서
2. 타임라인 + 에너지선 + Q줄
3. CUE SHEET (12열)
4. PLAN CUE 카드
5. 상태줄
```

이 순서, 이 블록 구성은 절대 바뀌지 않는다. 컨셉 패널은 블록 1과 2 사이에
새로 끼워 넣는다. 나머지는 각 블록 내부에 열/줄/배지를 추가하는 것뿐이다.

**이미 만들어진 상호작용 시안**이 있다 — `reports/final-verification-
20260921.html`을 브라우저로 열어 보면 컨셉 패널 접기/펼치기, 6칸 문법표,
가로↔세로 스크롤 연동, Q### 배지, 상태줄 GATE 배지가 정확히 어떻게
움직여야 하는지 동작으로 확인할 수 있다. 이 HTML은 임시 데모 색상(암막
톤 배경)을 쓰지만 실제 앱의 다크 테마 토큰과는 다르다 — **색상 값은 이
브리프의 §6 토큰 표를 따르고, 상호작용 동작만 이 데모를 참고하라.**

## 4. 디자인 제약 (감독이 이미 확정함 — 재협상 대상 아님)

1. 기존 5블록 레이아웃 유지. 전면 재설계·새 화면·새 내비게이션 없음.
2. 신규 컨셉 패널: 기본 접힘. 한글 라벨 3개 — "이 곡의 연출 / 이 곡의
   재료 / 지키는 것·하지 않는 것·아껴 두는 것". 각 항목을 클릭하면
   설명 4칸(무슨 뜻 / 무대에서 / 왜 이렇게 제안했나 / 바꾸려면)이 펼쳐진다.
3. 연출 설명 = 인과 불릿(워크시트 `concept` 필드 원문, 절대 요약·재작성
   하지 않는다) + 6칸 문법 요약 표(구간 → 색 → 기구·밝기 → 움직임 → 효과
   → 그래서 보이는 것).
4. 타임라인 블록 색은 Color Strip에서 직접 가져온다. 원샷·Mark 지점은
   타임라인 위에 점 줄(dot row)로 겹쳐 표시한다.
5. CUE SHEET는 기존 12열에 정확히 2열만 추가한다 — `Trigger`,
   `Track 예외`(트래킹 값이 기본값 `Track`이 아닐 때만 채움, 그 외 빈 칸).
6. PLAN CUE 카드는 하단에 3줄(Fade/Track · MIB/남김 · 헤드룸 요약)과
   `Q###` 배지를 추가한다. 같은 큐의 Q 번호는 타임라인 Q줄·CUE SHEET·
   PLAN CUE 카드 세 곳에서 반드시 동일해야 한다(예: 세 곳 모두 `Q014`).
7. 타임라인 가로 스크롤과 CUE SHEET 세로 스크롤은 서로 연동한다 — 한쪽을
   스크롤하면 다른 쪽이 같은 큐 위치로 따라 움직인다.
8. **한글이 주 언어다.** 영어 용어는 보조 표기로만, 작게. **비유 표현
   금지 — 실제 값으로 채운다**(예: "따뜻한 색"이 아니라 "노랑
   `#FFBE5A`", "밝게"가 아니라 "75%", "무빙 조명"이 아니라 "MOVER-U
   8대").
9. **접근성**: 어두운 방에서 곁눈질로 본다. 상태를 색으로만 표현하지
   않는다 — 모든 상태 표시는 도형이나 텍스트를 함께 갖는다(예:
   PASS/WARN/FAIL을 색 + 아이콘 + 글자로). 다크 테마 유지, 라이트 테마
   제안 금지.

## 7. 하지 말아야 할 것 (요약 — 전체 목록은 `design/constraints.md`)

- React + 순수 CSS 외 프레임워크·컴포넌트 라이브러리 추가 금지(Tailwind
  없음, shadcn 없음).
- 새 화면, 새 내비게이션, 전면 재설계 금지.
- 라이트 테마 제안 금지.
- 비유적 카피("따뜻한 느낌의 조명") 금지 — 항상 실제 값.
- 색만으로 상태 구분 금지.
- 존재하지 않는 기능(객석광, Gobo/Prism, LED 영상, 방송 특화, MA2/Eos
  콘솔 전환) 을 위한 UI 금지.

## 8. 산출물에서 기대하는 것

- 컨셉 패널의 접힘/펼침/4칸 설명 3가지 상태를 각각 화면으로.
- 타임라인 위 Color Strip 색 블록 + 원샷/Mark 점 줄.
- CUE SHEET 14열(기존 12 + Trigger + Track 예외) 헤더와 데이터 행 예시.
- PLAN CUE 카드 하단 3줄 + Q### 배지가 있는 카드 1장.
- 상태줄 GATE 배지(통과/경고 혼합 상태 예시 포함).
- 전체가 §6 다크 토큰으로 렌더된 하나의 합성 화면(위 5블록이 한 화면에
  이어진 모습).

감독 확인 필요: 컨셉 패널 접힘 상태에서 3개 항목 라벨 중 하나라도
줄바꿈이 필요할 만큼 길어질 경우(좁은 창 폭에서) 줄바꿈 허용 여부는
디자인 산출물을 보고 감독이 결정한다 — 이 브리프에서는 결정하지 않는다.

# SPEC-COPILOT-UNREQ-001 — 수용 기준

모든 기준은 **기계로 확인 가능**하거나, 불가하면 그 사실을 명시한다.
인용 수치에는 출처 트리·커밋을 붙인다. 콘솔 발사로 확인하는 기준은 하나도 없다.

## M1 — 측정 (게이트)

### AC-UNREQ-001 — 세 수치가 A·B 와 같은 표에 놓인다
측정 하네스 실행 출력이 다음을 모두 담는다: 걸리는 시나리오 수(n/21) · 걸리는 명령줄 수 ·
전량 스위트 파괴 수와 **그 분모**.
- **확인**: 출력에 세 값과 분모가 있다.
- **경계**: 분모가 빠진 출력은 불합격 — spec.md A.2 가 이 실수를 명시적으로 겨눈다.

### AC-UNREQ-002 — 대조군이 발사된다
같은 실행에서 **번호가 명시된 시나리오**가 「요청되지 않음」에 들어가지 않는다.
- **확인**: 출력에 대조군 행이 있고 「요청됨」으로 분류된다.
- **비공허성**: 대조군이 하나도 없으면 「0건 검출」은 증거가 아니다.
  하네스가 아무것도 못 잡는 상태와 구별되지 않는다.

### AC-UNREQ-003 — 날조 대조군이 안 걸린다
지시와 명령이 명백히 일치하는 인공 시나리오 1건을 넣고, 그것이 「요청되지 않음」에
**안 들어감**을 보인다.
- **확인**: 출력에 그 행이 「요청됨」으로 있다.

### AC-UNREQ-004 — 「판정 불가」가 따로 세어진다
「번호 미지정 위임」(예: 「포지션 프리셋 만들어줘」)이 「요청되지 않음」과 **다른 칸**에 세어진다.
- **확인**: 출력에 세 부류의 개수가 각각 있다.
- **경계**: 둘을 합친 하나의 숫자만 내면 불합격. spec.md G.1 이 이 SPEC 의 중심 위험으로
  지목한 것이 정확히 이 구별이다.

### AC-UNREQ-005 — 중단 조건이 판정된다
중단 조건은 **둘**이고 하나라도 걸리면 M1 은 **불통과**로 기록되며 M2·M3 은 착수되지 않는다(spec.md D.5).
- **조건 ①** 판정 불가 ≥ 요청되지 않음
- **조건 ②** 판정 불가가 대표 과업 유형(`corpus.task_type`, 10종) 중 1종 이상을 통째로 덮음
- **확인**: 결과 문서에 통과/불통과 판정이 명시된다.
- **주의**: 이 AC 는 「불통과가 나오면 안 된다」가 아니다. **불통과가 정직하게 기록되면
  합격**이다. M1 은 C 를 정당화하는 측정이 아니라 C 를 죽일 수 있는 측정이다(spec.md G.2).

## M2 — 범위 확정

### AC-UNREQ-006 — 결정 근거가 수치를 인용한다
결정 문서가 M1 산출 수치를 인용하고 출처 트리·커밋을 명기한다.
- **확인**: 문서에 수치 + 트리 + 커밋이 있다.
- **경계**: 「측정 결과 C 가 낫다」처럼 수치 없는 서술은 불합격.

## M3 — 구현 (M1 통과 시에만)

### AC-UNREQ-007 — 게이트가 안 바뀐다
`server/safety/` 아래 파일이 M3 커밋에 없다.
- **확인**: `git show --stat` 에 `server/safety/` 경로 0건.
- **예외**: M4 의 `blacklist.yaml` 변경은 별도 커밋이므로 이 기준과 무관하다.

### AC-UNREQ-008 — 새 UI 를 안 만든다
질문 카드가 기존 경로를 재사용한다.
- **확인**: 신설된 카드 타입·렌더러 0건. 기존 질문 카드 호출 지점을 재사용한 diff.

### AC-UNREQ-009 — 요청된 쓰기는 그대로 나간다
M1 이 「요청됨」으로 분류한 시나리오가 구현 후에도 질문 카드 없이 통과한다.
- **확인**: 전량 스위트에서 해당 경로 테스트가 초록.
- **경계**: 이것이 갈래 B 와의 차별점이다. 여기가 깨지면 C 는 B 를 경로만 바꿔 재현한 것이다.

## M4 — 게이트 v3→v4

### AC-UNREQ-010 — 버전과 항목
`blacklist.yaml` 이 `version: 4` 이고 `blacklist` 에 `Store Preset` 이 있다.
- **확인**: `grep` 로 두 값.

### AC-UNREQ-011 — 개정 이력이 절차를 따른다
헤더에 위양성 관측 근거(LXSEQ-003 M4) · 비용 실측(13건/10183) · 범위 명시가 있다.
- **확인**: 헤더 본문 판독.

### AC-UNREQ-012 — 잔여 비준이 보존된다
`UNCHANGED_SAFE` 에서 `Store Preset 4.1` 만 빠지고, 남은 `Store Group 3` 등이 여전히
비준 대상임이 주석으로 남는다.
- **확인**: 튜플에 나머지 항목이 그대로 있고, 주석에 그 취지가 있다.
- **경계**: 한 줄만 지우고 주석을 안 남기면 불합격 — 다음 개정자가 「Store 계열은 이제
  자유롭게 넣어도 된다」로 오독한다.

### AC-UNREQ-013 — 분모 경고가 헤더에 남는다
항목 1개당 테스트 4건이 늘어난다는 사실이 헤더에 적힌다.
- **확인**: 헤더에 해당 문장.
- **근거**: t86 실측 — 기준선 10179, 1항목 10183, 2항목 10187.

### AC-UNREQ-014 — 13건이 전부 갱신된다
`Store Preset` 추가 후 전량 스위트가 초록.
- **확인**: `uv run pytest -q` 실패 0.
- **주의**: 기준선을 먼저 잡고 비교한다. 갱신 전 13건 / 갱신 후 0건, 둘 다 기록한다.

## 공통

### AC-UNREQ-015 — 콘솔 발사 0건
이 SPEC 의 어떤 마일스톤도 MA3 에 명령을 보내지 않는다.
- **확인**: 커밋 diff 와 실행 로그에 콘솔 전송 경로 사용 0건.
- **근거**: 이 SPEC 을 낳은 사고가 승인 없는 콘솔 쓰기였다. 그것을 조사하며 같은 일을
  하면 안 된다.

### AC-UNREQ-016 — 변형 복원이 체크섬으로 확인된다
블랙리스트를 변형해 재는 모든 작업이 백업+`shasum` 대조로 복원됨을 기록한다.
- **확인**: 결과 문서에 복원 전후 체크섬.
- **경계**: `git checkout` 사용 흔적이 있으면 불합격 — 미커밋분을 날린다.

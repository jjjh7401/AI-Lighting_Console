# SPEC-COPILOT-UNREQ-001 — 실행 계획

## 0. 이 계획의 형태 — 첫 마일스톤이 게이트다

보통의 M1→M4 순차 진행이 아니다. **M1 은 통과·불통과를 가르는 게이트**이고,
M1 이 불통과면 M2·M3 은 착수하지 않는다(spec.md C.4 · REQ-UNREQ-006).
M4 는 M1 과 독립이므로 병행 가능하다.

```
M1 (측정·게이트) ──통과──> M2 (범위 확정) ──> M3 (구현)
       └────불통과────> 중단, 대안 재검토
M4 (게이트 v3→v4) ── M1 과 독립, 병행 가능
```

## 1. 마일스톤

### M1 — C 의 비용을 A·B 와 같은 단위로 잰다 [게이트]

| 항목 | 내용 |
|---|---|
| 산출물 | `server/tests/` 하위 측정 하네스 1종 + `.moai/reports/` 결과 |
| 요구 | REQ-UNREQ-001 ~ 004 |
| 선행 | 없음 |
| 판정 | spec.md F.1 ~ F.3 |

작업 순서:

1. 코퍼스 21 시나리오의 `instruction` 에서 **명명된 대상**을 뽑는 추출기를 만든다.
   기존 정규식(`_CUE_PRESET_REF` 등)을 먼저 뒤지고, 없는 것만 새로 쓴다.
2. `mock.commands` 의 **쓰기 대상**을 뽑는다. `Store`/`Label`/`Assign`/`Copy` 의 대상 토큰.
3. 대조하여 세 부류로 가른다: **요청됨** / **요청되지 않음** / **판정 불가**(번호 미지정 위임).
4. 날조 대조군을 같은 실행에 넣는다 — 번호가 명시된 시나리오가 「요청되지 않음」에 안 들어가야
   한다. 안 들어감을 출력으로 보인다.
5. 세 수치를 A·B 표와 같은 형식으로 낸다(분모 포함).

주의: 이 단계는 **판정만** 한다. 세션 코드를 고치지 않는다.

## 2. 측정 규율 (모든 마일스톤 공통)

- 블랙리스트를 변형해 재는 작업은 **백업 + `shasum` 대조**로 복원한다. `git checkout` 금지
  (미커밋분이 날아간다).
- 기준선을 먼저 잡고 비교한다. 기준선 없는 실패 수는 귀속 불가다.
- 실패 수를 적을 때 **분모를 함께** 적는다(spec.md A.2 — 항목 1개당 테스트 4건이 늘어난다).
- 인용 수치에는 출처 트리·커밋을 붙인다.
- **콘솔 발사 금지.** 판정은 검사 층에서 낸다.

## 3. 이 계획이 안 하는 것

- `Label` 계열 · `Store` 동사 전체 · `Assign`/`Copy` 전량 측정 · 축약 구멍(t91) ·
  MA3 실기 확인.

## 4. 미해결 — plan 단계에서 못 정한 것

1. **M1 하네스를 어디에 둘 것인가.** `server/tests/` 안이면 CI 가 매번 돌리고,
   `.moai/reports/` 스크립트면 안 돈다. 전자가 회귀 방어에 낫지만 코퍼스 변경 때마다
   깨질 수 있다. run 단계 첫 판단.
2. **「명명된 대상」 추출을 어디까지 할 것인가.** 번호만인지, 「그 프리셋」 같은 지시어까지인지.
   M1 의 「판정 불가」 정의가 여기 달렸다.
3. **M4 를 이 SPEC 에 두는 것이 맞는가.** M1 과 독립이라 별도 카드로 떼도 된다.
   묶어 둔 이유는 근거 수치가 같은 실측에서 나왔기 때문 — 떼면 근거가 문서 밖을 가리킨다.

## §A. 접근 요약

### §A.1 이 SPEC의 한 줄

**막히는 16건을 세 값으로 처분하고, 그 배정을 실측에 귀속시킨다. 측정이 없으면 배정도
없다 — 다만 미측정은 부재가 아니라 분기다.**

### §A.2 되돌리기 어려운 결정 우선순위 (리뷰 순서 — 빌드 순서 아님)

1. **처분 3값 축 자체** — 카드가 고정한 것이며 이 SPEC이 바꾸지 않는다. 다만 §A.3의
   **측정 종류 열**(읽기/쓰기/무관)이 없으면 ②가 두 종류를 뭉갠다. 이 열이 뒤집히면
   4-b·7-b의 배정 근거가 무너진다.
2. **승계 3건을 재측정하지 않는 결정**(§spec A.1) — 뒤집히면 M0 범위가 두 배가 되고,
   그룹 쓰기 프로브가 필요해져 비파괴 전제가 깨진다.
3. **양성 대조군 도입**(§B M0-3) — 날조 대조군만으로는 "전부 `ok:false`"를 판정으로
   쓸 수 없다. 이것이 없으면 M0의 NEGATIVE 판정 전체가 귀속 불가다.
4. **조준을 도구 표에 넣지 않는 결정**(REQ-B16-005 R) — 국소. 뒤집혀도 표기만 바뀐다.
5. 처분표 서식 — 기계적. 마지막.

### §A.3 빌드 순서가 다른 이유

리뷰는 처분 축부터 보지만, 빌드는 **프로브부터** 한다. 측정 없이 처분을 쓰면 이 SPEC이
지적한 결함(미측정을 부재로 읽음)을 그대로 재생산한다. M0가 끝나기 전에는 페이드·큐 내용·
팬틸트 3건의 처분 칸을 채우지 않는다.

**단, M2(조준 노출)는 M0과 병렬이다.** 측정 의존이 없기 때문이며, 이것이 카드 지시 4가
가리킨 성질이다.

### §A.4 M0 게이트 — 축별 분기 (모두 유효한 출력)

## §B. 마일스톤

### M0 — 비파괴 라이브 읽기 프로브 (문서 변경 0, 쇼파일 변경 0)

산출: `.moai/specs/SPEC-COPILOT-BLOCKED16-001/probe.md`

**M0-1. 프로브 매체 고정 [HARD]**

`server/tools/responder_roundtrip.py`의 opt-in `prop` 단계를 쓴다. `--skip-exec`가
명령을 실행하는 유일한 단계를 제거하므로 이 형태는 읽기 전용이다.

```bash
uv run python -m server.tools.responder_roundtrip --skip-exec \
    --host 127.0.0.1 --port 8000 --listen-port 9005 \
    --prop-path "<핸들 경로>" --prop-name "<속성명>" --wait 5
```

`--listen-port`는 현장 실측값 9005다(저장소 교훈 `project_copilot_deploy_m7_complete`).
`exec` 동사는 M0 전체에서 금지한다(REQ-B16-003).

**M0-2. 프로브 매트릭스 — 핸들 축을 먼저 나눈다**

한 핸들에서 후보가 소진된 것을 "읽을 수 없다"로 일반화한 선례가 있으므로(교훈
`no-readable-current-cue-property`), 각 게이트는 **핸들을 바꿔 가며** 쏜다.

| 게이트 | 핸들 축 | 후보 속성명 |
|---|---|---|
| A 페이드 Part 주소화 | ① `DataPool/Sequences/<n>` children(`state`) → **실물 큐 이름** 획득 ② `DataPool/Sequences/<n>/<cueName>` children → **part 이름** 획득 ③ `DataPool/Sequences/<n>/<cueName>/<partName>` | `CueInFade` (기지) · `CueOutFade` |
| B 큐 내용 | ① `DataPool/Sequences/<S>` ② `DataPool/Sequences/<S>/Cue <C>` ③ ②의 children(`state`) | `TrigType` · `Content` · `Values` · `Parts` · `Name` |
| C 팬/틸트 | `Patch/Stages/1/Fixtures/<slot>` | `pan` · `tilt` · `Pan` · `Tilt` |

**주소는 번호가 아니라 이름이다 [HARD]** — 실측 형식은
`prop:DataPool/Sequences/<n>/<cueName>/<partName>|CueInFade`이며 **part 이름은 큐 이름과
같다**(`.claude/skills/ma3-spatial-pointing/SKILL.md:167-169`, 실측 `5.0`).

**큐 이름의 점(.)은 MA3가 삼킨다** — `'Pos 2.28'`로 저장하면 실제 이름은 `Pos 228`이 된다
(`.claude/skills/ma3-spatial-pointing/SKILL.md:163-165`). 이름으로 오브젝트를 되찾을 때
**점 없는 이름**을 써야 한다.

v0.3.0의 게이트 A는 `Cue <C>` / `Part <P>` **번호 형식**을 썼다. 그 형식은 저장소 어디에도
실측 기록이 없고, 양성 대조군(기지 GO 기준점)을 미실측 형식으로 쏘면 **`ok:false`가
돌아와 배치 전체가 무효**가 된다 — plan §B M0-3의 자기 규정("`ok:false` 일색을 판정으로
쓸 수 없다")이 발동한다. **틀린 판정보다 나쁘다: 판정이 없는데 있었다고 믿게 된다.**
감사 2회차 P0-1r.

**게이트 A가 지금 묻는 것**: 이 이름 기반 형식이 **타 SPEC이 만든 큐**와 **다중 Part 큐**로
일반화되는가. 형식 자체는 미측정이 아니다 — CUETIME이 만든 큐 1건에서 실측됐다.

**세 축 모두 단일 핸들에 머물지 않는다** — 교훈 `no-readable-current-cue-property`
(한 핸들 소진을 "읽을 수 없다"로 일반화했고 정답은 핸들을 바꾸는 것이었다)는 게이트 B만이
아니라 A·C에도 적용된다. 초판이 B에만 적용한 것이 P0-1의 뿌리다.

`<n>`·`<cueName>`·`<partName>`·`<slot>`은 **하드코딩하지 않는다.** M0 착수 시 `state`로
실재하는 시퀀스·큐·픽스처를 먼저 열거해 **실물 이름**(게이트 A) 또는 **실물 번호**
(게이트 B·C)를 얻고, 그것을 원장에 적는다. 게이트 A의 열쇠는 번호가 아니라 **이름**이다. 존재하지 않는 객체에
쏜 `ok:false`는 "속성이 없다"가 아니라 "객체가 없다"이며, 둘을 섞으면 판정이 거짓이 된다.

**M0-3. 대조군 2종 [HARD] — 음성만으로는 부족하다**

| 대조군 | 형태 | 기대 | 없으면 무엇이 무너지는가 |
|---|---|---|---|
| **음성**(날조) | 실재 핸들 + 날조 속성명(`CueFadeee` 등) | `ok:false` | `ok:true`가 무의미해진다 — SCENE-001 `/CueOnlyy` 선례 |
| **양성**(기지) | A: `DataPool/Sequences/101/Pos 228/Pos 228` + `CueInFade`(CUETIME 실측 `5.0`. **점 없는 이름** — `Pos 2.28`이 아니다) / B: `DataPool/Sequences/<S>` + `CurrentCue` / C: 같은 슬롯 + `posx` | `ok:true` + 값 | **`ok:false` 일색을 판정으로 쓸 수 없다** — 프로브 장치 자체가 죽었을 가능성을 배제하지 못한다 |

양성 대조군은 GROUPGEN 게이트 A 설계에 없던 항이며, 이 SPEC이 더한다. 그쪽은 `COUNT`가
`ok:true`를 답해 장치 생존이 우연히 확인됐지만, 전 후보가 `ok:false`인 배치에서는 그 우연이
없다. **음성 대조군은 거짓 GO를 막고, 양성 대조군은 거짓 NEGATIVE를 막는다.**

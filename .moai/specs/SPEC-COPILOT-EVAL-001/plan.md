# SPEC-COPILOT-EVAL-001 — 구현 계획 (plan)

> 평가/리서치 SPEC. 산출물은 문서이며 프로덕션 코드는 생성하지 않는다.

## A. 핵심 결정 사항 (변경 가능성 높은 순 — 먼저 검토)

1. **평가 대상 grandMA3 onPC 버전 핀** — DESIGN.md는 "v2.x 고정"만 명시. 평가 환경 기록(REQ-EVAL-001)과 Phase 1 룰북 버전 분리에 직결되므로 세부 버전 확정 필요.
   - ✅ **결정됨 (2026-07-15)**: 평가 시작 시점의 **최신 안정 v2.x 릴리스**로 핀한다. 정확한 버전 번호는 환경 기록(REQ-EVAL-001 산출물)에 기록하며, MVP(SPEC-COPILOT-MVP-001)가 이 버전을 승계한다. 근거: 최신 안정판이 실사용 환경 대표성과 Phase 1 승계 가치가 가장 높음.
2. **평가 API 비용 예산 상한** — 시나리오 8종 이상 × 실제 Claude API 호출(REQ-EVAL-003). 폭주 방지를 위한 상한 필요.
   - ✅ **결정됨 (2026-07-15)**: 예산 상한 **$20** (전체). 상한 도달 시 평가를 중단하고 중간 결과를 보고한다. 시나리오당 반복 실행은 예산 내 우선순위 기반으로 조정한다. 근거: Phase 0 검증 목적에 충분한 규모이면서 자가 수정 루프 폭주 위험을 차단.
   - ✅ **갱신 (2026-07-15, LLM 프로바이더 amendment)**: boardop의 Claude/Gemini 듀얼 지원을 활용해 **Gemini 무료 등급 사용을 우선**한다. $20 상한은 **양 프로바이더 유료 사용분 합산**에 적용된다. 예산 여유 시 동일 시나리오의 Claude/Gemini 비교 실행(REQ-EVAL-013, 선택)이 허용된다.
3. **시나리오 세트 구성 원칙** — 8종은 Phase 1 성공 기준인 "대표 프로그래밍 작업 10종"(그룹 생성, 프리셋 저장, 큐 스토어, 시퀀스→executor 할당, 페이지 셋업, 매크로 생성, 이펙트 적용, 페이더 제어, 상태 조회, Lua 플러그인 배포)에서 도출한다. 이렇게 하면 Phase 0 평가 결과가 Phase 1 수용 기준과 1:1로 비교 가능하다. (결정됨 — 마커 불필요)

## C. 기술 접근

- 평가 기록은 격차 분석 문서와 같은 디렉터리(`.moai/project/research/`)에 배치한다 (예: `boardop-eval-log.md` — 파일명은 run-phase에서 확정 가능).
- boardop의 아키텍처 관찰 항목: OSC 경로(`/gma3/cmd`, `/python/feedback`), Lua responder 동작 방식, 3계층 지식 레이어, blast-radius 필터의 실제 차단 범위. **관찰·서술만 허용, 코드 인용 금지.**
- 안전장치 평가 시 파괴적 명령(Delete 등)은 **일회용 테스트 쇼파일**에서만 시도한다.

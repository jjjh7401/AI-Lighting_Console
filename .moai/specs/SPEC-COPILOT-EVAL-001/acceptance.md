## Given-When-Then 시나리오

### 시나리오 1 — 환경 구동 검증
- **Given** grandMA3 onPC와 boardop이 설치되고 LLM API 키(Anthropic 또는 Google Gemini — Gemini 무료 등급 우선 권장)가 구성된 평가 머신에서
- **When** boardop을 기동하여 onPC와의 OSC 연결을 수립하면
- **Then** 연결 성공 증거(로그/캡처)가 평가 기록에 남고, 환경 기록에 onPC 버전·boardop 버전·OS·Python 버전·LLM 프로바이더·모델 ID(6종)가 모두 기재된다.

### 시나리오 2 — 대표 시나리오 실행 기록
- **Given** 시나리오 세트(≥8종, Phase 1 대표 작업 10종에서 도출)가 정의된 상태에서
- **When** 각 시나리오를 boardop을 통해 실행하면
- **Then** 시나리오마다 입력 지시문·생성 명령·결과(성공/실패)·오류 유형·API 사용량이 평가 기록에 기재된다.

### 시나리오 3 — 격차 분석 산출
- **Given** 시나리오 실행 기록이 완료된 상태에서
- **When** 격차 분석 문서를 작성하면
- **Then** `.moai/project/research/boardop-gap-analysis.md`에 4개 축(한국어 UX / 안전장치 / 도구 커버리지 / 신뢰성)이 모두 다뤄지고, 격차 항목이 10개 이상이며, 각 항목에 Phase 1 반영 여부(반영/보류/미반영)와 근거가 표기된다.

### 시나리오 4 — 안전장치 관찰 (파괴적 명령, REQ-EVAL-011)
- **Given** 일회용 테스트 쇼파일이 로드된 onPC에서
- **When** 파괴적 명령(예: Delete 계열)을 유발하는 지시를 boardop에 입력하면
- **Then** boardop 안전장치(blast-radius 필터)의 차단/통과 동작이 관찰·기록되고, 그 결과가 격차 분석의 "안전장치 수준" 축에 반영된다.

### 시나리오 5 — 라이브 접근 소진 시 폴백 전환 (REQ-EVAL-014/015, 2026-07-16 amendment; 0.3.1 트리거 이진화; 0.3.2 Then 폴백 스코핑)
- **Given** 성의있는 접근 시도 이력(일자·채널·응답/무응답 결과 — spec.md §A ground truth: 베타 신청 이메일 준비 2026-07-15, 공개 저장소 코드 부재 확인 커밋 c13c274, 플랫폼 비호환 문서 증거)이 평가 기록에 문서화된 상태에서
- **When** 오케스트레이터의 AskUserQuestion 사용자 확인 기록(2026-07-16, "문서·영상 관찰 기반으로 SPEC 재조정" 선택)으로 문서/영상 관찰 기반 평가로의 전환이 확정되면
- **Then** 접근 시도 이력(일자·채널·결과)과 전환 확정 기록(확인 일자·선택 내용)이 평가 기록에 남고, 이후 **폴백 평가 하에서** 작성되는 모든 평가 근거 행은 "실행 확인" / "관찰 기반(실행 미확인)" / "관찰 불가"로 명시 구분되며(0.3.2 스코핑 — 라이브 접근이 이후 확보되어 라이브 실행으로 작성되는 행은 REQ-EVAL-015의 While 범위 밖이고, 엣지 케이스 2의 "실행 불가" 기록이 그대로 적용된다), REQ-EVAL-010의 코드 미포함 원칙(스크린샷 코드 전사 포함)이 관찰 근거 작성 전 과정에 적용된다.

## 엣지 케이스

- boardop이 현행 onPC 버전에서 구동 실패 → 실패 원인·시도한 조치를 기록하고 "신뢰성 격차" 항목으로 편입 (구동 실패가 SPEC 실패는 아님 — 단, AC-EVAL-001의 "구동 성공"은 호환 가능한 버전 조합 확보를 전제로 하므로, 어떤 조합으로도 구동 불가 시 blocker 보고로 회귀). **단, REQ-EVAL-014 폴백 트리거(문서화된 접근 시도 이력 + 오케스트레이터 AskUserQuestion 사용자 확인 기록)가 성립하면 blocker 보고 대신 문서/영상 관찰 기반 평가로 전환해 AC-EVAL-001을 폴백 경로로 충족한다.**
- 시나리오 실행 중 API 오류(rate limit 등) → 재시도 후에도 실패하면 해당 시나리오는 "실행 불가"로 기록하되 8종 최소치는 다른 시나리오로 충족.
- 동일 시나리오에서 비결정적 결과(성공/실패 혼재) → 반복 횟수와 함께 양쪽 결과 모두 기록, 신뢰성 격차 근거로 사용.
- 베타 신청 후 끝내 응답이 없음 (접근 채널이 사실상 폐쇄) → 무기한 대기하지 않는다. 폴백 전환은 평가자 자체 판단이 아니라 REQ-EVAL-014의 이진 트리거(문서화된 접근 시도 이력 + 오케스트레이터 AskUserQuestion 사용자 확인 기록)로 확정한다. 전환 확정 기록(확인 일자·선택 내용)과 접근 시도 이력을 평가 기록에 남긴다.

## 0. 한 줄

**④는 실재한다. 다만 기록된 경계가 틀렸다** — 「옆 트리 venv 를 빌려 쓰면 다른 트리를
검증한다」는 조건 없이는 거짓이고, 정작 **초록을 만드는 경로(pytest)에서는 발화하지
않는다.** 발화하는 자리는 따로 있고, 그 자리는 **조용하다.**

## 1. ④ — 먼저 쟀다, 고치기 전에

### 1.1 정말 그러한가 — `.pth` 는 살아 있다

```
$ cat ../t48/.venv/…/_editable_impl_*.pth   → …/worktrees/t48
$ cat ../t56/.venv/…/_editable_impl_*.pth   → …/worktrees/t56
$ cat ../t52/.venv/…/_editable_impl_*.pth   → …/worktrees/t52
```

각 트리의 `.pth` 는 **자기 트리를 가리킨다.** 여기까진 t54 의 기록과 같다.

### 1.2 그런데 트리 루트에서는 **발화하지 않는다**

```
cwd = t47 (트리 루트)
$ ../t56/.venv/bin/python -c "import server; print(server.__file__)"   → t47   ← 빌린 건데 t47
$ ../t52/.venv/bin/python -c "import server; print(server.__file__)"   → t47
```

**cwd 가 `.pth` 를 가린다.** `python -c` 는 현재 디렉터리를 `sys.path` 맨 앞에 넣고,
루트에는 `server/` 가 있으므로 자기 트리가 이긴다. 같은 명령에 `-P`(cwd 미삽입)를
붙이면 `.pth` 가 이겨 t56·t52 가 나온다 — 즉 **`.pth` 는 살아 있는데 평소엔 가려져 있다.**

> t54 의 기록은 `.pth` **내용을 읽고 추론한 것**이고 빌려 쓰는 상황을 실제로 발사하지
> 않았다. 「설정을 읽고 동작을 추론했다」 — 이 보드가 반복해서 잡아 온 형태다.

### 1.3 가려지지 않는 자리에서는 발화한다 — 그리고 **조용하다**

```
cwd = t47/server (하위 디렉터리 — 여기엔 server/ 가 없다)
$ ../../t47/.venv/bin/python -c "import server; …"   → t47   ← 대조군
$ ../../t56/.venv/bin/python -c "import server; …"   → t56   ← 발화
```

**같은 디렉터리, 같은 명령, 인터프리터만 다르다.** 경고는 **한 줄도 없다.**

### 1.4 초록을 만드는 경로에서는 발화하지 않는다

```
cwd = t47/server
$ t47 pytest  tests/test_zz_which_tree.py  → server = t47
$ t56 pytest  tests/test_zz_which_tree.py  → server = t47   ← 빌렸는데도 t47
```

pytest 는 테스트 파일의 base 디렉터리를 `sys.path` 앞에 넣는다. 이 저장소의 테스트는
**전부 `server/` 안에 산다**(밖에 있는 `test_*.py` 0건, 실측) 것이 구조적 방어가 된다.
`uv run` 도 안전하다 — 프로젝트 환경을 cwd 에서 재해석하고, `VIRTUAL_ENV` 가 어긋나면
**경고하고 무시한다**(실측).

### 1.5 그러면 발화하는 실물 자리는 어디인가 — 스크립트 경로

`server/tools/` 에 `import server` 하는 스크립트가 **7개** 있다(실측). 스크립트를 경로로
실행하면 `sys.path[0]` 이 `server/tools/` 라 가리는 것이 없다.

**날조 대조군 — 처방이 없을 때 실제로 틀린 결과가 나오는가:**

```
cwd = t47 (루트!)  ·  파일 = t47/server/tools/zz_which_tree_probe.py
$ .venv/bin/python          server/tools/zz_which_tree_probe.py  → t47   ← 대조군
$ ../t56/.venv/bin/python   server/tools/zz_which_tree_probe.py  → t56   ← 틀린 결과
```

**t47 의 파일을 t47 에서 실행했는데 t56 의 코드가 돌았다.** 경고 없음.
그리고 이 자리는 장식이 아니다 — **t60 의 측정 증거가 바로 이 `server/tools/` 스크립트로
생산됐다.** 즉 「초록인데 다른 나무의 것」이 성립하는 유일한 실물 경로다.

### 1.6 얼마나 쉬운가

```
$ git worktree list | wc -l                     → 35
$ ls -d .../worktrees/*/.venv | wc -l           → 28
```

트리 35개에 venv 28개. 빌려 쓰는 일이 일어날 만한가 — **일어난다.** 다만 §1.2 때문에
대부분의 형태에서는 무해하게 지나가고, 그래서 **일어나도 안 보인다.**

## 2. 판정 — 무엇을 고치고 무엇을 안 고치는가

| | 판정 |
|---|---|
| pytest 전량 초록 | **오염 불가** — 구조적으로 막힌다. 고칠 것 없음 |
| `uv run` / Makefile / CI | **오염 불가** — 경고하고 무시하거나 cwd 로 재해석. 실측 |
| `server/tools/` 스크립트 증거 | **오염 가능·무경고** — 실물 대조군으로 재현됨 |
| 트리 루트 `python -c` | 가려져서 무해 — **다만 운이다**(`-P` 하나면 뒤집힌다) |

[HARD] **처방은 `server/` 안이 자연스럽지만 이 카드는 `server/` 를 못 건드린다**(run 레인
M3 와 겹침). 그래서 이 카드는 **경계를 문서로 고정**하고, 도구 층 가드는 M3 머지 뒤
후속 카드로 넘긴다. 설계는 §5 에 적어 둔다.

## 3. ①②③ — 다시 진단하지 않았다

리드 지시대로 재진단하지 않았다. 다만 ②③은 **오늘 이 카드에서 1인칭으로 다시 밟았으므로**
그 관측만 적는다.

**② 쓰기 경계** — 이 세션의 대조 3점:

```
Read   t47/Makefile                → 성공
Bash   heredoc → t47/... 파일 쓰기  → 성공 (이 카드 전 구간이 그렇게 들어갔다)
Write  t47/zz_write_probe.txt      → "Path traversal detected: file is outside project directory"
```

**경로가 아니라 도구가 경계다.** 세션 시작 디렉터리가 형제 체크아웃이면 워크트리에
`EnterWorktree` 로 들어와도 안 바뀐다 — 시작 디렉터리는 세션 수명 동안 고정이다.

**③ 가드 거절 형태** — 오늘도 한 번 맞았다(`cd` + heredoc + 변수 결합). 판별 형태의
전수표는 이미 `SPEC-COPILOT-SHEETPIPE-001/progress.md` §E.2.7 에 대조군 7행으로 있고
main 에 실려 있다. **중복 표를 만들지 않았다.**

**① 격리 착지** — 재현 불가(요청 시점에 결정된다). 기록만 참조한다.

## 5. 후속 카드용 설계 (구현 안 함)

`server/tools/` 스크립트가 자기 트리를 검증하는지 스스로 확인하게 하는 것:

- `server/tools/` 안에 공용 헬퍼 하나 — `server.__file__` 이 스크립트 자신의 `__file__`

- 검사의 검사: 빌린 인터프리터로 돌리면 **반드시 빨개지는** 테스트 1건. 안 빨개지면
  헬퍼가 아무것도 안 지키는 것이다(§1.5 의 대조군이 그대로 그 테스트가 된다).

  있다」만 보여 준다.

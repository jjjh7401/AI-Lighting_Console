# t82 — label-sync 액션 SHA 고정

- 카드: t82 · 브랜치 `WT-pin-label-sync` · base `ada5e7d`
- 측정일: 2026-08-25 · 저장소 `jjjh7401/AI-Lighting_Console`
- **상태: ②에서 멈춤. 머지 안 함.**

## 0. 무엇을 막는 변경인가

t81 이 남긴 위험 하나는 A(아무것도 안 한다)로 **안 닫힌다**:

> `v2` 는 움직이는 태그다. 관리자가 그것을 미릴리스 커밋으로 옮기면 **우리가 아무것도
> 안 해도** 엔진이 바뀐다.

t81 에서 거절한 그 45커밋(엔진 교체판)을 **태그 이동 한 번으로 받게 된다.** 이 카드는
그 경로를 막는다 — 「지금 도는 코드」를 이름이 아니라 **주소**로 적는 것이다.

## 1. 무엇을 고정했는가 — 어노테이티드 태그를 역참조해서 확인했다

```
v2      → object.type=commit → 5207415819 0acb45f3077f9099fea818aa43f97a  (경량 태그)
v2.3.3  → object.type=tag    → 7753e99e…  → 역참조 → 5207415…             (어노테이티드)
```

**둘이 같은 커밋이다.** 즉 이 고정은:

- **최신 릴리스(`v2.3.3`, 2024-02-13)를 고정하는 것**이고,
- **지금 도는 코드와 동일**하므로 **동작 변화가 0** 이다.

> `v2.3.3` 의 `object.sha` 를 그대로 커밋으로 읽었으면 두 태그가 다른 곳을 가리키는 것으로
> **오독했을 것**이다. 어노테이티드 태그의 `object.sha` 는 커밋이 아니라 태그 객체다 —
> 실제로 그 값으로 `compare` 를 걸었더니 **404** 가 났고, 그 404 가 계기를 고치게 했다.

## 2. [HARD] 미리보기 — t41 결과와 대조

실행 **`32784013174`**(`workflow_dispatch`, `WT-pin-label-sync`, `dry-run: true`) → `success`.

```
Label diff 그룹        비어 있음         ← t41 때는 23행이었다
[missing]/[changed]/[added] 행 수   0
```

**무동작이다.** 라벨이 이미 `labels.yml` 과 맞으므로(t41 이 실제로 동기화했다) 재실행할
것이 없다. 배차서가 말한 검산이 그대로 성립한다 — **무동작이 아니었으면 뭔가 달라진 것**이다.

계기가 멀쩡한지도 확인했다: **같은 grep·같은 로그 형식**으로 t41 실행에서는 23행이 나왔다.
0 은 계기가 안 본 0 이 아니라 **잰 0** 이다.

## 3. [HARD] 경고는 어떻게 되는가 — **그대로 남는다**

```
Node.js 20 is deprecated …   → 이번 실행 로그에도 1건
```

**이 카드는 경고를 없애지 않는다.** 없앨 수도 없다 — 고정 대상이 지금 도는 바로 그
커밋이고, 릴리스된 어떤 판도 `node20` 이기 때문이다(t81 §2). 이 카드가 하는 일은
**「경고를 없애는 것」이 아니라 「모르는 사이에 엔진이 바뀌는 것을 막는 것」**이다.

t41 이 t35 의 목적을 다 못 이뤘다고 적었듯이, 이 카드도 자기 범위를 그대로 적는다.

## 4. 대가 — 자동 갱신을 잃는다

SHA 고정의 표준적 대가는 **업스트림 보안·버그 수정이 자동으로 안 들어온다**는 것이다.
`v2` 를 쓰면 관리자가 태그를 옮길 때 자동으로 받는다.

**다만 이 저장소에서는 그 손실이 지금 이론적이다:**

```
최신 릴리스 v2.3.3 = 2024-02-13 … 오늘(2026-08-25)까지 릴리스 0건
```

**2년 반 동안 자동으로 들어올 것이 없었다.** 그리고 자동으로 들어올 수 있었던 유일한 것은
t81 이 검토 끝에 **거절한** 그 미릴리스 엔진 교체판이다. 즉 이 고정이 막는 것은
「수정을 못 받는 것」이 아니라 「검토 안 한 판을 받는 것」이다.

**갱신은 앞으로 의도적 카드로 한다** — 릴리스가 나오면 그때 t41 절차(미리보기 → 대조 →
②에서 멈춤)로 받는다.

## 5. 일관성 — 예외가 아니다

이 저장소 워크플로 전수(실측):

```
label-sync.yml:43  actions/checkout@v7                      1st-party
label-sync.yml:50  EndBug/label-sync@5207415…  # v2.3.3     ← 유일한 서드파티
test.yml:33·38·45  actions/{checkout,setup-python,setup-node}@v7   1st-party
```

`uses:` 5개 중 **서드파티는 1개**다. 그 하나만 SHA 로 고정하는 것은 예외가 아니라
**서드파티 액션 고정이라는 표준 처방을 이 저장소에 정확히 적용한 것**이고, 1st-party
액션을 태그로 두는 관행과도 충돌하지 않는다.

## 6. 판정 대기

배차서 [HARD] 대로 ②에서 멈춘다. 머지하면 `paths` 때문에 **실제 실행이 즉시 뜬다.**
미리보기가 무동작이므로 실제 실행도 무동작이어야 하고, **그 일치가 머지 후 검산**이다.

[HARD] **머지 직전에 `v2` 를 다시 해소해라.** 지금 `5207415` 이지만 움직이는 태그다.
그 사이 관리자가 옮겼다면 **고정하려던 것과 다른 것이 지금 돌고 있다**는 뜻이므로,
값이 달라졌으면 머지하지 말고 보고한다.

## 7. Gaps — 재지 않은 것

- **머지 후 실제 실행은 아직 안 봤다.** §2는 브랜치 미리보기다.
- **고정한 커밋의 코드를 전수로 읽지 않았다.** t41·t81 에서 `dry-run` 갈래와
  `delete-other-labels` 기본값만 확인했다. 「지금 도는 것과 같다」는 **동일성**의 주장이지
  **안전성**의 주장이 아니다 — 지금 도는 것이 안전한지는 이 카드가 재지 않았다.
- **강제 실행(node20 → node24) 종료 시점은 여전히 모른다**(t81 Gap 그대로). 그날이 오면
  이 고정은 **문제를 고정하는 것**이 된다 — 그때는 갱신 카드가 필요하다.
- **SHA 고정이 공급망 위험을 얼마나 줄이는지는 안 쟀다.** 태그 이동 경로 하나를 막는다는
  것만 쟀다.

## 8. 머지 후 실측 — 무동작 예측이 맞았는가

머지 직전 `v2` 재해소: `commit 5207415…` — **그대로**. 고정 대상이 유효하므로 머지했다.

머지 `9b451e1` → push 실행 **`32784764529`**(`event=push`) `success`.

| 예측 | 실제 | |
|---|---|---|
| 무동작 (diff 0행) | **0행** | ✅ |
| Node 20 경고 **여전히 1건** | **1건** | ✅ |
| 라벨 31개, 집합 불변 | 31개, 양방향 차 공집합 | ✅ |
| 고정한 SHA 가 실제로 돌았는가 | 로그에 `label-sync@52074158190acb45f3077f9099fea818aa43f97a` | ✅ |

**경고가 남는다는 예측이 맞은 것도 성공이다** — 이 카드는 경고 제거를 약속하지 않았고,
약속하지 않은 것이 안 일어난 것을 확인했다.

로그의 SHA 는 **고정이 실제로 발효됐다는 유일한 직접 증거**다. 파일에 적은 것과 러너가
받아온 것은 다른 문장이라, 파일이 아니라 실행 로그에서 읽었다.

### 8.1 검산 도구가 옛 스냅샷을 읽을 뻔했다

머지 후 대조에 t41 의 비교 스크립트를 그대로 재사용했는데, 그 스크립트는 경로가
`/tmp/t41-actual.json` 으로 **하드코딩**돼 있었다. 그대로 돌리면 **오늘의 라벨이 아니라
t41 때의 스냅샷을 검사**한다 — 결과가 「전부 일치」로 나오지만 **아무것도 안 잰 것**이다.

알아챈 계기는 결과가 아니라 **명령을 다시 읽은 것**이다(결과는 두 경우가 똑같이 생겼다).
경로를 오늘 파일로 바꿔 다시 돌렸고, 위 표는 **새 스냅샷** 기준이다.

> 재사용한 검사는 **무엇을 읽는지**가 같이 옮겨오지 않는다. 「전에 쓴 검사라 믿을 만하다」가
> 가장 조용히 틀리는 자리다 — 통과했는데 대상이 틀린 경우는 실패 신호가 아예 없다.

## 9. 남는 것

- **경고는 그대로다.** 릴리스가 나올 때까지 안 사라진다(t81 §2).
- **갱신은 이제 의도적 카드다.** 릴리스가 나오면 t41 절차로 받는다.
- §7 의 Gap 넷은 그대로 열려 있다 — 특히 **「지금 도는 것과 같다」는 동일성 주장이지
  안전성 주장이 아니다.**

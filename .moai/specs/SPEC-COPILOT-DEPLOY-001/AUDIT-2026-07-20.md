## 렌즈별 발견사항

### 안전 불변식 보존 (safety-invariant) — 최우선

- **SAFETY-1 [high, 재검증 통과]** — AC-DEPLOY-014 검사 ③("소스 스캔 — 안전 게이트 미경유 OSC 송신 표면 접근 0건")이 스캔 도구·매치 패턴·"OSC 송신 표면"의 구체 정의·언어 범위를 명시하지 않아 결정적 테스트로 작성 불가. 검사 ①②는 기존 MVP 게이트가 손상되지 않았음만 재확인하므로, 셸이 **새로** 추가한 우회경로 탐지 책임 전부가 정의 안 된 ③에 실려 있음 → 아무것도 스캔하지 않고 trivially "통과" 가능. **최상위 위험의 유일한 실질 방벽이 assertion(주장)일 뿐 test(검증)가 아님.**
  - 권고: ③를 구체화 — (a) 정당한 송신 심볼 allowlist(게이트 send 함수만), (b) 스캔 메커니즘·패턴(raw socket 생성/직접 import/`127.0.0.1` 리터럴)을 **Python + Rust/Tauri 전 언어**에, (c) 미열거 신규 모듈 발견 시 fail-closed.
- **SAFETY-2 [medium]** — 교차언어 사각지대: AC-MVP-019는 Python import 경계 검사. 셸의 신규 표면(Tauri Rust 셸/sidecar 컨트롤러/updater/IPC)은 Python OSC 모듈을 import하지 않고도 `127.0.0.1:<console port>`로 raw UDP 송신 가능 → Python import 검사·③ 소스 스캔 모두에 불가시. 권고: "모든 OSC 송신" 열거를 **wire-level(콘솔 수신 포트 패킷 관측)**로 측정, A.4 IPC 결정 시 gate-transit AC 동반.
- **SAFETY-3 [medium]** — responder provisioning의 `Import Plugin` 콘솔 실행: REQ-DEPLOY-011(사용자 수동 로드)과 REQ-DEPLOY-024 괄호(앱이 실행) + 실제 구현("deploy verb→file+Import")이 불일치. AC-DEPLOY-006은 파일 복사만 검증 — 앱이 발행한 Import Plugin OSC가 단일 관문 통과 + 감사 로그됨을 검증하는 positive AC 없음. 권고: REQ-011/024 정합 + 1:1 감사로그 positive AC 추가.
- **SAFETY-4 [medium]** — updater 재시작 × 안전상태 지속성: Stage-2 updater가 백엔드를 재시작(persistent-server MVP엔 없던 능력). REQ-DEPLOY-025는 포트/리스너/타이머 정리만 다루고 **라이브 잠금(live-lock)/대기 중 승인/감사로그 연속성**의 재시작 후 보존을 다루지 않음. 재시작이 live-lock을 기본(unlocked)으로 초기화하면 활성 보호가 조용히 소실. 권고: 재시작 시 live-lock=ON/승인대기 보존 또는 fail-safe(재잠금) + 감사로그 생존 REQ/AC 추가.
- **SAFETY-5 [low]** — 세션 중 설정 UI로 OSC 포트 라이브 편집 미규정(우회는 아님, 오조준 가능). 권고: 라이브 포트 편집 허용 여부 + in-flight 명령 처리 규정.
- **무결함 확인(가치 있는 negative)**: REQ-023/024→AC-014 추적 정확 + AC-014 CI 상시 tier 정확; health UI는 기존 heartbeat 재사용으로 신규 송신 표면 0; 코어 게이트 무결성 재확인 정상.

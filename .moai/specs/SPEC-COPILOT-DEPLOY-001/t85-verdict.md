# t85 — 임시 포트가 상한이면 픽스처가 죽는다

- 카드: t85 · 브랜치 `WT-port-boundary` · base `2567dde`
- 측정일: 2026-08-25 · `server/tests/test_deploy_cross_language_scan.py`
- 콘솔 미접촉 · `server/tools/` 미접촉(run 레인 M4 와 파일 안 겹침)

## 1. [HARD] 날조 대조군 — 고치기 전에 먼저 쐈다

픽스처가 쓰는 것과 같은 형태로 설정 파일을 만들어 **경계 양쪽**을 쟀다:

```
sink.port = 65534 -> OK  console=65534 receive=65535
sink.port = 65535 -> SettingsError: receive_port must be in [1, 65535], got 65536
```

**재현된다.** 그리고 65534 는 정상이므로 「전부 거절하는」 상태가 아니다 —
경계 한 칸에서만 죽는다. 카드가 말한 확률 결함이 맞다.

## 2. 처방은 읽고 골랐다 — 「+1」에 의미가 없다

카드가 후보 셋을 줬지만 미리 정하지 않고, **픽스처가 두 포트를 실제로 어떻게 쓰는지**부터 읽었다.

```
:460   receive_port = {sink.port + 1}     ← 설정 파일에 쓰기만 한다
:468   return settings.console_port          ← 반환값에 receive_port 가 없다
:480   receive_port=0,  # ephemeral          ← gated_stack 이 직접 0 을 넘긴다
:505   receive_port=0,  # ephemeral          ← deploying_stack 도 마찬가지
```

파일 전체에서 `receive_port` 는 **세 번** 나오고, 그중 둘이 스택에 넘기는 `0` 이다.
**해석된 `settings.receive_port` 를 읽는 곳이 없다.** 즉 `+1` 은 인접성을 의도한 것이
아니라 **파일을 형식만 갖추게 하는 채움값**이다.

그래서 후보 판정:

| 후보 | 판정 |
|---|---|
| 두 포트 각각 할당 | **과하다** — 두 번째 포트가 쓰이지도 않는데 할당 로직을 늘린다 |
| 상한 근처면 −1 | **아무도 안 읽는 값에 분기를 만든다.** 그리고 §4 에서 이게 검사를 통과한다 |
| sink 를 상한−1 이하로 강제 | OS 가 주는 포트를 통제하려 든다 — 재시도 루프가 필요하고 취약하다 |
| **채택: 파생을 없앤다** | `receive_port` 를 앱 기본값(`DEFAULT_RECEIVE_PORT` = 9000)으로 고정 |

**분기를 만드는 대신 분기가 필요한 이유를 없앴다.**

## 3. 무엇을 바꿨나

`_settings_body(console_port)` 헬퍼를 만들어 픽스처가 그것을 쓰게 했다. 헬퍼로 뺀 이유는
**검사가 그 결정을 겨눌 수 있게** 하기 위해서다 — 픽스처 안에 인라인으로 두면 OS 가 준
포트에 의존해 경계를 시험할 수 없다.

독스트링에 **왜 파생하지 않는지**를 적었다(양쪽 스택이 `0` 을 넘기므로 읽히지 않는다),
그리고 **옛 형태가 어떻게 죽었는지**도 적었다 — 다음 사람이 「인접해야 하나?」로 되돌리지
않도록.

## 4. [HARD] 뮤테이션 — 검사가 장식이 아님을 보였다

백업 + 체크섬으로 했다(`git checkout` 미사용 — 미커밋분이 날아간다).

| # | 뮤테이션 | 결과 |
|---|---|---|
| M1 | 옛 파생 복원 (`console_port + 1`) | **KILL** — `[65535]` **와** 음성 대조군 둘 다 빨강. `[1]·[8001]·[65534]` 는 통과 |
| M2 | 클램프 처방 (상한이면 −1, 아니면 +1) | **KILL** — **음성 대조군만** 빨강, 파라미터 검사 4개는 **전부 통과** |

🔴 **M2 가 이 카드의 핵심이다.** 클램프는 카드가 준 후보 중 하나였고, **파라미터 검사만
있었으면 통과했을 것**이다. 음성 대조군(`test_the_body_does_not_derive_receive_port_from_console_port`)
이 그것을 잡는다 — 그 검사가 있어야 **「경계에서만 때운 것」과 「파생을 없앤 것」이 구분된다.**

M1 이 전부를 죽이지 않고 **경계 항목만** 죽인 것도 중요하다 — 판별력이 있다는 뜻이다.

복원 확인: `shasum` 이 백업과 **일치**(`0215c377…`), 복원 후 5개 통과.

## 6. Gaps — 재지 않은 것

- **실제로 OS 가 65535 를 주는 것을 관측하지 못했다.** 카드의 관측(run 레인이 한 번 밟았다)을
  옮긴 것이고, 나는 **주입으로 재현**했다. 주입이 실제 할당과 같은 경로인지는
  `resolve_effective_settings` 수준에서만 같다.
- **다른 픽스처에 같은 `+1` 패턴이 있는지 전수로 세지 않았다.** 이 파일만 봤다.
- **`WirePacketSink` 가 어떤 범위에서 포트를 받는지 안 봤다.** OS 임시 포트 범위가
  65535 를 포함하는지는 카드의 관측을 근거로 삼았다 — 내가 잰 게 아니다.
- **전량 스위트는 안 돌렸다**(run 레인과 겹칠 수 있어). 파일 전량 57개까지만 돌렸다.

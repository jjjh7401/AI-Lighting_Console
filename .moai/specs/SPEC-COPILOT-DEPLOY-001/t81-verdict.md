# t81 — Node 20 경고의 출처를 올린다

- 카드: t81 · 브랜치 `WT-label-sync-action-bump` · base `0989090`
- 측정일: 2026-08-25 · 대상 `EndBug/label-sync`
- **결과: 올릴 곳이 없다. 워크플로 변경 0.**

## 0. 판정

**어떤 릴리스된 판으로도 경고가 사라지지 않는다.** v3 은 존재하지 않고, 최신 릴리스
(`v2.3.3`, 2024-02-13)를 포함해 **모든 릴리스 태그가 여전히 `node20` 을 선언**한다.
`node24` 는 **릴리스되지 않은 기본 브랜치에만** 있고, 그 브랜치는 단순한 런타임 상향이
아니라 **동기화 엔진 자체가 교체된 판**이다.

따라서 이 카드는 「올렸다」도 「올렸으나 경고는 남는다」도 아니고 **「올릴 곳이 없다」**로
닫는다. 워크플로 파일은 **건드리지 않았다** — 부작용도 없었다.

## 1. [HARD] 상위 메이저가 실재하는가 — 없다

태그 전수(페이지네이션 적용, 12개):

```
v2.3.3  v2.3.2  v2.3.1  v2.3.0  v2.2.0  v2.1.0  v2.0.0  v2
v1.1.0  v1.0.0  v1  latest
```

**v3 없음.** 최상위는 `v2.3.3`.

릴리스 이력: `v2.3.3` = **2024-02-13**. 그 뒤로 **릴리스가 한 번도 없다**(2년 반).

## 2. [HARD] 경고가 사라지는가 — 릴리스된 판에는 답이 없다

`action.yml` 의 `runs.using` 을 ref 별로 쟀다:

| ref | `runs.using` | 경고 |
|---|---|---|
| `v2` (지금 쓰는 것, 오늘 `5207415`) | `node20` | 남는다 |
| `v2.3.3` (최신 릴리스) | `node20` | **남는다** |
| `latest` (움직이는 태그) | `node20` | **남는다** |
| `main` (기본 브랜치, 미릴리스) | **`node24`** | 사라질 것 |

**최신 릴리스로 올려도 경고는 그대로다.** 이 표가 이 카드의 핵심이다 — 「최신으로 올리면
되겠지」가 여기서 거짓이다.

`node24` 가 들어온 자리: `5594ed7` (2026-04-10, PR #316 "Update GitHub Actions runtime
from Node.js 20 to Node.js 24"). **기본 브랜치에만 있고 태그가 안 달렸다.**

## 3. 기본 브랜치는 「같은 액션의 새 런타임」이 아니다

```
v2.3.3...main   →  ahead 45 커밋 · 17 파일 변경
```

바뀐 것에 `src/index.ts` · `lib/index.js`(번들) · `package.json` 이 있고, 결정적으로
**동기화 엔진이 교체됐다**:

```
v2 판   github-label-sync ^2.3.1          (Financial-Times)
main 판 @endbug/github-label-sync ^3.0.0  (관리자 본인의 포크)
```

즉 미릴리스 커밋을 SHA 로 고정하는 것은 **런타임만 바꾸는 일이 아니라 엔진을 바꾸는 일**이다.

### 3.1 왜 포크가 생겼나 — t41 의 미해결 404 가 여기서 풀린다

업스트림 저장소 `Financial-Times/github-label-sync` 는 t41 에서 `gh api` 가 **404** 를 냈고
그때 원인을 못 밝혔다. 상류 이슈 **#321** 의 제목이 답이다:

> `github-label-sync` upstream repository appears to be gone?

**업스트림이 사라져서** 관리자가 포크(`@endbug/github-label-sync`)로 갈아탄 것이다.
t41 §9 의 Gap 하나가 이 카드에서 닫혔다.

## 4. dry-run 보증은 포크에도 그대로 있다 — 쟀다, 안 미뤘다

t41 에서 확인한 읽기 전용 보증은 **`github-label-sync@2.3.1` 것**이다. 엔진이 바뀌었으므로
그 확인은 **그대로 넘어오지 않는다.** 포크(`@endbug/github-label-sync@3.0.0`)를 직접 읽었다:

```js
if (options.dryRun) {
    return labelDiff;          // ← 유일한 변이 호출 앞에서 반환. 2.3.1 과 같은 모양
}
```

**보증은 살아 있다.** 다만 이건 「미릴리스 판을 써도 된다」는 뜻이 아니라, **쓰기로 결정한다면
미리보기 절차는 t41 과 같은 신뢰도로 쓸 수 있다**는 뜻이다.

## 5. 지금 실제 위험은 무엇인가

t41 의 실제 실행(`32781954418`)은 **경고를 내면서도 `success`** 로 끝났다. GitHub 이
node20 액션을 **node24 로 강제 실행**하고 있기 때문이다("being forced to run on Node.js 24").

따라서 **지금 깨져 있는 것은 없다.** 위험은 그 강제가 끝나는 시점에 발생한다. 그때까지
릴리스가 안 나오면 이 워크플로는 그때 멈춘다.

## 6. 리드 결정용 선택지 (내가 고르지 않는다)

| | 무엇 | 대가 |
|---|---|---|
| A | **아무것도 안 한다.** 릴리스를 기다린다 | 경고 유지. 강제 실행이 끝나면 그때 멈춘다. 저장소는 살아 있다(push 2026-08-14, 미보관, 열린 이슈 8) |
| B | 미릴리스 SHA(`5594ed7` 이후)로 고정 | 경고는 사라질 것. 대신 **릴리스 안 된 45커밋·엔진 교체판**을 쓰게 된다. 미리보기 절차는 §4 대로 쓸 수 있다 |
| C | 다른 액션으로 교체 | 범위가 이 카드보다 크다 |

**나는 A 를 실행했다** — 정확히는 **아무 변경도 하지 않았다.** 배차서가 「v3 이 없으면
올릴 곳이 없다로 닫는다」고 했고, B 는 **버전 상향이 아니라 미릴리스 코드 채택**이라
내가 단독으로 고를 판단이 아니다.

## 7. Gaps — 재지 않은 것

- **B 를 실제로 시험하지 않았다.** 미리보기를 돌리면 경고가 사라지는지 실측할 수 있지만,
  그건 **미릴리스 서드파티 코드를 `issues: write` 토큰으로 실행하는 것**이다. §4 로 코드는
  읽었으나 **실행은 안 했다.** 리드가 B 를 고르면 그때 t41 절차로 시험한다.
- **강제 실행이 언제 끝나는지 모른다.** GitHub 공지 날짜를 안 쟀다. 「그때 멈춘다」는
  시점 없는 문장이다.
- **`@endbug/github-label-sync@3.0.0` 의 diff 를 안 읽었다.** dry-run 갈래만 확인했고
  나머지 동작 차이는 안 봤다.
- **`v2` 는 여전히 움직이는 태그다.** 오늘 `5207415`. 관리자가 `v2` 를 미릴리스 커밋으로
  옮기면 이 저장소는 **아무 변경 없이도** 엔진이 바뀐다 — 그건 이 카드가 못 막는다.

## §A. 완료 정의 (Definition of Done)

1. AC-LDG-001~017 전부 그린. 전 항목이 **기계 검증**(grep / wc / git diff)이다 —
   이 SPEC은 산출물이 문서이므로 사람 판독이 필요한 항목은 §B의 판독 기준으로 고정한다.
2. M0 증거 원장(`evidence.md`)이 존재하고, 가이드 본문의 모든 능력 주장이 그 원장의
   한 행에 대응한다(AC-008).
3. `backlog-candidates.md`가 존재하고 9단계 전부에 행이 있다(AC-015).
4. 변경 파일이 허용 2경로뿐이다(AC-013).
5. plan 세션은 백로그를 **등록하지 않았다**(AC-016) — 등록은 lead의 몫.

## §B. 판독 기준 — 기계 검증이 대신할 수 없는 것

grep은 "문장이 있는가"를 세지만 "그 문장이 참인가"는 세지 못한다. 다음 두 항목은
**증거 원장 대조**로 판정하며, 원장 행이 없으면 FAIL이다:

| 판독 항목 | 판정 방법 |
|---|---|
| 능력 주장의 진위 | `evidence.md`의 대응 행에 **명령 + 관측 출력**이 있는가. 도구 설명문 인용만으로는 불충분(설명문은 지시문이지 동작 증명이 아님 — plan §A.4) |
| "감독 언어"인가 | AC-005/006이 기계적 하한선. 그 위의 문체 판정은 사용자 검수에 맡기고 SPEC 실패로 삼지 않는다 |

## §E. 품질 게이트

이 SPEC은 코드를 변경하지 않으므로 통상의 lint/test 게이트가 아니라 다음을 적용한다:

1. **경계 확인** — `git diff --name-only` 가 허용 2경로뿐(AC-013). 서버 코드 무접촉.
2. **회귀 스위프** — 코드 무변경이므로 기존 테스트 스위트는 실행 대상이 아니다. 다만
   AC-013이 그린이라는 사실 자체가 "코드 무변경"의 증거이며, 이를 근거로 스위트 생략을
   기록한다(생략 사실을 침묵하지 않는다).
3. **증거 원장 대조** — §B. 원장 행이 없는 주장 0건.

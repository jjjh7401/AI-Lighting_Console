## §0. 표기 규약 [HARD]

**규약 1 — grep 명령은 반드시 코드블록에 둔다.** 표 셀에 넣으면 파이프를 `\|`로 이스케이프하게
되고, `grep -E`는 `\|`를 선택이 아니라 **문자 그대로의 파이프**로 읽어 어떤 입력에도 0을
반환한다(1회차 D1).

**규약 2 — 모든 명령에 기대값을 붙인다.** 기대값 없는 맨 카운트는 어떤 수가 나와도
통과/실패를 말할 수 없다(2회차 N4).

**규약 3 — 변수를 쓰는 명령에는 빈값 가드를 넣는다.** `awk -v a=""` 는 수치 비교가 아니라
문자열 비교로 떨어져 **전부 탈락 → 0 → 통과**가 된다(2회차 N3, fail-open).

**규약 4 — 부인목록(denylist) 금지, 전량 대조(set difference)를 쓴다.** 알려진 3건만 찾는
명령은 4번째를 놓친다(2회차 N6).

**규약 5 — 명령은 작성 시점에 뮤테이션으로 검증한다.** "실패해야 하는 입력"을 만들어
실제로 실패하는지 확인한 뒤에만 AC에 싣는다. 검증 기록은 §G. **새로 쓴 명령도 헛돌 수 있다** —
2회차의 P0 3건이 전부 1회차 수정이 만든 것이었다.

## §B. 판독 기준 — 기계 검증이 대신할 수 없는 것

### 닫지 못한 것 — 명시

**1. 증거 원장의 자기인증 순환.** `$E`를 쓰는 주체와 그 원장으로 채점받는 주체는 같은 run
단계 행위자다. 이 SPEC이 닫은 것은 **형식**(행 존재·명령 열·출력 열·앵커 해석)이고, 닫지
못한 것은 **"그 명령을 실제로 돌렸는가"**다. sync 단계 독립 감사로 이관한다.

**2. REQ-LDG-015의 부정 주장.** "plan 세션이 큐에 등록하지 않았다"는 기계적으로 검증 불가다
— 큐 파일이 `.gitignore`(`.moai/state/`)에 걸려 어떤 `git diff`에도 나타나지 않고, 감사
시점에는 lead가 이미 등록했을 수 있다. AC-016은 **긍정 산출물 계약**만 본다.

두 항목 다 "해결됐다"고 주장하지 않는다.

## §D. 검증 명령 모음

```bash
set -u
G=docs/user-guide.html
E=.moai/specs/SPEC-COPILOT-LDGUIDE-001/evidence.md
B=.moai/specs/SPEC-COPILOT-LDGUIDE-001/backlog-candidates.md
T=server/orchestrator/tools.py
BASE=2092a42

# 등록 도구명 전량 (하드코딩 금지 — 개정 시점 재생성)
grep -oE '^            name="[a-z_]+",$' "$T" | sed 's/.*name="//;s/",//' | sort > /tmp/tools.txt

# D.1  단계 h2 9개
grep -oE '<h2 id="stage-[0-9]+"' "$G" | sort -u | wc -l          # 기대: 9

# D.2  3부 구조 + 순서
grep -c 'class="part-do"'  "$G"                                  # 기대: 9
grep -c 'class="part-app"' "$G"                                  # 기대: 9
grep -c 'class="part-gap"' "$G"                                  # 기대: 9
grep -oE 'class="part-(do|app|gap)"' "$G" | sed 's/.*part-//;s/"//' | tr '\n' ' '
#   기대: "do app gap " 가 9회 반복

# D.3  한계 절 비어있지 않음 — 제목 줄 제외 (2회차 N2)
grep -A3 'class="part-gap"' "$G" | grep -v 'class="part-gap"' | grep -v '<h[23]' \
  | grep -cE '[가-힣]'                                           # 기대: >= 9
grep -c '확인된 간극 없음' "$G"                                   # 기대: 간극 없는 단계 수와 일치

# D.4  오퍼레이터 보조 블록
grep -c 'class="op-note"' "$G"                                   # 기대: >= 1 (해당 단계마다)
#   〈혼합〉중복 판정: op-note 내부 문장을 공백 정규화 후 같은 단계 본문과 대조 → 완전 일치 0건.
#   정규화 규칙은 M5에서 $E에 기록한다.

# D.5  본문(부록 이전) 금지 토큰 — 빈값 가드 필수 (2회차 N3·N11)
A=$(grep -n '<h2 id="appendix-tools"' "$G" | cut -d: -f1)
[ -z "$A" ] && { echo "FAIL: 부록 마커 없음"; exit 1; }
head -n "$((A-1))" "$G" \
  | grep -cE 'SPEC-[A-Z]+|server/|\.py\b|manager-|\.moai/'       # 기대: 0

# D.6  도구 식별자는 부록 이후에만 — 전량 검사 (2회차 N3)
A=$(grep -n '<h2 id="appendix-tools"' "$G" | cut -d: -f1)
[ -z "$A" ] && { echo "FAIL: 부록 마커 없음"; exit 1; }
head -n "$((A-1))" "$G" | grep -oE '<code>[a-z_]+</code>' \
  | sed 's/<code>//;s|</code>||' | sort -u > /tmp/body_tokens.txt
comm -12 /tmp/body_tokens.txt /tmp/tools.txt | wc -l             # 기대: 0

# D.7  시간 예측 금지
grep -cE '[0-9]+ *(일|주|개월|시간) *(정도|쯤|이면|안에)' "$G"     # 기대: 0

# D.8  원장 배정표 행 수 == 등록 도구 수
wc -l < /tmp/tools.txt                                           # 기준값
grep -c '^| E-' "$E"                                             # 기대: 위와 일치
grep -c '^| E-[0-9]* | [^|]* | [^|]* |  *|' "$E"                 # 기대: 0 (공란 행 없음)

# D.9  16건 판정 + 미확인 표기
grep -cE 'covered-in-prose|stale|absent' "$E"                    # 기대: >= 16

# D.10 수치 주장 — 〈혼합〉추출 후 $E 재측정표와 대조
grep -oE '[0-9]+ *(가지|종|개|%|배)' "$G" | sort | uniq -c

# D.11 보존 판정 — 고정 SHA 기준 (2회차 N7)
git show "$BASE:$G" | grep -c '<h3'                              # 기대: 25
grep -cE '\| *(keep|merge|drop) *\|' "$E"                        # 기대: >= 25

# D.12 자체완결성 (회귀 금지)
grep -coE 'https?://[^"'"'"' ]+' "$G"                            # 기대: 0
grep -cE '<script|<link' "$G"                                    # 기대: 0

# D.13 변경 경로 봉쇄
git diff --name-only "$BASE"...HEAD

# D.14 안전 경고 — 위치 + data-ev 부착 + 원장 해석
grep -c 'class="warn"' "$G"                                      # N (하한 없음)
grep -c 'class="warn"[^>]*data-ev=' "$G"                         # 기대: 위 N과 일치
A=$(grep -n '<h2 id="appendix-tools"' "$G" | cut -d: -f1)
S=$(grep -n '<h2 id="stage-1"' "$G" | cut -d: -f1)
[ -z "$A" ] || [ -z "$S" ] && { echo "FAIL: 마커 없음"; exit 1; }
grep -n 'class="warn"' "$G" | cut -d: -f1 \
  | awk -v s="$S" -v a="$A" '$1 < s || $1 > a' | wc -l           # 기대: 0 (전부 단계 구간 내)

# D.15 백로그 3필드
grep -cE '^\| [1-9] \| [^|]+ \| [^|]+ \| [^|]+ \|' "$B"          # 기대: >= 9
grep -cE '^\| [1-9] \|[^|]*\|  *\|' "$B"                         # 기대: 0 (빈 필드 없음)

# D.16 인계 계약 (긍정 산출물만 — §B 참조)
test -s "$B" && echo "존재"                                      # 기대: "존재"
grep -c '등록은 lead가 수행한다' "$B"                             # 기대: >= 1

# D.17 앵커 해석
for a in $(grep -oE 'href="#[^"]+"' "$G" | sed 's/href="#//;s/"//'); do
  grep -q "id=\"$a\"" "$G" || echo "MISSING: $a"
done                                                              # 기대: 출력 없음

# D.18 data-ev 앵커 해석 + 부착 누락 (2회차 N5)
grep -oE 'data-ev="E-[0-9]+"' "$G" | sed 's/data-ev="//;s/"//' | sort -u \
  | while read -r id; do
      grep -qE "^\| $id \|" "$E" || echo "UNRESOLVED: $id"
    done                                                          # 기대: 출력 없음
#   부착 누락: part-app 구간의 <p> 중 data-ev 없는 것
grep -A20 'class="part-app"' "$G" | grep '<p' | grep -vc 'data-ev='   # 기대: 0

# D.19 유령 식별자 — 전량 대조 (2회차 N6, 부인목록 금지)
grep -oE '<code>[a-z_]+</code>' "$G" | sed 's/<code>//;s|</code>||' | sort -u > /tmp/used.txt
comm -23 /tmp/used.txt /tmp/tools.txt                            # 기대: 허용목록 항목만 (유령 0)
```

## §F. 품질 게이트

1. **경계 확인** — `git diff --name-only "$BASE"...HEAD`가 허용 2경로뿐(AC-013). 서버 코드 무접촉.
2. **테스트 스위트 생략 — 사유 명시** — 코드 무변경이라 실행 대상이 아니다. 더해 이 워크트리에는
   `ui/node_modules`가 없어 `npm test`가 `vitest: command not found`로 실패하는데, 이는
   환경 사유이며 변경 내용과 무관하다. 생략 사실을 침묵하지 않는다.
3. **증거 원장 대조** — §B. 원장 행이 없는 주장 0건.
4. **잔여 위험 2건** — §B 말미의 자기인증 순환 + REQ-015 부정 주장. 이 SPEC 안에서 닫히지 않는다.

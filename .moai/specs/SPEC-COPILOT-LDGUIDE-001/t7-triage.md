## 0. [HARD] 「9건」이 실제로 9건인가 — 검산됨, 다만 **파생값이다**

문서 자신은 9를 말하지 않는다. 문서는 **16건**이라고 말한다.

```
후보 표 행(기계 집계)      16
문서의 단계별 집계표 합계   16   (1·2·2·2·2·2·2·2·1)
문서 이력의 진술            "16개 항목 수거"
```

셋이 일치한다. 그러면 9는 어디서 오는가 — **큐와의 차집합**이다:

```
t4  코파일럿 개선: 콘솔 판독 경로 측정   → 채널폭(2) · 그룹멤버십(4) · 페이드시간(6) · 큐내용(7)   = 4건
t5  코파일럿 개선: 복원 경로 설계        → 그룹/프리셋 되돌리기(4) · 수정 되돌리기(7) · 인계 패키지(9) = 3건
                                                                                    16 − 4 − 3 = 9
```

**9는 맞다. 다만 문서가 말한 수가 아니라 큐를 빼서 나온 수**이므로, t4·t5 의 담당 범위가
바뀌면 9도 바뀐다. 아래 표는 그 차집합을 자리별로 명시한다 — 다음 사람이 다시 빼지 않도록.

## 2. 「이미 끝난 결정」 후보 — 하나 나왔다

### 2.1 🔴 B(단계 2, 콘솔 직접 패치) — 전제가 바뀌었다

문서(2026-08-17)의 근거는 *"실행 경로가 이 빌드에서 동작하지 않는다는 것이 기능 계약에
명시돼 있고"* 였다. 지금 코드를 읽으면 그 문장은 **영구 계약이 아니라 조건 가드**다:

```python
if execution_port is None:
    return _error_result(call, "execution port is not wired — 앱이 플러그인을 실행할 수 없다 …")
```

즉 「못 쓴다」가 아니라 **「포트가 안 물렸으면 안 쓴다」**이다. 그리고 쓰기 경로 자체는
`server/orchestrator/tools.py:1881` 의 `execution_port.execute(command)` 로 존재한다.

**다만 내가 확인한 것은 코드 상태뿐이다.** 이 카드는 콘솔 미접촉이라 실기로 쓰기를
해 보지 않았다. 프로젝트 기록에는 t66 이 그룹 18개를 실제 콘솔에 올렸다고 되어 있으나
**그건 내 관측이 아니라 기록**이다(§4 Gap).

**제안**: B 를 「기능을 만드는 카드」가 아니라 **「문서·계약을 현재 코드에 맞추는 카드」**로
재분류할 것. 원문의 「이 제약을 영구 계약으로 굳힐 것인가」라는 질문은 **전제가 이미 흔들려
있으므로** 그대로 물으면 잘못된 선택지를 준다.

## 3. 제안 — 묶음과 순서 (등록은 리드가)

원문 §「묶어서 볼 만한 것」은 묶음 셋을 제시했고 그중 둘(판독·복원)은 이미 t4·t5 로
카드가 됐다. 남은 9건에 대해 **새 묶음 셋**을 제안한다.

| 묶음 | 항목 | 왜 묶이나 | 비용 |
|---|---|---|---|
| **P1 — 있는 것을 보이게** | C(조준 노출) · A(대조 판정 기준) | 둘 다 **새 기능이 아니라 노출·기준의 문제**다. 코드는 이미 있고 결정만 없다 | 가장 낮다 |
| **P2 — 라이브러리를 열기** | E(사용자 정의 룩·장르) · F(이미지→룩) | 둘 다 룩 라이브러리 입력 경로 문제. E 가 스키마를 열면 F 의 착지점이 생긴다 — **E 가 F 의 선행** | 중간 |
| **P3 — 판독에 걸린 것** | D(포커스 차트) · H(반응 감지) | 둘 다 「콘솔이 그 값을 주는가」에 걸린다. t4 와 같은 성질이라 **t4 의 프로브에 얹는 것이 싸다** | t4 에 얹으면 낮다 |

묶이지 않는 둘:

- **G(오디오 분할)** — 9건 중 **유일하게 새 의존성**이 필요하다. 크기가 다른 카드이고,
  「구간 입력을 더 쉽게」 쪽이면 의존성 없이 끝날 수도 있다. **먼저 어느 쪽인지 정할 것.**
- **I(다중 콘솔)** — 범위 결정이지 구현이 아니다. 「비범위로 문서에 고정」이면 P1 과 같은 크기,
  「범위에 넣기」면 이 목록에서 제일 큰 카드다. **정하기 전에는 크기를 모른다.**

### 3.1 순서 제안

```
P1 (C·A)  →  P3 를 t4 프로브에 얹기  →  P2 (E → F)  →  G·I 는 범위 결정 먼저
```

근거: P1 은 결정만으로 닫히고, P3 는 이미 예정된 측정에 얹으면 추가 비용이 거의 없다.
P2 는 순서 의존(E→F)이 있어 뒤로. G·I 는 **크기를 모르는 상태**라 카드로 세우기 전에
범위 질문을 먼저 닫는 편이 싸다.

## 4. Gaps — 재지 않은 것 / 남의 관측

- 🔴 **B 의 실기 동작은 내가 안 쟀다.** 코드 상태만 읽었다. 「t66 이 콘솔에 18개를 올렸다」는
  **프로젝트 기록이지 내 관측이 아니다.** B 를 카드로 세울 때 실기 확인이 선행돼야 한다.
- **H(반응 감지)는 판정 불가.** 「원리적 불가」가 참인지는 콘솔 프로브가 필요하고, 이 카드는
  콘솔 미접촉이다. **「아니다」로 적지 않고 「모른다」로 적었다.**
- **F 의 색 토큰 0건은 함수 범위 grep**(`sed` 로 함수 블록을 잘라 센 것)이다. 함수 경계
  패턴이 어긋나면 0이 나올 수 있다 — 카드로 세울 때 다시 확인할 것.
- **I 의 매치 1건을 오탐으로 단정하지 않았다.** `web/dash.py` 를 열어 보지 않았다.
- **E-N 근거 원장(`evidence.md`)을 대조하지 않았다.** 원문 표의 근거 열이 가리키는 원장 행을
  하나도 열어 보지 않았다 — 원문의 근거 주장은 **그대로 옮긴 것**이지 내가 검증한 게 아니다.
- **t4·t5 의 담당 범위는 큐 카드 본문에서 읽었다.** 그 카드들이 실제로 그 항목들을 닫고 있는지
  진행 상태까지는 확인하지 않았다(t4 는 본문에 「채널폭 미측정」이라 적혀 있어 그대로 실었다).

## 부록 — t36 과 t78 은 같은 뿌리다 (리드 요청, 직접 확인함)

배차서가 「t78 에 적어 두라」고 했으나 **큐를 고치지 않았다** — 큐의 생산자는 리드 하나이고,
기존 카드 본문에 붙이는 것도 큐 변경이다. 그래서 여기 적고 리드에게 보고한다.

**릴레이가 아니라 큐에서 직접 읽었다:**

```
t36 본문: "moai update --templates-only 가 수정 54 + 신규 9 …
           신규에 moai-kanban-foreman · moai-domain-design-dna · rule-authoring.md
           · kanban-dispatch-detail.md 등"                       ← 그 파일이 신규 목록에 있다
t78 본문: "kanban-dispatch 스텁이 main 에 없는 companion 을 15번 가리킨다"
```

**결론**: 매달린 포인터 15개는 개별 결함이 아니라 **하네스 스냅샷이 뒤처진 것의 증상**이다.
`kanban-dispatch-detail.md` 는 없어진 파일이 아니라 **아직 안 들어온 파일**이고,
t36 의 템플릿 동기화가 그것을 가져온다.

**그래서 t78 을 스텁 편집으로 고치면 안 된다.** 포인터를 지우거나 companion 을 손으로 만들면
t36 이 동기화할 때 충돌하거나, 더 나쁘게는 **없어도 되는 것으로 오해되어 t36 의 신규 9에서
빠질** 수 있다. t48 이 그 포인터를 지우지 않고 남긴 판단이 결과적으로 옳았다.

**제안**: t78 을 독립 카드가 아니라 **t36 의 검산 항목**으로 볼 것 — t36 을 실행한 뒤
`git ls-tree origin/main …/kanban-dispatch-detail.md` 가 1을 내면 t78 은 자동으로 닫힌다.
닫히지 않으면 그때가 진짜 t78 이다.

**단, t78 의 두 번째 절반은 t36 으로 안 닫힌다.** t78 본문은 「그 companion 이 이 저장소에
거짓인 실측을 싣는다」도 함께 든다 — t48 이 찾은 `"measured on this repository"` 지시어
문제다. 템플릿 동기화는 그 문장을 **그대로 가져온다.** 즉 t36 이 t78 의 (a)는 닫고
(b)는 **오히려 이 저장소에 들여온다.**

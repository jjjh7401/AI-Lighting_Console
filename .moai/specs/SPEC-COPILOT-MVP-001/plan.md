# SPEC-COPILOT-MVP-001 — 구현 계획 (plan)

> Tier L 구현 SPEC. 선행 SPEC-COPILOT-EVAL-001(Phase 0)의 격차 분석 결과가 범위 확정 입력이다.

## A. 핵심 결정 사항 (변경 가능성 높은 순 — 먼저 검토)

1. **UI 프레임워크** — DESIGN.md §9는 "React or Svelte" 병기, 선택 기준 미정. UI 마일스톤(M5) 착수 전 확정 필요.
   - ✅ **결정됨 (2026-07-15)**: **React** 채택. 근거: 컴포넌트 생태계와 WebSocket 클라이언트 패턴의 성숙도가 우세.
2. **지원 MA3 세부 버전 핀** — "v2.x 고정"만 확정. Lua API/OSC 스펙과 룰북 버전 분리에 직결. Phase 0 평가 환경에서 쓴 버전을 기본 후보로 한다.
   - ✅ **결정됨 (2026-07-15)**: Phase 0 평가에서 핀된 버전(평가 시작 시점 최신 안정 v2.x)을 **그대로 승계**한다. 버전 정보는 §F fold-in 절차를 통해 유입된다. 근거: 평가 데이터와 구현 대상의 버전 일치가 룰북·회귀 테스트의 유효성을 보장.
   - ✅ **유입 완료 (2026-07-16, §F fold-in v0.3.0)**: 승계 버전 = **grandMA3 onPC 2.4.2** (Phase 0 평가 환경 — macOS 빌드, `boardop-eval-log.md` §1 항목 1). 룰북·Lua API/OSC 스펙·회귀 테스트 스위트는 v2.4.2 기준으로 작성한다. spec.md §C의 "세부 버전 핀은 plan.md 결정 사항을 따른다" 위임과 정합 (spec.md 본문 변경 불요).
3. **문법 오류율 측정 코퍼스 규모** — acceptance.md는 감사 지적(MVP-M2, 5% 경계 분해능 문제)을 반영한 기본값을 정의했다: 표준 시나리오 ≥20종 × ≥3회 반복, 분모(생성 명령 라인) ≥300 하한, 미달 시 반복 추가. 이 기본값 자체는 사용자 확인 가능(user-confirmable) 항목으로 유지한다.
   - ✅ **결정됨 (2026-07-15)**: **기본값 승인** — 표준 시나리오 ≥20종 × ≥3회 반복, 분모(생성 명령 라인) ≥300 하한, 통합(pooled) 비율 판정. 근거: 5% 임계 판정에 충분한 경계 분해능(1건당 0.33%p) 확보.
4. **감사 로그 저장 형식/위치** — DESIGN.md 미상세 (파일 vs DB, 로테이션 정책, 쇼파일 백업과의 연계 경로).
   - ✅ **결정됨 (2026-07-15)**: **JSONL 파일**, 일별 로테이션, **90일 보존**. 저장 경로는 구현 시 `server/` 하위에서 결정한다. 근거: 의존성 없는 추가 전용(append-only) 형식이 감사 무결성·검수 용이성에 적합.
5. **OSC 주소 체계** — 초기에는 송신 `/cmd`만 확정이었고 수신 주소가 미정이었다. 아래 결정으로 송수신 전체가 자체 네임스페이스로 통일되었다 (송신 주소도 `/copilot/cmd`로 갱신 — v0.2.0 amendment 반영).
   - ✅ **결정됨 (2026-07-15)**: 자체 네임스페이스 **`/copilot/*`** 채택 — `/copilot/cmd`(명령 송신), `/copilot/feedback`(피드백 수신), `/copilot/state`(상태 조회) 등. boardop 주소 체계(`/gma3/cmd`, `/python/feedback`)와의 **비호환은 의도적 선택**으로, 동시 설치 시 충돌을 방지한다. 후속 정합: **개정 완료 (2026-07-15, v0.2.0 amendment)** — spec.md REQ-MVP-001·§A·acceptance·design·research 전체에 `/copilot/cmd` 정식 반영됨.
6. **문법 밸리데이터 구현 방식** — 자체 파서 작성이 확정 방향(외부 라이브러리 부재)이나, 검증 깊이(키워드 화이트리스트 수준 vs 완전 문법 파싱)는 M4에서 격차 분석 결과를 반영해 확정. (Phase 0 산출물이 입력이므로 마커 대신 의존성으로 관리)
7. **왕복 <10초 판정의 조작적 정의 승인** — acceptance.md "왕복 시간 측정 방법"은 사용자 명시 기준 "<10초"를 중앙값 집계·웜캐시 조건·재시도 턴 제외로 조작화했다 (감사 지적 MVP-M3/m7 반영). 이는 원 기준의 축소 해석(narrowing)이므로 사용자 서명이 필요하다.
   - ✅ **결정됨 (2026-07-15)**: **승인됨** — 측정 코퍼스 중앙값 <10초 판정 + p95 보고, 웜캐시 조건, 인간 승인 대기·콜드스타트 제외. acceptance.md의 잠정(provisional) 문구는 "사용자 승인 완료 (2026-07-15)"로 갱신됨.
8. **LLM 프로바이더 전략** — ✅ **결정됨 (2026-07-15)**: "Gemini 평가 + 멀티 프로바이더 추상화" 채택 (v0.2.0 amendment). LLM 클라이언트는 프로바이더 중립 추상화 계층 뒤에 위치(§B.12 REQ-MVP-038), 지원 프로바이더는 Anthropic Claude + Google Gemini(설정 파일 전환, REQ-MVP-039), 기본 프로바이더는 프로바이더별 문법 오류율 측정 결과로 결정 — <5% 통과 중 비용 우선(REQ-MVP-040), 캐싱은 프로바이더별 능력 적용(REQ-MVP-041). 활성 구성은 단일 프로바이더·단일 모델 유지(REQ-MVP-006 개정).
   - **정련 (v0.2.1, 감사 AM-M1 — 사용자 규칙의 기각 아님)**: 적격(eligible) = AC-MVP-002(오류율) **AND** AC-MVP-003(왕복 중앙값) 프로바이더별 동시 통과; 적격 중 비용 우선(측정 코퍼스 1회 실측 청구액, 무료 등급 0 계상); 운영 중 AC-003 지속 미충족 시 다른 적격 프로바이더로 폴백(설정 전환 + 감사 로그).

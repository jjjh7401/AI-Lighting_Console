## 문법 오류율 측정 방법 (AC-MVP-002의 정의 — MVP-M2 반영)

1. **코퍼스**: 대표 프로그래밍 작업 10종 각각에 대해 **표준 한국어 지시문 2개 이상 변형** = 표준 시나리오 **≥20종**.
2. **실행**: 표준 시나리오 세트를 **≥3회 반복 실행**.
3. **분모 하한**: 전체 실행에서 모델이 생성한 **명령 라인 총수 ≥300** (한 시나리오가 여러 명령 라인을 생성할 수 있음). 300 미달 시 반복 횟수를 증가시켜 충족한다. (근거: 5% 임계 판정의 경계 분해능 — N=300에서 1건당 0.33%p.)
4. **분자**: 문법 밸리데이터 또는 콘솔이 **문법 오류로 거부한 명령 라인 수** (최초 생성 기준 — 자가 수정 후 성공해도 최초 오류는 분자에 포함).
5. **비결정성 정책**: 프로덕션 추론 설정(모델 ID, thinking/effort 설정)을 고정·기록하고 동일 설정으로만 측정한다. 회차별 오류율과 통합(pooled) 오류율을 함께 보고하되, **판정은 전 회차 통합(pooled) 오류율** 기준으로 한다.
6. **판정**: pooled 오류율 (분자/분모) < 5% 이면 PASS.
7. 코퍼스 규모 기본값(≥20종 × ≥3회, ≥300라인)은 **사용자 승인 완료 (2026-07-15**, plan.md §A-3 결정 기록**)** — 본 기본값이 확정 기준이다.
8. **프로바이더별 실행 (2026-07-15 amendment)**: 본 절차는 지원 프로바이더 각각(Anthropic Claude / Google Gemini)에 동일 코퍼스·동일 규칙으로 적용되어 **프로바이더별 pooled 오류율**이 기록된다 — REQ-MVP-040의 기본 프로바이더 선정 입력. **AC-MVP-002의 <5% 판정은 선정된 기본 프로바이더의 pooled 오류율 기준**이다.

## 왕복 시간 측정 방법 (AC-MVP-003의 정의 — MVP-M3 반영)

1. **시작 이벤트**: 사용자 지시 메시지가 UI로부터 WebSocket으로 **서버에 수신된 시각**.
2. **종료 이벤트**: 해당 지시의 실행 결과(콘솔 피드백)가 **서버에 수신된 시각** (responder 결과 회수 완료 시점).
3. **제외 구간**: ① **인간 승인 대기** — 승인 요청 표시 시각부터 사용자 결정 수신 시각까지를 측정에서 공제. ② **첫 턴 캐시 write** — 측정 세션 시작 전 워밍업 1턴을 수행하여 **웜캐시(warm-cache) 조건**에서 측정한다 (콜드 스타트 턴은 측정 코퍼스에서 제외하고 참고치로만 별도 기록).
4. **재시도 분리**: 자가 수정 재시도가 발생하지 않은 **단일턴 실행만** 판정 코퍼스에 포함한다. 재시도 발생 턴은 별도 집계하여 건수·소요와 함께 보고한다 (판정 제외, 정보 제공).
5. **집계·판정**: 판정 코퍼스(표준 시나리오 실행 전체)의 **중앙값(median) < 10초 = PASS**. **p95는 보고 의무**(판정 기준 아님).
6. 단일 실행이 10초를 초과해도 중앙값 기준을 충족하면 PASS다 (이진 판정 명확화).
7. **기준 축소 해석 — 사용자 승인 완료 (2026-07-15)**: 본 조작적 정의(중앙값 집계·웜캐시 조건·재시도 턴 제외)는 사용자 명시 성공 기준 "지시→실행 왕복 < 10초"의 축소 해석(narrowing)이며, clarification gate에서 **사용자 승인이 완료**되었다 (plan.md §A-7 결정 기록 참조). 본 정의가 확정 판정 기준이며, REQ-MVP-041의 프로바이더별 캐시 조건은 측정 조건일 뿐 이 판정 기준을 완화하지 않는다 (AM-M2c).
8. **프로바이더별 실행 (AM-M2b — 오류율 방법 §8과 대칭)**: 본 왕복 측정은 **적격 후보 프로바이더 각각**(Anthropic Claude / Google Gemini)에 동일 코퍼스·동일 규칙으로 적용되어 프로바이더별 중앙값·p95가 기록된다 — REQ-MVP-040 (i)의 적격 판정 입력. **AC-MVP-003의 판정은 선정된 기본 프로바이더의 중앙값 기준**이다.

## Given-When-Then 시나리오

### 시나리오 1 — 정상 작업 수행 (한국어 자연어 → 실행)
- **Given** onPC가 구동되고 Lua responder가 로드된 상태에서, 라이브 잠금이 비활성이고 웜캐시 조건일 때
- **When** 사용자가 채팅 UI에 "보컬 그룹 만들어줘" 류의 한국어 지시를 입력하면
- **Then** 시스템이 명령을 생성 → 문법 검증 통과 → (비위험이므로 승인 없이) OSC `/copilot/cmd`로 실행 → responder가 결과를 회수 → UI에 한국어 결과 보고가 표시되고, 왕복 시간이 "왕복 시간 측정 방법"의 판정 코퍼스에 기록된다.

### 시나리오 2 — 블랙리스트 명령 차단 (핵심 안전 시나리오)
- **Given** 라이브 잠금 비활성 상태에서
- **When** 사용자가 파괴적 결과를 유발하는 지시(예: "시퀀스 다 지워줘" → `Delete` 계열 명령 생성)를 입력하면
- **Then** 안전 게이트가 해당 명령을 승인 대기로 보류하고, UI에 명령 내용·위험 사유·승인/거부 버튼이 표시되며, **승인 전까지 OSC 송신이 0건**이고, 거부 시 번들 전체가 미실행 처리되며, 보류·거부 이벤트가 감사 로그에 기록된다.

### 시나리오 3 — 자가 수정 루프 (기실행분 보호 포함)
- **Given** 정상 구동 상태에서
- **When** 모델이 생성한 명령이 콘솔에서 오류를 반환하면
- **Then** 오케스트레이터가 오류를 모델에 회신하여 수정된 명령으로 재시도하되, 재시도는 미실행 잔여분과 신규 수정 명령에만 적용되고(기실행 명령 재전송 0건), 3회 이내 성공 시 결과를 보고하며, 3회 모두 실패 시 재시도를 중단하고 사용자에게 실패와 사유를 한국어로 보고한다.

### 시나리오 4 — 라이브 잠금 모드 (잠금-우선 포함)
- **Given** 사용자가 UI에서 라이브 잠금을 활성화한 상태에서 (승인 대기 중 활성화된 경우 포함)
- **When** 실행성 지시를 입력하거나 보류 중 명령의 승인이 도착하면
- **Then** 시스템은 콘솔로 어떤 명령도 전송하지 않고 제안 카드만 생성하며, 보류 중이던 위험 명령도 실행 불가로 전환되고(잠금이 승인보다 우선), 실행은 잠금 해제 후 명시적 재트리거로만 가능하다.

### 시나리오 5 — Lua 플러그인 배포 (파괴적 스캔 포함)
- **Given** 정상 구동 상태에서
- **When** 사용자가 "페이지 정리해 주는 플러그인 만들어줘" 류의 지시를 입력하면
- **Then** 모델이 Lua 소스를 생성 → pcall 컴파일 검증 통과 → 파괴적 내용 스캔 결과(블랙리스트 `Cmd()` 호출 유무)가 리뷰어에게 표시 → 리뷰 게이트에서 사용자 승인 → 배포되어 onPC에서 플러그인이 확인된다. 컴파일 실패 시에는 배포 없이 자가 수정 루프로 회귀하고, 파괴적 내용 포함 시 "파괴적" 플래그와 함께 등록되어 이후 호출마다 인간 승인이 요구된다.

### 시나리오 6 — 간접 호출 우회 시도 봉쇄
- **Given** 본문에 `Delete` 계열 명령을 포함한 매크로 X가 콘솔에 존재하는 상태에서
- **When** 사용자가 (또는 모델이 생성한 명령 시퀀스가) `Go Macro X` 류의 간접 호출을 실행하려 하면
- **Then** 안전 게이트가 매크로 본문을 조회·전개하여 블랙리스트 명령을 검출하고 인간 승인 대상으로 보류하며, 본문 조회가 불가능한 경우에도 미검증 호출로서 승인 보류되고, 어느 경로로도 승인 없는 OSC 송신은 발생하지 않는다.

## 엣지 케이스

- **승인 대기 중 라이브 잠금 활성화**: 보류 중 위험 명령은 잠금 활성화 시점에 실행 불가로 전환 (REQ-MVP-035, AC-MVP-023 — 시나리오 4에 통합).
- **OSC 결과 확인 타임아웃 (송신 유실/피드백 유실 구분 불가)**: "실행 미확인" 상태 보고 + 부수효과 명령 자동 재전송 금지 (REQ-MVP-032, AC-MVP-020).
- **블랙리스트 키워드가 안전한 맥락에 포함** (예: 오브젝트 이름에 "Delete" 문자열): 위험 분류는 명령 구문 기준으로 판정하되, 간접 호출은 전개-또는-보류(REQ-MVP-026)로 커버한다. 오탐(FP)은 승인으로 해소 가능; 미탐(FN)은 폐쇄 블랙리스트 집합 × 표현 변형 코퍼스(AC-MVP-004의 ≥18케이스)에 대해 0건이어야 한다 (안전 비대칭).
- **API 무응답/타임아웃**: 사용자에게 한국어 오류 보고, 재시도 카운트에 포함.
- **한국어 지시의 다의성**: 파괴적 임의 추측 금지 + 대상 확인 요청 (REQ-MVP-036, AC-MVP-024).
- **왕복 시간 콜드 스타트**: 첫 턴 캐시 write는 판정 코퍼스에서 제외 (웜캐시 조건 — "왕복 시간 측정 방법" ③). 콜드 스타트 소요는 참고치로 별도 기록.

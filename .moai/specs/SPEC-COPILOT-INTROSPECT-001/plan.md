## §A. 접근 요약 (Context)

본 절은 **되돌리기 어려운 결정을 먼저** 배치한다. 빌드 순서(§B)와 리뷰 순서(§A.1)는 다르며, §A.2가 그 편차를 설명한다.

### §A.1 결정 우선순위 (리뷰 순서 — 빌드 순서 아님)

| 순위 | 결정 | 위치 | 왜 먼저 검토해야 하는가 |
|---|---|---|---|
| **1위** | **열거 가능성 판정과 그 정합성 게이트** — 어떤 열거원을 신뢰할 것인가, 신뢰의 기준은 무엇인가 | spec.md REQ-INTROSPECT-001/004/005 · ASSUMPTION-46/47 · **M1** | 이 SPEC의 존재 이유가 "그럴듯한 오판을 구조적으로 없애는 것"인데, 열거원을 반쯤 믿으면 **같은 결함을 새 표면에서 재생산**한다. M1 판정이 M2 이후 범위 전체를 좌우한다(GO/NEGATIVE 분기). |
| **2위** | **회신 스키마 형상** — `introspect`가 이름+타입만 나르는가, 절단 신호와 총계를 어떻게 표현하는가, `props`의 이름별 결과 형상 | spec.md REQ-INTROSPECT-002/013/014/015 · **M2** | 와이어는 콘솔 재배포를 요구해 되돌리기 비용이 가장 높다. **첫 배포 전에 형상을 확정해야 한다.** |
| **3위** | **요청 문법** — 동사 2개 분리와 `props`의 이름 목록이 커맨드 라인을 타는 방식 | spec.md §A.3 · REQ-INTROSPECT-016 · **M2/M3** | 와이어이며, 모호성이 남으면 `Executor 80` 같은 핵심 경로가 파싱 단계에서 깨진다. 2048바이트 예산도 여기서 결정된다. |
| 4위 | **서버 소비 형상** — 신규 좁은 포트 프로토콜의 시그니처, 게이트 배선 지점, 감사 주체 문자열 | spec.md REQ-INTROSPECT-018/022/023 · **M4** | Python 측이라 되돌리기 비용이 낮지만, 감사 주체에 값이 새어 들어가면 민감정보 경계가 무너진다. |
| 5위 | 테스트·코퍼스 축 확장, 프로브 CLI 도구 | **M3/M5** | 기계적 — 상위 결정이 확정된 뒤 자연히 따라온다. |

### §A.2 빌드 순서가 리뷰 순서와 다른 이유

빌드는 **M1(라이브 프로브)이 첫 마일스톤**이다. 이 저장소의 교훈 두 건이 그 순서를 강제한다:

- *"조회 가능 ≠ 조작 가능"* — 정적으로 확인되는 것과 실사격이 답하는 것은 다르다.
- *"정적 프로브가 답할 수 없는 것은 실사격만 답한다"* — 그리고 여기서 답이 필요한 질문(ASSUMPTION-46: 열거가 가능한가)은 문서·코드·룰북 어디에도 답이 없다. 룰북 grep 결과 핸들 접근자 API 문서 **0건**이다.

M1 결과가 부정이면 M2의 범위가 절반으로 줄어든다(§A.3). 따라서 M1은 조사이지 구현이 아니며, M2 착수 전에 반드시 닫힌다.

빌드 순서: **M1(프로브) → M2(응답기) → M3(와이어 문서 + Python 트윈) → M4(서버 소비 경로) → M5(회귀·경계) → M6(배포 + 라이브 검증) → M7(발견 산출물)**.

### §A.3 M1 게이트 — 두 분기 모두 유효한 출력

| 분기 | 조건 | M2 이후 범위 | 기록 방식 |
|---|---|---|---|
| **GO** | 열거원 하나 이상이 REQ-INTROSPECT-004 정합성 게이트 통과 | `introspect` + `props` 둘 다 | design.md §5에 채택 열거원과 그 근거 |
| **NEGATIVE** | 어떤 열거원도 게이트 미통과 | **`props`만** 출하. `introspect` 관련 REQ(001~005)는 `[DEFERRED]`로 재표기 | design.md §5에 시도한 사다리 전체와 각각의 실패 양상 |

**NEGATIVE는 실패가 아니다.** `props` 단독으로도 22회 라운드트립이 1~2회가 되고, "없다"의 근거가 개별 추측에서 **일괄 판독 기록**으로 바뀐다. 다만 `[DEFERRED]` 재표기는 spec.md 본문 편집이므로 manager-develop이 직접 할 수 없다 — 오케스트레이터 경유 manager-spec 재위임이 필요하다(§G B-2).

## §B. 마일스톤 (M1..M7)

### M1 — 라이브 열거 가능성 프로브 (cycle_type=ddd, 조사 중심 · **LIVE 필수**)

**목적**: ASSUMPTION-46/47/48/49를 닫는다. 코드 변경 0, 쇼파일 쓰기 0. ASSUMPTION-48(OSC 직접 회신)이 부정되면 M1은 중단하고 블로커를 보고한다(§F).

- **프로브 플러그인 작성**: 응답기와 별개인 일회용 Lua 플러그인. 대상 핸들 하나를 해석해 아래 사다리를 **전부** 시도하고, 각각의 결과(성공/실패, 반환 타입, 항목 수)를 한 회신으로 돌려준다. 사다리는 **후보이지 확립된 API가 아니다** — 전부 pcall 방어:
  1. `getmetatable(handle)` → 테이블인가 → `__index`가 **테이블**인가 → `pairs()` 순회 가능한가
  2. `pairs(handle)` 직접 (── `__pairs` 메타메서드가 있어야 성립)
  3. 카운트+이름 접근자 쌍 후보: `handle:PropertyCount()` + `handle:PropertyName(i)`, `handle:GetPropertyDisplayName(i)`, `handle:PropertyType(i)`
  4. 정수 인덱스 판독: `handle:Get(i)` — 이름이 아닌 색인으로 열거되는가
  5. 덤프 후보: `handle:Dump()` — **반환값**이 있는가(출력 부작용만 있고 반환이 없으면 무용 — §C.2 Printf 천장)
- **정합성 교차 대조(핵심)**: 같은 세션에서 동일 핸들에 대해 `prop`으로 판독 가능이 이미 확인된 이름들(Executor: `Index`·`Fader`; Sequence: `CurrentCue`)을 대조군으로 쓰고, 각 열거원의 결과가 그 이름들을 **포함하는지** 확인한다. 포함하지 못하는 열거원은 그 자리에서 폐기한다(REQ-INTROSPECT-004).
- **부작용 무변화 확인**(ASSUMPTION-49): 프로브 전후로 대상 오브젝트를 `state`로 재조회해 형상 무변화를 기록한다.
- **증거 채널**(ASSUMPTION-48): OSC 직접 회신만 허용한다. 서버측은 콘솔 링크의 왕복 헬퍼에 임의 커맨드 라인과 요청 id를 넘겨 프로브 플러그인을 호출하고 회신을 수신한다(기존 `server/tools/responder_roundtrip.py` 패턴 계승). OSC 직접 회신이 실패하면 M1은 중단하고 블로커를 보고한다 — `Store Macro` 폴백과 쇼파일 쓰기는 허용하지 않는다(§F).
- **대상 핸들 최소 집합**: `Executor <n>`(재생 중 1 + 정지 1), `DataPool/Sequences/<n>`, 그리고 대조용으로 클래스가 다른 핸들 1종(예: `DataPool/Groups/<n>`).
- **결정 게이트**: GO/NEGATIVE를 판정하고 design.md §5에 접어 넣는다. **판정에서 폴백하지 않는다** — 부정 판정 시 조용히 진행하지 않고 블로커로 보고한다(SCENE-001 M0의 규율 계승).
- 산출물: 프로브 로그(`.moai/state/verify/introspect-m1-*.log`), 프로브 Lua 소스, design.md §5 fold-in, ASSUMPTION-46~49 판정.

### M2 — 응답기 확장 (`props` 무조건 + `introspect` 조건부)

- `M.handle_request` 디스패치에 분기를 **가산 추가**한다. 기존 5개 분기와 회신 6종 kind는 무변경(REQ-INTROSPECT-012).
- `props`: 이름 목록 파싱(첫 토큰, 콤마 구분, 공백 불가) → 각 이름을 `M.safe_property` 경유 판독 → 이름별 결과 조립. **판독 실패는 정상 경로**이며 회신을 중단시키지 않는다.
- `introspect`(M1 GO 시): M1이 채택한 열거원 하나만 구현한다 — 사다리 전체를 옮기지 않는다. 채택원이 답하지 못하면 **명시적 실패 회신**(REQ-INTROSPECT-005), 빈 목록 성공이 아니다.
- **값·함수 취급**: 값의 Lua 타입만 노출하고 함수 타입은 **호출하지 않는다**(REQ-INTROSPECT-009). `tostring()`으로 타입만 확인.
- **예산 처리**: 기존 `build_snapshot`의 size guard 패턴을 그대로 따라 항목을 뒤에서 제거하며 `truncated` 신호를 세운다. `introspect`는 축소 이전 관측 총계를 별도 필드로 보존한다(REQ-INTROSPECT-015). `props`는 개별 값 축약 시 항목별 축약 표시(REQ-INTROSPECT-008).
- `M.VERSION` 1.5.0 → **1.6.0**. `M.PROTO`는 1 유지.
- **테스트**: `server/tests/lua_mock_env.py`의 lupa 하네스로 실제 플러그인 파일을 로드해 검증한다. 최소 축: 두 동사 각각의 성공/실패/절단, 함수 타입 필드 미호출, `Cmd()` 미호출, `prop`↔`props` 디스패치 비혼선(D-3).

## §C. 기술 제약

- **신규 런타임 의존성 0.** Lua 측·Python 측 모두 기존 표면 안에서 해결.
- **와이어 프로토콜 버전 1 유지.** 가산 추가만 허용(REQ-INTROSPECT-012).
- **요청 예산**: MA3 커맨드 라인 2048바이트(실측 고정). `props` 요청 전체(`Plugin "CopilotResponder" "props <id> <list> <path>"` 래퍼 포함)가 이 안에 들어야 한다.

## §F. 확정 결정 (run-phase 진입 전 해소 완료)

- **결정: `props` 이름 목록 상한 = 16.** 구속 제약은 요청측 2048B가 아니라 회신측 1900B다. plan-audit review-1의 2026-08-03 산술에 따르면 percent-encoding은 약 3배 팽창하고, 대표 성공 항목은 약 111B, 엔벨로프는 약 185B이므로 안전 적재는 약 15항목이다. 16은 전-성공+전형값 회신에서 약 2001B로 경계를 넘을 수 있으나 REQ-INTROSPECT-013/014의 절단 신호가 이를 포착한다. 실사용 판독 횟수(약칭 "22" — `research.md` §1의 카운트 약칭 정리 참조)는 2회 왕복으로 처리하며, M3 산술 고정 테스트가 이 상한을 최종 고정하고 M6이 실물 최대 길이 요청으로 확인했다.
- **결정: M1 매크로 폴백 불허 — 쇼파일 쓰기 0 유지.** 2026-08-03 사용자 결정에 따라 ASSUMPTION-48(OSC 직접 회신)이 부정되면 M1은 그 지점에서 중단하고 블로커를 보고한다. 이 경우 `introspect`는 DESCOPE하고, `props`만 출하한다.
- **결정: `console/lua/` PRESERVE 예외 승인 — 삭제줄 전문 고정 방식.** 2026-08-03 사용자 승인. `console/lua/`는 선행 SPEC(OVERLAP-001, AC-OVERLAP-019)이 잠근 10경로 중 하나이며 `origin/main`(3176900)까지 위반 0이었다. **본 SPEC이 최초 접촉**이고, 응답기 확장이 목적이므로 잠금과 정면 충돌한다. **이 SPEC 6문서 어디에도 이 잠금에 대한 언급이 없었고, plan-audit review-1의 D7(교차-SPEC 정합)도 잡지 못했다** — 감사의 갭이며 여기 기록한다(다음 SPEC의 D7은 PRESERVE 경로 목록을 대조 대상에 넣을 것).
  - **집행 형상**: 게이트를 끄지 않는다. `server/tests/test_overlap_preserve.py`의 `_SAFETY_ALLOWED_DELETED_LINES` 선례와 동일하게 — 가산은 허용, **삭제 9줄(`PROTOCOL.md` 5 + `copilot_responder.lua` 4)은 전문 고정**, 변경 파일 집합도 고정. 목록 밖 삭제·신규 파일은 게이트 사망. 추가 불변식 2건: 파일별 `added > deleted`(승인 근거가 "가산"이므로 축소는 승인 밖), `VERSION` 삭제 1줄 ↔ **출하 버전 추가 1줄** 대응(기대값은 응답기 소스의 `M.VERSION`에서 파생한다 — 리터럴로 박았더니 정당한 후속 범프에서 게이트가 깨졌다, 2026-08-03 실측).
  - **비공허성 실측**: 핀 1줄 제거 → 2 failed / 허용 파일 1개 제거 → 1 failed / 예외를 빈 dict로 → 3 failed / 복원 → 5 passed.
  - **M6 주의**: 재배포가 `console/lua/` 아래 다른 파일(예: `.xml` 래퍼)을 건드리면 게이트가 다시 운다. 그것이 의도한 비용이며, 목록 확장은 리뷰를 거친다.

### Decision: sub-agent (Mode 5, 순차)

### 정당화

마일스톤이 **직렬 의존**한다: M1 판정이 M2 범위를 정하고, M2 와이어가 M3 문서·트윈을 정하고, M3가 M4 포트를 정한다. 병렬화할 독립 축이 없다. 또한 라이브 콘솔은 **직렬 자원**이며(동시 접근 불가), M1·M6이 그 자원을 점유한다.

### 경계 사례

M5(회귀·경계)의 테스트 축들은 서로 독립이므로 그 안에서만 병렬 검증 배치가 유효하다 — 이는 오케스트레이터의 단일 턴 다중 Bash 검증 배치로 충분하며 별도 에이전트 팬아웃을 요구하지 않는다.

### 재위임 필요 지점 (B-2)

M1이 NEGATIVE면 spec.md의 REQ-INTROSPECT-001~005를 `[DEFERRED]`로 재표기해야 한다. manager-develop은 spec.md 본문을 편집할 수 없으므로, **오케스트레이터 경유 manager-spec 재위임**이 필요하다. 이 사실을 M1 완료 보고에 명시할 것.

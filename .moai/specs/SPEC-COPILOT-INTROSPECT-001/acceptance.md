# SPEC-COPILOT-INTROSPECT-001 — 인수 기준 (acceptance)

status: draft (v0.1.0, 2026-08-03) · Tier L · 본 문서는 spec.md의 요구를 관측 가능한 검증 기준으로 전개한다.

## §A. 개요

본 SPEC의 성공 기준은 두 층위다:

1. **무조건** — `props`(명시 이름 일괄 판독)가 출하되고, 읽기 전용·가산성·절단 신호·민감정보 경계가 훼손되지 않는다.
2. **조건부(M1 GO 시에만)** — `introspect`(열거)가 출하되고, 열거 결과가 정합성 게이트를 통과한다.

**부분 성공을 성공으로 위장하지 않되, 부분 성공을 실패로도 위장하지 않는다.** M1이 NEGATIVE면 AC-INTROSPECT-002/003/004는 미달성으로 정직하게 기록되고, 나머지는 전량 PASS여야 한다.

**라이브 표시 규율**: `(LIVE)`가 붙은 AC는 실물 onPC 2.4.2 왕복으로만 판정 가능하며, 소프트웨어 AC와 구분해 집계한다.

## §B. Given-When-Then 시나리오

### 시나리오 1 — 후보 추측이 일괄 왕복이 된다 (무조건)

- **Given** 두 동사를 포함한 응답기가 배포되어 있고, 코디네이터가 겪은 것과 동일한 후보 이름 집합을 Executor 핸들에 대해 판정하려 한다.
- **When** 개발자 진단 경로가 후보 이름들을 담은 `props` 요청 1건(상한을 넘으면 2건)을 보낸다.
- **Then** 이름별 판독 성공 여부·값 타입·값이 담긴 회신이 돌아오며, `Index`가 함수 타입임이 **값을 해석하지 않고도** 타입 필드로 드러난다. 라운드트립 횟수는 후보 수가 아니라 요청 수에 비례한다.

### 시나리오 2 — 핸들이 실제로 무엇을 노출하는지 되묻는다 (조건부: M1 GO)

- **Given** M1이 정합성 게이트를 통과한 열거원을 확정했고 `introspect`가 출하되어 있다.
- **When** `introspect`가 Sequence 핸들에 대해 실행된다.
- **Then** 필드 이름과 각각의 Lua 타입 목록이 돌아오고, **어느 열거원이 답했는지가 회신에 명시**되며, 그 목록은 `prop`으로 독립 확인된 `CurrentCue`를 **포함**한다.

### 시나리오 3 — 절단은 반드시 드러난다 (무조건)

- **Given** 회신이 페이로드 예산을 넘기는 크기의 대상 핸들이 있다.
- **When** 두 동사 중 하나가 그 핸들에 대해 실행된다.
- **Then** 회신은 항목이 축소된 채로 오되 **축소 신호가 세워져 있고**, `introspect`의 경우 **축소 이전 관측 총계**가 함께 온다. 축소 신호 없는 축소 회신은 발생하지 않는다.

### 시나리오 4 — 열거 불가는 명시적 실패이지 빈 성공이 아니다 (조건부: M1 GO)

- **Given** 채택된 열거원이 특정 핸들에 대해 답하지 못한다.
- **When** `introspect`가 그 핸들에 대해 실행된다.
- **Then** 회신은 명시적 실패이며, 필드 0개의 성공 회신이 아니다 — 소비자가 "필드가 없다"와 "열거하지 못했다"를 혼동할 수 없어야 한다.

### 시나리오 5 — M1 NEGATIVE 시 정직한 DESCOPE (조건부)

- **Given** M1 프로브가 어떤 열거원도 정합성 게이트를 통과시키지 못했다.
- **When** run-phase가 M1 완료 시점에 도달한다.
- **Then** `introspect` 관련 REQ는 `[DEFERRED]`로 재표기되고(manager-spec 재위임 경유), `props` 축은 그대로 진행되며, design.md §5에 시도한 사다리 전체와 각각의 실패 양상이 기록된다. **"열거는 불가능하다"는 결론이 실패가 아니라 정직한 조사 결과로 보고된다.**

### 시나리오 6 — 발견 산출물은 부정 결론도 유효하다 (LIVE)

- **Given** 자기진단 능력이 라이브로 검증되었다.
- **When** M7이 Executor·Sequence 핸들에 그 능력을 적용한다.
- **Then** 관측 기록과 함께 *"실행 여부·진행률에 해당하는 필드가 발견되었다 / 발견되지 않았다"*는 명시적 결론이 남는다. 후자도 DoD를 충족한다.

## §C. AC (GEARS 형식 — 통과 판정 방법을 각 AC에 명시)

### AC-INTROSPECT-001 — `props` 일괄 판독 (무조건)

**When** `props` 요청이 이름 목록과 경로를 담아 도달하면, the 응답기 **shall** 이름별 판독 결과를 하나의 회신으로 돌려준다.

- 대상 요구: REQ-INTROSPECT-006
- **통과 판정**: lupa 하네스 테스트 — 판독 가능 이름 2개 + 판독 불가 이름 2개를 섞은 요청이 4개 항목 전부를 개별 결과와 함께 반환. 판독 실패가 회신을 중단시키지 않음.

### AC-INTROSPECT-002 — 열거 회신 (조건부: M1 GO)

**When** `introspect` 요청이 해석 가능한 경로에 대해 도달하면, the 응답기 **shall** 필드 이름 집합과 각 이름의 Lua 값 타입을 회신한다.

- 대상 요구: REQ-INTROSPECT-001
- **통과 판정**: lupa 하네스 — 모의 핸들에 대해 이름·타입 쌍이 반환됨. + 라이브 왕복 1건.
- **M1 NEGATIVE 시**: 미달성으로 기록(N/A 아님 — 사유 명시).

### AC-INTROSPECT-003 — 열거원 출처 명시 (조건부: M1 GO)

The `introspect` 회신 **shall** 어떤 열거원이 답했는지를 담는다.

- 대상 요구: REQ-INTROSPECT-003
- **통과 판정**: 회신 페이로드에 출처 식별자 필드가 존재하고, 값이 M1에서 채택된 열거원과 일치. 출처 필드 부재 회신이 하나라도 있으면 FAIL.

### AC-INTROSPECT-004 — 정합성 게이트: 전량 채택 또는 전량 폐기 (조건부: M1 GO)

**When** 열거원의 결과가 동일 핸들에서 `prop`으로 독립 확인된 판독 가능 이름을 하나라도 누락하면, the 응답기 **shall** 그 열거 결과를 **전량 폐기**하고 부분 채택하지 않는다.

- 대상 요구: REQ-INTROSPECT-004 / ASSUMPTION-47
- **통과 판정**: lupa 하네스 — 대조 이름을 의도적으로 누락하는 열거원을 주입했을 때 결과가 부분 반환되지 않고 전량 폐기됨. **뮤테이션 필수**: 폐기 로직을 제거하면 이 테스트가 반드시 빨개져야 한다(통과하면 재료가 잘못된 것).

### AC-INTROSPECT-005 — 열거 불가는 명시적 실패 (조건부: M1 GO)

**When** 채택 열거원이 답하지 못하면, the 응답기 **shall** 실패로 회신하며 빈 목록 성공 회신을 하지 않는다.

- 대상 요구: REQ-INTROSPECT-005
- **통과 판정**: lupa 하네스 — 열거원 실패를 주입했을 때 회신이 실패 형상. 성공 형상 + 빈 목록이면 FAIL.

### AC-INTROSPECT-006 — 값 미노출 (열거 측) (조건부: M1 GO)

The `introspect` 회신 **shall not** 필드 값을 담는다.

- 대상 요구: REQ-INTROSPECT-002
- **통과 판정**: 회신 스키마 검사 — 값 필드 부재. + 코드 리뷰: 열거 경로가 값을 페이로드에 넣지 않음.

### AC-INTROSPECT-007 — `ok` 의미론 (무조건)

The `props` 회신 최상위 `ok` **shall** "요청이 처리되었다"만을 의미하며, 이름별 성공 여부는 항목별로만 표현된다.

- 대상 요구: REQ-INTROSPECT-007
- **통과 판정**: 전 이름이 판독 실패인 요청도 최상위 `ok`가 성공. `PROTOCOL.md` §4.8에 이 의미론이 명문화되어 있음(문서 검사).

### AC-INTROSPECT-008 — 값 축약 표시 (무조건)

**When** 개별 값이 항목 예산을 초과하면, the 응답기 **shall** 축약하고 해당 항목에 축약 사실을 표시한다.

- 대상 요구: REQ-INTROSPECT-008
- **통과 판정**: lupa 하네스 — 예산 초과 값 1건에 축약 표시가 세워짐. 표시 없는 축약 값이 있으면 FAIL.

### AC-INTROSPECT-009 — 읽기 전용: `Cmd()` 미호출 (무조건, 협상 불가)

The 두 동사의 처리 경로 **shall not** `Cmd()`를 호출한다.

- 대상 요구: REQ-INTROSPECT-009
- **통과 판정**: (a) lupa 하네스 — 두 동사 실행 후 모의 커맨드 로그가 **비어 있음**. (b) 정적 검사 — 신규 처리 경로 소스에 `Cmd(` 부재.

### AC-INTROSPECT-010 — 읽기 전용: 함수 필드 미호출 (무조건, 협상 불가)

The 응답기 **shall not** 열거·판독 과정에서 발견된 함수 타입 필드를 호출한다.

- 대상 요구: REQ-INTROSPECT-009
- **통과 판정**: lupa 하네스 — 호출되면 카운터를 올리는 함수 필드를 모의 핸들에 심고, 두 동사 실행 후 카운터가 0. **뮤테이션 필수**: 호출을 넣으면 빨개져야 한다.

### AC-INTROSPECT-011 — 실행 경로 미결합 (무조건)

The 두 동사 **shall not** `exec`/`deploy` 계열과 공유 분기를 갖고, 회신은 읽기 계열 주소로만 나간다.

- 대상 요구: REQ-INTROSPECT-010
- **통과 판정**: lupa 하네스 — 두 동사의 회신이 상태 회신 주소로 송신됨(모의 송신 캡처 확인). + 디스패치 코드 리뷰.

### AC-INTROSPECT-012 — 판독 전량 pcall 방어 (무조건)

The 필드 판독 **shall** 전부 pcall 방어되며, 미지 이름 판독 실패가 회신을 중단시키지 않는다.

- 대상 요구: REQ-INTROSPECT-011
- **통과 판정**: lupa 하네스 — 판독 시 raise하는 필드를 심어도 나머지 이름의 결과가 정상 반환.

### AC-INTROSPECT-013 — 가산성: 기존 동사·kind 무변경 (무조건, 협상 불가)

The 응답기 확장 **shall** 가산적이며 기존 5동사·6 kind 형상과 프로토콜 버전 1을 무변경 유지한다.

- 대상 요구: REQ-INTROSPECT-012
- **통과 판정**: 기존 responder 테스트 전량 PASS(무수정). + 회신 페이로드의 프로토콜 버전 필드가 1. + `PROTOCOL.md` §4.1~§4.6 diff 없음.

### AC-INTROSPECT-014 — 절단 신호 (무조건, 협상 불가)

**When** 회신이 예산을 초과하면, the 응답기 **shall** 항목을 축소하고 축소 신호를 세운다. 신호 없는 축소 회신은 존재하지 않는다.

- 대상 요구: REQ-INTROSPECT-013 / REQ-INTROSPECT-014
- **통과 판정**: lupa 하네스 — **상한을 확실히 넘기는** 재료로 축소를 유발하고 신호 확인. **뮤테이션 필수**: 신호 세우는 줄을 제거하면 빨개져야 한다. 재료가 상한 미만이면 이 AC는 무효(재료 선택 오류).

### AC-INTROSPECT-015 — 총계 보존 (조건부: M1 GO)

The `introspect` 회신 **shall** 축소 이전 관측 총계를 담는다.

- 대상 요구: REQ-INTROSPECT-015
- **통과 판정**: 축소된 회신에서 (총계 − 반환 항목 수) > 0이 계산 가능. 총계 필드가 반환 항목 수와 같으면 FAIL.

### AC-INTROSPECT-016 — 요청 예산 강제 (무조건)

The 서버 빌더 **shall** 이름 목록의 개수·길이 상한을 강제하고, 상한 초과 요청을 송신 전에 거부한다.

- 대상 요구: REQ-INTROSPECT-016 / ASSUMPTION-50
- **통과 판정**: (a) 상한 초과 요청이 빌더에서 거부됨. (b) **산술 고정 테스트** — 최대 요청 문자열 길이 ≤ 2048. (c) Lua CONFIG 상한과 Python 상한의 동치 테스트.

### AC-INTROSPECT-017 — 전 필드 값 덤프 모드 부재 (무조건)

The 본 SPEC **shall not** 한 요청으로 모든 필드 값을 돌려주는 모드를 제공한다.

- 대상 요구: REQ-INTROSPECT-017
- **통과 판정**: 코드 리뷰 + 와이어 문서 검사 — 그런 동사/플래그가 존재하지 않음.

### AC-INTROSPECT-018 — 감사에 값 부재 (무조건, 협상 불가)

The 감사 항목 **shall** 경로와 요청 이름만 담으며 판독된 값을 담지 않는다.

- 대상 요구: REQ-INTROSPECT-018
- **통과 판정**: `test_safety_console.py` 확장 — 고유한 감시 문자열을 값으로 돌려주는 모의 콘솔로 조회 후, 감사 로그 전체에 그 문자열이 **부재**. **뮤테이션 필수**: 값을 감사 주체에 넣으면 빨개져야 한다.

### AC-INTROSPECT-019 — 1 송신 = 1 감사 항목 (무조건)

**When** 조회가 타임아웃으로 실패해도, the 게이트 **shall** 이미 보낸 OSC 요청에 대한 감사 항목을 남긴다.

- 대상 요구: REQ-INTROSPECT-023
- **통과 판정**: 타임아웃 케이스에서 감사 항목 1건(실패 표시) 존재. 기존 `state_query`/`property_query`와 동일 규율.

### AC-INTROSPECT-020 — 포트 규율 + OSC 경계 무변경 (무조건)

The 서버측 소비 경로 **shall** 좁은 포트 → 게이트 → 링크 규율을 따르며, OSC 브리지 import 경계는 기준선 대비 무변경이다.

- 대상 요구: REQ-INTROSPECT-022
- **통과 판정**: `test_architecture.py` PASS + 경계 grep 기준선 대비 diff 없음.

### AC-INTROSPECT-021 — 툴 개수 18 유지 (무조건)

The 본 SPEC **shall not** LLM 대면 툴을 추가한다.

- 대상 요구: REQ-INTROSPECT-024 / 결정 D-4
- **통과 판정**: 툴 정의 개수 = **18**(기준선 동일). `build_toolset` diff 없음.

### AC-INTROSPECT-022 — `prop` ↔ `props` 디스패치 비혼선 (무조건)

The 디스패치 **shall not** `props` 요청을 `prop` 분기로, `prop` 요청을 `props` 분기로 처리한다.

- 대상 요구: 결정 D-3
- **통과 판정**: lupa 하네스 — 두 요청 각각이 자기 kind의 회신을 반환. 회신 kind가 교차되면 FAIL.

### AC-INTROSPECT-023 — 버전 범프 + 문서 동기화 (무조건)

**When** 응답기가 변경되면, the 변경 **shall** `M.VERSION` 범프와 `PROTOCOL.md` Revision note를 동반한다.

- 대상 요구: REQ-INTROSPECT-025
- **통과 판정**: 소스의 `M.VERSION`이 base(`1.5.0`)보다 높고, `PROTOCOL.md` 상단에 그 버전의 Revision note가 존재(기존 4건과 동일 형식) + §2 요청 표에 동사 행 추가 + §4 신규 kind 절 존재. **버전 리터럴을 이 AC에 고정하지 않는다** — 소인으로 인한 정당한 추가 범프(1.6.0 → 1.6.1)까지 계약 위반으로 읽히기 때문이다(2026-08-03 실제 발생: 게이트 테스트에 박아둔 `1.6.0` 리터럴이 1.6.1에서 깨졌다).

### AC-INTROSPECT-024 — 부작용 무변화 (LIVE, 무조건)

**While** 자기진단 조회가 수행되어도, the 대상 오브젝트 **shall** 변경되지 않는다.

- 대상 요구: REQ-INTROSPECT-009 / ASSUMPTION-49
- **통과 판정**: 라이브 — 조회 전후 대상 오브젝트를 `state`로 재조회해 형상 동일. 차이가 있으면 FAIL이며 즉시 블로커.

### AC-INTROSPECT-025 — 라이브 왕복 (LIVE, 무조건 / 열거 축은 조건부)

**When** 두 동사를 포함한 응답기가 배포되면, the 두 동사 **shall** 실물 콘솔에서 성공·실패·절단 각 1건 이상 왕복한다.

- 대상 요구: REQ-INTROSPECT-006 (+ M1 GO 시 REQ-INTROSPECT-001)
- **통과 판정**: 라이브 로그에 동사별 성공 1 / 실패(미존재 경로) 1 / 절단 1 기록. `props` 최대 길이 요청 1건 포함(ASSUMPTION-50 확정).

### AC-INTROSPECT-026 — 발견 산출물과 명시적 결론 (LIVE, 무조건)

**When** 자기진단 능력이 라이브 검증되면, the SPEC **shall** Executor·Sequence 핸들의 관측 기록과 함께 "실행 여부·진행률 필드의 발견/미발견" 결론을 남긴다.

- 대상 요구: REQ-INTROSPECT-019 / REQ-INTROSPECT-020 / ASSUMPTION-52
- **통과 판정**: progress.md §E.2에 관측 기록 + 명시적 결론 문장 존재. **"발견되지 않았다"도 PASS.** 모호한 "아마도"는 FAIL.

### AC-INTROSPECT-027 — 클래스 단위 안정성 판정 (LIVE, 무조건)

**When** M7이 동일 클래스의 서로 다른 인스턴스 최소 2개를 대조하면, the 기록 **shall** 필드 집합의 안정/불안정을 명시한다.

- 대상 요구: ASSUMPTION-51
- **통과 판정**: 2개 인스턴스의 결과 대조 기록 존재 + 안정/불안정 결론. 불안정이면 "클래스 단위 일반화 금지"가 후속 인계에 기록됨.

### AC-INTROSPECT-028 — 기능 미구현 경계 (무조건)

The 본 SPEC **shall not** 재생 상태·진행률·페이드 잔여시간을 소비하는 기능을 구현한다.

- 대상 요구: REQ-INTROSPECT-021
- **통과 판정**: 커밋 범위에 `server/web/**`·`ui/src/**` 변경 0건. `cue_monitor` 판독 경로 무변경.

### AC-INTROSPECT-029 — M1 판정의 정직한 처리 (무조건)

**When** M1이 GO 또는 NEGATIVE로 닫히면, the 판정 **shall** 근거와 함께 design.md §5에 명시적 결론으로 남는다.

- 대상 요구: spec.md §A.4 / plan.md §A.3 / ASSUMPTION-46
- **통과 판정**: design.md §5에 시도한 사다리 전체와 각각의 결과가 기록됨. 모호한 "아마도" 금지. NEGATIVE면 `[DEFERRED]` 재표기가 수행됨(manager-spec 재위임 경유).

### AC-INTROSPECT-030 — 전체 회귀 (무조건, 협상 불가)

The 전체 테스트 스위트 **shall** run-phase 킥오프 기준선 대비 신규 실패 0건이다.

- 대상 요구: 전 SPEC 공통
- **통과 판정**: pytest + vitest 전량. 기준선은 **run-phase 킥오프 시점에 재측정**한다 — plan-phase 수치 재사용 금지.

### AC-INTROSPECT-031 — Python 요청 빌더 검증 규율 (무조건)

The Python 트윈(`server/bridge/protocol.py`) **shall** `introspect`와 `props` 두 동사의 요청 빌더를 모두 제공하며, 기존 빌더와 동일한 검증 규율을 적용한다.

- 대상 요구: REQ-INTROSPECT-026 / REQ-INTROSPECT-016
- **통과 판정**: protocol 빌더 테스트 — 두 동사의 빌더 2종이 존재하고, 정상 입력으로 만든 요청 문자열은 단일 라인이며 큰따옴표를 포함하지 않음. 요청 id 토큰 패턴 위반, 큰따옴표 포함 입력, 개행 포함 입력, `props` 이름 목록 상한 초과는 모두 송신 전 거부되고, 이름 목록 상한은 Lua CONFIG 상한과 동치.

## §D. Edge Cases

- **필드가 0개인 핸들**: "필드가 없다"와 "열거하지 못했다"를 반드시 구분해야 한다(AC-INTROSPECT-005). 전자는 성공+빈 목록, 후자는 실패 — 이 둘을 한 형상으로 접으면 본 SPEC이 없애려는 오판이 그대로 남는다.
- **이름 목록에 중복이 있는 요청**: 중복은 collapse하되 응답 항목 순서는 요청 순서를 보존한다(`read_properties`의 기존 규율과 동일).
- **판독 중 값이 바뀌는 경우(재생 중 핸들)**: 조회 시점 스냅샷이며 TOCTOU 완화는 범위 밖 — 기존 상태 조회 seam의 일반 계약을 상속한다. 단 M1의 부작용 무변화 확인(AC-024)에서는 **정지 상태 핸들**을 대조에 쓴다(재생 중 핸들은 자연 변화하므로 대조군으로 부적합).
- **값에 콤마·따옴표·비ASCII가 포함되는 경우**: percent-encoded JSON이 이미 흡수한다. 단 회신 인코더의 이스케이프 클래스가 UTF-8 연속 바이트를 훼손하지 않는지는 기존 계약(1.1.0에서 수정된 바이트 명시 클래스)을 상속 확인한다.
- **이름 목록에 공백이 들어온 요청**: 첫-토큰 파싱이 깨지므로 서버 빌더가 **송신 전에** 거부해야 한다(AC-INTROSPECT-016). 콘솔측 파싱 실패에 의존하지 않는다.
- **배포 왕복 실패**: M6에서 Import 후 신규 kind가 예상과 다르게 관측되면 M2로 회귀하며 SPEC 실패로 집계하지 않는다.

## §E. Quality Gate 기준

- pytest/vitest 전체: run-phase 킥오프 기준선 대비 신규 실패 0건.
- `ruff check`: 터치 파일 전용 clean(기존 baseline 위반은 본 SPEC 무관으로 별도 표기).
- 신규 처리 경로에 `Cmd(` 부재(정적).
- 세이프티·오케스트레이터의 OSC 브리지 import 경계 grep: 기준선 대비 무변경.
- 툴 정의 개수: **18**.
- 응답기 기존 회신 kind 6종의 형상 회귀: 전량 PASS(무수정 테스트).
- 라이브 프로브 로그가 **읽기 전용임을 로그 자체에서 확인 가능**해야 한다(발화 0·쓰기 0). 매크로 폴백을 쓴 경우 생성된 객체 번호와 사용자 GUI 삭제 요청이 기록되어야 한다.
- 뮤테이션 필수 지정 AC 4건(004·010·014·018)은 각각 해당 로직 제거 시 반드시 빨개져야 한다 — 통과하면 재료 선택 오류로 간주하고 재작성한다.

## §F. Definition of Done

1. **M1 판정이 GO/NEGATIVE 어느 쪽이든 design.md §5에 근거와 함께 명시적으로 기록되어 있다** — 부정 결과도 DoD를 충족한다(AC-INTROSPECT-029).
2. **M1 GO인 경우**: M2~M7 완료, AC-INTROSPECT-001~031 전량 PASS 또는 사유가 기록된 N/A.
3. **M1 NEGATIVE인 경우**: `introspect` 관련 REQ가 `[DEFERRED]`로 재표기되고(manager-spec 재위임 경유), AC-INTROSPECT-002/003/004/005/006/015는 미달성으로 정직하게 기록되며, **나머지 AC 전량 PASS**. `props` 축은 완결된다.
4. **협상 불가 AC는 어느 분기에서든 문자 그대로 전량 PASS**: 009(`Cmd()` 미호출), 010(함수 미호출), 013(가산성), 014(절단 신호), 018(감사에 값 부재), 021(툴 18), 024(부작용 무변화), 028(기능 미구현 경계), 030(전체 회귀).
5. **AC-INTROSPECT-026의 결론 문장이 존재한다** — "발견되었다" 또는 "발견되지 않았다". 이것이 본 SPEC의 실질적 산출물이며, 모호한 서술은 DoD 미충족이다.
6. 재생 상태·진행률 **기능**이 구현되지 않았다(AC-INTROSPECT-028) — 후속 SPEC 권고만 기록된다.
7. `PROTOCOL.md`가 응답기 소스와 동기화되어 있다(AC-INTROSPECT-023) — 두 문서가 갈라진 채로 닫지 않는다.

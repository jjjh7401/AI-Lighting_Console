## 1. 확인 대상 넷 — 눈으로 볼 것

경로는 하나다: 앱에서 곡 확정 → `prepare_songcue` → 큐 저장.
`prepare_songcue` 는 별도 실행면이 아니라 `run_commands` 의 호출자다
(`server/orchestrator/tools.py:2937-2944`) — 승인 게이트·감사 로그가 같은 통로에 걸린다.

### A. 반복 후렴이 안 사라지는가
- 코드: 라벨마다 **1회차가 고른 룩을 기억**하고 2회차 이후가 되돌아온다 (`server/looks/songcue.py:459`, `server/looks/section_intent.py:234`).
- 회차 사이의 변화는 룩 교체가 아니라 **사다리**가 만든다: `dimmer_hit → zoom_pinch → iris_pinch`, 한 큐에 하나씩 (`songcue.py:93-110`). 밝기만 누적, 액센트는 갈아탄다.
- **눈으로**: 후렴 1과 후렴 2가 **같은 색·같은 자리**인데 후렴 2가 더 밝거나 빔이 더 좁다.
- **반증이면**: 후렴 2가 다른 색으로 갈아탔다 → §7 위반.

### B. 곡이 바뀌면 룩이 바뀌는가
- 코드: 다음 곡이 직전 곡 룩을 피하고, 피하지 못하면 `cross_song_looks.reused_look_ids` 로 **보고**된다 (`songcue.py:1178`).
- **눈으로**: 곡 A 마지막 큐와 곡 B 첫 큐의 색이 다르다.
- **주의**: 재사용은 실패가 아니라 보고 항목이다 — 보고가 비었는지도 같이 본다.

### C. 드롭 앞이 어두워지는가
- 코드: 드롭 직전 큐의 Dimmer 를 낮춘다. 바닥은 **20** (`DARKNESS_FLOOR`, `songcue.py:126`), 정본 §6 표의 최저값 인용이지 지어낸 숫자가 아니다.
- 못 뺀 경우는 버려지지 않고 **사유와 함께** 나온다 — 7종 (`songcue.py:65-73`): 선행 큐 없음 / 6행 없음 / 같은 6행 / 이미 어두움 / 디머 없음 / 큐 미저장 등.
- **눈으로**: 드롭 직전에 무대가 한 번 내려앉았다가 드롭에서 올라온다.
- **반증이면**: `withheld_darkness` 목록과 사유를 그대로 적어 온다 (사유가 판별기다).

### D. 무빙이 도는가 — 곡당 1큐 한계 포함
- 코드: **한 곡에 무빙은 정확히 한 큐**. 가장 센 대역, 같으면 이른 큐 = 사실상 드롭 (`songcue.py:662-701` `_movement_carrier`).
- 나머지 후보는 `MOVEMENT_TURN_BOUNDARY` 사유로 withheld — 같은 지시 턴에 두 번째 `Step 2` 가 들어가면 dedupe 가 접어 **페이저가 아닌 1스텝**으로 저장되기 때문.
- **눈으로**: 드롭 큐 **하나에서만** 무빙이 돈다. 다른 구간에서 도는 것을 기대하지 말 것.
- **반증이면**: 드롭에서 안 돌거나 / 두 큐에서 돈다.

## 2. 회차 순서

1. P1~P3 통과 확인
2. 곡 A 확정 → `prepare_songcue` → **감독 승인 후** 쓰기 → A·C·D 눈으로 확인
3. 곡 B 같은 방식 → B(곡 전환) 확인
4. 각 항목마다 withheld 보고(어둠·무빙)를 그대로 회수해 기록

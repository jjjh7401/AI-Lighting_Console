Worktree implementation status / Vectorworks → grandMA3

도면을 읽고, 불확실한 것만 묻는 자동 패치

AI Lighting Console은 Vectorworks export 또는 MVR을 콘솔의 실제 인벤토리와 대조합니다. 확정 가능한 부분은 자동으로 계획하고, Fixture Type·주소·FID처럼 위험한 빈칸만 사용자에게 묻습니다.

기준일 2026-08-11대상: grandMA3 onPC 2.4.2.x형태: 단일 HTML / 오프라인 열람 가능
결론
반자동 패치 워크플로는 구현·테스트 완료.

파일 판독, 콘솔 대조, 안전한 대화형 보완, Lua 실행 계획, 실행 후 읽기 재검증까지 동작합니다. 서버가 MA3 Patch Editor에 직접 쓰는 완전 자동 생성은 구현하지 않았고, 안전을 위해 하지 않습니다.

02 / 전체 구조

파일에서 검증까지의 흐름

자동화는 계획까지, 실제 쇼파일 쓰기는 사람의 최종 확인 뒤에만

“자동”은 사용자의 시간과 실수를 줄이는 범위입니다. 확인되지 않은 콘솔 쓰기를 추측으로 자동 실행하는 뜻은 아닙니다.

04 / 사용자 경험

질문은 실패가 아니라 안전장치입니다

좋은 자동화는 모르는 값을 채우지 않습니다. 이 시스템은 아래 순서로 사용자 시간을 최소화합니다. 정상 항목은 조용히 통과시키고, 쇼파일에 영향을 주는 결정만 명확한 선택지로 바꿉니다.

파일만 올립니다

도면 export나 MVR 파일을 업로드하면 대화 세션에만 유지됩니다. 모델이 파일 바이트를 다시 요구하지 않고 분석 도구가 직접 사용합니다.

차이만 봅니다

콘솔의 실제 Patch와 비교합니다. 이미 맞는 장비는 “이미 패치됨”으로 판단해 재생성 대상에서 제외합니다.

모르는 값만 답합니다

예: 라이브러리에 Fixture Type이 없음. 사용자는 콘솔에서 타입 선택, MVR/GDTF 제공, 해당 타입 건너뛰기 중 하나를 고릅니다.

안전한 계획을 검토합니다

주소·모드·FID 범위가 정리된 Lua 계획을 받습니다. 이 단계까지 서버는 읽기와 계획만 했습니다.

MA3에서 최종 실행합니다

실제 쇼파일 변경은 사용자만 수행합니다. 이 분리는 잘못된 타입/주소가 생방송 쇼에 반영되는 사고를 막습니다.

결과를 다시 읽습니다

서버가 콘솔 인벤토리를 다시 읽어 생성됐는지, 여전히 막혔는지, 무엇을 더 해결해야 하는지 보고합니다.

05 / 안전 경계

의도적으로 하지 않는 일

서버가 하는 일

  • 파일을 판독하고 설계상의 장비 목록을 만듭니다.
  • 현재 콘솔의 장비·주소·라이브러리를 읽고 충돌을 찾습니다.
  • 안전하게 결정할 수 있는 값만 계획에 넣습니다.
  • 누락 정보를 질문 카드로 바꾸고 답에 따라 다시 계획합니다.
  • Lua를 만들어 사람이 실행한 뒤 실제 결과를 읽어 검증합니다.

서버가 하지 않는 일

  • 사용자 없이 AddFixtures를 실행하지 않습니다.
  • 없는 Fixture Type을 비슷하다는 이유만으로 임의 매핑하지 않습니다.
  • GDTF 파일을 콘솔 라이브러리에 몰래 설치하지 않습니다.
  • 콘솔이 오프라인, 라이브 잠금, 승인 부재일 때 실행 경로를 우회하지 않습니다.
  • 응답이 불확실한 OSC 명령을 자동 재전송하지 않습니다.

이 경계는 기능 부족을 숨긴 문구가 아닙니다. 실제 onPC에서 서버 경로의 AddFixtures 시도는 장비 생성 0대로 끝났고, 성공 여부를 확정할 수 없는 쓰기를 자동화하지 않는 쪽을 제품 결정으로 채택했습니다.

07 / 아직 남은 일

구현하지 못한 것과 필요한 조건

항목상태왜 아직 아닌가다음에 필요한 것
서버가 Patch Editor에 직접 장비 생성미구현 · 의도적실 onPC의 서버 실행 경로에서 픽스처가 0대 생성됐다. 생성 여부가 불확실한 쓰기를 자동화할 수 없다.MA3가 지원·검증한 안전한 생성 API/실행 컨텍스트 또는 사용자가 Patch Editor에 진입한 라이브 절차.
누락 Fixture Type 자동 해결미구현 · 금지이름이 비슷해도 DMX 모드·footprint가 다르면 잘못 패치된다.사용자 콘솔 선택, 정확한 type alias, 또는 MVR/GDTF 제공과 MA3 라이브러리 등록.
실물 쇼에서 장비 생성까지 종단 검증미완료라이브 시험은 파일 분석·질문 카드까지 확인했다. 누락 타입이 있어 생성 단계는 의도적으로 멈췄다.모든 대상 Fixture Type이 콘솔 Library에 있는 쇼와, 최종 실행을 수행할 운영자.
GDTF 콘솔 자동 설치미구현콘솔의 파일 설치·Library 반영은 작업자 확인이 필요한 외부 변경이다.사용자가 ~/MALightingTechnology/gma3_library/fixturetypes에 배치하고 Library에서 확인.
릴리스 공증·자동 업데이트·Windows 배포기반만 구현macOS arm64 PyInstaller/Tauri 기반은 있으나 실제 인증서·Windows 빌드 호스트·Stage-2 auto-update는 없다.Developer-ID 인증서, Windows CI/빌드 호스트, auto-update 설계와 검증.

10 / 운영자가 다음에 할 일

실사용 전 준비 체크

도면을 패치 후보로 만들 때

  1. Vectorworks에서 Instrument Data export 또는 MVR을 만듭니다.
  2. UI의 VWX 파일 버튼으로 업로드합니다.

  2. 안전한 복구 지점의 쇼파일에서 작업합니다.
  3. 사용자가 MA3에서 최종 실행합니다.
  4. 시스템이 다시 읽어 “생성됨 / 아직 보류” 결과를 확인할 때까지 기다립니다.

M0~M5 전 마일스톤 완료라이브 비전 스모크 통과main 머지 완료

이번 작업의 목표는 조명감독이 배치 스케치(그림·레퍼런스 사진·도면 낙서)를 채팅에 붙이면, 코파일럿이 그 그림의 구조를 읽고 배치 계획을 제안하는 것이었습니다. 그림을 "잘 알아맞히는" 것이 아니라 정직하게 읽는 것이 핵심입니다 — 그림에 적힌 글씨("간격 2m", "MMX x6")는 데이터로 쓰고, 그림에 없는 수치는 절대 지어내지 않고 질문으로 넘깁니다. 실제 콘솔에 쓰는 것은 기존 승인 경로 (arrange_fixtures) 그대로이므로 새 쓰기 표면은 0개입니다.

사용자가 보게 되는 흐름

1
첨부 — 채팅 입력창의 단일 첨부 버튼으로 이미지를 올립니다. 파일 종류가 목적지를 결정합니다 (이미지 → 배치 분석, CSV/XLSX → 벡터웍스 패치). 썸네일과 업로드 확인 알림이 뜹니다. PLAN
2
분석 — analyse_layout_image 툴이 비전 모델을 1회 호출해 구조 사양(패턴·겹·대수·대칭·주석·미해결 항목)을 뽑습니다. 콘솔로는 아무것도 보내지 않습니다. PLAN
3
질문 — 그림 어디에도 없는 값(예: "삼각형 한 변 길이")은 기존 질문 카드로 하나씩 확인합니다. 모델이 값을 지어내는 것은 금지. PLAN
4
승인 — 승인 카드에 그림 속 글씨의 원문과 해석을 나란히 보여줍니다 ("삼각형 간격 3m" → spacing 3.0). OCR 오독은 여기서 사람이 잡습니다. 승인
5
실행 — 승인 후에만 기존 arrange_fixtures(백업 → 쓰기 → 재검증) 단일 경로로 좌표를 기록합니다. LIVE

지키기로 한 원칙 (위반은 결함)

원칙의미
구조는 읽고, 픽셀 수치는 읽지 않는다그림의 비율에서 치수를 추정하는 출력은 금지. 수치 출처는 (a) 그림 속 글씨, (b) 조명감독의 답변 둘뿐.
그림 속 글씨는 데이터다단, 승인 카드에 원문·해석을 나란히 노출해 오독("2m"→"12m")을 사람이 잡게 한다.
비전 결과는 제안이다실행은 기존 arrange_fixtures 단일 경로. 새 콘솔 쓰기 표면 금지.
base64는 대화 컨텍스트에 넣지 않는다세션이 바이트를 보관하고, 비전 호출 시에만 어댑터가 이미지 블록으로 첨부.
추측 금지그림이 대상 픽스처를 지정하지 않으면 반드시 질문. 이미지를 못 읽는 프로바이더(claude_code)는 조용히 버리지 않고 정직하게 거부.

이번에 만들어진 것

M1 — 업로드 채널

WebSocket 메시지 layout_image_upload를 서버·UI 양쪽 허용목록에 동시 등록. MIME은 PNG·JPEG·WebP만, 디코드 후 5MB 상한. 위반은 오류로 거부하고 세션에 보관하지 않습니다. 세션은 최신 1장만 보관(교체형)하며, 저장·영속화 없이 접속 수명과 함께 사라집니다.

M2 — 프로바이더 이미지 배선

UserMessage에 images 필드를 기본값 빈 튜플로 추가 — 기존 코드는 무변경 동작. anthropic 어댑터는 이미지 블록 배열로, gemini 어댑터는 Part 바이트로 조립. claude_code 어댑터는 이미지를 조용히 버리는 대신 "이 프로바이더는 이미지를 읽을 수 없다"고 정직하게 답합니다.

M3 — analyse_layout_image 툴

세션 보관 이미지 + 감독의 설명을 받아 비전 1회 호출로 구조 사양 JSON (pattern/layers/symmetry/confidence/annotations[원문+해석 쌍]/unresolved)을 반환. 콘솔 실행 동사 0개.

M4+M5 — 세션 배선 + 통합 테스트

업로드→분석→질문→승인→arrange 전체 흐름을 mock 프로바이더 스크립트로 관통하는 통합 테스트 1건 포함, 총 38개 테스트(크기·MIME 거부, 어댑터별 와이어 페이로드, 정직 거부, 주석 쌍 노출, 미해결 질문 라우팅).

UI — 첨부 버튼 통합

이미지용·CSV용 버튼을 따로 두지 않고 하나의 첨부 버튼으로 합쳤습니다. 파일 확장자/MIME이 목적지(배치 분석 vs 벡터웍스 패치)를 자동으로 결정합니다.

라이브 스모크 — 실제 비전 모델로 확인한 것

✅ 2026-08-15 통과 (gemini-3.5-flash, 10.8초) — 삼각형 3개 × MMX 3대, 손글씨 주석 3종이 든 테스트 이미지.
  • 주석 OCR 3종 전부 정확: "삼각형 간격 3m"→spacing 3.0 · "H 5.5m"→z 5.5 · "MMX x3"→count+type, 삼각형별 적용 구분까지.
  • 지어내지 않음: 그림에 없는 "삼각형 한 변 길이"는 unresolved로 넘어가 질문 대상이 됨. 픽셀 추정 수치 0건.
  • 어휘 밖 값을 발명하지 않음: 패턴 어휘에 triangle이 없어 rows + 레이어 노트로 강등 표현 — 설계 의도대로의 정상 동작.

개선 제안

1. triangle 패턴 프리셋 추가 (스펙에 이미 v2 후보로 기록됨)

지금은 삼각형 그림이 rows로 강등되어 삼각형 꼭짓점 좌표를 실제로 만들 프리셋이 없습니다. 스모크에서 정확히 읽어낸 구조를 실행으로 못 잇는 것이 현재 가장 큰 간극입니다. 추가하려면 어휘·검증·spatial/presets.py·arrange_fixtures 프리셋 목록이 함께 넓어져야 합니다 (계약 §3 + ARRANGE_PRESETS).

2. 실기 1턴 왕복 스모크

라이브 스모크는 비전 분석까지만 실측했습니다. 실제 onPC + 실제 프로바이더로 업로드→분석→질문 답변→승인 카드→arrange 실행→좌표 재검증을 한 턴으로 관통하는 실기 확인이 남아 있습니다. SPATIAL 결함 2(무승인 좌표 기록)의 전례를 볼 때, 승인 카드가 이 경로에서도 실제 렌더되는지 사람 입회로 보는 것이 값어치가 큽니다.

3. 확신도(confidence)의 UI 노출

구조 사양에 confidence가 있지만 승인 카드에서 감독이 보는지 확인이 필요합니다. 낮은 확신의 패턴 판독은 주석 원문-해석 쌍처럼 시각적으로 구별해 주면 "모델이 자신 없어 하는 부분"을 승인 단계에서 더 빨리 잡을 수 있습니다.

4. 업로드 UX 소소한 것들

  • 드래그앤드롭 / 클립보드 붙여넣기 — 스케치는 사진 찍어 바로 붙이는 경우가 많아 첨부 버튼보다 자연스럽습니다.
  • 교체 알림 — 세션이 최신 1장만 보관하므로, 두 번째 업로드가 첫 장을 조용히 덮습니다. "이전 이미지를 교체했습니다" 안내가 있으면 혼동을 줄입니다.
  • 5MB 초과 시 클라이언트 사전 안내 — 서버 거부 전에 UI에서 크기를 먼저 알려주면 왕복이 줄어듭니다. (요즘 폰 사진 원본은 5MB를 쉽게 넘습니다 — 클라이언트 측 리사이즈도 후보.)

5. 스펙 상태 문구 동기화

spec.md는 status: in-progress이고 CHANGELOG는 "라이브 스모크만 남음"이라 적혀 있는데, 스모크는 이미 통과했습니다. v1 범위 기준으로는 완료 조건이 대부분 찼으므로 completed 전환(또는 실기 1턴을 명시적 잔여로 남기는 개정)을 정리해 두면 다음 세션 혼선이 없습니다.

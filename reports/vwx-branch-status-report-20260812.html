01 개요

원래 목표는 하나의 문장이었다 — "Vectorworks에서 설계한 장비를 조명 콘솔에 자동으로 패치하고, 문제가 생기면 사용자에게 대화로 물어서 수동 개입을 받는다." 이 목표는 세 SPEC으로 쪼개져 구현됐다.

SPEC담당 범위상태

가장 중요한 단일 발견

원래 목표는 서버가 콘솔의 AddFixtures를 직접 실행하는 완전 자동 패치였다. AUTOPATCH-001 M0 라이브 프로브가 서로 다른 실행 경로 10가지·인자 조합 8종을 전부 실측한 결과 전량 0건 생성 — 서버 단독 트리거로는 원리적으로 되지 않는다는 것이 실측으로 확정됐다. 그래서 v0.1.3에서 반자동 모델로 설계를 전환했다: 서버가 계획을 생성 → 사람이 콘솔에서 직접 실행(Patch 편집기가 열려 있어야 함) → 서버가 재조회로 검증. 이것은 실패가 아니라 정확히 사용자가 최초에 요청한 그 형태다 — "자동 패치에 문제가 생기면 사용자에게 일부 수동을 요청". 다만 "문제가 생기면"이 아니라 "항상" 사람의 마지막 실행 클릭이 필요하다는 점이 원래 기대와 다르다.

이번 세션이 발견한 두 번째 플랫폼 한계

OSC 설정 화면의 Interface 드롭다운(어느 네트워크 어댑터로 OSC를 받을지)은 onPC 2.4.2에 명령줄·파일 경로가 전혀 없는 GUI 전용 기능이다 — 라이브 검증: Set 'ShowData'.'OSCBase' 'Interface' "lo0" 및 정수형 1 둘 다 Illegal value. 해법으로 템플릿 쇼파일(CopilotOscTemplate.show)을 만들어 New Show 대신 그 파일에서 Save As로 시작하면 Interface 설정이 쇼파일에 저장돼 함께 따라오도록 우회했다 — 사용자 클릭 0건. 단, New Show로 시작하면 여전히 GUI 클릭 1회가 필요하다.

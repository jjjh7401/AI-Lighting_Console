0. 한눈에

이 보고서는 새 SPEC(SPEC-LDBEAT-001)이 무엇을 만들고, 콘솔로 보내는 부분을 어떻게 만들지 정리한 거예요. 송신 장치(emitter — 앱의 데이터를 콘솔 명령 줄로 바꿔 보내는 부분)가 핵심이에요.

감독이 런북 모드에서 곡을 역할 6개 × 마디 격자로 보고, 칸을 고치고, 승인 한 번으로 콘솔에 보내는 기능이다. 보낸 결과는 콘솔에 역할별 시퀀스 6개 + 트랙 6개짜리 타임코드 1개로 만들어지고, 타임코드를 재생하면 마디에 맞춰 각 역할이 따로 움직인다.

새 송신 장치는 완전히 새로 짜지 않는다. 앱에는 이미 곡 큐용 타임코드를 만드는 코드(server/looks/songcue.py, 트랙 1개)와 승인 게이트가 있다. 새 장치는 그 부품(빈 번호 판독·이름 규칙·승인 경로)을 그대로 쓰고, 트랙을 여러 개로 늘리고 트랙마다 박자 이벤트를 심는 부분만 새로 만든다. 그 명령 꼴은 t520 이 실기에서 이미 돌려 본 것이다.

1. 무엇을 만드나 — 감독이 쓰는 흐름

감독님이 실제로 쓰게 될 순서예요. 다섯 단계 모두 런북 모드 안에서 일어나요.

단계감독이 하는 일앱이 하는 일
1. 보기런북 모드에서 곡을 연다격자 표시 — 행은 4마디, 열은 SCENE · BACK PULSE · SIDE CHASE · MOVER-U · MOVER-D · ACCENT. 처음엔 0~25마디
2. 고치기칸을 눌러 바꾼다(예: 「11~13마디 MOVER-U 를 틸트 웨이브로」)화면은 문장만 만들고 서버가 검사·적용한다. 틀린 값은 이유 하나를 대며 거절. 되돌리기 20단계
3. 승인승인 카드에서 명령 묶음 전체를 한 번 본다구간(묶음) 단위로 명령 파일 하나 — 칸마다 따로 묻지 않는다
4. 보내기—승인한 바이트 = 실제 보낸 바이트인지 대조(t512 비교기 로직). 다르면 실패로 표시
5. 재생콘솔에서 타임코드를 되감고 재생, 음원을 같이 튼다스피드 마스터 BPM 은 「콘솔에서 직접 설정」 안내만(자동 설정 방법 미확인)
  • 실기 미확인 모양(서클·발리후)은 칸에 「⚠ 실기 미확인」 표시. 곡 기본값으로는 넣지 않고, 확인 전에는 보내지 않는다.
  • 코파일럿 메인 화면과 기존 런북 블록 다섯 개(헤더·컨셉·큐시트·곡 타임라인·게이트 바)는 그대로 둔다. 격자는 새 블록이다.

3. 만드는 순서 — 단계마다 감독이 보는 것

마일스톤(milestone — 중간 완료 지점)마다 감독님이 무엇을 보게 되는지 함께 적었어요. 콘솔에 쓰는 단계는 M1 과 M4 둘뿐이에요.

마일스톤내용콘솔 쓰기감독이 보는 것
M1 프로브실기 미확인 넷을 작은 시험으로 가른다: ① 타임코드 트랙 3개 이상 ② 그룹 하나 선택 페이저가 큐에 저장되나 ③ 같은 그룹의 다른 속성을 두 시퀀스가 잡으면 섞이나 ④ 서클·발리후있음(승인 파일 → 「실행」, 새 번호만)깜박임·혼선·모양을 눈으로 판정
M2 격자 화면·저장격자 블록, LOVE ATTACK 기본값, 저장 위치 확정없음화면 모양(와이어프레임) 확인
M3 편집 연산마디·역할 단위 고치기, 화이트리스트·거절 사유없음칸 고치기·되돌리기
M4 송신새 송신 장치 + 승인=송신 대조 앱 이식있음0~25마디 실기 재생(음원과 함께)
M5 미확인 표시⚠ 표시, 기본값 제외없음표시 확인
M6 BPM 안내「콘솔에서 직접 설정」 안내없음문구 확인

M1 결과가 M4 의 설계를 바꿀 수 있다 — 특히 ①이 실패하면 트랙 6개 대신 다른 묶음 방식이 필요하다(§4-5).

예시 — 18마디 1박(0:37.9)에 BACK PULSE 가 「킥 박 100%」로 바뀐다면, 시각은 앞 여유 3초 + (18×4)×60/112.35 ≈ 41.45초예요. 송신 장치는 BACK PULSE 시퀀스에 그 큐를 만들고(Group 4 ; … 한 줄 → Step 2 → Store Sequence), BACK PULSE 트랙에 Store Property 'Time' 41.45 … 'Go+' 이벤트 하나를 심어요. 박 수만으로 센 값은 41.45초지만, 음악 지도의 실제 18마디 첫 박은 37.9초라 다운비트 위상(약 0.5초)을 빼면 40.9초가 돼요 — t520 이 실기에서 쓴 이벤트에도 40.9초가 있어요. 앱은 마디표의 실제 시각을 써야 해요.

### 4-1. 위치와 경계

  • 새 모듈 하나(가칭 server/looks/beat_grid_emit.py)를 songcue.py 옆에 둔다.
  • 연출 경로 server/director/emit.py 와 그 재생 계약(manual_go·trig_time)은 손대지 않는다. 기존 큐시트 재생은 그대로 돈다.
  • 곡 큐 경로에서 가져다 쓰는 것: 빈 번호 판독(timecode_slot_verdict, 시퀀스 빈 번호 고르기), ASCII 이름 정리(_ascii_label), 승인 게이트 경로.
  • 입력은 서버에 저장된 격자 하나뿐이다. 화면이 명령을 직접 만들지 않는다.

### 4-2. 입력 → 출력

입력(격자): 곡 BPM(112.35)·다운비트 위상, 그리고 역할마다 「몇 마디 몇 박에 → 무엇으로」 바뀌는 칸 목록. 칸 하나는 고정값(밝기·색·위치) 또는 반복 동작(펄스·체이스·움직임 — 모양·주기 박 수·축·위상) 중 하나다.

출력(명령 묶음, 승인 파일 한 개) — 묶음 순서는 t520 이 실기에서 돌린 것과 같다:

묶음내용실기 근거
① 역할 시퀀스 6개역할마다: 큐마다 Group N ; Attribute … At …(선택 한 줄) → 반복 동작이면 Step 2 값 + 속도·주기 → Store Sequence S Cue k '<라벨>' CueFade f → ClearAll. 끝에 Set Sequence S Property 'Name' '<곡명> - <버전> <역할>'[잰 것] t520 승인 파일 587줄, Store Sequence 22 · 이름 줄
② 타임코드 뼈대Store Timecode T · 이름 · Duration · Store Timecode T.1 · 역할마다 Assign Sequence S At Timecode T.1.i[잰 것] t520 트랙 2개, t516 트랙 2개
③ 트랙 이벤트트랙마다 Store Type 'CmdSubTrack' Timecode T.1.i.1 → 그 안에 바뀌는 시각마다 Store Property 'Time' t 'AbsTime' t 'Token' 'Go+'[잰 것] t520 트랙당 이벤트 7·15개, 계획 시각 뒤 첫 표본(≤0.7초) 안에 큐 진행
④ 재생(별도 승인)Top Timecode T → Go Timecode T, 음원은 앞 여유 3초 뒤 시작[잰 것] Top 이 0.00 으로 되감음, 음원 띄운 시각 TC 3.002초

시각 계산: 마디·박 → 초 = 앞 여유 3초 + (마디 × 4 + 박) × 60 / BPM. 반복 동작의 주기도 박 수로만 적고, 실제 속도는 스피드 마스터 15(112) 에 묶는다.

### 4-4. 승인과 대조

  1. 격자 → 명령 묶음 생성(서버).
  2. 가짜 콘솔 리허설 → 대조 PASS 확인.
  3. 승인 카드: 묶음(구간) 단위로 한 번.
  4. 송신 → 감사 로그의 실제 보낸 줄을 재구성 → 승인 파일과 sha256 동일 + 설명 안 되는 줄 0건이어야 성공. 비교 로직은 approval_vs_sent.py 를 바이트 그대로 앱 모듈로 옮긴다(새로 발명하지 않는다).

### 4-5. 방식 비교

방식내용장점단점
A. 새 모듈 + 곡 큐 부품 재사용 (권장)위 4-1~4-4기존 큐시트·연출 재생이 안 흔들린다. 실기로 돌려 본 명령 꼴 그대로모듈 하나가 늘어난다
B. emit.py 에 타임코드 방식 추가연출 경로 재생 계약을 넓힘장치가 하나기존 연출 재생 경로를 다시 검증해야 한다
C. songcue.py 를 직접 확장곡 큐 경로에 트랙·이벤트 추가코드가 가장 적다기존 곡 큐 생성(LDRENDER 결과)과 섞여, 옛 연출과 리듬 연출을 나란히 비교하기 어려워진다

M1 ①(트랙 3개 이상)이 실패하면: 트랙을 둘로 줄이고 나머지 역할 시퀀스는 SCENE 큐의 명령으로 함께 출발시키는 방법이 후보다. 다만 큐 명령 방식은 실기에서 잰 적이 없다.

6. 안 잰 것과 남은 위험

재 보지 못한 것을 따로 적었어요 — 확인된 것처럼 읽히지 않게요.

  • 타임코드 트랙 3개 이상, 그룹 한 선택 페이저 저장, 다른 속성 겹침, 서클·발리후 — 모두 M1 이 잰다. 그 전에는 해당 송신을 열지 않는다.
  • 곡 큐 경로의 부품을 그대로 쓸 수 있는지는 코드만 읽었다. 함수 경계(인자·반환)가 격자에 맞는지는 M4 설계 때 확인한다.
  • 스피드 마스터 BPM 을 곡과 함께 싣는 방법(G9)은 모른다 — 감독이 콘솔에서 직접 맞춘다.
  • 음원과 타임코드 동기는 t520 의 재생 스크립트(앱 밖)로만 맞춰 봤다. 앱 안에서 음원을 같이 트는 것은 이 SPEC 범위가 아니다.
  • 전곡(26~82마디)을 한 묶음으로 보낼 때의 명령 줄 수·쓰기 시간은 안 쟀다(0~25마디가 587줄).
